ailx10说：这篇是我2023年10月写的。这个 WebLogic 实验，我给自己分了两步：先写文件，再做进程执行。请求进到 WLS 的 SOAP 接口后，XMLDecoder 处理输入的方式成了重点；能在磁盘上看见文件，比只盯着 HTTP 状态更容易确认发生了什么。后面页面返回 500，连接却仍然出现，也算是一次挺直接的提醒：异常响应不代表前面的动作没有执行。这篇把两条验证路线并排留下，方便以后回看时，知道每个现象到底支持哪个结论。

---

原案例分析 WLS Security 对输入 XML 的反序列化处理；具体版本、组件与补丁适用性须单独核对。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

实验结束后可在确认项目目录和 Compose 配置后关闭该项目的服务；原文的全局 Docker 清理命令已移除。

访问出现 404 只说明有 HTTP 响应，不能单独证明漏洞环境已经就绪。
