ailx10说：这篇是2020年7月之前写的，后来又改过。内网信息收集的第一篇，我先围着一台主机转：网络、软件、服务、用户、端口、补丁、共享和代理，能问的都逐项问一遍，再往域和其他存活主机扩展。把命令堆在一起其实很容易，难的是知道每个输出下一步能帮我判断什么，所以我把批处理和用途一起记。里面也有当时的拼写和命名小毛病，现在看很有初学痕迹。它更像一张检查单，提醒我先认识所在环境，不要看到一个常见端口就急着猜漏洞。

## 一、手动收集信息

最最最基本的命令，了解一下就行了，实战都要靠储备的油猴子脚本。

1、查询网络配置信息（入门级）

```
ipconfig /all
```

![](/notes-assets/874b1658decb6c423efc.webp)

2、查询操作系统和软件信息（入门级）

```
systeminfo | findstr /B /C:"OS 名称" /C:"OS 版本"
```

![](/notes-assets/4ef0c29b13d035456419.webp)

```
echo %PROCESSOR_ARCHITECTURE%
```

![](/notes-assets/940832b4e4f8465d151c.webp)

```

```

![](/notes-assets/7ec2256eb045a8bd3d70.webp)


![](/notes-assets/41f856bbedfd462a4547.webp)

## 五、探测域内存活主机

1、利用NetBIOS快速探测内网（软件需要下载）

```

```

![](/notes-assets/1cf8c6786398f70fcbc1.webp)

2、利用ICMP协议快速探测内网（贼鸡儿慢）

```
for /L %I in (1,1,254) DO @ping -w 1 -n 1 192.168.160.%I | findstr "TTL"
```

4、端口Banner信息（nc是个好东西）

获取服务端的Banner信息后，可以在漏洞库中查找对应CVE编号的POC、EXP，检测漏洞是否存在，从而有针对性的进行安全加固。

```
nc -nv 127.0.0.1 22
```

![](/notes-assets/dd97e7d16c6c914ce355.webp)

- 文件共享服务端口（21、22、69、2049、139、389）
- 远程连接服务端口（22、23、3389、5900、5632）
- Web应用服务端口（80、443、8080、7001、7002、8089、9090、4848、1352）
- 数据库服务端口（3306、1433、1521、5432、6379、5000、9200）
- 邮件服务端口（25、110、143）
- 网络常见协议端口（53、67、68、161）

5、Nmap主机扫活（重头戏）

```
nmap -sP 192.168.160.1/24
```
