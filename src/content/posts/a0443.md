ailx10说：这篇是2022年1月之前写的，后来又改过。换 vssadmin 再做一次卷影副本，我在 Server 2012 上创建副本，然后从图形界面找到对应位置，把 NTDS 复制出来。和 ntdsutil 那篇对照起来，底层思路相近，操作入口却不一样。笔记保留了我当时怎么找到文件的过程，也留下了清理副本的步骤。现在看，收尾反而值得格外小心：不能为了删实验副本，顺手把不相干的旧备份删了。拿到一份正在使用文件的快照，只完成了数据获取这一段，后面分析又是另一件事。

---

- 创建和删除卷影拷贝
- 列出卷影拷贝的信息
- 显示已安装的所有卷影拷贝写入程序（writers）和提供程序（providers）
- 改善卷影拷贝的存储空间的大小

原文通过图形界面找到副本，但没有提供完整的复制命令；以下是当时观察记录。

![](/notes-assets/7456e42f1f705cc6831e.webp)

第一步：创建卷影拷贝

```
vssadmin.exe create shadow /for=c:
```

![](/notes-assets/b5aa99bfc49092780558.webp)

第二步：从卷影拷贝中提取`ndts.dit`文件

![](/notes-assets/ad1d7391c84900e79d05.jpg)

见证奇迹的时刻，成功的把`ntds.dit`复制出来了\~

![](/notes-assets/8d2a3139c7d27b992126.webp)

---

结束后应核对快照 ID，清理本次实验创建的副本；删除快照不会抹去事件日志。

第一步：查看

```
vssadmin.exe list shadows
```

![](/notes-assets/805d1696755de47d28a4.jpg)

第二步：根据 ID 清理实验快照；原文的 Oldest 可能删除无关备份，不能照搬。

请先确认本次实验创建的快照标识，再依据系统文档进行有针对性的清理；不要使用删除最旧快照的示例。

![](/notes-assets/4866176bf021483e3471.webp)

第三步：再查看

```
vssadmin.exe list shadows
```

![](/notes-assets/3dc4437f6f1500626390.webp)

![动图](/notes-assets/8235b8569190480bcc6d.gif)


本篇完\~

清理时最不能图省事的是删错副本。按自己这次创建的标识核对，比简单删除最旧对象更可靠；实验收尾和实验成功一样，都需要清楚知道自己动了什么。
