ailx10说：这篇是在2022年1月之前写的，后来又改过。快工作三年时，我从 C/C\+\+ 写到 Python，再碰大数据和设计，发现自己越来越喜欢调用现成接口，不太愿意深挖底层了。于是写这篇和自己聊聊：这是效率提高，还是某种能力正在被放下？我还拿一段之前写的 C 小程序作例子，把名字、学号字符变成二进制输出，看看手里那点基本功还在不在。文章没有替专精或管理选一个标准答案，更多留住那个阶段的犹豫，工作越做越杂，得重新想自己到底想往哪里长。

---

`scanf` 未限制输入长度，输入中缺少加号时还可能解引用空指针，格式化类型也需要核对。

调用成熟组件与理解底层并不矛盾，选择取决于工作目标、维护成本和风险。

技术广度与专业深度可随阶段调整，并没有统一答案。

![](/notes-assets/a29c31beb3468c9ecdbb.jpg)

组织目标会影响个人方向，但也可以通过沟通和计划积累可迁移能力。



```
// hello.cpp : Defines the entry point for the console application.
//

#include "stdafx.h"
#include <string.h>

void _2jinzhi(int n)
{
	long ans = 0;
	int r,i =1,step=1;
	while(n!=0)
	{
		r = n%2;
		n/=2;
		ans += r*i;
		i*=10;
	}
	printf("%08d",ans);
}


void asc(char* s)
{
	char *a = s;
	while(*a != 0)
	{
		_2jinzhi(*a++);
		printf(" ");
	}
}

int main(int argc, char* argv[])
{
	printf("Hello World!
");
	printf("输入你的学号+姓名的拼音：");

	char numer[1024];
	scanf("%s",numer);
	char* name = strstr(numer,"+");
	*name = 0;

	asc(numer);
	printf("
");
	asc(name+1);

	return 0;
}
```
