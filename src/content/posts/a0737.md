ailx10说：这篇是我2024年4月写的。分析一条 WordPress 文件读取告警，本来只是想看看下载器的路径参数，结果顺着站点往下走，拿到的配置内容又简短又刻意，登录页面也有点不对劲，我开始怀疑自己是不是踩进蜜罐了。于是把请求、返回和页面现象一起记下来。它没有一个百分之百“破案”的结尾，更多是一次分析中途的警觉：前面看似拿到了东西，后面却越来越像有人故意摆出来让你看。把这种不确定也写下来，比硬把故事讲圆更像当时的现场。

---

WordPress Simple File List下载器路径穿越告警，作者追踪站点收到极简配置字符串与登录页面，怀疑蜜罐。

## 结论与待核验条件

只有行为异常不足证蜜罐，作者未截图配置响应且站点下线，漏洞编号关联需回查不直接确认。

## 历史实验记录

今天分析告警，不小心踩到了蜜罐![原文图表](/notes-assets/1dcd026e3db7a86275be.svg)，事件的起因是 WordPress Simple File List 这个插件，其中 **`ee-downloader.php`** 存在任意文件读取漏洞(CVE-2022-1119)，威胁载荷如下：

```
GET /wp-content/plugins/simple-file-list/includes/ee-downloader.php?eeFile=../../../../wp-config.php HTTP/1.1
```

我追踪到了一个网站，疑似存在这个漏洞，但是读取的都是一堆无意义的内容：

当时访问的 `wp-config.php` 返回的是 "**DB\_NAME DB\_PASSWORD"**，就这2个字符串，忘记截图了，现在已经无法访问了。我有WordPress的目录结构![原文图表](/notes-assets/1dcd026e3db7a86275be.svg)：

![](/notes-assets/4c793c62c1cb77230798.webp)

然后我访问了 `wp-login.php` 页面，幸好这次截图了，要不然有嘴都说不清楚。

```
/wp-content/plugins/simple-file-list/includes/ee-downloader.php?eeFile=../../../../wp-login.php
```

![](/notes-assets/7668ac63fab0f06ad190.webp)

非常像是一个蜜罐，我早上踩了一下，晚上再看，站点已经下线，无法访问了，不知道啥时候再开。

怀疑本身是有价值的线索，但不能补成已经证实的陷阱。下次遇到类似情况，及时保存原始响应与环境，往往比事后努力回忆更管用。
