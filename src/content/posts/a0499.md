ailx10说：这篇是2022年1月之前写的，后来又改过。真正看 libinjection\_xss 的时候，我先注意到它会按几种可能的上下文尝试读取，再由回调给出标签、属性、值和注释这些 token，最后才做风险判断。这样拆开，原来那些看似绕过的小变化，就能放回解析步骤里看。笔记把几个黑名单和 URL 协议分支都记下，像是沿代码走一遍程序的眼睛。它并不是把浏览器完整搬了进来，所以我更愿意把它理解成一种有边界的分析方法；先知道怎么读、再知道怎么判，两步分开后代码也没那么神秘。

## XSS语义引擎总体流程

![](/notes-assets/1fcfa26823bedb4f3ef8.jpg)

xss状态图

`int libinjection_xss(const char* s, size_t len)`

根据该版本的检测规则，返回 1 表示命中，返回 0 表示未命中；二者都不能单独证明所有浏览器上下文中的安全性。以下为五个不同的初始化上下文：

> `libinjection_is_xss(s, len, DATA_STATE)`  
> `libinjection_is_xss(s, len, VALUE_NO_QUOTE)`   
> `libinjection_is_xss(s, len, VALUE_SINGLE_QUOTE)`   
> `libinjection_is_xss(s, len, VALUE_DOUBLE_QUOTE)`   
> `libinjection_is_xss(s, len, VALUE_BACK_QUOTE)`

判断流程：

`libinjection_h5_init` 初始化阶段

`libinjection_h5_next` 核心处理阶段 内置回调函数 给匹配串打标签

`h5.token_type == DOCTYPE` --\> `1 实锤`

`h5.token_type == TAG_NAME_OPEN` --\> `is_black_tag` 触发黑标签 实锤

`h5.token_type == ATTR_NAME` --\> `is_black_attr` 还需继续判断 触发黑属性

`h5.token_type == ATTR_VALUE` --\>

> `TYPE_BLACK` --\> `1 实锤`   
> `TYPE_STYLE` --\> `1 实锤`   
> `TYPE_BLACK` --\> `is_black_url` 触发黑URL 实锤  
> `TYPE_ATTR_INDIRECT` --\> `is_black_attr` 只要不是`TYPE_NONE` 就实锤

`h5.token_type == TAG_COMMENT` --\>

> \` --\> `1 实锤`   
> `[if` \|\| `xml` --\> `1 实锤`  
>  `IMPORT` \|\| `ENTITY` --\> `1 实锤`

## XSS语义引擎重要数据结构

```
typedef struct h5_state {

    const char* s;// 匹配串

    size_t len; // 匹配串的长度

    size_t pos; // 当前的位置

    int is_close; // 标签闭合状态位

    ptr_html5_state state; // 回调函数 下一轮执行

    const char* token_start; // 攻击串

    size_t token_len; //  攻击串长度

    enum html5_type token_type; // 攻击串类型

} h5_state_t;
```

判断是不是XSS攻击，就看回调函数给攻击串打上什么攻击类型的标签，攻击串类型如下：


属性 URL 应对照 TYPE_ATTR_URL 分支，不能把 token 类型本身直接当作攻击标签。

这套启发式给了一个具体实现视角，却不是把整个浏览器搬了进来。知道它怎样看输入，也就更容易继续问：它忽略了什么、例外又在哪里。
