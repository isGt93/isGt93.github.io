ailx10说：这篇是我2023年6月写的。Windows 网络服务这章又让我回到 RPC、用户信息和 NetBIOS 名称这些基础线索。我按 rpc 端点、SAMR 和名称表一路试着看，后面碰到旧版 pwdump3，读取哈希那一步没有成功，也照样留下。读旧书时很容易以为照着敲总该有答案，实际环境一换，工具就可能停住。这篇记下的是能看到哪些服务信息、又在哪儿卡住，像给前面的 Windows 系统实验加一张网络侧的观察表。

---

本文整理 Windows RPC、SAMR 与 NetBIOS 的历史信息收集，原文保留了获取密码哈希失败的记录。

核查提示：历史工具和权限条件需核对；保留失败证据，端点和名称发现不等于已获取密码。 旧版内容与实验仍需逐项核验。

![](/notes-assets/43f4583a2882d5c09d37.webp)

1、微软RPC服务

1）枚举可访问的RPC服务器接口

RPC服务在TCP、UDP 135端口进行监听，通过rpcdump.exe可以列出已注册的RPC端点

```
rpcdump.exe  -p ncacn_ip_tcp 192.168.0.107
```

![](/notes-assets/04cc20be58a5482a137f.webp)

2）通过SAMR与LSARPC接口收集用户详细资料

walksam工具可以查询SAMR命名管道接口（ \\pipe\\samr ），收集用户信息

```
walksam.exe 192.168.0.107
```

![](/notes-assets/67386db2c71a8979883b.webp)

2、NetBIOS名服务

NetBIOS名服务可以通过UDP 137端口进行访问，该服务能够处理NetBIOS名称表（NBT）请求。

1）使用nbtstat获取NetBIOS名称表

```
nbtstat -A 192.168.0.107
```

![](/notes-assets/710307c82cc7cf02a85c.webp)

2）使用winfo枚举系统信息[\[1\]](#ref_1)

```
winfo.exe 192.168.0.107 
```

![](/notes-assets/e55826dfc21036d25c4a.webp)
