ailx10说：这篇是在2023年5月之前写的，后来又改过。读到 Internet 主机和网络枚举，我把搜索语法、WHOIS、DNS 正反向查询、区域传送这些入口挨个摆出来，又装 SpiderFoot 看自动聚合能把它们串成什么样。以前信息收集像到处点页面，按一章的顺序走，才更容易问出下一步的问题：这个名字还能关联什么，这个地址又带出哪些线索。文章就是从手动查询走到工具归拢的一次练习，重点在让公开信息彼此接上，而不是收回来一堆看着很满却不知用途的数据。

---

本文整理搜索、WHOIS、DNS 和信息聚合的历史枚举方法。不同数据源的权限和隐私保护会影响结果覆盖。

核查提示：区域传送失败不代表机制失效；隐私保护与模块访问条件限制信息覆盖，所有信息说法过强。 旧版内容与实验仍需逐项核验。

本章介绍渗透测试的第一阶段：信息收集。主要讨论了web搜索引擎、whois信息登记、web爬虫、dns服务器扫描等，是基础中的基础，属于新人入门第一课。

2）DNS区域传送技术

DNS区域文件包含了某个特定DNS域名服务器存储的所有信息，一般主备DNS服务器进行信息同步的时候，就是靠DNS区域传送。文章介绍的命令，现在已经不灵了，技术革新太快了，过去的招数不顶用了。

> `axfr` 是一种 DNS 查询类型，全称为 "Zone Transfer"。当您使用 `axfr` 查询时，您将会从 DNS 服务器中获取整个 DNS 区域的副本。这通常用于备份或复制 DNS 区域数据。

```
dig @relay2.ucia.gov 129.81.198.in-addr.arpa axfr
```

![](/notes-assets/afddbdc04782e4a24562.webp)

在这个命令中，符号 "@" 表示要查询的 DNS 服务器的名称或 IP 地址。

在这个命令中，它指定要查询的 DNS 服务器为 "[http://relay2.ucia.gov](http://relay2.ucia.gov)"。

4、web信息收集爬虫（**SpiderFoot**）

1）安装

```
 wget https://github.com/smicallef/spiderfoot/archive/v4.0.tar.gz
 tar zxvf v4.0.tar.gz
 cd spiderfoot-4.0
 pip3 install -r requirements.txt
 python3 ./sf.py -l 127.0.0.1:5001
```

2）运行

```
所有的“蜘蛛脚”模块都将被启用(速度很慢)，但是关于目标的每一条可能的信息都将被获取和分析。
```

![](/notes-assets/5344c522e7b7ea4d4fef.webp)

3）查看结果

```
一把把知乎的所有信息收入囊中
```

![](/notes-assets/dd2e3397875fe4ce31d0.webp)

某个模块没结果，不代表相关信息不存在；区域传送失败也不是机制失效。记下查询时间和访问条件，之后复查才能分辨变化来自目标还是方法。
