ailx10说：这篇是2019年12月之前写的，后来又改过。这是较早一次 iodine 练习，我按九个步骤配 NS、A、服务端地址和客户端接口，再 ping、加路由，最后在隧道里 SSH。抓 dns0 和 eth0 时，同一份通信在不同位置呈现的样子让我挺有印象，后来再学检测也能回头拿来对照。文章里有些域名和口令拼写不一致，实际搭时得把它们统一。这个小实验让我把认证口令和数据加密分开：iodine 让通路建立，SSH 负责里面那层保护，各自的作用看清楚了，才不会把“有密码”都当成一回事。

---

2019 iodine九步配NS/A、iodined10.0.0.1和客户端dns0 10.0.0.2，ping/路由后SSH，比较dns0与eth0；可省直连IP经内DNS解析。

核查提示：iodine密码用于认证不提供数据加密，SSH内层加密不同；示例hackbji/hackbiji、hackbjipasswd拼写不一致，NS域与服务后缀必须匹配。 原环境及图内细节尚未逐项核验。

本实验研究 iodine 的 DNS 隧道与其内部 SSH 会话。iodine 密码用于认证，不应误认为它自动为所有数据提供加密；SSH 自身提供加密。

以下九步记录 DNS 隧道中建立 SSH 连接；注意域名和密码配置必须在两端一致。

第一步：添加一条NS记录

> 我这里的设置是`dns.hackbiji.top`指向`dnsns.hackbiji.top`，想要解析`dns.hackbiji.top`这个子域名，就需要去访问`dnsns.hackbiji.top`这个域名服务器

![](/notes-assets/3bc1aba36f63f4a951c6.jpg)

第二步：添加一条A记录

> 将域名服务器解析到咱们的控制的公网服务器IP地址，我的域名服务器是`dnsns.hackbiji.top`，对应的公网IP地址是`96.45.188.252`

![](/notes-assets/49b794e6e9f52ae941bf.jpg)

第三步：通过`iodine`建立DNS隧道

- `-f` 前台显示
- `-P` 设置通信密码（我的密码是hackbijipasswd）
- `10.0.0.1` （我设置的服务器私有网址，也可以设置为其他地址）
- `dnsns.hackbiji.top` （我的域名，也可以设置为`dns.hackbiji.top`）

```
iodined -fP hackbijipasswd 10.0.0.1 dnsns.hackbji.top
或
iodined -fP hackbijipasswd 10.0.0.1 dns.hackbji.top
```

![](/notes-assets/4e40acfffb048df0f7bf.jpg)

第四步：查看服务器IP地址

- 多了一个`dns0`接口，IP地址是咱们设置的`10.0.0.1`

![](/notes-assets/a94f3a61e4b7d885b65f.jpg)

第五步：本地客户端连接服务器

- `-fP hackbijipasswd` 前台显示，并设置密码（hackbijipasswd）
- `96.45.188.252` 我的服务器IP地址
- `dnsns.hackbiji.top` 我的域名（必须和服务器设置的域名保持一致）

```
iodine -fP hackbjipasswd 96.45.188.252 dnsns.hackbiji.top
或
iodine -fP hackbjipasswd 96.45.188.252 dns.hackbiji.top
```

![](/notes-assets/b297091b9d8e5b40d60f.jpg)

第六步：查看本地客户端IP地址

- 多了一个`dns0`接口，并且IP地址是自动生成和服务器一个网段的`10.0.0.2`

![](/notes-assets/45495a4a3b2aa325d59f.jpg)

第七步：从本地Ping通服务器`10.0.0.1`

- 这时我们的DNS隧道建立成功了

![](/notes-assets/53cb28668abb2a0f104a.jpg)

第八步：查看本地路由

- 访问`10.0.0.0`网段的流量都会走`dns0`隧道接口

![](/notes-assets/5bf04c5c8e10381cfd63.jpg)

第九步：从本地dns0隧道登陆远程服务器

- `ssh`穿越`dns0`隧道，成功登陆远程服务器

![](/notes-assets/4df4733e6617bbd98c1c.jpg)

---

如果发生在内网，你无法访问外网IP（`96.45.188.252`）的时候，可以去掉IP地址，直接通过内网的DNS服务器帮你请求，依然能达到建立隧道的效果。

```
iodine -fP hackbjipasswd dnsns.hackbiji.top
```

口令认证和数据加密不是同一件事，内层SSH又是另一层保护。连同域名和密码的拼写一起核对，才能让这个老实验在回看时少一点莫名其妙的连接失败。
