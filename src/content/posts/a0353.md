ailx10说：这篇是2022年1月之前写的，后来又改过。以前用工具看 URL 解码，好像只是把几个百分号换掉，这次我干脆用 C 自己写一遍。先准备查表，把两位十六进制变成字节，再考虑循环读到尾部时怎么收场。写下来之后，才发现字符、数字值和缓冲区长度并不是一回事，短字符串、零字节和结束标记都得认真处理。这篇是把熟悉的 HTTP 小动作拆到字节层的一次练习；代码没有复杂算法，可只要自己来接手边界，就会知道库函数平时替我做了多少不起眼的工作。

---

`Content-Type`指定为`application/x-www-form-urlencoded` 的时候

我们提交的数据编码形式是通过`&`连接 比如key\="\<hack\>"`&`value\="ailx10"

同时`<hack>`和`ailx10`会进行URL编码

> key\=`%3C`hack`%3E`\&value\=ailx10

`%3C:<` `%3E:>`

`0x3C`是`<`的`ASCII`码 `%3E`是`>`的`ASCII`码

百分号编码表示字节，例如 %3C 表示字节 0x3C；文本如何解码还取决于字符编码。

---

解码过程将合法的百分号和两位十六进制数字转换为对应字节。表单格式还可能要求将加号还原为空格。

这里方便理解以`ASCII`码为例子 记住不仅仅是`ASCII`码哦

当我们遇到`%`的时候 意味着转码开始 连续2个16进制数字 比如`%3C`

> `URL`转码就是将`%3C`转为`char`型10进制数据`60` 记住这里只占1个字节哦

解释一下`HEX2DEC`数据的意义

16进制转10进制的转换表 `ASCII`码10进制48是字符`0` 65是字符`A` 97是字符`a`

在看看`HEX2DEC`数组

> 查表时 HEX2DEC\[48\] 为 0，HEX2DEC\[65\] 与 HEX2DEC\[97\] 均为数值 10，不是字符 A 或 a。

原代码仅说明查表思路：未明确返回输出长度或添加结尾零，未处理加号；短输入、百分号后的非法字符和解码后零字节也需要校验。下方代码未经运行，不宜直接用于生产。

```
void utils_uri_decode(const unsigned char* sSrc,char* dst) {
    const unsigned char *pSrc = sSrc;
    size_t src_len = strlen((const char*)sSrc);
    const unsigned char *src_end = pSrc + src_len;
    const unsigned char *src_last_dec = src_end - 2;

    char *pStart = dst;
    char *pEnd = pStart;

    while (pSrc < src_last_dec) {
        if (*pSrc == '%') {
            char dec1, dec2, guard = -1;
            if (guard != (dec1 = HEX2DEC[*(pSrc + 1)])
                && guard != (dec2 = HEX2DEC[*(pSrc + 2)])) {
                *pEnd++ = (dec1 << 4) + dec2;
                pSrc += 3;
                continue;
            }
        }
        *pEnd++ = *pSrc++;
    }

    while (pSrc < src_end) {
        *pEnd++ = *pSrc++;
    }
    return;
}
```
