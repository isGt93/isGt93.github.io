ailx10说：这篇是我2024年2月写的。第一次看到“我的楼兰”，我也先把它当成一个固定名称，追到页面才发现，界面第一行是创建时自定义的名字，第二行才是密码，名字本身并不能直接说明来源。我继续把 Base64 和 deflate 解开，再放到本地看文件、命令、SQL、批量操作和代理功能。于是这篇从认名字开始，最后变成一份拆代码、对界面的笔记。让我记住的反倒是这个小转折：样本给自己贴的招牌，和它真正来自哪里、能做什么，并不是同一件事。

---

辨认楼兰为可自定义名称的大马，Base64/deflate解码后本地复现文件、命令、SQL、批量与代理功能。

## 结论与待核验条件

gzinflate对应raw deflate，示例wbits表达式待核；加密免杀表述不能代表实际检出率，工具名称非可靠归因。

## 历史实验记录

跟踪我的楼兰webshell进入到一个网站，应该是这个webshell的官网，提供了asp和php的木马![原文图表](/notes-assets/1dcd026e3db7a86275be.svg)下载，并且是免杀马，功能相当强大，第一行是自定义webshell的名称，第二行是webshell的密码，也就是说其实这个webshell![原文图表](/notes-assets/1dcd026e3db7a86275be.svg)真正的名字，并不叫我的楼兰，只是创建的时候，webshell填写的名称叫我的楼兰

![](/notes-assets/e5418844069eb59ea638.webp)

可以看到这个webshell官网是一直更新的，尝试解密我的楼兰 webshell

```
# -*- coding: utf-8 -*-

# python3.8 解密我的楼兰



import base64

import zlib



encoded_string = "....(省略)...."

# encoded_string = encoded_string.replace("

","")

# 进行 base64 解码

decoded_bytes = base64.b64decode(encoded_string)

# 进行 gzinflate() 处理

inflated_bytes = zlib.decompress(decoded_bytes, -zlib.MAX_WBITS | 16)



# 将字节流解码为字符串

resulting_string = inflated_bytes.decode('utf-8')



print(resulting_string)
```

解密后看到PHP原文，也能看到很多加密，怪不得说是免杀，感情你的代码全是加密
