ailx10说：这篇是我2023年10月写的。这一篇想把 SSRF 后面的路走远一点：先让 WebLogic 帮我探内网服务，再看能不能和 Redis 交互，最后才到写定时任务。做的时候，并不是每个返回都直白告诉我“端口开着”，得从错误和响应差异里慢慢判断。我把这串过程记下来，是因为它把几个单独看很小的缺口接到了一起。不过每一段都有自己的条件：Redis 的认证、写权限、任务文件格式都得成立，不能把一次靶场结果当成 SSRF 必然能到达的终点。

---

原实验先观察服务端发起请求，再将其与靶场中的 Redis 配置问题组合。结果依赖 Redis 访问控制、写入权限和 cron 有效解析。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

实验结束后可在确认项目目录和 Compose 配置后关闭该项目的服务；原文的全局 Docker 清理命令已移除。
