ailx10说：这篇是我2024年2月写的。一条 XSS 告警里出现了很特别的追踪函数名，我顺着搜，先找到相似讨论，再对到 Arachni 的源码。既然名字已经认出来，索性把工具装起来，打开它的 Web 界面，再用 socat 把本地端口转出去试用。于是这篇不只是给载荷贴个标签，也记下从日志线索走到工具本身的过程。平时见到的扫描请求常常只有一小截，回头去看发出它的那一端，才更容易理解那个奇怪函数为什么会出现在请求里。

---

今天告警巡检，发现一个有趣的 xss 载荷

```
GET /CheckCode.aspx?SafeKey=</script><script>window.top._webscan_taint_tracer.log_execution_flow_sink()</script> HTTP/1.1
```

在 stackoverflow 中找到了相似的载荷如下：

```
javascript:window.top._arachni_js_namespace_taint_tracer.log_execution_flow_sink()
```

日志特征与 Arachni 的部分源码模式相似，但该特征可能被模仿，不能单凭它确认攻击者身份或使用工具。

> Someone was probably using Arachni[\[1\]](#ref_1)to check your site for vulnerabilities.

![](/notes-assets/0a4c492184cdafcc6210.webp)

对比github仓库中的 Arachni 代码，果然发现了，是xss漏洞扫描

```
grep -r "log_execution_flow_sink()" .



./components/checks/active/xss_dom_script_context.rb:        'window.top._%s_taint_tracer.log_execution_flow_sink()'

./components/checks/active/xss_script_context.rb:        'window.top._%s_taint_tracer.log_execution_flow_sink()'
```

下载并安装并执行最新的 Arachni ，默认只能本地访问

```
wget https://github.com/Arachni/arachni/releases/download/v1.6.1.3/arachni-1.6.1.3-0.6.1.1-linux-x86_64.tar.gz

tar xvf arachni-1.6.1.3-0.6.1.1-linux-x86_64.tar.gz

./arachni_web
```

![](/notes-assets/11bcbc29d4b32c729d0a.webp)

配置端口转发，让它可以从互联网访问

```
socat TCP-LISTEN:8888,reuseaddr,fork TCP:127.0.0.1:9292
```

访问 我的VPS的 8888 端口，就可以访问 Arachni 了
