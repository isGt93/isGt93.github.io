ailx10说：这篇是2024年7月之前写的，后来又改过。DVWA 搭进 Docker 后，我拿 XSStrike 从低安全级别的 DOM、反射和存储型 XSS 开始扫。看着同一个工具换 URL、GET 和 POST，真正变化的是会话、输入位置和数据落点，尤其存储型测试会在留言板里留下内容。笔记把当时的命令和结果保存下来，方便下一轮继续对照。自动化看起来省事，背后还是一轮正常业务请求；先把登录状态和目标页面对上，工具输出才不至于只是屏幕上一串热闹的文字。

---

本文记录 XSStrike 对 DVWA 初级设置下三类 XSS 的历史扫描；工具输出需要结合页面行为验证。

实验依赖靶场会话与安全级别，应在独立环境中创建测试账号。

以下记录的是一次工具测试，不能据此评价其他工具的全部能力。

![](/notes-assets/0fc0c7916c07bad95895.webp)

所以，我选Web漏扫的关键因素是：

- 可以使用Cookie带状态扫描（因为大部分网站需要登录）
- 可以自定义HTTP 请求头（因为大部分网站有请求头校验）
- 可以指定具体的网址（因为需要快准狠的精确漏扫）
- 可以使用GET/POST方式（因为大部分网站是POST请求）
- 可以扫描HTTPS站点（因为大部分网站是HTTPS协议）

以入门级的XSS为例，使用XSStrike进行XSS漏洞扫描，可以精确的对具体的网址进行Web漏扫。

（1）测试Dom型XSS漏洞（GET请求）

```
python3 xsstrike.py -u http://192.0.2.10:4280/vulnerabilities/xss_d/?default=English --headers "Cookie: PHPSESSID=<实验会话>; security=low"
```

![](/notes-assets/4edc757698b2bb31c739.webp)

（2）测试反射型XSS漏洞（GET请求）

```
python3 xsstrike.py -u http://192.0.2.10:4280/vulnerabilities/xss_r/?name=ailx10 --headers "Cookie: PHPSESSID=<实验会话>; security=low"
```

![](/notes-assets/bc3ccd2e77f5f3c4ac54.webp)

（3）测试存储型XSS漏洞（POST请求）

```
python3 xsstrike.py -u http://192.0.2.10:4280/vulnerabilities/xss_s/ --headers "Cookie: PHPSESSID=<实验会话>; security=low" --data "txtName=ailx10&mtxMessage=hi+hacker&btnSign=Sign+Guestbook"
```

![](/notes-assets/fa08cf1e2c7af2069727.webp)

存储型测试可能向留言板写入多条记录，测试后应检查并清理。

![](/notes-assets/5ee5a04fab1f0b65884f.webp)

扫描提示不能替代浏览器验证与根因分析。

尤其是存储型测试，请求发出去以后，页面内容真的会变化。回看这组实验，除了工具报了什么，我还得记住自己向站点写进了什么，以及浏览器最后怎样处理这些内容。
