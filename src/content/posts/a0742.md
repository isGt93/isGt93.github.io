ailx10说：这篇是我2024年4月写的。这次不是替别人看数据丢失，而是自己做实验时手快，把目录里的文件删了。懊恼归懊恼，总得试试能不能救，于是装上 TestDisk，又专门建一个文本文件、过一分钟删除，再从头走恢复流程。文件名能找回来，内容却空了，最后反倒在 swap 里看到部分残留。这篇就这样把一场操作失误变成了小实验，结果并不漂亮，却挺有记忆点：恢复工具给你一个文件，不代表当时写进去的字也跟着回来了。

---

今天在做实验的时候，不小心`rm * -rf`，把目录下的文件都删除了，尝试了 TestDisk，发现能恢复一点，于是我做了下面的实验，创建 `ailx10.txt` 文件，1分钟后删除文件，下面是 TestDisk 恢复过程：

![](/notes-assets/eacefad0283aafc243ca.webp)

实验是在ubuntu20上做的，需要先安装TestDisk，然后开始恢复：

```
sudo apt-get install testdisk
```

（1）运行 testdisk （是否创建log文件）

![](/notes-assets/30f8f541e642e8f5044a.webp)

（2）选择 Disk /dev/sda（选择磁盘sda）

![](/notes-assets/0ee320bb4b739d54ef0e.webp)

（3）选择 \[EFI GPT\] EFI GPT partition map （选择分区）

![](/notes-assets/13065cbcf2663d3111a8.webp)

（4）选择 \[ Advanced \] Filesystem Utils （选择文件系统）

![](/notes-assets/3dae963ed52cea6ed7ad.webp)

（5）选择 3 P Linux filesys. data （选择分区）

![](/notes-assets/123555da8ded12fa887a.webp)

（6）选择 home（因为我删除的文件在 home 路径下）

![](/notes-assets/307bd9e6fe4bd9eaf72f.webp)

（7）选择 `ailx10.txt`  （可以发现文件大小是0，即使恢复，内容也是空的）

![](/notes-assets/f918e0a3f769f7388dba.webp)

（8）然后按 C 确认恢复

![](/notes-assets/50c72dfaaaecb2b4b942.webp)

（9）恢复了选中的2个文件

![](/notes-assets/5e797787149239eb6ba6.webp)

（10）查看恢复效果，只能说一般般，并没有恢复出我想要的内容， 因为`ailx10.txt` 内容是空的，但是`.ailx10.txt.swp` 有一点点内容

![](/notes-assets/fe1f43e8d7edb0e23d00.webp)

你使用 TestDisk 恢复过什么删除的文件吗？评论区告诉我～

文件名回来和内容回来是两回事。这个失败值得留下：后续写入、TRIM和文件系统都可能影响结果，发现丢失后先减少写入，比急着反复尝试更重要。
