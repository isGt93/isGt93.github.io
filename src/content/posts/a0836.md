ailx10说：这篇是在2023年6月之前写的，后来又改过。Unix RPC 这一章代码和工具名不多，却把服务发现这件事又拧紧了一点。rpcinfo、Nmap、showmount 各自问到的东西不完全一样，有时 portmapper 被过滤，后面的查询表现也跟着变。我就把这些关系摆出来看，免得一个工具没回话，就匆忙觉得所有服务都不存在。文章像一次针对老协议的路线练习：先找到目录，再沿登记信息去找服务，目录问不到时，也要知道那会怎样改变自己后面的观察。

---

![](/notes-assets/3f346c80279a2b55b13c.webp)

1、使用rpcinfo列出可访问的RPC服务端点

```
rpcinfo -p 220.130.155.245
```

![](/notes-assets/c7b22a324a1219dfab67.webp)

2、使用Nmap发现运行在高端口的RPC服务

```
nmap -Pn -sR 218.4.233.64
```

![](/notes-assets/3bd01b19ac7c81124604.webp)

3、如果对RPC portmapper服务的网络访问被目标系统过滤，使用showmount等RPC客户端访问时就会失败

```
howmount -e atomex.direct.quickconnect.to
```

![](/notes-assets/e8fdfdec8852c6769e8b.webp)

发现服务、访问端口和获得文件权限是几件不同的事。把旧命令拼写与选项核对好，测试结果才不会因为工具层面的差错被误读。
