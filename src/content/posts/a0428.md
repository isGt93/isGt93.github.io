ailx10说：这篇是2022年1月之前写的，后来又改过。Hashcat 这次我用六位数字和已知的弱口令做对照，先跑掩码，再用字典批量匹配，顺手记了两次耗时。看到结果出来很快，确实容易感叹工具厉害，但这题本来就把候选范围缩得很小，计时也包含不同开销。我还提了以前 ZIP 没跑出来的经历，让这篇不只剩一个顺利例子。这里做的是离线猜测，不是在登录页撞库，也不是给 MD5 做解密；弄清工具究竟试了哪些候选，速度数字才不会把问题讲歪。

## 1、Hashcat简介

Hashcat 支持多种算法和模式，具体支持以工具版本和帮助为准。

输入`hashcat -h`，遍可以看到一堆帮助信息，从这里就可以感受到它的强大，牛逼之大，三两页装不下～

![](/notes-assets/a792637d8e13c520d96c.jpg)

## 2、Hashcat的简单使用

原文对六位数字样本记录约 26 秒；该数字包含实际环境开销，不是通用速度。

- -a 3 暴力破解（后面的`?d?d?d?d?d?d`表示6位数字，属于暴力破解）
- -m 0 说明需要破解的是MD5

```
hashcat -a 3 -m 0 --force e10adc3949ba59abbe56e057f20f883e ?d?d?d?d?d?d
```

![](/notes-assets/c0cb2f87deee205ea415.jpg)

字典模式逐一验证候选口令与散列是否匹配，属于离线口令审计，不是在线撞库登录；原次测试约六秒。

![](/notes-assets/65702f7b6b05d0833060.webp)

- -a 0 字典模式（后面的pass.txt表示明文密码文件，也就是需要撞的密码库）
- -m 0 说明需要破解的是MD5

```
hashcat -a 0 -m 0 --force hash.txt pass.txt
```

![](/notes-assets/bb59e8a7157e89cc0440.jpg)
