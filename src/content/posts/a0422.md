## 1、系统服务权限配置错误

windows系统服务文件在操作系统启动时加载执行，并在后台调用可执行文件。如果一个低权限的用户对此类系统服务调用的可执行文件拥有写权限，那么就可以替换该文件，并随着系统启动获得控制权限。

Windows 服务使用不同的服务账户，不是所有服务都以 SYSTEM 运行；风险由其实际权限与可写位置共同决定。

PowerUp下的实战github项目地址：

提供了一些本地提权方法，可以寻找目标机器中的windows服务漏洞。

## 2、注册表键AlwaysInstallElevated

当计算机和用户两处 AlwaysInstallElevated 策略均启用时，安装权限可能被滥用；原实验是人为启用两处策略后成功。

windows install是windows操作系统的组件之一，专门用来管理配置软件服务。它除了是一个安装程序，还用于管理软件的安装、组件的添加、删除、监视文件的还原、通过回滚进行灾难恢复。windows install通过msiexec.exe安装MSI文件，双击MSI文件就会运行msiexec.exe。

在运行中输入`gpedit.msc`，然后以管理员方式打开：

- 配置「计算机配置」
- 配置「用户配置」

![](/notes-assets/80dd7d32405e76436915.jpg)

双击，选择已启用，确定。

![](/notes-assets/32be291eb0b6d829b123.jpg)

准备工作完成，见证奇迹的时候到了：

```
Get-RegistryAlwaysInstallElevated
Write-UserAddMSI
```

![](/notes-assets/2b9f1a11fea0aa1e7a6a.webp)

```
msiexec.exe /q /i UserAdd.msi
```

运行这个命令，会弹窗。你可以修改创建的用户名、密码和用户组，这里默认就好了。

![](/notes-assets/9129e539a16bb90f9011.jpg)

输入`net user`，发现新增了一个用户：backdoor ，实验成功～

![](/notes-assets/d17174f666580bb0a7a1.webp)

## 3、可信任服务路径漏洞

利用了windows文件路径解析的特性，如果一个服务调用的可执行文件没有正确处理所引用的完整路径名，这个漏洞就会被攻击者用来上传任意可执行文件。

未加引号且包含空格的路径只是潜在条件；还需要搜索位置可写，并且服务以较高权限运行并被触发。

```
wmic service get name,displayname,pathname,startmode | findstr /i "Auto" | findstr /i /v "C:\Windows\" | findstr /i /v """
```

遗憾的是，我的演示系统没有这样的漏洞～

## 4、自动安装配置文件

网络管理员在内网中给多台机器配置同一个环境时，通常不会逐个配置，而是使用脚本批量部署。在这个过程中，会使用安装配置文件。这些文件中包含所有的安装配置信息，其中一些还可能包含管理员账号和密码。

## 5、计划任务

高权限任务加载的程序或目录如果被低权限用户修改，可能在触发时影响执行；工具来自微软不代表不会被安全产品告警。

通过AccessChk查看指定目录的权限配置情况：

```
accesschk64.exe -dqv "C:\Program Files (x86)" -accepteula
```

![](/notes-assets/1179478b97689737ff4d.webp)

查看某个驱动器下所有「权限配置」有问题的文件夹：

```
accesschk64.exe -uwdqsUsers c:\
```

![](/notes-assets/a36ea49c89e04826de22.webp)

查看某个驱动器下所有「权限配置」有问题的文件：

```
accesschk64.exe -uwdqsUsers c:\*.*
```

![](/notes-assets/a5beed7c0e8489c889b8.webp)

本篇完～

路径有空格、目录能写、服务会被高权限触发，这些条件得一起成立才有意义。配置实验的收获，是看见条件怎样叠加，而不是给某个服务名贴一张危险标签。
