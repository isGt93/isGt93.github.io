ailx10说：这篇是2019年12月之前写的，后来又改过。这个上传实验我故意把前端做得像有检查：页面只让选 jpg，抓到请求以后再改文件名，看看后端会不会继续收下。结果真正的问题不在浏览器提示有多认真，而是服务器几乎没做类型验证，只处理上传错误和重名就保存了。把前后端代码摆在一起之后，绕过过程反而很容易理解。这篇想记的是客户端检查为什么不能独当一面；后面能不能执行，还要看文件被放到哪里、服务器会不会把它当脚本，不能把上传成功和所有后果直接等同。

---

发生在客户端的一种绕过，假如前端限制只能上传图片，那么怎么上传我们的PHP文件`shellcode`呢？

示例记录了文件被服务端接受。上传成功本身不等于代码执行：只有文件可被访问，且服务端按脚本解释该文件等条件成立时，才可能产生进一步影响。

![](/notes-assets/c7353409b15a5a3c0943.jpg)

---

前端代码：

```
<!-- index1.html by ailx10 -->
<html>
<head>
<title>ailx10</title>
</head>
<body>
<script type="text/javascript">
    function selectFile(fnUpload)
    {
        var filename = fnUpload.value;
        var mime = filename.toLowerCase().substr(filename.lastIndexOf("."));
        if(mime != ".jpg")
        {
            alert("Please select a photo upload in jpg format");
            fnUpload.outerHTML=fnUpload.outerHTML;
        }
    }
</script>

<form action="upload1.php" method="post" enctype="multipart/form-data">
<label for="file">FileName:</label>
<input type="file" name="file" id="file"  value="file" onchange="selectFile(this)" /><br />
<input type="submit" name="submit" value="submit" />
</form>
</body>
</html>
```

后台代码：

```
// upload1.php by ailx10
<?php
if($_FILES["file"]["error"] > 0)
{
    echo "Return Code:" . $_FILES["file"]["error"] . "<br />";
}
else
{
    echo "Upload:" . $_FILES["file"]["name"] . "<br />";
    echo "Type:" . $_FILES["file"]["type"] . "<br />";
    echo "Size:" . ($_FILES["file"]["size"]/1024) . " kb<br />";
    echo "Temp file:" . $_FILES["file"]["tmp_name"] . "<br />";
    if(file_exists("upload/" . $_FILES["file"]["name"]))
    {
        echo $_FILES["file"]["name"] . "already exists.";
    }
    else
    {
        move_uploaded_file($_FILES["file"]["tmp_name"],"upload/" . $_FILES["file"]["name"]);
        echo "Stored in:" . "upload/" . $_FILES["file"]["name"];
    }
}
?>
```

参考文献：《Web安全攻防：渗透测试实战指南》电子工业出版社

这次问题不在于浏览器按钮有多容易改，而在于后端没有独立承担判断。把请求和保存结果并排放好，就能解释为什么界面上的限制没有成为真正的边界。
