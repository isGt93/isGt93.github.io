ailx10说：这篇是在2019年12月之前写的，后来又改过。碰到加密 ZIP，文件就在眼前却打不开，很容易让人想找个工具试试。我拿自建的六位数字密码压缩包做小实验，用 fcrackzip 分别走定长枚举和字典这两条路，顺便看看候选密码出现以后，怎样再用解压结果确认。刚上手时，成功跑出一个简单口令确实很直观；往后才会意识到，字符范围和长度一变，工作量可能差得很远。这篇记的是一次入门尝试，重点在理解搜索空间和验证过程，不是说拿到一个工具就能打开所有压缩包。

---

加密压缩包的口令恢复通常依赖候选口令：工具逐个尝试，直到找到可验证的结果。本文只讨论自己创建、拥有处理权限的测试文件。

## 搜索空间

假设口令恰好由六位数字组成，候选数量是 `10^6 = 1,000,000`。如果长度和字符集扩大，候选数量会迅速增长；运行时间还取决于加密格式、工具实现和设备性能，不能用固定年数概括。

## 创建隔离样本

准备不含敏感数据的测试文件，并用交互方式设置测试口令：

```bash
printf 'test data\n' > sample.txt
zip -e sample.zip sample.txt
```

交互输入可以避免把口令直接写进命令行历史。`zip -e` 创建的传统 ZIP 加密并不适合作为现代敏感数据保护方案。

## 比较枚举与词表

在支持对应格式的环境中，可指定六位数字作为搜索范围：

```bash
fcrackzip -b -l 6-6 -c 1 -u sample.zip
```

如果事先准备了只含测试候选的词表，也可以使用：

```bash
fcrackzip -D -p candidates.txt -u sample.zip
```

`-u` 用解压过程进一步验证候选结果；不同版本和 ZIP 加密方法的支持情况可能不同，请先查看本机 `fcrackzip --help`。验证结果时，应确认解压成功且内容与样本一致；找不到口令只说明本次候选范围和运行条件下没有找到。

候选命中还要经过实际校验，耗时也跟口令空间和环境有关。这次练习更像一把尺子，让口令长度和候选范围从抽象数字变成能观察的工作量。
