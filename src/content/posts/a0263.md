ailx10说：这篇是我2024年9月写的。这篇更像一次没走完的复现。我想做 Webmin 的另一个漏洞，手边却借用了旧靶场，模块检查给了线索，最后没有得到预期连接。途中改密码、登录后台、调用已有的 shell 功能，这些都记了下来，但它们本来就依赖已知权限，不能拿来替代漏洞成功的证据。我保留这篇，就是不想让笔记只有顺利的部分；环境错配时，继续堆工具往往解决不了根本问题，先确认版本和前提，比看到 check 提示就下结论更重要。

---

本文记录一次未能完成的历史复现：实验借用了针对另一 CVE 的环境，工具检查有响应但未获得预期结果。

使用已知 root 账号登录后的合法命令功能不能证明漏洞成功；check 阳性也不能单独确认完整利用。

（1）进入 docker 修改密码

```
find / -name "changepass.pl"

/usr/share/webmin/changepass.pl /etc/webmin/ root password
```

![](/notes-assets/71c5f0c747047534178e.webp)

（2）使用 root:password 登录成功，左下角直接可以拿到webshell

![](/notes-assets/67c1b2b4faf90da32eec.webp)

（3）加载自定义模块，metasploit中默认没有 `webmin_pu_escape_bypass_rce.rb`

![](/notes-assets/eddb7ff12d456e4038f2.webp)

自己下载到 `$HOME/.msf4/modules/exploits/webmin` 这个目录下，没有则创建这个目录

```
wget https://pentest.com.tr/blog/webmin_pu_escape_bypass_rce.rb -O webmin_pu_escape_bypass_rce.rb
```

重新加载`reload_all` 之后再次查看，`webmin_pu_escape_bypass_rce.rb` 已经有了

![](/notes-assets/1339dc6446b341618539.webp)

（4）显示有洞，需要填写用户名和密码，很鸡肋，却还没有利用成功

```
use exploit/webmin/webmin_pu_escape_bypass_rce
```

![](/notes-assets/0567de9abf9fc3e581b1.webp)

check 是ok的，但是拿不到shell，不知道网上的复现环境是从哪弄的，有没有人知道？

![](/notes-assets/9e2fd4a6e374bb2e74dc.webp)

check阳性却没有得到会话，就保留这个停点。一次没有走通的实验也能有价值，前提是把尝试过的东西与尚未证明的结论分开，而不让正常管理功能冒充漏洞效果。
