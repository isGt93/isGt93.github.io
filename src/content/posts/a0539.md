ailx10说：这篇是我2022年4月写的。我想把恶意 DNS 请求和发起它的进程对上，先调研 Sysmon，发现不同系统的坑不少，就在苹果电脑里又开了一台 Win10 虚拟机。装好后最关键的不是命令，而是把 DNS 记录配置打开；看到事件 22 里有进程和域名，再去找 EVTX 文件和解析办法。这篇把一个终端检测的小想法拆成了可见的几步：先采到请求，再匹配情报，最后才谈处置。它像给后续方案打的地基，第一块砖其实是日志能不能完整留下来。

---

这里安装

```
sysmon.exe -i 
```

最关键的是DNS监控的配置文件[\[1\]](#ref_1)了

```
sysmon.exe -c sysmonconfig-export.xml
```

然后去【控制面板\\系统和安全\\管理工具\\事件查看器\\应用程序和服务日志\\Microsoft\\Windows\\Sysmon】里面查看DNS记录，记住这里事件ID是**22**，这里我们请求谷歌，可以找到请求的进程～

![](/notes-assets/0a0fbcec0e944845451c.jpg)

日志路径如下：

```
%SystemRoot%\System32\Winevt\Logs\Microsoft-Windows-Sysmon%4Operational.evtx
```

![](/notes-assets/2b3f119551bd08022aab.jpg)

当我打开的时候，发现并不是文本文件，幸运的是，我发现有python解析库（python-evtx），我们需要提取域名和进程，不过这都是后话了。

![](/notes-assets/d209ddb44a92f8cf664e.jpg)

这次实际做到的是看见日志，后面的自动隔离还只是计划。进程上下文和情报可信度不能省略，否则一个方便的联动，也可能把普通请求处理成误处置。
