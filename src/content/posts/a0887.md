ailx10说：这篇是在2018年12月之前写的，后来又改过。思考语义检测时，我先问了个有点孩子气的问题：人能看懂中文和英文，是不是也能给攻击定义一套“词加语法”？于是回到上下文无关语法，终结符、非终结符、产生式和起始符，配上简单字符串和算术式，慢慢看展开与归约怎么走。文章像一张还在推敲的草稿，把安全里的念头接到编译原理上。它没有一下造出完整检测器，但给我一个更明确的方向：别只问某个词在不在，也去问这些词凑在一起成了什么结构。

- 什么是汉语？是汉字\+语法吗？
- 什么是英语？是单词\+语法吗？

我们能够看懂这篇文章，是因为我们认识里面每一个汉字，理解这门语言的语法。那么我们能不能定义一门攻击语言？

- 比如XSS攻击语言：JS token \+ JS语法？
- 比如PHP攻击语言：PHP token \+ PHP语法？

语法分析可检查输入是否符合指定语法，但合法性本身不能证明是否存在攻击。

## 上下文无关语法

> 上下文无关语法G：终结符集合T \+ 非终结符集合N \+ 产生式集合P \+ 起始符号S

由起始符经过产生式推导出的终结符串构成该文法的语言。

```
S -> AB
A -> aA | ε
B -> b | bB
```

产生式用非终结符定义可替换结构；终结符是最终输入符号，ε 表示空串，不是普通终结符。

```
A:{ε ,a ,aa ,aaa , ...}
B:{b ,bb ,bbb , ...}
S:{b ,bb ,ab ,abb ,aab ,aabb ,...}
```

文法能表达一些正则无法表达的嵌套结构，但不意味着解析一定比正则更快。

再来看看`上下文无关语法`更强大的表达能力：

```
E -> E OP E | (E) | N
OP -> = + - * /
N -> [0-9]+
```

**整数算术表达式**！哇哦，简直了 \~

```
E:{1 ,123 ,1-1 ,(1+1)*(1+2) ,...}
```

很明显，我们知道`1+1`符合语法E，`1+-1`不符合语法E，那么机器是怎么知道的呢？

参考文献：[自己动手写编译器](http://pandolia.net/tinyc/)（[pandolia.net/tinyc/](http://pandolia.net/tinyc/)）

语法合法和安全不是同一个判断，换了工具也不自动更快。把真实解释器与输入上下文带回来，抽象语法才不会被误当成攻击识别的万能答案。
