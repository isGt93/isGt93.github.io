ailx10说：这篇是我2022年7月写的。ufw 这篇继续沿用同一套本机 SSH、远端 RDP 的对照，只是把配置放到它管理的文件里，配 sysctl 和 NAT 规则后再启用验证。熟悉的规则换个入口出现，正好让我看见 ufw 和底层包过滤之间的关系，不只是记一个更方便的命令。文章还放了抓包结果，想把配置与实际数据对起来。转发是否改变监控可见性，不能靠工具名字判断；对我更有用的是把每次访问都当作一次检查，看规则到底有没有按想象执行。

---

ufw配置sysctl、NAT REDIRECT与远端DNAT/SNAT，启防火墙后验证本机SSH和远端RDP，操作沿用iptables规则。

## 技术条件与证据边界

关键配置文件内容在图，称ufw升级版iptables不准确；转发不必绕过南北监控，需结合采集位置，开端口不单独证明转发。

## 历史实验与原文记录

第一步：配置允许端口转发

```
vim /etc/ufw/sysctl.conf
```

![](/notes-assets/6ce4d0c93306aae3974e.webp)

第二步：本地端口转发配置

```
*nat

:PREROUTING ACCEPT [0:0]

-A PREROUTING -p tcp --dport 8022 -j REDIRECT --to-port 22

COMMIT
```

![](/notes-assets/03bbe19a3b2a4ff9fad1.jpg)

第三步：启动ufw防火墙

```
ufw allow 22

ufw enable

service ufw start

service ufw status
```

![](/notes-assets/84cdf1ecd5d95b03eceb.jpg)

第四步：验证本地端口转发

```
ssh ailx10@192.168.199.247 -p 8022
```

![](/notes-assets/e43de71b9f2ed8829b05.jpg)

第五步：额外配置端口远程转发

```
vim /etc/default/ufw
```

![](/notes-assets/0dc2791a62a0cc4c8731.webp)

第六步：配置端口远程转发，直接去iptables实验中复制就行

```
-A PREROUTING -p tcp --dport 13389 -j DNAT --to-destination 192.168.199.185:3389

# PREROUTING链：在进行路由选择前处理数据包（做目标地址转换）

# 去往跳板机机 13389 端口的流量 转发 到内网的3389端口





-A POSTROUTING -p tcp -d 192.168.199.185 --dport 3389 -j SNAT --to-source 192.168.199.247

# POSTROUTING链：在进行路由选择后处理数据包（对数据链进行源地址修改转换）

# 去往内网 3389 端口的流量 修改源IP是跳板机
```
