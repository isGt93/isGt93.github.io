ailx10说：这篇是我2023年6月写的。VPN 平时像一个“连上就能用”的客户端，这章把我拉到服务端口和协商消息前面。用 ike-scan 看 IPsec 的入口、指纹和参数，再试不同模式，后面又用 Nmap、OpenSSL 看 SSL VPN 的证书。每一步都在问服务愿意返回什么，而不是等登录以后才开始了解它。我把这些观察按顺序留下，像把黑盒外壳先摸一圈。做完这一章，“这边有个 VPN”终于不只是一个名称，后面还有协议和实现给出的具体线索。

1、IPsec VPN

1）IPsec服务端点枚举

```
ike-scan 192.168.0.1/24
```

![](/notes-assets/564249bb497f5035b1c6.webp)

2）IPsec服务端点指纹识别

```
ike-scan --showbackoff 192.168.0.108
```

![](/notes-assets/51e27a32f990812d184f.webp)

3）使用ike-scan进枚举系统支持的transforms

```
ike-scan -M --trans=5,2,1,2 192.168.0.108
```

![](/notes-assets/0867c67235927cc5d743.webp)

4）使用ike-scan进行野蛮模式用户枚举

```
ike-scan --aggressive --multiline --id=ailx10 192.168.0.108
```

![](/notes-assets/722305a1d4ebcd467c79.webp)

5）通过窃听野蛮模式数据包发现用户名

```
sudo tcpdump -n -i eth0 -s 0 -X udp port 500
```

![](/notes-assets/73e3442bf4687bd7c149.webp)

2、SSL VPN

1）SSL VPN指纹识别

```
nmap -Pn -sV 61.159.180.218 -p 1443
```

![](/notes-assets/5fdb5439c598b306a1a8.webp)

2）SSL VPN 证书识别

```
openssl s_client -connect 61.159.180.218:1443
```

![](/notes-assets/119fc9a61612a06b2f04.webp)

识别到证书，不代表通过了VPN认证，更不是漏洞证明。旧算法组合适合用来理解协商，不应不加区分地变成今天的配置建议。
