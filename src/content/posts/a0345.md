ailx10说：这篇是2022年2月之前写的，后来又改过。继续读 DDoS 论文时，我先给 HTTP 攻击和防护过程做分类，再把检测技术、SDN、OpenStack、IoT 等方向放进这张框架里。看得越多，越容易把“听过”当成“会了”，所以笔记里也留着 Slow Request 和工具的待办项。这篇不是一口气掌握很多方案的展示，而是当时读资料时想把关系理顺的尝试。分类能帮我知道下一篇在解决什么问题，真正比较方法还得回到数据、实验和具体指标，不能只靠标题里的新技术判断好坏。

---

原笔记按预防、监控、检测和缓解四个阶段整理 DDoS 研究，并归纳 HTTP 攻击类型、检测技术及 IDPS、SDN、云平台与物联网相关论文方向。

## 原笔记的阅读线索

作者记录的一篇综述题为 *A Review Of Recent Detection Methods For HTTP DDoS Attacks*，把攻击讨论分为会话泛洪、请求泛洪、非对称高负荷请求和慢请求／响应四类；其中慢请求部分在原笔记中标为待研究。后续笔记还提到基于熵、机器学习、FPGA、SDN 控制器以及物联网僵尸网络的不同研究方向。

这些名称适合用来继续查资料，不能直接视作对各方法效果的验证。原记录没有为每项工作提供完整书目信息，也没有完整实验细节；比较时仍需核查原论文和评估条件。

## 用四阶段组织问题

预防关注减少暴露面与资源准备；监控收集流量及服务状态；检测区分异常与正常流量；缓解则采取限流、过滤或上游协作等措施。不同系统的实现和权衡不同，阶段之间也可能循环。

机器学习或人工智能并不会自动降低误报，仍需要明确数据集、模型、阈值、基线与评价指标。SYN 流量本身也不能被简单归为低速攻击；攻击速率和流量形态应根据具体实验判断。

原笔记中部分慢请求和工具主题标为待研究，不应改写为已完成实验。多数论文缺少完整书目信息，本文仅整理阅读提纲，模型细节和效果需核查原论文。

几篇工作排在一起，差异才会显出来：谁在做识别，谁还验证了处置效果。把这些问题写进笔记，比只积累更多论文标题更接近自己的研究准备。
