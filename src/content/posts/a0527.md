ailx10说：这篇是在2022年1月之前写的，后来又改过。蜜罐忽然卡得厉害，后台 CPU 还被限制，我第一反应就是是不是中了挖矿。重启以后服务又好了，这反倒让我更想查个明白，于是装上 ClamAV、更新库，扫了一遍指定目录，再回头看蜜罐日志里的请求和时间分布。这篇记录的是一次从怀疑中毒出发的排查，并没有拿到确认感染的证据。它有那种自己服务器一出异常就想刨根问底的劲头，也留下了猜测和实际扫描结果并不总能对上的地方。

---

---

今天在访问自己的蜜罐的时候，发现卡的要死，一度怀疑是不是Linux服务器中毒了。然后，我打开后台看了一下，发现CPU高使用率，导致被限制了，这让人的第一印象是啥？挖矿病毒。我的第一反映是这样的。

---

![](/notes-assets/99215568444639c981b9.webp)

二话不说，重启了服务器，发现蜜罐又好了，惊喜，因为我写了一个Linux系统定时任务，会自动拉蜜罐进程。按理说，病毒没这么脆弱吧，这就让我有了对Linux系统杀毒的念想。

![](/notes-assets/d8f38e05778643345c3f.jpg)

既然都已经打开了蜜罐，就看一看。发现僵尸网络活动的时间：

- 晚上7点：这个时候大家都已经吃完晚饭，休息放松
- 凌晨：这个时候大家都已经准备睡觉了
- 上午11点：这个时候大家都准备吃饭了

访问时间分布需要结合时区、样本量和业务基线，不能直接推断攻击者动机。

![](/notes-assets/ceaa71616b391280c348.webp)

来源 IP 的地理位置和请求比例不能直接代表攻击者国籍或国家网络安全水平。

- 50%：中国
- 30%：美国
- 20%：其他国家

![](/notes-assets/5de49ffb1559e459e282.webp)

SSH登陆上服务器，通过top命令查看了一下CPU、磁盘使用率情况，发现都比较正常，基本上大消了挖矿病毒的猜想，但是万一是个铁憨憨呢，只在夜里爆发怎么办？

![](/notes-assets/e1aed15e5c767ed3e288.webp)

于是，有了Linux病毒查杀的念想，说干咱就干。

## 第一步：安装clamav

```
apt install -y clamav
```

![](/notes-assets/fde2351897f3f7a95e10.webp)

## 第二步：更新病毒库

```
freshclam
```

![](/notes-assets/46e9244b5842f0ada55d.jpg)

## 第三步：扫描

- -r：迭代目录
- -l：指定日志路径
- --max-dir-recursion：指定目录深度

```
clamscan -r /etc --max-dir-recursion=5 -l /root/etcclamav.log
```

![](/notes-assets/01cb71bd7a51b51710c3.webp)

在授权环境中按需选择扫描路径。未发现结果仅说明本次扫描范围内没有命中已有规则。
