ailx10说：这篇是在2019年12月之前写的，后来又改过。当时我在整理 PHP 攻击检测规则，顺着 CRS 的几段表达式往下看，发现开标签、上传后缀、流包装器、序列化、变量函数和环境变量都藏着不少门道。我把规则拆出来，旁边再记它大概想抓什么，后面还收了高危函数和告警函数的名单。这篇像一份读规则时的边注，不是每个词出现就一定有攻击，而是先把检测器的视角看清：它在哪些位置警惕，为什么会把这些看起来零散的写法放到一起。

---

PHP规则片段覆盖开标签、上传后缀、php流、序列化、变量函数与环境变量，再提220高危和200告警函数。

## 技术条件和待核查点

实际来源应CRS规则不只OWASP Top10；缺SecRule目标ID阶段动作无法直接部署，反序列化特征不是恶意必然、路径归一化应匹配后端解析。

## 原实验与代码

规则片段参考 OWASP Core Rule Set（CRS）类规则；具体规则来源、版本及上下文需要对照原始项目核实。

简单的整理了一下PHP攻击防范规则，黑客大佬可能会联想到很多PHP注入，评论区欢迎大家一起讨论哈，包括不限于PHP注入姿势，PHP花式绕过WAF\~

**#PHP开标签**

- `@rx (<\?(?!xml\s)|<\?php|\[(/|\\)?php\])` \\
- `"msg:'PHP Injection Attack: PHP Open Tag Found'`\\
- `t:none,t:urlDecodeUni,t:lowercase`\\

![](/notes-assets/40999887e638d41cf951.jpg)

**#文件上传**

- `@rx .*\.(php\d*|phtml)\.*$` \\
- `msg:'PHP Injection Attack: PHP Script File Upload Found`\\
- `t:none,t:lowercase`\\

![](/notes-assets/1eaebdb0bd833b1c9d40.jpg)

**#IO流**

- `@rx (?i)php://(std(in|out|err)|(in|out)put|fd|memory|temp|filter)`\\
- `msg:'PHP Injection Attack: I/O Stream Found'`\\
- `t:none`\\

![](/notes-assets/29b77747a0d1bc3d4cad.jpg)

**#PHP反序列化**

- `@rx [oOcC]:\d+:\".+?\":\d+:{.*}` \\
- `msg:'PHP Injection Attack: Serialized Object Injection'`,\\
- `t:none`\\

![](/notes-assets/f904772c0b19c589e87a.jpg)

**#变量函数调用**

- `@rx \$+(?:[a-zA-Z_\x7f-\xff][a-zA-Z0-9_\x7f-\xff]*|\s*{.+})(?:\s|\[.+\]|{.+}|/\*.*\*/|//.*|#.*)*\(.*\)` \\
- `msg:'PHP Injection Attack: Variable Function Call Found'`\\
- `t:none`\\

![](/notes-assets/ae4d0f88753840520ef0.jpg)

**#PHP变量**

- `@rx (?:HTTP_(?:ACCEPT(?:_(?:ENCODING|LANGUAGE|CHARSET))?|(?:X_FORWARDED_FO|REFERE)R|(?:USER_AGEN|HOS)T|CONNECTION|KEEP_ALIVE)|PATH_(?:TRANSLATED|INFO)|ORIG_PATH_INFO|QUERY_STRING|REQUEST_URI|AUTH_TYPE)`\\
- `msg:'PHP Injection Attack: Variables Found'`\\
- `t:none,t:normalisePath,t:urlDecodeUni`\\

![](/notes-assets/7382a72a010bbda828ad.jpg)

规则片段能帮助理解特征，却不是拿来直接部署的完整策略。匹配到序列化或某个函数也不自动等于恶意，真正的判断还要接回应用如何解释这些内容。
