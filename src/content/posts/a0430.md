ailx10说：这篇是2022年1月之前写的，后来又改过。票据传递这次，我先把目标会话的票据导出、转到另一台机器再导入，之后又用已知用户材料向 KDC 取票，比较两种做法的路径。看着认证不像再输入一次密码，背后仍然需要已经拿到的身份材料和对应权限。笔记把导出、生成、导入和远程访问分成几段，也让我明白工具显示 OK 只是某一步完成，最后资源愿不愿放行还得实际看。这篇更像把 Kerberos 图里的票据拿到手上走一圈，原来抽象的流程才慢慢具体起来。

---

本文记录 Kerberos 票据导出、导入及使用既有凭据申请票据的历史实验。票据是认证凭据，不能称为无需认证。

![](/notes-assets/e95dc8dbb9f38550cd07.webp)

能否导出其他会话票据依赖权限；向当前会话导入票据与访问远程资源也需要分别验证。

## 1、使用mimikatz进行票据传递

使用横向移动神器`mimikatz`可以将内存中的票据导出来，首先在目标机器上以管理员权限运行下面的命令，就可以直接导出一堆不同主机的票据信息（KIRBI文件），从中选择一个目标系统自己的，移动到黑客机器上。（顺便说一下，直接在黑客机器上也能拿到目标机器的票据～）

- 在目标机器上以管理员权限，输入命令，获得票据
- 将票据移动到黑客机器上

```
mimikatz.exe "privilege::debug" "sekurlsa::tickets /export"
```

![](/notes-assets/d0c6fa360141c3d03205.jpg)

票据导入后还需验证目标服务的认证与授权。

原文导入票据后出现 OK 提示；该提示只说明导入步骤，不能单独证明目标资源访问成功。

```
mimikatz.exe "kerberos::ptt "[0;34c63]-2-0-60a10000-ailx00@krbtgt-HACKBIJI.TOP.kirbi"
```

![](/notes-assets/c6b620aefcb33531bdae.jpg)

最后，让我们一起见证奇迹吧，喜悦～

不同认证方式各有条件，单次实验无法比较其普适成功率。
![](/notes-assets/cc3a462e44c8c9a2d55a.webp)

## 2、实用kekeo进行票据传递

- kekeo下载地址：[github项目地址](https://github.com/gentilkiwi/kekeo)
- kekeo也是一款开源的票据传递工具
- kekeo需要指定域名、用户名、NTLM哈希来生成票据

原文使用已有用户 NTLM 材料向 KDC 请求票据；适用权限和协议条件应单独核查。

```
kekeo.exe "tgt::ask /user:ailx00 /domain:hackbiji.top /ntlm:8155bcb25220245086d66e6333898426"
```

运行后，就会生成`ailx00`的票据，把这个票据移动到黑客的机器上。

![](/notes-assets/8a4963f6fbe8e55e14a0.jpg)

原文报告导入票据；实际资源访问还需要独立验证。
![](/notes-assets/3d8ee4044933429d8e66.jpg)

最后，让我们一起见证奇迹吧，刺激～

单次结果不能证明票据传递总是比其他方式更有效。
![](/notes-assets/51676c3259e945d0a48d.jpg)

本篇完～

能导入票据和能访问目标资源，仍然要分别记录。把票据来源、当前会话和服务授权接起来，才不会把“有了材料”误解成“已经没有认证门槛”。
