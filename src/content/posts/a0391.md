ailx10说：这篇是我2024年8月写的。这次织梦我沿会员找回密码的流程试，把安全问题参数换成特殊的数值形式，再看返回的 key 链接能否继续重置另一个会员。改完后登录成功，让这个逻辑问题有了具体结果；但会员里的 admin 和后台管理密码并不是一回事，后面尝试也没有把它们变成同一个账号。这篇把这个区别留下来，免得标题一写“任意用户”就让人自动联想到后台。正常找回流程有哪些状态、哪一步没把身份锁紧，才是我这次练习最想看清的。

---

DedeCMS5.7.7会员安全问题重置通过safequestion\=0.0与空答案得到key链接，改另一会员密码并登录；id1改会员admin但未改变后台密码。

核查提示：这是会员权限，不能串成获取后台管理员；实验借后台查询目标mid，现实盲猜不同条件，\&amp;解码是HTML实体。 原实验和代码未重新运行，图内细节有待核验。

周末复现一下织梦CMS 5.7 SP2 任意用户密码重置漏洞，是在github上下载的 DedeCMS 5.7.7，这个漏洞可以修改任意会员的密码，但是提前并不知道用户的id，所以只能盲猜，尝试修改id\=1的会员密码，这是admin的id，确实修改成功了，但是admin不支持从会员登录，然后去后台登录，发现并没有修改后台密码。

注册2个账号，用于测试：

- 用户名：ailx11 密码：666666
- 用户名：ailx13 密码：333333

![](/notes-assets/0ee54ab701ec71065d2e.webp)

登录ailx11账号，尝试重置ailx13的密码，这里需要去后台看用户ailx13的mid是多少（mid\=7）

```
http://192.168.0.108/member/resetpassword.php?dopost=safequestion&safequestion=0.0&safeanswer=&id=7
```

![](/notes-assets/c430fae5801fee04f77a.webp)

查看源代码可知，跳转链接（请忽略返回的107，那是因为之前搭建网站的时候 DHCP IP地址是107），注意跳转链接中的`&amp;`是 HTML 实体字符，代表符号 `&` ，替换后跳转链接如下：

```
http://192.168.0.108/member/resetpassword.php?dopost=getpasswd&id=7&key=h4DXKLat
```

![](/notes-assets/d11b416ed077b131343c.webp)

现在，可以重置ailx13用户的密码了，将其新密码设置成 123456

![](/notes-assets/e5b658a5ea270dada884.webp)

尝试使用 123456 登录 ailx13的账号，登录成功

![](/notes-assets/3a3e934e3fa175458126.webp)

另一次尝试涉及名为 admin 的会员账户；原记录明确该密码不能用于后台管理员登录。

![](/notes-assets/16ebb53a19d2faa08862.webp)

结果停在实际验证过的位置，反而更清楚。会员密码变化是一个具体问题，后台管理员密码没有随之改变也是一个具体结果，两者都应当留在记录里。
