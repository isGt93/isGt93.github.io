ailx10说：这篇是在2025年9月之前写的，后来又改过。研究大模型时，我想把自己的工具交给别人远程调用，于是问题从“本地能跑”变成了“服务怎么放到服务器上”。顺着 FastMCP 的 SSE 接口搭骨架，再用 Docker 和 supervisord 管启动、重启，自己熟悉的部署办法也就和新协议接上了。这篇记的是那次从脚本走向服务的小过程，核心日志功能没有在正文里全放出来。让我感到实用的是，原先只能自己在命令行里开的工具，终于开始有了一个可以被外面接过来的入口。

---

本文记录使用历史 FastMCP SSE 接口、Docker 和 Supervisor 启动服务的思路。示例有未定义变量及配置缺口，自动重启不保证永远可用；公网服务还需要认证与 TLS。

核查提示：compressed\_log未定义，supervisor配置加载未明确，重启非永远可用；公网无认证TLS/输入范围，按历史框架介绍。 原实验、代码和图片细节未逐项复测。

我的容器镜像大小只有150M，非常小巧，使用supervisord管理python3服务，可以保证MCP服务永远正常运行，即使有异常，也能自动重启，非常方便。

![](/notes-assets/f8f577d4b6fcb262ab36.webp)

MCP可以将大模型和旧的程序做了一个完美的融合，如果做一些基础提效工具网站，一句话需求，自动调用工具去解决，我觉得应该会火。比如帮我渗透一个Web网站，大模型自动调用漏扫工具，印象中一些工具厂商已经提供类似的MCP服务了，这必然是未来的发展趋势。MCP服务的框架如下，仅供参考：

- 

```
docker-compose.yml
```



```
services:
  mcp-server:
    build: .
    container_name: mcp-server
    ports:
      - "8000:8000"
    restart: always
```

- 

```
Dockerfile
```



```
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
RUN pip install supervisor

COPY . .

CMD ["/usr/local/bin/supervisord"]
```

- 

```
requirements.txt
```



```
mcp==1.13.1
```

- 

```
supervisord.conf
```



```
[supervisord]
nodaemon=true

[program:mcp_server]
command=python mcp_server.py
directory=/app
autostart=true
autorestart=true
```
