ailx10说：这篇是我2023年9月写的。我当时想试试：WebLogic 的测试页面里，上传功能到底能带来多大影响。实验不是从默认生产环境直接开始的，而是先在后台启用测试页，再调整工作目录，随后通过 keystore 上传入口放入 JSP，最后根据响应里的线索找到文件。整个过程比“传个文件就控制网站”多了好几个前提，所以我把这些配置也记了下来。它更像一次把风险链路接完整的练习：入口、目录、文件能否被访问和解释，得一步步确认。

---

本文记录 WebLogic Web Service Test Page 的历史上传实验。

原实验先启用测试页并修改工作目录；生产环境测试页默认关闭这一前提不可省略，目录和口令均为样例。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明Weblogic 任意文件上传漏洞（CVE-2018-2894）环境搭建成功了

![](/notes-assets/ae627a86514056d53def.webp)

执行`docker compose logs | grep password`可查看管理员密码，管理员用户名为`weblogic`，密码是`yRc9TV24`

![](/notes-assets/784891a70e232cc84301.webp)

登录后台页面，点击`base_domain`的配置，在“高级”中开启“`启用 Web 服务测试页`”选项：

![](/notes-assets/3bfa446245756aa0916b.webp)

![](/notes-assets/894f2bcbfa86653c722a.webp)

访问`http://144.34.162.13:7001/ws_utc/config.do`，设置Work Home Dir为`/u01/oracle/user_projects/domains/base_domain/servers/AdminServer/tmp/_WL_internal/com.oracle.webservices.wls.ws-testclient-app-wls/4mcj4y/war/css`。将目录设置为`ws_utc`应用的静态文件css目录，访问这个目录是无需权限的，这一点很重要。

![](/notes-assets/a0ddcc6039208f384ddd.webp)

然后点击安全 -\> 增加，然后上传 `jsp webshell`（来自冰蝎）：

![](/notes-assets/97f8821d76c3a7348b9b.webp)

记得提前打开`burpsuite`，这样在`proxy -> http history` 下，就能查看所有通信流量，上传后，查看返回的数据包，其中有时间戳

![](/notes-assets/d3b73c5f2d93a458a163.webp)

使用冰蝎客户端连接 `http://144.34.162.13:7001/ws_utc/css/config/keystore/1694515986635_shell.jsp`，密码是默认连接密码`rebeyond`，即可获得 `webshell`

![](/notes-assets/d6b0f36dc895028c0735.webp)
