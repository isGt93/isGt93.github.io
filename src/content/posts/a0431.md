ailx10说：这篇是2022年1月之前写的，后来又改过。PsExec 这篇先从微软工具入手，拿已有账号或 SMB 会话启动远程 cmd，再观察以 SYSTEM 运行的结果，随后换到 Metasploit 的几个模块对照。有的在 Win7 没成功，Server 2012 又能跑，换模块以后情况也变了。这样的过程比一句“支持远程控制”更有信息，权限、系统和工具实现都在参与。笔记留下每次尝试，是想知道失败停在何处；不经过远程桌面并不代表没有服务和进程痕迹，后台运行也仍然是具体发生过的动作。

---

PsExec 支持以已有凭据远程运行进程，历史实验展示 Sysinternals 工具与 Metasploit 模块的差异。无需 RDP 不代表没有服务、共享或进程日志。

## 1、PsTools工具包中的PsExec

- [pstools微软下载地址](https://docs.microsoft.com/en-us/sysinternals/downloads/pstools)
- 验证环境是 windows server2012 --\> win7

第一步：建立`IPC$`管道

```
net use \192.168.160.135\ipc$ "W2ngluoanquan" /user:HACKBIJI\Administrator
```

第二步：通过`PsExec.exe`获得远程系统的控制权

-accepteula 接受许可提示；-s 请求以 SYSTEM 运行，但仍需适当的远程管理权限。

```
.\PsExec.exe -accepteula \192.168.160.135 -s cmd.exe
```

![](/notes-assets/9a21cb8e9821765db396.jpg)

未指定 -s 时进程身份取决于认证上下文和配置，不一定是管理员。

![](/notes-assets/d416f414b0a740478143.webp)

如果没有提前建立好`IPC$`，PsExec也可以通过指定账号和密码的方式，进行远程连接。

```
.\PsExec.exe \192.168.160.135 -u HACKBIJI\ailx00 -p WoShi@Ailx10 cmd.exe 
```

![](/notes-assets/1ee6e550ae36a87bb3b2.webp)

## 2、metasploit中的psexec模块

metasploit是著名的漏洞检测工具框架，整合了漏洞扫描、漏洞利用、后渗透安全检测等
