ailx10说：这篇是我2025年2月写的。url 这道题，我当时看完 writeup 还是没完全明白。知道有 flag.php，也知道要 POST 一个 url，就先试 data 这样的包装器，观察 invalid url、host not allowed 这些反馈。后来照着题解换成特定输入，结果是出来了，可中间那段校验到底怎样工作，缺着源码就解释不全。这篇没有把这种困惑藏起来。它记录的是“复现了输入，但机制还没补齐”的状态，留着以后继续追；有时候把自己不懂的地方写准，比硬编一条流畅的推理更有意义。

---

原题允许提交 URL。作者尝试 data 包装器并遇到限制，后通过参考题解得到结果，但未取得足够源码解释验证机制。

![](/notes-assets/f878ba06dd206448806a.webp)

扫描目录，只发现一个 `flag.php` ，访问无果

![](/notes-assets/caff8b459b8be35cb8a6.webp)

尝试POST请求，发现 error: invalid url ，说明 url 的值不对

![](/notes-assets/fd342571fec373728557.webp)

原实验报告出现 host not allowed；data URL 中看似域名的部分不能因此认定为真实远程主机，其解析与检查方式须结合源码分析。

```
url=data://text/plain;base64,YWlseDEw
```

YWlseDEw 是 ailx10 的 base64编码

![](/notes-assets/a8dea4f379430afd4386.webp)

writeup 看的一头雾水，`bjNrMA==` 是 `n3k0` 的base64编码，这么一访问，flag就到手了

```
url=data://baidu.com/plain;base64,bjNrMA==
```

![](/notes-assets/050639bad1e8dbc0350a.webp)

原作者推测该请求与 flag.php 有关，但没有源码证明，保留为待解释问题。

提交 `url=data://baidu.com/plain;base64,bjNrMA==` ，拿flag。

但是，没有给任何提示，导致读取 `flag.php` 没有任何头绪，看了 writeup，清一色的只给拿flag的载荷。

没有源码支持的部分，就保留为未解释现象。知道自己在哪一步借助了外部题解，反而能给下一次重看留下具体问题，比编一个圆满机制更实在。
