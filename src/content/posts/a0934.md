ailx10说：这篇是2022年4月之前写的，后来又改过。给 Neo4j 提速，我想先离线为节点分配稳定数字 ID，省去后面反复查字符串。可原来的 SQLite 处理半小时数据，自己却跑了四十分钟，实在等不住，就去找架构师讨论 Redis。对方先想到断电和故障，我当时只想先做个 demo 看一眼，亲自写完试下来，确实比旧实现快。这篇保留了那种工程讨论的温差：稳定性要想，零到一也得先有东西。那次几秒与十几秒的对照只是自己的实验，却让我找到了下一步优化该往哪挪。

---

快速ID篇对SQLite与Redis映射字符串类型到稳定整数做Python对比，称1万行4秒比16秒快。

## 前提和待核查点

SQLite逐次提交无索引对比不公平；Redis计数读取写入非原子有并发碰撞，持久化与唯一约束不可忽略。

## 历史笔记与实验记录

为了让 neo4j 入库加速，我想到了给每个节点添加一个离线的ID，这个的好处是后面的数据，不需要查询字符串，直接根据数值类型的离线ID快速 merge 入库，这块的核心就是如何维护好这个离线ID，鉴于上次我使用的sqlite发现30分钟的数据，需要40分钟来处理，实在是慢的不像话，于是我和架构师bao总进行了讨论。

讨论如何基于redis来实现，架构师一上来就考虑各种异常，什么redis断电了，redis故障了，我说咱们就写一个demo，应该不会出现这种企业级的问题，毕竟先要从零到一，有一才能谈未来嘛，本着这样的思想，我亲自写了一个简单的程序，测试了一下性能，redis果然完爆了sqlite，同样多的数据，redis需要4秒，而sqlite需要16秒。

```
import sqlite3

import os

import redis

import pandas as pd

import time



def create_db():

    dbfile = "id.db"

    if os.path.exists(dbfile):

        conn = sqlite3.connect(dbfile)

        c = conn.cursor()

        return c,conn

    else:

        conn = sqlite3.connect(dbfile)

        c = conn.cursor()

        c.execute("""

        CREATE TABLE IDDB

        (ID INTEGER PRIMARY KEY NOT NULL,

        NAME   CHAR(256)   NOT NULL,

        TYPE   CHAR(10)    NOT NULL);

        """)

        conn.commit()

        return c,conn



def getid(c,conn,name,type):

    cursor = c.execute("SELECT ID,NAME,TYPE from IDDB WHERE name='{}' AND type='{}'".format(name,type))

    data = list(cursor)

    if len(data) > 0:

        for row in data:

            id = row[0]

            return id

    else:

        c.execute("INSERT INTO IDDB (type,name) VALUES ('{}','{}')".format(type,name))

        conn.commit()

        id = getid(c,conn,name,type)

        return id



def get_id_src_ip(x,c,conn):

    return getid(c,conn,x.src_ip,"id_src_ip")



def get_id_web_domain(x,c,conn):

    return getid(c,conn,x.web_domain,"id_web_domain")



def get_id_response_content(x,c,conn):

    return getid(c,conn,x.response_content,"id_response_content")



def requestIPNode(c,conn):

    df = pd.read_csv("test10000.csv",usecols=["src_ip","a1","a2"])

    df.dropna(axis=0,how="any",inplace=True)

    df.drop_duplicates(inplace=True,ignore_index=True)

    df["id_src_ip"]=df.apply(get_id_src_ip,args=(c,conn),axis=1)

    df.to_csv("data/requestIPNode.csv",index=False)



def get_id_by_sqlite():

    start = time.perf_counter()

    c,conn = create_db()

    requestIPNode(c, conn)

    conn.close()

    end = time.perf_counter()

    print("sqlite 耗时：{}".format(end-start))





def getid2(r,name,type):

    num = int(r.get("foo"))

    key = "{}_{}".format(type,name)

    if r.exists(key):

        return int(r.get(key))

    else:

        r.set(key,num+1)

        r.set("foo",num+1)

        return num+1





def get_id_src_ip2(x,r):

    return getid2(r,x.src_ip,"id_src_ip")



def requestIPNode2(r):

    df = pd.read_csv("test10000.csv", usecols=["src_ip", "a1", "a2"])

    df.dropna(axis=0, how="any", inplace=True)

    df.drop_duplicates(inplace=True, ignore_index=True)

    df["id_src_ip"] = df.apply(get_id_src_ip2, args=(r,), axis=1)

    df.to_csv("data2/requestIPNode.csv", index=False)





def get_id_by_redis():

    start = time.perf_counter()

    r = redis.StrictRedis(host='localhost', port=6379, db=0)

    if not r.exists("foo"):

        r.set("foo","0")

    requestIPNode2(r)

    end = time.perf_counter()

    print("redis 耗时：{}".format(end-start))



if __name__ == "__main__":

    get_id_by_sqlite()

    get_id_by_redis()
```

快不等于唯一性和持久化都正确，计数与写入也要处理并发。把公平基线补齐，这次比较才会帮助选方案，而不是只记住一个看起来更快的名字。
