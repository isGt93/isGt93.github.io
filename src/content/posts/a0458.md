ailx10说：这篇是2022年7月之前写的，后来又改过。nc 这次不提供交互 shell，而是把一个连接接给另一个连接：先转本机 SSH，再让跳板转到 CentOS 的 SSH。两边能登录以后，我又看客户端和跳板抓包，试着理解中继时每段数据长什么样。它是一个很小的拼装练习，可也能看出不同 nc 实现的参数差异，监听是否只接一次也会影响使用。笔记留下的是当时那版工具的结果，最想说明的仍是转接动作本身；换了程序，原本的连接和协议并不会因此神秘地消失。

---

nc -c串接同机8888到22、跳板7777到CentOS22，分别访问SSH并比较客户端和跳板抓包。

## 技术条件与证据边界

-c不是所有nc实现都支持，监听默认一次连接限制；反复单边流量结论需检查抓包环境，转接本身不会使请求包消失。

## 历史实验与原文记录

实验环境：

- macos：192.168.199.206
- kali：192.168.199.247
- centos：192.168.199.236

实验一：本地端口转发，将kali的8888端口转发到22端口

```
nc -lp 8888 -c "nc 127.0.0.1 22"
```

![](/notes-assets/2e39217278a09ffe50ac.jpg)

再看抓包情况，黑客视角来看，还是从客户端到服务端没有流量，但是服务端到客户端

![](/notes-assets/dd699bfc6e8926199b07.jpg)

受害者视角来看

![](/notes-assets/14084c288750e568bf6e.jpg)

实验二：远程端口转发，访问kali的7777端口，就是访问centos的22端口

```
nc -lp 7777 -c "nc 192.168.199.236 22"
```

![](/notes-assets/e0d953a1fbd878638566.jpg)

再看看抓包情况，从黑客视角来看，一样的都是单边流量
