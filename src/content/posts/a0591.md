ailx10说：这篇是我2025年8月写的。客户那边偏偏是 32 位 Win10，我原来发出去的工具跑不起来，周末就专门开虚拟机补一份。Python 3.8.9、Nuitka 编出的模块、PyStand 和嵌入式运行时一块块拼，Tkinter 又让过程多停了一下。这篇留下的是一次为具体环境返工的记录。平时随口说“Windows 程序”，真交付时位数、解释器和界面库都不能省；这次把它们逐个对上，也就给下一次遇到类似老环境留了一条能回查的路。

为32位Win10搭Python3.8.9、编译PyStand及Nuitka pyd，组合嵌入式runtime和site-packages，处理Tkinter错误。

核查提示：MinGW安装叙述与实际Visual Studio生成器需区分；Tkinter修复在图待读，所有库须架构一致。 旧环境及截图细节未逐项核验。

本文记录在 32 位 Windows 环境组合 Nuitka、PyStand 和嵌入式 Python 的实验。解释器、扩展模块和运行库的架构与 ABI 必须匹配。

## 第一环节：安装32位的python3.8.9[\[1\]](#ref_1)和nuitka

在这里下载32位的python安装程序和32位的嵌入式软件包，安装好之后就可以`pip install nuitka`

注意：python3.8 是支持在win7上跑的最后一个版本

![](/notes-assets/2b4b364a743df79b94bf.webp)

## 第二环节：编译32位的pystand[\[2\]](#ref_2)

- 首先要下载 MinGW-w64[\[3\]](#ref_3) ，请务必选择 Win32 （32位）的版本，解压即可使用，注意配置环境变量。
- 然后安装 CMake[\[4\]](#ref_4)，请务必选择 Win32 （32位）的版本，安装过程中会默认配置环境变量。
- 最后下载pystand[\[2\]](#ref_2) ，解压后创建 build 目录，进行编译，得到 `PyStand.exe` ，重命名为 `main.exe`。

```
mkdir build
cd build

cmake .. -G "Visual Studio 17 2022" -A Win32
cmake --build . 
```

## 第三环节：构建可执行程序框架

![](/notes-assets/ba3f228188a71c1166e4.webp)

- `runtime`：文件夹内容是下载的嵌入式python解压缩
- `site-packages`：文件夹内容是你的项目的`site-packages`
- `main.exe`：是你编译的`PyStand.exe`重命名得到的
- `main.int`：是你的python 入口程序
- `app.pyd`：是你后续nuitka编译的pyd文件

## 第四环节：编译程序做准备

nuitka 编译的时候要下载 `14.2.0posix-19.1.1-12.0.0-msvcrt-r2.zip` [\[5\]](#ref_5) ，一般下载很慢，提前下载好，解压到对应的目录（具体在你初次运行nuitka编译的时候，会提示你的）：

```
C:\Users\ailx10\AppData\Local\Nuitka\Nuitka\Cache\DOWNLO~1\gcc\x86\14.2.0posix-19.1.1-12.0.0-msvcrt-r2\mingw32\bin\gcc.exe
```

解压后，重命名为 `14.2.0posix-19.1.1-12.0.0-msvcrt-r2`，再nuitka编译就得到`pyd`文件了
