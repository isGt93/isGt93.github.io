ailx10说：这篇是我2022年6月写的。这一课想回答一个简单问题：不认识局域网里的机器，能不能从它对 UDP 的反应里发现存在？我一边发探测，一边用原始套接字抓 ICMP，先拿 ping 对照，再看端口未开放时返回的内容，顺便分清 Windows 和类 Unix 的写法。比起直接开扫描器，这个小程序把“发出去了、收回来了什么”拆得很清楚。我把每一步现象记下来，也让平时课本里的 ICMP 错误第一次成为自己手里可以用来判断环境的具体线索。

---

本文记录通过 UDP 探测和 ICMP 响应观察主机存活的实验。目标或防火墙可能不返回 ICMP，无响应不能证明主机离线。

核查提示：端口关闭不保证回ICMP，需相关请求/类型来源校验，代码只抓一包不能独自完成主机发现。 原实验、代码和图片细节未逐项复测。

1、在mbp电脑上特权执行sniffer脚本，因为使用了原始套接字，必须要root权限

![](/notes-assets/6ae8b6c687e8b85257e3.jpg)

2、在kali虚拟机上执行一个ping命令，在mbp端就可以抓到ICMP应答包了，可以看到kali上的知乎IP地址和mbp上看到的是一样的，说明知乎网站是存活的

![](/notes-assets/cc0593dea3ae29ff7c7f.jpg)

3、同样的，我们在kali虚拟机上执行一个udp请求，比如使用nmap扫描8888端口

![](/notes-assets/4eab39c585860c1ffca8.jpg)

4、我们也能在mbp端收到一个icmp应答报文，同样可以判断知乎是存活的

![](/notes-assets/23b9db0ad6374bb25f5a.webp)

参考代码：

```
# -*- coding: utf-8 -*-
# @Time    : 2022/6/4 5:29 PM
# @Author  : ailx10
# @File    : sniffer.py

import socket
import os

HOST = "192.168.0.102"

def main():
    if os.name == "nt":
        socket_protocol = socket.IPPROTO_IP
    else:
        socket_protocol = socket.IPPROTO_ICMP

    sniffer = socket.socket(socket.AF_INET,socket.SOCK_RAW,socket_protocol)
    sniffer.bind((HOST,0))
    sniffer.setsockopt(socket.IPPROTO_IP,socket.IP_HDRINCL,1)

    if os.name == "nt":
        sniffer.ioctl(socket.SIO_RCVALL,socket.RCVALL_ON)

    print(sniffer.recvfrom(65565))

    if os.name == "nt":
        sniffer.ioctl(socket.SIO_RCVALL,socket.RCVALL_OFF)

if __name__ == "__main__":
    main()
```

关闭端口未必回包，没收到也不等于离线。把请求关联、类型和来源核对起来，发现主机才不是只等一个碰巧出现的响应。
