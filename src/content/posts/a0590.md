ailx10说：这篇是我2025年5月写的。日志发送工具在自己 Win10 上跑得好好的，到了客户的 Win7 却报缺 DLL。装运行库、修系统都没解决，最后把 cryptography 和 bcrypt 版本往回对，程序才启动。这篇像一次典型的现场兼容事故：开发机上的顺利，到了旧系统面前并不算数。我把尝试过的方向和最后接上的依赖都记下来，免得下次再从第一步绕起。工具能发日志是业务功能，先让它在客户那台机器上活起来，却是交付里最现实的一关。

---

日志发送工具在Win7缺DLL，装运行库和修复无效，降cryptography及bcrypt后启动。

核查提示：具体个案非通用修复，旧依赖安全与功能需评估；直接造日志不验证真实采集检测全链。 旧环境及截图细节未逐项核验。

本文记录一个 Python 工具在 Win7 缺 DLL 后通过调整依赖启动的个案。旧依赖可能引入安全和兼容风险，结果不能作为通用修复。

（1）从 msdn i tell u 下载了 win7 sp1

![](/notes-assets/688fbda903681a3c0d82.webp)

（2）运行我的 poclogsender 报错，缺失 dll

![](/notes-assets/1f2720846290a12bd9b8.webp)

（3）尝试安装 vc\_redist.x64[\[1\]](#ref_1) 依然报错，DLL load failed

![](/notes-assets/5bdf69befc66ee8e7c35.webp)

![](/notes-assets/c83177616269198bf137.webp)

（4）使用360安全卫士进行系统修复，还是报错 cryptography,bcrypt,six 错误

![](/notes-assets/80d425d4ebede2fdbb3d.webp)

![](/notes-assets/51887e095b230d96b046.webp)

（5）替换成适配 win7 的依赖库，再次运行，就可以了

```
pip install cryptography==3.4.8
pip install bcrypt==3.1.7
```

![](/notes-assets/d430e6dd08a41e73e44f.webp)
