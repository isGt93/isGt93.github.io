ailx10说：这篇是我2024年9月写的。这个 ThinkPHP5 实验里，我先从数组键进入 SQL 的位置做报错观察，接着又在异常页面里看到了数据库配置，于是继续尝试用这些信息连接数据库。几个结果挨着出现，很容易一句话说成“注入拿到了所有密码”，但实际上 SQL 返回值和配置泄露是两条不同的信息来源。我把这段过程留下，就是想分清每一步到底给了我什么。直接连库还得网络可达，靶场里知道容器地址的便利，也不能当成外面访问时天然拥有的条件。

---

编辑核查提示：SQL user() 与异常页泄露数据库密码是两个不同渠道；本次连接发生在容器环境，不能推断外部网络一定可达数据库。 原题代码和外部地址未重新运行；截图细字及水印仍待核对。

本文记录 ThinkPHP5 数组键参与 SQL 拼接所产生的 SQL 注入和异常页信息泄露。SQL user() 结果与配置页中出现的数据库密码属于不同信息来源。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build//可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明 ThinkPHP5 SQL注入漏洞 \&\& 敏感信息泄露 环境搭建成功了

使用泄漏的信息登录docker容器中的mysql数据库，查看表中的内容

```
docker inspect <container_name_or_id> # 获取容器的IP地址
mysql -h 172.18.0.2 -P 3306 -u root -p
use cat;
show tables;
select * from user;
```

![](/notes-assets/a69851327bd59e9dc6ac.webp)

一个报错既可能泄露数据，也可能提供继续连接的材料。把注入和配置泄漏各自的作用写清楚，后面的数据库登录才有具体来路。
