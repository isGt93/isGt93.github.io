ailx10说：这篇是在2024年1月之前写的，后来又改过。告警一多，人工导成 Excel 筛一遍，很容易把相似请求反复看好几次。我就想，能不能先按内容把它们归一归，再把时间花在真正不同的那部分上？于是用 HTTP 响应的词集合做 MinHash，接 LSH 找近似项，还考虑把请求和响应合在一起。这篇就是一次面向分析工作的轻量尝试。算法名字并不新鲜，可放回那些重复、失败和噪声混在一起的告警里，它解决的是一个很具体的问题：让同样的内容少占几次人的注意力。

原实验将相似响应作为候选；归并并不代表告警无害，仍需检查原始证据。

![](/notes-assets/51d79c28c7b942b0a027.webp)

LSH 用于近似相似项检索：候选可能遗漏或误匹配，需结合真实样本和阈值复核。原示例的最小邻居索引分组并不保证得到一致的连通分量。

```
import pandas as pd
from datasketch import MinHashLSH, MinHash


file_path = '1.xlsx'
df = pd.read_excel(file_path, engine='openpyxl')
http_responses = df['HTTP响应内容'].tolist()

# 定义LSH参数
permutations = 128  # 哈希函数排列数量
threshold = 0.8  # 相似度阈值

# 初始化MinHashLSH
lsh = MinHashLSH(threshold=threshold, num_perm=permutations)

# 创建并添加MinHash到LSH
for idx, response in enumerate(http_responses):
    # 初始化MinHash对象
    m = MinHash(num_perm=permutations)
    # 一种简单的处理方法是按单词分割响应内容
    words = response.split()
    for word in words:
        m.update(word.encode('utf-8'))
    # 将MinHash添加到LSH
    lsh.insert(str(idx), m)

# 创建字典以存储相似内容的索引列表
similar_responses = {}
for idx, response in enumerate(http_responses):
    m_query = MinHash(num_perm=permutations)
    words = response.split()
    for word in words:
        m_query.update(word.encode('utf-8'))
    result = lsh.query(m_query)
    # 更新字典
    for r in result:
        if r != str(idx):
            if str(idx) in similar_responses:
                similar_responses[str(idx)].append(int(r))
            else:
                similar_responses[str(idx)] = [int(r)]

# 创建新列记录相似内容的索引
similar_index = {}
for idx, similar in similar_responses.items():
    min_idx = min(int(idx), min(similar))
    similar_index.update({int(idx): min_idx})

# 将相似内容的索引写入新列
df['相似内容索引'] = df.index.map(lambda x: similar_index.get(x, x))
output_file_path = '2.xlsx'
df.to_excel(output_file_path, index=False)

# 输出结果
print(df)
```

近似相似不等于同一个事件，更不等于无害。归并应当保留回到原始请求的路，既减少噪声，也别把少数真正不同的内容一并压没了。
