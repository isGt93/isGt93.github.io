在以太网中，主机发送 IPv4 数据包时，需要知道下一跳对应的 MAC 地址。地址解析协议（ARP）用于在本地网络中建立 IPv4 地址与链路层地址之间的映射。本文介绍正常解析过程，以及错误映射可能造成的影响。

## ARP 如何解析地址

假设主机 A 需要向同一网段的主机 B 发送数据：

1. A 查询邻居缓存，寻找 B 的 IPv4 地址对应的 MAC 地址。
2. 如果没有可用记录，A 在本地链路广播 ARP 请求，询问该地址对应的硬件地址。
3. B 收到请求后，通常向 A 回复自己的 MAC 地址；A 更新缓存，并使用该地址发送以太网帧。

如果目标在其他网段，路由通常选择默认网关作为下一跳：此时 A 需要解析的是网关的 MAC 地址，而不是远端网站的 MAC 地址。邻居缓存不是永久不变的，具体更新方式和超时时间取决于系统实现。

## 伪造映射会造成什么影响

ARP 本身没有对报文发送者提供强身份认证。在某些网络和系统条件下，如果主机接受了伪造的 ARP 信息，邻居缓存可能把某个 IPv4 地址关联到错误的 MAC 地址。

以原实验为例：受控主机的地址是 `192.168.206.129`，网关 IP 是 `192.168.206.2`。实验机发送伪造信息后，原文观察到受控主机的网关 IP 对应到实验机的 MAC 地址，随后无法正常联网。

需要区分：**发生变化的是缓存中网关 IP 对应的 MAC 地址，并不是网关 IP 本身。** 如果错误地址无法转发流量，连接可能中断；如果设备能够转发，流量也可能经过该设备。实际行为取决于网络拓扑、终端策略和转发配置，不能仅凭缓存变化断言数据已被读取。

## 如何观察和排查

在获授权的实验网络中，可以对照网关实际 MAC 地址与受控主机的邻居缓存，观察映射发生变化的时间，并结合抓包、交换机日志和网络拓扑判断原因。注意高可用网关切换、设备更换和网络重配置也可能导致合法的 MAC 地址变化。

原文使用 Netwox 的历史版本发送报文；这里不把未复核的工具参数当作通用操作指南。不同系统是否接受特定 ARP 报文也需要在对应环境中验证。

## 防护思路

- 在适合维护的场景中，对关键设备配置静态邻居项，并建立变更流程；大规模环境需要评估维护成本。
- 在支持的交换网络中，结合 DHCP Snooping、动态 ARP 检测等能力约束异常映射，部署前应根据设备和网络架构验证配置。
- 使用 TLS、SSH 等经过正确验证的端到端加密协议保护应用通信，减少链路被干扰时敏感数据暴露的风险；加密并不能阻止所有断网或流量丢弃。
- 监测关键网关地址的映射变化，结合资产记录排查异常。

参考：[RFC 826：以太网地址解析协议](https://www.rfc-editor.org/rfc/rfc826)。

那次无法联网，说明错误映射已经影响了通信，却不能顺带证明流量被读取。把缓存变化和连接现象分别留下来，后面排查时就不会把所有网络异常都归成一种攻击。
