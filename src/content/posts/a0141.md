ailx10说：这篇是在2024年1月之前写的，后来又改过。这组 Windows 逆向题里，一道会检查调试进程，我就转去静态读代码，把分块异或的字符串一点点还原；另一道把字符放进四乘四的格子，得先反推置换，再接着处理输出。这篇记录的是两种不太一样的绕路：不一定非要把程序完整跑到最后，有时把数据怎样变化弄明白，也能走通。里面有些字符串和中间值很依赖原样本，重看时不能只抄最后脚本；更值得留下的是我怎样把一段伪代码改写成可以反向推回去的步骤。

---

本例从反编译代码跟踪字符串数据流，再根据异或或置换规则推导输入。

1、使用IDA逆向一个windows可执行程序 `fts.exe`

（1）当检测到`ida.exe`和`lr4x[LCG].exe` 进程，程序就无法走进flag 的循环中，因此这里演示使用IDA静态程序分析，直接求出flag。

（2）找到main函数，反编译：

![](/notes-assets/c070343a6d7b898ea325.webp)

（3）分析代码可知：将字符串"w}pvj"拷贝到v8中，并对v8中的每个字节与十六进制数0x11u进行异或操作，然后输出异或后的字符，使用python编程得到：`flag{`

```
v8 = bytearray(5)

v8[:5] = b"w}pvj"



for i in range(5):

    v8[i] ^= 0x11

    print(chr(v8[i]), end='')

# flag{
```

![](/notes-assets/a141393b0e50cc60dadc.webp)

2、使用IDA逆向一个windows可执行程序 `crackme2.exe`

（1）先找入口main函数

![](/notes-assets/e5e0d1b670d69a1712cc.webp)

（2）分析关键流程，比较字符串 v5 和 s 的一部分字符是否相等

通过逆向思维，反求满足条件的 v5 \= Y0u\_g0T\_th3\_f14g

```
s = "Ygtf00h1uT34___g"



def calculate_v5():

    v5 = ""

    for i in range(0, 16, 4):

        for j in range(4):

            v5 += s[i // 4 + 4 * j]

    return v5



result_v5 = calculate_v5()

print(result_v5)

# Y0u_g0T_th3_f14g
```

（3）继续查看是一段异或运算，直接算出flag的值，这里注意下str的值

![](/notes-assets/b5e9a6bfc92a6a6d765e.webp)

（4）编写python直接计算flag，也可以直接输入Y0u\_g0T\_th3\_f14g ，让程序自己输出flag

```
str_values = [0xD4, 0x72, 0x14, 0x5B, 0xBD, 0x77, 0x86, 0x06, 0xDE, 0x7B, 0xFC, 0x78, 0x80, 0x97, 0x3D, 0x94]



# 对应的v5字符串

v5 = "Y0u_g0T_th3_f14g"



# 进行异或操作

for k in range(16):

    str_values[k] ^= ord(v5[k])



# 将异或后的值转为十六进制字符串

hex_str = ''.join(format(val, '02x') for val in str_values)



# 输出结果

print("flag{%s}" % hex_str)
```

![](/notes-assets/f80f4c17a16cf8bd1f8d.webp)

看似杂乱的字符，背后可能只有几个确定的变换。把顺序和索引写清楚，程序就从一团难读的伪代码，变成了能够逐项检查的约束。
