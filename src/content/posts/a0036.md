ailx10说：这篇是在2022年3月之前写的，后来又改过。研究靶场时，我一口气搜到 Vulhub 和 VulnHub，名字只差一个字母，刚开始真有点傻傻分不清。弄明白之后才发现，一个偏向用 Docker 快速搭单个漏洞环境，另一个更像完整靶机的练习场。我干脆拿 Heartbleed 试了一遍，启动环境、访问站点、放入自己的 User-Agent，再看看响应里会不会出现它。于是这篇就成了一个从认名字到动手验证的小记录。它想帮人省掉的，是还没开始研究漏洞，就先在环境和平台之间绕圈子的时间。

---

Vulhub 和 VulnHub 名称相近，但练习方式不同：前者提供基于 Docker Compose 的漏洞环境集合；后者提供可下载的靶机等安全练习资源。

## Vulhub：聚焦具体漏洞

Vulhub 通常以某个软件或漏洞为单位组织环境，适合观察漏洞的触发条件、影响和修复方式。按照项目中的对应目录说明启动环境，例如：

```bash
docker compose up -d
# 完成测试后，在同一目录关闭环境
docker compose down
```

不同实验的服务、端口和验证方式不同，应以相应目录的说明为准。不要把示例服务直接暴露在公网。

## VulnHub：练习完整过程

VulnHub 的资源通常以虚拟机镜像等形式提供。练习时可能需要自行识别服务、梳理线索和分析权限边界，适合将多个技能串成完整流程。具体资源的目标和难度各不相同。

## 如何选择

想理解某个漏洞原理时，可以从单一漏洞环境开始；想练习信息收集、排查和记录完整过程时，可以选择综合靶机。两者都应运行在隔离网络中，完成后关闭环境并清理临时数据。

参考：[Vulhub 项目](https://github.com/vulhub/vulhub)、[VulnHub](https://www.vulnhub.com/)。

一次小漏洞实验适合把条件看得很细，一台完整靶机则会逼人把零散线索接起来。知道这两种练习各自回答什么问题，比争论哪个更适合所有人更有帮助。
