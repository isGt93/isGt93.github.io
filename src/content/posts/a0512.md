ailx10说：这篇是在2019年12月之前写的，后来又改过。数据终于攒起来一点，我却在一边跑任务、一边开虚拟机时把电脑折腾崩了，重启后系统还没能正常起来。恢复之后，总不能把前几天的扫描再做一遍，就从 Elasticsearch 里找已完成记录，继续接着跑。后半篇又拿开放端口做聚类和展示，看看数据能不能给出一点新的结构。这篇把基础设施的狼狈和分析的尝试放在一起，正好留下一个小项目真实的样子：先保证任务能续上，再慢慢谈数据里能看出什么。

跑了5天，终于把40万公网IP地址开放web服务的IP地址给找出来了，大约10万条数据，对这10万条数据进行nmap深度扫描，记录IP地址的地理位置，web首页内容和内容字节数，记录其他开放的端口。以上，就是基础情报系统。

期间，一边构建情报，一边玩电脑的时候，开多了虚拟机导致电脑崩溃，无奈重启。重启后发现kali系统启动失败，最后一条命令搞定：

`原记录使用 fsck 修复文件系统；该操作应先确认文件系统、挂载状态并准备备份，不应在已挂载且正在使用的文件系统上盲目执行。`

成功重启kali之后，重启了es-head发现已经有1万多条记录了，这时候不能直接启动main函数，因为会造成已经跑过的IP重复跑。于是写一个小脚本，查看es中已经存储了哪些IP了，把这些IP从10万情报IP中给踢掉。

def portlist(fname1="TIP0.3",fname2="TIP0.5"):

    f = open(fname1,"r")

    f2 = open(fname2,"w+")

    dt = dict()

    for line in open(fname1):

        i  = 0

        line = f.readline()

        line = line.strip()

        line = line.split(",")

        for port in line:

            i += 1

            if i == 1:

                continue

            else:

                if dt.has_key(port):

                    dt[port] += 1

                else:

                    dt[port] = 1

    dt = sorted(dt.items(),key=lambda item:item[1])

    for port in dt:

        f2.write(port[0]+":"+str(port[1])+"

")

    f.close()

    f2.close()
