## `SQL注入1`

点开是这样的 需要我们提供用户名和密码 然后提交 提示信息是`Source`

![](/notes-assets/2d1266dacc48d91950b3.jpg)

点开提示信息是下面这样的

```
<html>

<head>

Secure Web Login

</head>

<body>

<?php

if($_POST[user] && $_POST[pass]) {

    mysql_connect(SAE_MYSQL_HOST_M . ':' . SAE_MYSQL_PORT,SAE_MYSQL_USER,SAE_MYSQL_PASS);

  mysql_select_db(SAE_MYSQL_DB);

  $user = trim($_POST[user]);

  $pass = md5(trim($_POST[pass]));

  $sql="select user from ctf where (user='".$user."') and (pw='".$pass."')";

    echo '</br>'.$sql;

  $query = mysql_fetch_array(mysql_query($sql));

  if($query[user]=="admin") {

      echo "<p>Logged in! flag:******************** </p>";

  }

  if($query[user] != "admin") {

    echo("<p>You are not admin!</p>");

  }

}

echo $query[user];

?>

<form method=post action=index.php>

<input type=text name=user value="Username">

<input type=password name=pass value="Password">

<input type=submit>

</form>

</body>

<a href="index.phps">Source</a>

</html>
```

源码把用户输入拼接进 SQL；下文展示原题中的字符串边界问题。

`$sql="select user from ctf where (user='".$user."') and (pw='".$pass."')";`

用户名输入 `admin')#` 直接拿到结果

原来的`SQL`语言是这样`select user from ctf where (user='$user') and ...`

我们输入`admin')#`是下面这样

`select user from ctf where (user=' admin')# ' ) and ...`

原题中输入改变了 SQL 语句的字符串边界并注释后续条件。实际防御应使用参数化查询，而不是依靠拼接或黑名单。

![](/notes-assets/a9e5b4572278a66ad39d.jpg)

两道题的表面形式不同，背后都在提醒我关注转换发生的那一刻。输入没有变，程序对它的解释却变了，漏洞常常就躲在这几步之间。
