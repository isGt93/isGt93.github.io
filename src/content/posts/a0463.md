**亮点1:DNSMap 映射处理**

1、DNSMap 介绍

基于网络捕获的 DNS 查询响应数据而自适应地构建映射关系，同时也解决了可见性问题与 DNS 通配符问题。同时可根据邻近 IP 承载类似服务时，提供聚合视图，能够很好解决 CDN 与云服务厂商中 IP 灵活复用检测的问题。

基于的假设：

- 相同 IP 地址托管的 FQDN 通常是相似的，
- 且相邻 IP 地址托管类似的FQDN集合的下

通过DNSMap可以得到相同IP范围（IP集合）的足够相似的FQDNs集群（域名集合），并将可疑映射形成二部图。简单来讲，这个算法的输入是DNS流量，输出是\<FQDNs-IPs\>二部图。

2、映射提取与过滤

这里介绍了DNSMap中间过程的原理，主要的映射则是 FQDN 与 IP 的关联映射。发生映射冲突的域名通常是相似的，而相邻的 IP 地址则承载相似的域名集。 这里是对图中的相似域名划分到一个 FQDN 节点，然后将域名对应的IP地址划分到一个集合中，再次构建一个新的二部图，三元组是\<FQDN节点集合，边的集合，IP地址集合\>，定义为**IPBlock**。具体步骤如下：

- 定义域名差异度DD
- 使用聚类算法对域名进行聚类，将相似的域名聚到同一类，形成一个 FQDN 节点
- 域名聚类完成后，则还需要构建映射图，在这里称为 **IPBlock**，，它是一些FQDN 节点与 IP 节点的集合

后续的特征提取的输入则是这样的 **IPBlock**，而这些图组件最后才经过分类，识别是否为可疑的活动组件，即是否与 Fast-flux、Domain-flux 相关。

**亮点2:图组件特征选择与分析**

针对每一个IPBlock，提取4个维度的特征，分别是图结构特征、节点特征、边特征、黑名单特征（备注：指的是恶意IOC，包括恶意域名和恶意IP，数据来源于情报），那么针对存在黑名单的IPBlock打上恶意标签，不存在黑名单的IPBlock打上正常标签，之后基于决策树模型进行机器学习的训练。

1、图结构特征

- 节点数量：节点越多，越是恶意的
- 节点度数：度数越大，越是恶意的
- 节点间性：连接性越大，越是恶意的

![](/notes-assets/fb3c9d94c46842c27ee6.jpg)

2、节点特征

1）域名节点

- Whois：更新越多越靠谱，完整度越大越靠谱，创建越早越靠谱
- 域名层级：层级越多越恶意，TLD、2LD越多越恶意
- 域名词法：字符随机性越强越恶意，字符长度分布越广越恶意，正常单词越少越恶意，TLD越不常见越恶意，IP连接的域名2LD自负重复度越低越恶意，域名中数字越多越恶意

![](/notes-assets/feb73722f2788bef087d.jpg)

2）IP节点（备注：响应IP）

- Whois：越完整越靠谱
- AS（自治系统号）：越多越恶意
- IP：网段越多越越恶意

![](/notes-assets/ef53d6f771a85ac00e63.jpg)

3、连接边特征

- 80%的良性域名的TTL大于600秒
- 90%的fast-flux域名的TTL小于600秒

![](/notes-assets/df8ac452f3b3e4f6d85c.jpg)

4、黑名单特征

- 恶意域名越多，IPBlock越是恶意的
- 恶意IP越多，IPBlock越是恶意的

![](/notes-assets/985d8b67c110a4ae3a68.jpg)

图上的热闹不自动代表恶意，黑名单没见过也不等于正常。论文给的是一套分析办法，样本、标签和时间范围放回去以后，结果才有可以讨论的尺度。
