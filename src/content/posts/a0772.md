ailx10说：这篇是我2024年12月写的。一次 HIDS 演示，工具似乎每天只对第一次见到的软件告警，项目经理提议改个名字再试。我琢磨了一下，干脆看看加壳会带来什么变化，最后还是挑了 UPX，在 Linux 上给 ELF 做一次压缩再运行。于是有了这篇短短的操作记录。它的背景不是为了追求一个高深技巧，而是演示时遇到一个小问题，顺势多试一种处理方式。工作里很多知识就是这么来的，起点也许只是一句“那你换一下看看”，后来就变成了自己的工具箱。

---

UPX 主要用于压缩可执行文件，不等于安全加密；加壳后程序仍能运行，也不能证明能绕过检测。



（1）Ubuntu 安装 UPX 并对目标软件进行加壳

```
# 安装UPX
apt-get install upx-ucl

# 直接对可执行程序进行加壳
upx xmrig2 
```

![](/notes-assets/81cf10b2ed7fc816d826.webp)

（2）加壳完成后，旧的程序就不存在了（记的提前备份），再次运行，发现加壳软件可以正常执行

![](/notes-assets/96fb4dee88d684de1e51.webp)

能运行只是一个观察点，不是免检证明。保留原文件和压缩条件，之后分析大小、特征或告警变化时，才不会连比较的起点都找不回来。
