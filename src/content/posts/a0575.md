ailx10说：这篇是在2023年12月之前写的，后来又改过。以前写 Python，我常是解决一个小目标就收工；这回开始想做框架，才发现要换一种组织方式。把函数写在不同模块里，再用配置里的名字动态导入和调用，功能就不必全堆在一条固定流程中。我拿 importlib 做了个小例子，接着想到递归搜索和调查链怎样接下去。这篇记录的是那一点思路变化：从自己在代码里逐个点名调用，转向让框架按约定去找，后面再增加功能，也就有了一个能继续伸展的位置。

---

假设有这样的一个目录，这里面的方法，都是用户自己写的

```
# 目录结构
bypass
    log4j.py
    fast_json.py
```

我提供一个框架，通过配置文件，`@`标识自动引入这里面的方法，这样就能实现动态的自动化编排，比如先进行`xxx`查询，查询的结果进行`@bypass.log4j.abc`动态函数处理后继续查询， 再对查询的结果进行`@bypass.log4j.def` 动态函数处理后继续查询，依次类推，可以一直递归下去，这就实现了由配置文件控制的深度调查搜索框架～

```
# 配置文件
{
    "search":"xxx",
    "chain":{
        "search":"@bypass.log4j.abc",
        "chain":{
            "search":"@bypass.log4j.def",
        }
    }
}
```

这里的一个核心是python自定义函数动态调用

```
# python3

import importlib

def run_function(module_name, function_name):
    try:
        module = importlib.import_module(module_name)
        function = getattr(module, function_name)
        function()
    except ImportError as e:
        print(f"Error importing module {module_name}: {e}")
    except AttributeError as e:
        print(f"Error accessing function {function_name} in module {module_name}: {e}")

# 解析配置文件
config = {"f1": "@bypass.log4j.abc"}

for key, value in config.items():
    if value.startswith("@"):  # 如果值以 "@" 开头，表示需要动态导入
        module_and_function = value[1:].split('.')
        if len(module_and_function) == 3:  # 确保分割后有三个部分
            module_name = '.'.join(module_and_function[:-1])
            function_name = module_and_function[-1]
            run_function(module_name, function_name)
        else:
            print(f"Invalid format for value {value} in configuration")
```

按照配置信息，在bypass目录下，建一个log4j 文件，文件中有函数 abc

```
def abc():
    print("hello world")
```

运行，就能根据配置文件，动态调用自己写的函数了，效果如下，成功调用 `abc`，打印了`hello world`

现在实现的是一个简单调用，还没有递归和结果传递。把配置来源、参数和可调用检查补清楚，再向框架扩展，才不至于把灵活性变成难以控制的执行入口。
