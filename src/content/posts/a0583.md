ailx10说：这篇是在2024年6月之前写的，后来又改过。前一轮把 Nuitka 跑过以后，我继续把最常用的几个参数拎出来解释：编一个模块、带一个包、跟随或排除依赖，输出给谁运行。再配 PyStand 试着缩短发布流程，工具链缓存的位置也顺手记下。这篇很像给自己做的一张命令卡，不追求讲完所有选项，而是把真用到的那几种情况分清。离开一次性的小例子，代码更新和反复交付更频繁，参数理解清楚一点，后面每次发版就能少靠试错。

---

解释Nuitka模块/包/standalone及包含跟随排除参数，配PyStand加快发布，记录工具链缓存位置。

核查提示：大量解释为作者理解；编译不同加密，绝对无法破解不成立，速度取决项目规模与缓存。 旧环境及截图细节未逐项核验。

本文整理 Nuitka 的编译和依赖参数，并记录与 PyStand 组合的方式。编译不等于加密，效果与速度取决于项目、平台和缓存。

```
nuitka --module some_module.py # 扩展模块编译，生成pyd文件，可代替py文件

nuitka --module some_package --include-package=some_package # 软件包的编译，编译整个软件包并嵌入所有模块

nuitka --standalone main.py # 程序分发，可以把程序发送给其他人使用，缺的是打包速度很慢
```

我经常用上面第一条和第二条，速度快，并且别人无法破解Python源代码，然后配合韦一笑的PyStand[\[1\]](#ref_1)，可以秒级出包，嘎嘎香。

下面的太多可以不看，抛砖引玉，欢迎指正：

**--help**：**帮助信息**

```
show this help message and exit
```

![](/notes-assets/588404a5ac970d8ed63f.webp)

**--version：版本信息**

```
 Show version information and important details for bug reports, then exit. 
```

![](/notes-assets/ceed7c5dce13f0bc9d34.webp)

**--module**：**我理解是将python代码转化成pyd代码，相当于C语言的dll文件，并且没有人能破解出原来的python文件，这非常重要，算是对你的Python代码进行了无法破解的加密，尽管这并不是加密，只不过`--module` 好像只能针对单个文件进行转化，但是配合`--include-package` 可以对整个包编译**

```
Create an importable binary extension module executable instead of a program.
```

![](/notes-assets/b7bad733716efe0ceda3.webp)

**--standalone：我理解是将打包的exe提供给别人使用，使用这条指令，隐含的自动带上 --follow-imports，强制对所有项目代码，包括第三方依赖进行编译，会很慢，生成一个main.dist目录，和下面的区别就是它会生成一个文件，不是一个单独的exe**

```
Enable standalone mode for output. 
This allows you to transfer the created binary to other machines without it using an existing Python installation. 
This also means it will become big. 
It implies these option: "-- follow-imports" and "--python-flag=no_site". 
```

![](/notes-assets/d3926e7944315a835584.webp)

**\--onefile：我理解是standalone的另一种形式，直接生成一个exe，同样会很慢**

```
On top of standalone mode, enable onefile mode. 
This means not a folder, but a compressed executable is created and used. 
```

![](/notes-assets/e12aabe501a7de76f53c.webp)

**--include-package\=PACKAGE：我理解是对整个包进行编译，会递归子包，但是这个命令不能单独使用，后面需要有主程序，或者配合`--module` ，速度都很快，这2种模式输出结果不同**

```
Include a whole package. 
Give as a Python namespace,e.g. "some_package.sub_package" 
and Nuitka will then find it and include it and all the modules found below that disk location in the binary or extension module it creates, 
and make it available for import by the code. 
To avoid unwanted sub packages, e.g. tests you can e.g. do this "--nofollow-import-to=*.tests".
```

![](/notes-assets/c2c32a088a7089d5aa33.webp)

**--include-module\=MODULE：我理解是对一个模块进行编译，但是这个命令不能单独使用，后面需要有主程序，或者配合--module ，速度都很快，这2种模式输出结果不同**

```
Include a single module. 
Give as a Python namespace,e.g. "some_package.some_module" 
and Nuitka will then find it and include it in the binary or extension module it creates, 
and make it available for import by the code.
```

![](/notes-assets/1b0932df9a0507b4d1e3.webp)

**--follow-imports：我理解是将所有的import包都进行编译，包括第三方的包，比如pandas等，会很慢，同样后面需要有主程序，或者配合--module**

```
Descend into all imported modules. Defaults to on in standalone mode, otherwise off.
```

![](/notes-assets/2028bda1c3897c67bfd8.webp)

**--follow-import-to\=MODULE/PACKAGE：我理解是对指定的几个包进行编译，很快，搞不明白和--include-package\=MODULE/PACKAGE有啥区别**

```
Follow to that module if used, or if a package, to the whole package. 
Can be given multiple times.
```

![](/notes-assets/48c6fe639278a3f2e3d5.webp)

**--nofollow-import-to\=MODULE/PACKAGE：我理解是不指定对某些包进行编译**

```
Do not follow to that module name even if used, 
or if a package name, to the whole package in any case,overrides all other options. 
Can be given multiple times. 
```

![](/notes-assets/87582864fd0e4f9abf7a.webp)

**--nofollow-imports: 我理解是不要自动包含任何被导入的模块，--standalone下这个参数是无效的**

```
Do not descend into any imported modules at all,
overrides all other inclusion options and not usable for standalone mode. 
```

![](/notes-assets/a64f5fa1f9edc7a2958f.webp)
