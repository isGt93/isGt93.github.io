ailx10说：这篇是在2024年11月之前写的，后来又改过。PHP 的 MD5 检查题做多了，我发现大家口头都说“绕过”，实际却可能是三条完全不同的路：数组让函数走到异常返回，0e 形式碰到宽松比较，或者用 fastcoll 做出真正相同的摘要。于是我把散在题解里的情况收拢起来，连搜索脚本和二进制编码也一起留着。这篇更像一次给自己纠偏的小结，免得下次又把类型问题叫成算法破解。看条件时，输入是什么类型、比较是不是严格、运行在哪个 PHP 版本，都比记一个神奇字符串更要紧。

---

PHP 摘要检查中，数组类型错误、0e 数字字符串宽松比较和两个不同输入产生相同 MD5 摘要是三类不同机制。严格比较并不普遍允许数组绕过。

（1）历史类型错误案例：只有在特定旧版 PHP 函数接受到数组并返回 NULL、且两个结果都被继续比较时，才可能出现相等。现代 PHP 可能抛出 TypeError。下方示例两个数组本身相同，并不能证明不同值绕过；输出说明也需复核，不能照搬。

![](/notes-assets/bb095ddd999e0cde7ccb.webp)

```
<?php



// 定义要比较的两个值，注意这里它们是是否，可以绕过MD5检查，输出都是NULL

$value1[] = "";

$value2[] = "";



// 计算每个值的MD5哈希

$hash1 = md5($value1);

$hash2 = md5($value2);



// 比较两个MD5哈希值

if ($hash1 === $hash2) {

    echo "MD5哈希值相等。";

} else {

    echo "MD5哈希值不相等。";

}



// 输出MD5哈希值以供参考

echo "

$value1 的MD5哈希: " . $hash1;

echo "

$value2 的MD5哈希: " . $hash2;



?>

```

（2）在适用的 PHP 版本中，完整符合数字字符串形式的 0e 摘要可能在宽松比较中表现为相等；不能只检查前缀。

![](/notes-assets/9d745c3d81f611b389e9.webp)

```
<?php



function findMD5Collisions($prefix, $maxCount = 1) {

    $matches = [];

    // 循环尝试不同的字符串

    for ($i = 0; $i < pow(10, 12); $i++) {

        // 生成一个候选字符串

        $candidate = $prefix . $i;

        // 计算 MD5 哈希值

        $md5 = md5($candidate);

        // 检查哈希值是否符合要求

        if (preg_match("/^0e[0-9]{30}$/", $md5)) {

            $matches[] = $candidate;

            echo "找到的字符串: " . $candidate . "

";

            echo "MD5 哈希值: " . $md5 . "

";

            // 如果找到了足够的匹配项，就停止

            if (count($matches) >= $maxCount) {

                break;

            }

        }

    }

    return $matches;

}



$prefix = "ailx10"; // 我们希望字符串以 "ailx10" 为前缀

$maxCount = 2; // 我们想要找到2个匹配项

$strings = findMD5Collisions($prefix, $maxCount);

if (!empty($strings)) {

    echo "总共找到 " . count($strings) . " 个符合条件的字符串。

";

} else {

    echo "未找到符合条件的字符串。

";

}

?>



找到的字符串: ailx10597395974

MD5 哈希值: 0e607193511294857832340276123482

找到的字符串: ailx101258820612

MD5 哈希值: 0e410179301007418220015365512318

```

（3）fastcoll 构造不同输入具有相同 MD5 摘要属于碰撞，与 0e 宽松比较不同。工具输出及脚本未复测；安全系统应避免依赖 MD5 抵抗碰撞。

![](/notes-assets/86dfe85d6713bd93a2bf.webp)

```
from urllib.parse import quote_from_bytes

import hashlib





def calculate_md5(file_path):

    """ 计算文件的 MD5 哈希值 """

    hash_md5 = hashlib.md5()

    with open(file_path, 'rb') as f:

        for chunk in iter(lambda: f.read(1024), b''):

            hash_md5.update(chunk)

    return hash_md5.hexdigest()





def compare_files(file1_path, file2_path):

    """ 比较两个文件的 MD5 哈希值是否一致 """

    # 计算第一个文件的 MD5 哈希值

    md5_file1 = calculate_md5(file1_path)



    # 计算第二个文件的 MD5 哈希值

    md5_file2 = calculate_md5(file2_path)



    # 比较两个哈希值

    if md5_file1 == md5_file2:

        print(f"文件 {file1_path} 和 {file2_path} 的内容一致 (MD5: {md5_file1})")

    else:

        print(f"文件 {file1_path} 和 {file2_path} 的内容不一致")

        print(f"{file1_path} 的 MD5: {md5_file1}")

        print(f"{file2_path} 的 MD5: {md5_file2}")



def read_and_url_encode(file_path):

    """ 读取文件内容并进行 URL 编码 """

    with open(file_path, 'rb') as file:

        content = file.read()

        # 使用 quote_from_bytes 对二进制数据进行 URL 编码

        encoded_content = quote_from_bytes(content)

    return encoded_content



def main():

    file1_path = 'a1.txt'

    file2_path = 'a2.txt'



    # 读取并编码第一个文件

    encoded_content1 = read_and_url_encode(file1_path)

    print(f"文件 {file1_path} 的 URL 编码内容:")

    print(encoded_content1)



    # 读取并编码第二个文件

    encoded_content2 = read_and_url_encode(file2_path)

    print(f"文件 {file2_path} 的 URL 编码内容:")

    print(encoded_content2)



    # 比较这2个文件的MD5值

    compare_files(file1_path, file2_path)



if __name__ == "__main__":

    main()
```

分类以后，原先一堆看似相似的绕过就有了位置。以后审计到摘要判断，先看输入类型和比较方式，再看是否真的需要讨论碰撞，思路会清爽很多。
