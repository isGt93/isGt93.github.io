ailx10说：这篇是在2024年3月之前写的，后来又改过。Nuitka 打一个复杂程序等了一个小时，我索性趁等待去翻官网手册，把官方例子改成带 src 包的小项目再试。简单程序一路顺，加入 pandas 后，时间和依赖又明显多起来；module、普通编译、standalone、onefile 也各有不同的分发方式。这篇就是等待中顺手做的小对照。它没只留下“打包很慢”的抱怨，而是把项目规模、参数和输出文件摆在一起，看看究竟哪一步在替自己省事，哪一步又把成本带了进来。

---

依次测试Nuitka模块、普通编译、standalone和onefile，加入pandas后编译慢，比较排除依赖与完整分发。

核查提示：排除库需另提供兼容依赖；原生扩展不等不可逆或无法破解，版本参数变化宜保留上下文。 旧环境及截图细节未逐项核验。

本文比较 Nuitka 模块、独立分发和单文件打包。排除依赖时仍需在目标环境提供兼容版本；原生编译并不意味着无法逆向。

![](/notes-assets/b12c760e666738f0a737.webp)

1）正常安装 nuitka

```
pip install nuitka
```

![](/notes-assets/56ac773755287db79b6b.webp)

2）正常运行程序，一般一个入口函数，加一个src依赖包

![](/notes-assets/a832fdb2b44ca196e132.webp)

3）嵌入所有模块的编译

```
nuitka --follow-imports hello.py
```

![](/notes-assets/3ca579ca652d6c906e10.webp)

第一次运行报错，复制一个`python38.dll` 过来就ok了

![](/notes-assets/86b0add2018ff670ee33.webp)

并且src下的所有python文件，都可以删除，程序依然正常运行

![](/notes-assets/92262a9126f871d372fa.webp)

4）如果你想对src模块代码编译成C\+\+，保护自己的代码不被破解

```
nuitka --module src/talk.py
```

![](/notes-assets/65a9e2f310c411e9f400.webp)

生成的pyd，可以代替原来的python文件，并且是安全，无法还原成py文件

![](/notes-assets/6b871ba17a37715d9de4.webp)

5）打包分发（文件夹）

默认会带 --follow-imports 功能，嵌入所有模块

```
nuitka --standalone --output-dir=out2 hello.py
```

![](/notes-assets/be89ad8d07fdbe6d99a7.webp)

进入 `out2\hello.dist` ，直接运行exe程序，成功，可以把dist 压缩发给别人玩耍啦

![](/notes-assets/2c9c03508a7b1851481c.webp)

6）打包分发（1个exe）

```
nuitka --onefile --output-dir=out3 hello.py
```

![](/notes-assets/3b76ddaa50679a1d795b.webp)

直接把exe发给别人，就能愉快的玩耍了，nuitka 打包就是这么简单！！！

二更：

我在`hello.py` 中加入了 `import pandas as pd` ，打包一下子就慢了很多

```
nuitka --onefile --output-dir=out3 hello.py
```

打开文件夹一看，好家伙，似乎把我pandas都转成C\+\+扩展，这不行啊

![](/notes-assets/4a74244504b8208de3f2.webp)

![](/notes-assets/546740c2cfe2bc788d95.webp)

使用 `--nofollow-import-to`，不要使用 `--nofollow-imports` ，因为V2.1.3版本的nuitka的 `--standalone` 模式下，`--nofollow-imports`参数是无效的，一定要先看看你自己的nuitka版本，网上很多教程都老了，要学会查看`nuitka -h`帮助信息了。

```
nuitka --standalone --nofollow-import-to=pandas,numpy --output-dir=out2 hello.py
```

![](/notes-assets/a4f7cc966c79f1d7b54d.webp)

这个时候运行的时候会报错

![](/notes-assets/f0ec4c35aacf49f34ab9.webp)

然后要复制一大堆东西，才让这个exe跑起来，打包快是快了，但是你让我复制一大堆东西，有点心累啊

![](/notes-assets/ddca764dd5baf00f7607.webp)

三更：

终于明白了，nuitka打包自己用可以很快，但是你要打包给别人用，那么对不起

```
nuitka --nofollow-imports --follow-import-to=src --output-dir=out5 hello.py
```

![](/notes-assets/d5ba5f37a8f19f1685d1.webp)

你要是想打包快，然后复制一堆东西，可以使用下面的命令

```
nuitka --standalone --nofollow-import-to=pandas,numpy --output-dir=out2 hello.py
```

你要是不想复制一堆东西，能够忍受打包慢，可以使用下面的命令

```
nuitka --standalone --output-dir=out2 hello.py
```

排除依赖能减轻打包，却把责任交给了目标环境。速度、体积和可移植性常常要一起权衡，不能只挑其中一个数字好看就算方案完成。
