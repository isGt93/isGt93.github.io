ailx10说：这篇是我2023年7月写的。有人把抓包当成无法动过手脚的现场，我就顺着想，既然 pcap 是文件，它能不能先被改过，再让工具重新抓到？于是试了 tcprewrite，调整源和目的 IP，再用 tcpreplay 重放，回到 Wireshark 里观察。这样一来，包看着仍然像正常捕获，来路却多了一道处理。我把安装和实验流程记下来，不是为了给截图添花样，而是想把一个容易忽略的环节摆出来：分析流量时，除了看包里有什么，也得问问这份数据是怎样到手的。

---

步骤一：安装 libpcap-dev

```
sudo apt-get install libpcap-dev
```

步骤二：下载源代码[\[1\]](#ref_1)，并编译安装 **tcprewrite**

```
./configure 
make
sudo make install
```

步骤三：准备pcap包，以访问知乎的pcap包为例，记住篡改前的信息

- 源地址：192.168.0.108
- 目的地址：103.41.167.234

![](/notes-assets/9b8064bcf118d36adad7.webp)

步骤四：跟着ailx10，开干

修改pcap包的源IP地址，从192.168.0.108改成1.1.1.1

```
tcprewrite --srcipmap=192.168.0.108:1.1.1.1 -i ../zhihu.pcap -o ../zhihu2.pcap
```

修改pcap包的目的IP地址，从103.41.167.234改成2.2.2.2

```
tcprewrite --dstipmap=103.41.167.234:2.2.2.2 -i ../zhihu2.pcap -o ../zhihu3.pcap
```

步骤五：见证奇迹

![](/notes-assets/faa19bf7a8e0eeb1de6d.webp)

如果你想将整个数据包里的源IP地址和目的IP地址内容都替换掉

- 所有的 220.181.107.131 替换成 3.3.3.3
- 所有的 192.168.0.108 替换成 4.4.4.4

![](/notes-assets/bec863ea15f057812a68.webp)

替换前

一条命令，直接替换：

```
tcprewrite --srcipmap=220.181.107.131:3.3.3.3,192.168.0.108:4.4.4.4 --dstipmap=220.181.107.131:3.3.3.3,192.168.0.108:4.4.4.4 -i ../tcp.pcap -o ../tcp2.pcap
```

![](/notes-assets/f0ce14338df4fa1825bc.webp)

替换后
