ailx10说：这篇是在2019年12月之前写的，后来又改过。看完 XSS 和 SQL 的开源实现，我也想试试能不能做一个 PHP 的语义检测小样。于是先从规则里抽 token，琢磨哪些用指纹查、哪些还要确认上下文，再用 flex 写切词和 demo，连 Makefile 一起搭起来。这个项目后来取消了，没能按设想继续走下去，但最初的设计和尝试还留在这里。这篇有意思的地方不是交出了一个成熟引擎，而是记录我怎样从研究别人的实现，迈到自己拼一个雏形。

语义引擎在安全界的地位非常高，并且也是近几年刚刚兴起的新型攻击检测技术。著名安全公司长亭科技的核心技术，就包含了XSS语义引擎、SQL语义引擎、PHP语义引擎、JAVA语义引擎。

原文记载了作者当时接触到的开源实现，其项目历史和当前维护状态需查阅项目仓库核实。

![](/notes-assets/9ce5607e505747d4c1c9.jpg)

**如何自定义攻击检测语义引擎？**

**拷问着每一个安全研究者！**

经过对2款开源语义引擎的研究和调研，发现2款引擎的设计思路完全不一样，这就对开发一款新型的语义引擎带来了一定的困扰？我们到底用哪个作为新引擎的模板呢？经过半个月时间对攻击特征的研究，在一定程度上领悟了XSS语义引擎和SQL语义引擎为何采用完全不同的思路。突然灵感闪现，为什么不融合这2款语义引擎的设计思路，来设计新型的语义引擎呢？

立马行动，花了2天时间重新阅读了PHP的CRS规则集，提炼出8种token，其中5种token采用2分查找指纹库，3种token采用威胁确认，写了一个简单的demo验证了猜想，发现可行，泪奔有木有啊。

demo非常简单，但是设计思路及其巧妙，采用flex切词，打上token标记，根据token类型进行预处理，再进行2分查找指纹库或威胁确认，效果如下：

![](/notes-assets/8dead11a35cbe4967fac.jpg)

makefile文件：

```
run: phplib

	./phplib < tx



phplib: lex.yy.c libinjection_php_data.h libinjection_php.c

	gcc -o $@ $^



lex.yy.c: php.l

	flex $^

```

旧世界的防御规则已经统治安全圈10多年了，新世界的机器学习和语义引擎还在不停较量，问苍茫安全大地，谁主沉浮？值得每一位安全从业者反思！

后续：领导取消了机器学习与语义引擎项目！2018的我一事无成，还抗了2个C，祝好，安全云再见，态势感知你好，2019加油。

项目后来没有继续，这份笔记就保留在设计和试做的阶段。它留下的是一条探索路线，而不是已经完成误报、漏报和性能验证的产品结论。
