ailx10说：这篇是我2025年1月写的。filemanager 的题目表面一直在上传、重命名，真正的关键却是文件名先被存进库，后面又进了另一条更新语句。我从备份源码里把这两次使用接起来，再试着改变扩展名字段，让后续改名走到原本不该允许的结果。这篇记录的是一份数据“第一次看着没事，第二次才出问题”的过程。回头看，只有盯住上传入口还不够，得继续追数据库里取出的值去了哪里；存进库并不会自动让输入变安全，这一点在这道题里很直观。

---

本文记录文件名先被保存、随后再次进入 SQL 语句的历史案例。

存储操作成功不代表后续拼接安全；原记录中的文件对应关系和转义行为仍需源码与截图核对，扩展名变化不等同于代码执行。

难度系数：5（官方系数：7）

审计代码，主要是文件上传和文件修改，需要掌握2个函数

- `basename()` 函数返回的是 路径中的文件名，并且它会移除路径部分，只保留文件名（包括扩展名）
- `pathinfo()` 函数返回一个包含文件路径信息的数组。数组中包含以下几项：

- `dirname`：文件的目录路径
- `basename`：文件名，包括扩展名
- `extension`：文件的扩展名
- `filename`：文件名，不包括扩展名

文件上传流程梳理：

- 文件上传要求：文件的扩展名必须在允许的列表中（`gif`, `jpg`, `png`, `zip`, `txt`）
- SQL查询数据库，如果文件名和文件扩展名存在，则上传失败
- SQL更新数据库

文件修改流程梳理：

- SQL查询数据库，如果文件名不存在，则修改失败
- SQL更新数据库，这里提取了`newname`的文件名，去覆盖`oldname`
- 文件重命名，扩展名不变，只更改文件名

（1）上传文件 `',extension='.jpg` ，实际查询数据库的语句是

```
select * from `file` where `filename`= '\',extension=\'' and `extension`='.jpg'
```

插入数据的 `filename` 实际上是 `',extension='` ，这里有转义单引号

```
insert into `file` ( `filename`, `view`, `extension`) values( '\',extension=\'' , 0 , '.jpg')
```

![](/notes-assets/ada2df48a6f67456f7fe.webp)

（2）文件修改，将 `',extension='` 修改成 `1.jpg`，查询语句是（这个地方，不知道为啥多了个转义？）

```
select * from `file` where `filename`='\',extension=\''
```

这里存在 SQL 二次注入，从数据库中读出来的时候，转义就没有了，成功删除了扩展名

```
update `file` set `filename`='1.jpg',`oldname`='',extension='' where `fid`=xxx
```

![](/notes-assets/9479bc809d372ee39bc3.webp)

（3）上传`1.jpg`的一句话木马

```

（4）将 `1.jpg` 重命名为 `1.php`

```
update `file` set `filename`='1.php',`oldname`='1.jpg' where `fid`=xxx

扩展名字段变化以后，后续允许的操作也跟着变了。把数据库状态和文件状态同时记录下来，链路就不会被简化成一句“改了后缀就成功”。
