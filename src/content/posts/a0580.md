ailx10说：这篇是我2024年3月写的。我已经知道 Python 包不可能靠一个参数就永远藏好，就又想试混淆：就算文件被翻出来，至少别直接长着自己写时的样子。pyminifier 能改名字、换非拉丁标识符，还能处理多个文件，可函数名那一轮改完没跑通，换成变量混淆才运行起来。这篇保留了这点反复。保护和可运行之间有拉扯，尤其多个模块互相调用时，一个名字改得不对，自己的程序会先找不到自己；所以最后还得回到实际运行去验。

---

基于python3.8，我的实验过程如下：

1）安装 pyminifier ，已经10年没更新了，还能用，确实牛逼

```
python3 setup.py install
```

![](/notes-assets/231a57e260a4002ec711.webp)

2）混淆前的python主程序，代码逻辑暴露，很容易理解，简单的就像 1\+1\=2

![](/notes-assets/bc47d195ec563ad8099b.webp)

3）使用 pyminifier 的 obfuscate 参数进行简单混淆

```
pyminifier --obfuscate  --outfile=new_a.py  a.py
```

![](/notes-assets/054f4b0339d8969a8ffc.webp)

4）查看混淆后的python代码，函数方法名称，类的名称，变量名称都被替换了

- 这里出现了一点问题，替换的不够准确，导致代码无法执行
- 定位是obfuscate-functions有点问题，将 obfuscate 替换成 obfuscate-variables 才能正常运行

```
pyminifier --obfuscate-variables  --outfile=new_a.py  a.py
```

![](/notes-assets/5f3c1450cd16b22c200b.webp)

5）使用 pyminifier 的 nonlatin 参数进行超级混淆

```
pyminifier --obfuscate --nonlatin --outfile=new2_a.py  a.py
```

6）再查看混淆后的代码，函数方法名称，类的名称，变量名称都是乱码了，但是程序依然能正常运行

![](/notes-assets/fc29013fb606ae0edf4f.webp)

7）可以对多个python文件，同时混淆，输出到指定目录，直接win了

```
pyminifier --obfuscate --destdir=out  a.py src/my_add2.py
```

![](/notes-assets/b408616aeea3af015099.webp)
