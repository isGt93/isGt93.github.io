ailx10说：这篇是在2024年8月之前写的，后来又改过。分析过那么多挖矿脚本，我终于想亲自看看，挖矿到底能挣多少。两台小服务器跑了一天，预估收益却只有一分钱，那个落差足够让我先写一句“收手吧”。不过既然都跑起来了，也没白费这轮实验，我顺手看监护、定时任务、服务和矿池通信，把登录、收任务、提交结果几类消息记下来。这篇前半带点吐槽，后半还是回到数据：钱少得可怜，抓到的协议过程却能用来理解，告警里那些反复出现的外联究竟在忙什么。

---

本文记录两台服务器运行 XMRig 的历史资源、收益和协议观察。收益取决于硬件、时间和电价，不能线性外推到其他机器。

下列历史代码含持久化操作，只适合阅读分析；不应在未授权系统中运行。

（1）下载挖矿程序

我尝试写一个脚本，实现自动下载并运行挖矿程序

```
#!/bin/bash

FILE_PATH="/tmp/xmrig"
CONF_PATH="/tmp/config.json"
# 检查文件是否存在，如果不存在则下载
if [ ! -f "$FILE_PATH" ]; then
    MINE_URL="http://[IP]:8080/xmrig"
    CONF_URL="http://[IP]:8080/config.json"
    wget -O "$FILE_PATH" "$MINE_URL"
    wget -O "$CONF_PATH" "$CONF_URL"
    chmod +x "$FILE_PATH"
fi

# 获取 'xmrig' 进程的 PID
PID=$(pgrep -f "$FILE_PATH")

# 如果有进程在运行，杀死它
if [ -n "$PID" ]; then
    kill -15 $PID
    echo "Sent SIGTERM to process with PID: $PID at $(date)"
fi

# 等待一段时间让进程优雅地关闭
sleep 5

# 重新启动 'xmrig'
"$FILE_PATH" &
echo "Restarted process at $(date)"
```

挖矿需要矿池、矿工、钱包，参数-o指定矿池，-u指定钱包，-p指定矿工


（4）添加启动项

原文展示 systemd 服务；ExecStart 不通过 shell 解析 \&，脚本路径与参数需要核查。

```
#!/bin/bash

# 定义服务名称和脚本路径
service_name="xmrig"
script_path="/tmp/xmrig"

# 创建 systemd 服务文件
cat <<EOF | sudo tee /etc/systemd/system/${service_name}.service
[Unit]
Description=XMRig Mining Script
After=network.target

[Service]
Type=simple
ExecStart=${script_path} &
Restart=always
RestartSec=10s
User=root
WorkingDirectory=/tmp

[Install]
WantedBy=multi-user.target
EOF

# 重新载入 systemd 配置
sudo systemctl daemon-reload

# 启用并启动服务
sudo systemctl enable ${service_name}.service
sudo systemctl start ${service_name}.service

# 输出状态信息
echo "XMRig service has been enabled and started on boot."
```
