ailx10说：这篇是我2023年1月写的。自己的工具能被拆回源码以后，我马上去试保护办法。先选了旧版 PyInstaller 的 key 参数，加上 AES 相关环境，把程序重新打包，再用前面那些工具拆开看看。依赖那层的表现变了，可主文件仍能反编译出来，于是又想到把入口尽量做薄。这篇保留的是第一次补救尝试，不是一次彻底封住所有入口的胜利。它把“加了参数”变成一个可以对照的实验：包里究竟哪一部分改变了，哪一部分还和原来一样看得见。

---

用旧PyInstaller的key参数加密打包，解包依赖失败而主文件仍可反编译，因此建议主文件精简。

核查提示：单工具失败不证明保密，主文件未保护；必须连读578，后篇展示内置密钥导致可破解。 旧环境及截图细节未逐项核验。

本文记录旧版 PyInstaller 加密打包实验。解密密钥需要随程序分发，专用工具未能恢复某些文件不证明代码保密；后续 A0578 对该方法进行了补充。

### 第一步：python代码加密打包成exe，密钥是ailx10

```
pyinstaller -F -w --key ailx10 main.py
```

![](/notes-assets/3ed090c48dc32a6939de.webp)

### 第二步：尝试对exe进行解包，发现解包出现大量错误提示

```
python pyinstxtractor.py main.exe
```

![](/notes-assets/73171cf0c1d3dff326c9.webp)

### 第三步：进入文件夹，未找到引入的python源文件

该文件夹中的所有文件都是加密的，打开都是乱码

![](/notes-assets/1de3470c8b70491860cb.webp)

### 第四步：对python主文件原文图表进行修改，添加一行魔数原文图表

这里用的python3.7版本，随便找一个python3.7编译的pyc文件，把魔数复制过来就ok了

![](/notes-assets/962cb2e9e7b940a3a1f8.webp)

### 第五步：逆向pyc文件，得到python主文件源码

可见加密的仅仅是import进来的python文件，主文件依然是可以破解的，所以主文件越简单越好～

```
uncompyle6 main.pyc > main.py
```

![](/notes-assets/2c658450a58dd0987643.webp)

一个工具解不开，不代表秘密就能安全放进去。主文件仍然露出来的结果已经很说明问题，也给后面继续研究内置密钥留下了线索。
