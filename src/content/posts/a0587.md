ailx10说：这篇是在2025年4月之前写的，后来又改过。项目要在 Linux 上运行，又希望尽量保护 Python 代码，我就把 Nuitka 的目光从 Windows exe 转到 Ubuntu 的 .so。先编单文件，再试带 src 的包，第三方依赖仍得配齐，放进相同 Docker 镜像后再看移植。这篇延续的是前面打包实验，但换了交付环境。它让我重新把“代码变成了什么”和“运行它还缺什么”分开：扩展模块能替代一部分源码文件，真正要交到现场，还得把解释器和依赖条件一起安排好。

---

1、在ubuntu系统上安装 Nuitka

```
python3 -m venv venvpy12
source venvpy12/bin/activate
pip install nuitka
```

![](/notes-assets/60a248618518213cc81e.webp)

2、确保存在GCC且版本号大于等于4.7，因为这是支持C11标准的最低版本

```
gcc --version
```

![](/notes-assets/54c44c6efea8c6902e1b.webp)

3、构建简单的示例项目（略）

![](/notes-assets/90a46b602d870525f470.webp)

4、打包自己的单个python程序

很快，即使代码中有 `import pandas` 也没事，只编译自己写的代码，在linux平台会生成`.so`文件，这个文件可以取代对应的`.py` 文件，实现代码的保密（注意这里并没有打包pandas，需要额外提供pandas的site-packages，也就是把三方的依赖库单独拿出来）

```
python -m nuitka --module --output-dir=build myfunc.py
```

![](/notes-assets/151d33e97733b7d319cd.webp)

5、打包自己的模块src文件夹所有程序

同上，也很快，即使代码中有 `import pandas` 也没事，只编译自己写的代码，在linux平台会生成`.so`文件，这个文件可以取代对应的所有的`.py` 文件，实现代码的保密（注意这里并没有打包pandas，需要额外提供pandas的site-packages，也就是把三方的依赖库单独拿出来）

```
python -m nuitka --module src --include-package=src --output-dir=build
```

![](/notes-assets/05522395df9b500a1ac6.webp)

同镜像能减少差异，却不替架构和Python ABI作保证。编译模块仍可分析，交付时先说明兼容条件，比一句“保护了源码”更能帮接手的人少踩坑。
