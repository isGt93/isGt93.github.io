ailx10说：这篇是2022年1月之前写的，后来又改过。练完固定目的地，我又试 SSH 的动态转发，在 Kali 开一个 SOCKS 入口，经 Ubuntu 访问 Windows 网站。为了看清变化，还给 Windows 配规则阻断直接来源，再让浏览器走代理，配抓包比流向。这样一做，比只记一个 -D 参数直观多了：浏览器把请求交给谁，网站最后看见的又是谁。笔记里还有 DNS 和代理类型这些容易藏在界面里的细节；能 ping 通与 Web 能访问也不是同一回事，最好把直连和代理两轮放在一起看。

---

SSH-D在Kali建10101 SOCKS入口经ubuntu跳板访问Windows网站，Windows规则阻断Kali IP，浏览器代理访问并抓包核流向。

核查提示：ping失败不单独证明Web不可达，须直连HTTP对照；浏览器SOCKS类型和DNS位置核心在图，-g可能暴露监听。 原环境、代码和图内细节尚未逐项核验。

本篇文章讲的是「SSH隧道的动态转发」，基本实验环境如下：

- kali rolling （192.168.160.140）小黑所处位置
- ubuntu18 （192.168.160.137）跳板机
- windows10 （192.168.160.1）目标网站

![](/notes-assets/910938abcd27923b2368.jpg)

## 第一步：检查网络环境。ping 失败不能单独证明 HTTP 不可访问，应额外做直接 HTTP 连接对照。

- 在kali rolling上ping不通windows10
- 说明防火墙配置成功，开始实验
- 防火墙配置可见附录

![](/notes-assets/5e75b4e95fb49dacf8dd.jpg)

## 第二步：在kali rolling上利用跳板机执行动态代理

- 执行跳板机动态代理
- 输入跳板机的密码

```
ssh -CfNg -D 10101 ailx11@192.168.160.137
```

![](/notes-assets/bd6c0e43eb0e4a225236.jpg)

## 第三步：在kali rolling上配置浏览器代理

- 配置手动代理
- 端口选择动态代理端口10101

![](/notes-assets/cea8e9fbe87318a31115.jpg)

## 第四步：见证奇迹，通过浏览器访问windows10站点

- windows10上运行的网站是Wampserver
- 即使ping不通，也能访问windows10上的网站

![](/notes-assets/51777e448e1d2195ef67.jpg)

## 第五步：在kali rolling上抓包查看真实流量

- 跳板机帮助kali rolling访问windows10站点

![](/notes-assets/f58d97e9374f10db6a32.jpg)

- 跳板机使用ssh隧道，将windows10站点返回的数据，发送给kali rolling

![](/notes-assets/59afedc0575d276fe224.jpg)

## 附录（如何在windows10上配置防火墙，阻断IP地址的访问）

> 控制面板\\系统和安全\\Windows Defender 防火墙

![](/notes-assets/8d91551cde833b2cef91.jpg)
> 高级设置\\入站规则\\新建

![](/notes-assets/38d4721438b896f807c8.jpg)
> 作用域\\此规则应用于哪些远程IP地址\\添加\\输入IP地址\\下一步

![](/notes-assets/21391be99d2b1e0d9eb3.jpg)
> 操作\\阻止连接\\下一步\\随便起一个名字（比如testssh-d）

![](/notes-assets/1154aca96809ca3e1387.jpg)
> 查看规则是否已经启用（大功告成）

代理生效的证据应当来自对应的应用流量，不能只拿ping不通作反衬。把浏览器类型、DNS位置和监听范围一起记下，换一台机器才有可能复现同样的路径。
