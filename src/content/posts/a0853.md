ailx10说：这篇是在2023年9月之前写的，后来又改过。JSONHijacking 这一课继续用两个站点做对照：先在 A 登录，再去访问 B，看看跨站脚本请求能带回什么信息。我把接口、浏览器行为和 JSONP 的加载方式接起来，才慢慢分清，页面换了地方，原来的登录状态仍可能参与后面的请求。文章留着当时实验的几个步骤，也带着初次把这条链跑出来的新鲜感。它让我不再只盯“返回的是 JSON 还是页面”，而是继续追问，这份内容最终会落到谁的脚本手里。

JSONHijacking篇在A登录后访问B，展示跨站接口请求与隐私读取，用JSONP解释跨域脚本加载。

## 前提和待核查点

水坑是投递场景不是JSON劫持定义；JSONP与普通JSON、加载与读取需分清，响应及回调凭证条件关键。

## 历史笔记与实验记录

JSON 劫持与跨站读取有关，水坑只是可能的投递场景，二者不是同一概念。JSONP 与普通 JSON 的加载和读取条件不同，应结合响应格式、认证与浏览器行为判断。

究其原理就是，A网站的JS脚本可以向B网站发送数据，但是大多数情况并不能接收B网站的数据返回，只有B网站返回图片、CSS、JS形式的数据时，A网站是可以接收B网站的返回的。既然JS可以跨域加载，那么JSONP就是利用了这一漏洞，将接口设计成JSON格式，经过简单的变形，就符合JS的语法规范，于是就可以跨域调用JSONP接口来获取数据来。

前提：准备好docker环境，下载好书籍配套实验环境，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～
