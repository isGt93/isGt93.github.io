ailx10说：这篇是我2024年5月写的。告警里有段隐藏执行的脚本，看着很可疑，我就沿它加载的地址继续追，没想到最后落到了微信广告。中间 URL 一层层变，靠手点有点乱，我又写 Python 把拼接过程重建出来，拿 Burp 多观察几轮，比较同一入口怎样转向不同位置。这篇像一段从“是不是恶意代码”出发的小追踪，最终发现的是广告流量的安排。它提醒我的不是所有隐藏都等于同一种风险，而是先把跳转路走完整，眼前那一小段代码才有解释。

这段代码的具体逻辑分析如下：

（1）设置文档标题和隐藏文档元素

```
document.title = "Loading...";
document.documentElement.hidden = 1;
```

（2）立即调用的匿名函数

```
(function () {
    // 函数体
})();
```

（3）生成一个随机的字符串作为标识符 `rmd`，用于构建 URL

```
const geUrl = 'https://9d781dcd7047bce07bf97c5ee19c1f85.wayawa.top/xnh' + rmd + '?href=' + encodeURIComponent(btoa(location.href.split('#')[0]));
```

（4）创建了一个 XMLHttpRequest 对象 `xhr`，并发送了一个 GET 请求到之前构建的 URL，当请求完成后，会调用定义的 `onload` 函数来处理响应

```
const xhr = new XMLHttpRequest;
xhr.onload = function () {
    // 处理响应
};
xhr.open("GET", geUrl, !0);
xhr.send();
```

（5）获取响应内容 `xhr.responseText`，然后通过 `document.open()` 方法打开一个新的文档，在新文档中写入响应内容

```
xhr.onload = function () {
    const onHash = window.onhashchange;
    const h = xhr.responseText;
    const a = document.open("text/html", "replace");
    a.write(h);
    a.close();
    window.onhashchange = onHash
};
```

原文以 Python 重建部分 URL；Python 的 URL-safe Base64 与 JavaScript btoa 并不完全等价，需按实际字符与编码验证。

```
#!/usr/bin/env python
# -*- coding: utf-8 -*-
# @Time    : 2024/5/26 10:47
# @Author  : ailx10

import random
import base64
from urllib.parse import urlparse, urlencode

def generate_new_url(current_url):
    # 生成随机标识符
    rmd = ''.join(random.choices('abcdefghijklmnopqrstuvwxyz0123456789', k=7))

    # 获取当前 URL 的域名部分
    domain = urlparse(current_url).scheme + '://' + urlparse(current_url).netloc

    # 构建查询参数部分，将当前 URL 进行 base64 编码并进行 URL 编码
    query_params = urlencode({'href': base64.urlsafe_b64encode(current_url.split('#')[0].encode()).decode()})

    # 拼接新的 URL
    new_url = domain + '/xnh' + rmd + '?' + query_params

    return new_url

# 测试
current_url = 'https://9d781dcd7047bce07bf97c5ee19c1f85.wayawa.top/hsxidrpzkww3302flw46fsqibxhlzjtfm37'
new_url = generate_new_url(current_url)
print("即将请求的 URL 是:", new_url)
```
