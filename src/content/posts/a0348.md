ailx10说：这篇是2022年1月之前写的，后来又改过。为了有地方收集 Web 请求，我在 Ubuntu 16 上搭 Glastopf。先编译沙箱扩展，再补 Python 2 的依赖，折腾到服务能启动以后，日志和 SQLite 里终于有了可以分析的记录。文章把这些准备步骤留得比较细，因为看一份干净的结果，很容易忘掉前面依赖版本花的工夫。蜜罐开起来以后，新的问题才开始：爬虫、误访问和攻击请求都可能进来，不能把每个来源都直接叫僵尸网络。搭环境只是给后面的分析准备了一本会不断长大的原始记录。

---

依赖列表中的 `sqlalchem` 与 SQLAlchemy 包名不一致；旧版本依赖和 BFR 构建仍需核实。

本文记录 Ubuntu 16 环境中部署 Glastopf 和 BFR 的历史过程；Python 2 依赖已经陈旧，应隔离实验环境并核查版本。

我是在纯净的ubuntu16上安装的蜜罐，因此需要一些额外的工作要做，不过经过30分钟的折腾，最终我的第一个Web蜜罐，成功上线了，哈哈哈鹅

**第一步：安装必要的组建**

```
sudo apt-get update
sudo apt-get install python2.7 python-openssl python-gevent libevent-dev python2.7-dev build-essential make
sudo apt-get install python-chardet python-requests python-sqlalchemy python-lxml
sudo apt-get install python-beautifulsoup mongodb python-pip python-dev python-setuptools
sudo apt-get install g++ git liblapack-dev gfortran libmysqlclient-dev
sudo apt-get install libxml2-dev libxslt-dev
sudo pip install --upgrade distribute
```

![](/notes-assets/96f06349aadf8fe344ba.jpg)

**第二步：安装并配置PHP沙箱环境**

```
cd /opt
sudo git clone git://github.com/mushorg/BFR.git
cd BFR
sudo phpize
sudo ./configure --enable-bfr
sudo make && sudo make install
```

![](/notes-assets/50b1b40a3a66e2a8cfab.webp)

这时候还需要配置一下，找到自己的bfr.so的位置，在php.ini文件尾巴上追加就好了。

```
zend_extension = /usr/lib/php/20151012/bfr.so
```

![](/notes-assets/c051254ce3666bfcdb85.webp)

**第三步：安装Web蜜罐**

```
cd /opt
sudo git clone https://github.com/mushorg/glastopf.git
cd glastopf
sudo python setup.py install
```

原环境出现依赖问题，下方为历史依赖清单；拼写和版本需参考项目文档。

原文通过 pip 安装依赖，不能保证当前环境可复现。

```
gevent
webob
pyopenssl
lxml
sqlalchem
jinja2
beautifulsoup
requests
cssselect
pymongo
MySQL-python
hpfeeds
pylibinjection
libtaxii
python-logstash
botocore
urllib3
```

解决掉依赖后，再次运行`python setup.py install`，就搞成了。

![](/notes-assets/2131477cc66abc21111c.webp)

**第四步：建立目录并运行蜜罐**

```
cd /opt
sudo mkdir myhoneypot
cd myhoneypot
sudo glastopf-runner
```

启动后检查蜜罐服务和日志状态。

当有人访问我们的蜜罐的时候，就会被蜜罐记录在日志里面。咱们刚刚上线，谷歌的搜索引擎爬虫就开始光顾了～

![](/notes-assets/0699f48fad427c39eeb2.webp)

原文使用 SQLite 检查日志；能记录的内容取决于配置。

蜜罐可用于观察请求特征，但不能仅凭请求就断定来源设备是僵尸网络成员。

![](/notes-assets/1b3aba13d01e30a70b30.jpg)

原文记录一个来源地址，单独一次访问不足以证明来源性质。

![](/notes-assets/0bf9ff90b559310d3c71.webp)![](/notes-assets/cd10738545ab624ba8ae.jpg)

持续运行时应限制权限并保护采集数据。

![](/notes-assets/f0ee1898aeed2f228b28.webp)

蜜罐跑起来以后，真正有用的是可追溯的请求记录。把采集、存储和分析分成几层，后面看到异常输入时，就能回到原始证据而不是只剩一条告警文字。
