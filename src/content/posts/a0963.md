ailx10说：这篇是在2018年11月之前写的，后来又改过。试完 Apriori，我又拿 FP-growth 做了一个更小的模拟：把 IP、User-Agent、目标 URL 编成十来条事务，看看高频组合和规则能不能被挖出来。数据很少，反倒容易一行行对照，结果里某个 URL 和某个 UA 的关联，也能直接回到原记录去查。文章借“僵尸主机”这个题目开头，实际先解决的是关联挖掘这一步怎么跑。它像在真实大数据之前搭的一张小沙盘，先用能看清的例子摸准输入和输出的关系。

---

事务数据由 12 条合成记录组成，每条记录包含 IP、UA 与 URL。

> FP-growth 使用 FP 树挖掘频繁项集，避免 Apriori 的部分候选生成过程；性能取决于数据。

FP-growth算法发现频繁项集的基本过程如下：

- 构建FP树
- 从FP树中挖掘频繁项集

## 1.数据搜集和数据清洗

```
ip=ip1,ua=ua1,target=url1
ip=ip2,ua=ua1,target=url1
ip=ip3,ua=ua1,target=url1
ip=ip1,ua=ua1,target=url2
ip=ip2,ua=ua1,target=url2
ip=ip3,ua=ua1,target=url2
ip=ip4,ua=ua2,target=url2
ip=ip5,ua=ua3,target=url2
ip=ip5,ua=ua6,target=url6
ip=ip6,ua=ua3,target=url4
ip=ip7,ua=ua4,target=url4
ip=ip8,ua=ua5,target=url5
```

## 2.训练样本

```
patterns = pyfpgrowth.find_frequent_patterns(transactions, 3)
rules = pyfpgrowth.generate_association_rules(patterns, 0.7)
```

## 原实验使用最小支持计数 3 和置信度 0.7；支持计数与支持比例不同。

```
{('target=url1',): (('ua=ua1',), 1.0)}
```

## 共同 UA 或 URL 只能构成调查线索，不证明主机属于僵尸网络；需要更大数据、标签、时间和基线证据。

```
import pyfpgrowth

transactions=[]

with open("../data/KnowledgeGraph/sample7.txt") as f:
    for line in f:
        line=line.strip('
')
        ip,ua,target=line.split(',')
        transactions.append([ip,ua,target])


patterns = pyfpgrowth.find_frequent_patterns(transactions, 3)
rules = pyfpgrowth.generate_association_rules(patterns, 0.7)

print rules
```

共同访问一个目标，是线索而不是结案证据。把时间、行为和标签继续补进来，关联规则才可能成为分析的一部分，而不只是给几台主机换上“僵尸”的名字。
