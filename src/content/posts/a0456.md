ailx10说：这篇是2022年7月之前写的，后来又改过。轮到 firewalld，我在 Kali 启动它，打开 masquerade，再分别把端口转本机 Web 和内网远程桌面，reload 后逐项访问、抓包。以前容易把各种防火墙名字当成互相替代的黑盒，自己配过才更清楚管理界面、后端规则和 NAT 的层次。笔记把永久配置和实际生效也放在一起，提醒我写进配置并不是结果已经验证。每换一个工具，还是回到那个老问题：监听和目的地址在哪里，源地址怎么回去，规则究竟在哪个区域起作用。

---

步骤一：启动防火墙

```
systemctl start firewalld



# 关闭防火墙：systemctl stop firewalld

# 查看防火墙状态：systemctl status firewalld
```

![](/notes-assets/2fd54d4de2d02e386ff8.jpg)

步骤二：开启IP伪装（也就是端口转发）

```
firewall-cmd --permanent --add-masquerade
```

![](/notes-assets/a613721f72620796e613.webp)

步骤三：本地端口转发

```
firewall-cmd --permanent --add-forward-port=port=8888:proto=tcp:toport=80

firewall-cmd --reload



# 查看防火墙开放端口：firewall-cmd --list-all
```

![](/notes-assets/b7d978ed7526d8a10296.jpg)

访问80端口ok

![](/notes-assets/8897e7fc07ee64868646.jpg)

访问8888端口ok

![](/notes-assets/4a695190c0ef73ab838b.jpg)

步骤四：远程端口转发

```
firewall-cmd --permanent --add-forward-port=port=9999:proto=tcp:toaddr=192.168.199.185:toport=3389

firewall-cmd --reload
```

![](/notes-assets/747513cbff36534ca25e.jpg)

输入用户名和密码，即可登录到远程主机

![](/notes-assets/d60a20dd0f3708ced97d.jpg)

步骤五：使用wireshark 在 跳板机上抓包，可以看到IP和端口转变过程

![](/notes-assets/0ba7c6b62a908aabca1a.jpg)

masquerade 是一种源地址转换方式，并不等同于端口转发。

换了管理工具，转发和源地址转换仍不是同一个动作。理解它们各自解决的问题，比把某个前端当成一种全新的网络原理更有帮助。
