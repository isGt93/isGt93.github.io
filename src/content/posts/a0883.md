ailx10说：这篇是在2018年12月之前写的，后来又改过。词能切出来了，下一步就得看它们怎么组成句子。我用 Bison 配合 flex，先做一个整数计算器，让加减乘除的优先级、结合性和产生式动作都能在结果里显出来。两个文件和 Makefile 放一起，几条规则就能跑出一个可用的小解析器，挺容易让人继续往里钻。文章记的就是这个从 token 到结构的过渡，抽象的动作表和语法归约不再只在概念里，而是直接决定同一串数字符号最后算出什么。

---

本文记录 flex 与 Bison 配合构建整数计算器的历史示例；代码转录和构建文件未编译验证。

提取源码中的换行、转义和构建脚本可能受损，需与原文件核对并编译后再使用。

bison和flex配合使用，可以将用户提供的语法规则转化为一个语法分析器。

bison的作用：通过产生式多次构造，最终得到一个动作表，然后利用这个动作表去解析句子。bison读取用户提供的语法产生式，生成一个C语言格式的动作表，并将其包含进一个名为**yyparse()**的C函数，这个函数的作用是利用这个动作表来解析token流，这个token流是由flex生成的词法分析器扫描源程序得到。

用例子来解释，看看下面这个整数计算器程序：

生成token流的flex文件`calc.l`：

```
%{
#include "y.tab.h"
%}

%%
[0-9]+          { yylval = atoi(yytext); return T_NUM; }
[-/+*()
]      { return yytext[0]; }
.               { return 0; /* end when meet everything else */ }
%%

int yywrap(void) { 
    return 1;
}
```

生成语法规则的bison文件`calc.y`：

%token 声明符号，生成器按规则分配编号，并非随机；%left 声明结合性和优先级。语义动作中 $$ 代表产生式左侧值，$1 代表右侧第一个符号的值。

```
%{
#include <stdio.h>
void yyerror(const char* msg) {}
%}

%token T_NUM

%left '+' '-'
%left '*' '/'

%%

S   :   S E '
'        { printf("ans = %d
", $2); }
    |   /* empty */     { /* empty */ }
    ;

E   :   E '+' E         { $ = $1 + $3; }
    |   E '-' E         { $ = $1 - $3; }
    |   E '*' E         { $ = $1 * $3; }
    |   E '/' E         { $ = $1 / $3; }
    |   T_NUM           { $ = $1; }
    |   '(' E ')'       { $ = $2; }
    ;

%%

int main() {
    return yyparse();
}
```

makefile文档：

```
calc: y.tab.c lex.yy.c
	gcc -o $@ $^

y.tab.h y.tab.c y.output: calc.y
	bison -vdty %JSON%lt;

lex.yy.c: calc.l
	flex %JSON%lt;
```

运行结果：一个简单算术计算器诞生了\~
