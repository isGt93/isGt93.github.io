ailx10说：这篇是在2019年12月之前写的，后来又改过。第一版 MyMap 大约一秒才看一个地址，我算了一下，照这个速度把目标范围跑完，时间根本不现实。手头又没有一大堆机器，只能先在单机上换办法：离线定位筛区域，让 masscan 先过一遍，再交给 Nmap 深一点看。这篇记录的是一次被速度逼出来的改版。范围、筛选顺序和工具分工一变，整个项目才有继续往前跑的可能；我也顺便记下了虚拟主机、Host 和错误响应这些后来冒出来的新问题。

---

MyMap002离线ip2region筛合肥约198万IP，masscan80筛556，再Nmap约9万记录，谈Host虚拟主机与400系列响应。

## 技术条件和待核查点

masscan80不是ping过滤，地理库准确99.9/C快百倍无验证；开900端口不能证明蜜罐，不开445不说明全城没有，IP响应不能识别所有域名。

## 原实验与代码

考虑了demo版本运行的速度非常慢，差不多1秒一个IP地址，全球40亿个IP地址，那么就需要运行40亿秒，等于跑126年才能跑完，这当然不是我想要的。因此，后期需要考虑多线程、分布式，假设我有126台电脑，那么只需要跑1年。

目前实力它允许啊，咱们还是单机版、单线程。调研了一下，其中咱们CN的IP地址数量大约是4亿，平均每个省份差不多1000万个IP地址，平均到每个市差不多100万个IP地址。对于一个拥有50万个IP地址的市来说，一秒1个指纹速度，需要50万秒，6天不到，于是我就把目标瞄准了合肥市，看看咱们的威胁情报系统首秀能做点什么？

![](/notes-assets/fb1c999d9776ca341ebb.jpg)

这里找了一个离线的IP地址库（**ip2region**），原文记录的准确率为 99.9%，未提供独立验证依据，可以看出合肥的ID是1233

> `https://github.com/lionsoul2014/ip2region`

这个库实际上就是利用大厂的对外开放的API，然后把全球的IP地址地理位置给记录下来的。首先，我们需要把这个库中满足地理位置是合肥的IP地址给找出来，这里我非常后悔用的是python，对于有性能要求的场景，那必须是用C来跑啊，不同语言与实现的性能差异需针对同一数据和任务做基准测试。

```
// unsigned int 数字转IP地址 扫描全球40亿IP地址

void getip(unsigned int x,char* ip)

{

  int a = x/(256*256*256) % 256;

  int b = x/(256*256) % 256;

  int c = x/256 % 256;

  int d = x % 256;

  sprintf(ip,"%d.%d.%d.%d",a,b,c,d);

  return;

}
```

![](/notes-assets/317508030a81ab6208b8.jpg)

C语言，30分钟就扫描完40亿IP地址，其中归属地合肥的IP地址有198万条，比我上面预估的多了一倍，那么我可能要花费2周时间才能收集完这198万条数据的指纹。这里有个问题，有些IP地址不提供服务的，比如我的上网IP地址，因此要过滤掉。这里我先通过masscan快速过滤一下ping不同的IP地址。masscan的扫描速度很快，大约3分钟就从198万IP地址中挑选出开放80端口的主机，大约500条，少的可怜啊！扫描速度一秒10000，命令如下：

```
masscan -p80 -iL hf.db --rate 10000 > 80.hf
```

![](/notes-assets/b1be49552f73517cfc9b.webp)

对这556个IP地址进行Nmap扫描，将扫描的结果存储到ES中，大约1小时就能跑完。实际上，很多网站，通过IP直接访问都会返回404、403、502，还有很多说跟目录不让请求，当然最多的是403拒绝访问。也就是说网站不允许你通过IP访问，即使nslookup也查看不到IP地址对应的域名。所以，梳理网络上的资产并不是一件容易的事情，即便如此，我也能获取大量的数据。

![](/notes-assets/85b8726a2f71159754f3.webp)

由于存在大量这样的IP地址，所有即使开放了80端口，我们也拿不到网站的信息。通过curl命令，可以轻松的拿到页面的返回内容，这里可以通过返回内容的长度进行过滤，下一版本优化这里。

![](/notes-assets/1ba4b82434488f44b8db.jpg)

在开发002版本也遇到一些有意思的事情，比如有一个家庭网络摄像头弱口令，比如老乡鸡的企业路由器弱口令，等等。

![](/notes-assets/d00583bd3724b90346ef.jpg)

发现一个开放较多端口的地址；仅凭开放端口数量无法判定是否为蜜罐，本次样本没有观测到开放 445 端口的地址，不能据此推断该区域所有主机均未开放，数据挖掘是一件有趣的事，里面的宝藏等着后来者慢慢挖掘。

![](/notes-assets/3cb02164941a44bf2534.jpg)

最后，500多个IP地址，情报数据超过了9万多条，这一版本做的我不太满意，期待一下003版本吧 ～

![](/notes-assets/640ef7f820e3da0fd475.webp)

有了筛选结果，也别急着把特殊端口解释成蜜罐、把没扫到解释成不存在。地理库、虚拟主机和响应条件都会影响这幅图，记录它们比夸一个速度数字更有用。
