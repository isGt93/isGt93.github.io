ailx10说：这篇是2019年12月之前写的，后来又改过。上传系列做到这里，我试着用 getimagesize 判断图片，结果又遇到同时带着图片结构和 PHP 内容的文件。检测能认出图片，和后面 PHP 会不会解释它，是两条不同的路径；把两边拼在一起，才有了实验里的结果。我把制作、上传和访问的过程留下，想知道检查到底证明了什么。现在看，这个小练习最有用的地方不是“图片里藏脚本”有多神奇，而是每一道验证都有自己的范围，过了一道并不代表后续处理就安全了。

---

发生在服务端的一种绕过，假如服务端检查上传图片的宽度和高度，限制只能上传图片格式，那么怎么上传我们的PHP文件`shellcode`呢？

---

下面观察带有额外内容的图片在上传校验和服务端解析阶段的不同表现。

第一步：准备一张图片，

第二步：准备要上传的shellcode文件，

第三步：构造包含额外内容的测试图片。

第四步：上传构造的测试图片。

![](/notes-assets/5a02d6200c58fee75254.jpg)

图像识别与脚本解释是两个独立过程；仅通过图像检测不意味着额外内容会自动执行。

---

前端代码：

```
<!-- index4.html by ailx10 -->
<html>
<head>
<title>ailx10</title>
</head>
<body>



<form action="upload4.php" method="post" enctype="multipart/form-data">
<label for="file">FileName:</label>
<input type="file" name="file" id="file"  value="file"  /><br />
<input type="submit" name="submit" value="submit" />
</form>
</body>
</html>
```

后台代码：

```
// upload4.php by ailx10
<?php
if($_FILES["file"]["error"] > 0)
{
    echo "Return Code:" . $_FILES["file"]["error"] . "<br />";
}
else
{
    if(!getimagesize($_FILES["file"]["tmp_name"]))
    {
        exit("Not allowed suffixes");
    }

    echo "Upload:" . $_FILES["file"]["name"] . "<br />";
    echo "Type:" . $_FILES["file"]["type"] . "<br />";
    echo "Size:" . ($_FILES["file"]["size"]/1024) . " kb<br />";
    echo "Temp file:" . $_FILES["file"]["tmp_name"] . "<br />";
    if(file_exists("upload/" . $_FILES["file"]["name"]))
    {
        echo $_FILES["file"]["name"] . "already exists.";
    }
    else
    {
        move_uploaded_file($_FILES["file"]["tmp_name"],"upload/" . $_FILES["file"]["name"]);
        echo "Stored in:" . "upload/" . $_FILES["file"]["name"];
    }
}
?>
```

这次把“像图片”和“只会作为图片使用”分开了。把保存位置、名字和服务器解释方式连起来，才能知道一个有效图像为什么仍可能进入不该去的处理路径。
