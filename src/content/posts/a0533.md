ailx10说：这篇是在2022年1月之前写的，后来又改过。一次性口令平时见得多，我这回想把“会变的验证码”从概念变成自己能运行的小例子。用 pyotp 先看 TOTP 在同一个时间片内怎样生成和验证，再拿 HOTP 对着计数值试一遍，才把两者的区别摸得更具体。这篇从短信和登录时常见的场景切入，落到几行 Python 上。它不是做出一套完整认证系统，而是先把时间、计数和验证的关系看清；图形验证码又是另一类问题，不能因为都叫验证码就放进同一个篮子。

---

pyotp演示TOTP同30秒时间片now验证，HOTP用两个随机整数at验证，讨论短信与图形验证码并修正CAPTCHA非二因素。

核查提示：HOTP应单调计数同步非随机或每运行必变，verify不自动拒重放；passwd Base32非高熵秘密，短信接收者唯一及TOTP像短信并不严谨。 本文的旧环境、代码和图片细节尚未逐项重测。

一次性口令包括基于时间的 TOTP 和基于计数器的 HOTP。短信验证码可能是一次性口令；图形验证码通常用于区分自动化行为，本身不等同于第二认证因素。

实际上，这是一种增强验证的方式，短信验证码属于比较好的双因素验证，因为绑定了手机号，所以接收人就是唯一的，但是这也导致隐私问题泄露，比如国外的REG007就能花钱买到手机号注册的网站，如果发现你注册了某个色情APP，那不就很尴尬了嘛\~

今天的主题是OTP，老规矩只看代码，不聊内幕。这是在研究零信任SDP软件定义边界的时候，有幸接触到的，简单学习了一点皮毛，在这里班门弄斧，密码学大佬轻喷哈\~

- TOTP（时间同步） 每次运行的时候，口令30秒内不变，是不是超级像短信验证码
- HOTP（事件同步） 每次运行的时候，口令都会立即发生变化，是不是超级像登陆验证码

下面是2个具体的demo案例，两个OPT使用方法的差异非常小，但是网上很少能找到HOTP的案例（真的找不到），所以记录一下，以防止自己迷路，快速成长，少走弯路\~

## 一、TOTP案例demo

![](/notes-assets/1368f359ced8158e65cb.webp)

```
# -*- coding: utf-8 -*-
"""
@Time ： 2021/3/10 20:07
@Auth ： ailx10
@File ：demo-totp.py
@IDE ：PyCharm
"""
import base64
import pyotp

string = "passwd"
key = base64.b32encode(string.encode(encoding="utf-8"))

totp_func = pyotp.TOTP(key)
my_key = totp_func.now()
print("一次性口令1：",my_key)

my_key2 = totp_func.now()
print("一次性口令2：",my_key2)

status = totp_func.verify(my_key)
print("一次性口令验证状态：",status)
```

## 二、HOTP案例demo

![](/notes-assets/49ef900a05a122d3d598.webp)

```
# -*- coding: utf-8 -*-
"""
@Time ： 2021/3/10 20:23
@Auth ： ailx10
@File ：demo-hotp.py
@IDE ：PyCharm
"""
import base64
import pyotp
import random

string = "passwd"
key = base64.b32encode(string.encode(encoding="utf-8"))
random.seed(version=2)
r1 = random.randint(1,9999)
r2 = random.randint(1,9999)
hotp_func = pyotp.HOTP(key)
my_key = hotp_func.at(r1)
print("一次性口令1：",my_key)

my_key2 = hotp_func.at(r2)
print("一次性口令2：",my_key2)

status = hotp_func.verify(my_key,r1)
print("一次性口令验证状态：",status)
```
