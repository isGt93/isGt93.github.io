ailx10说：这篇是在2022年8月之前写的，后来又改过。有一天看电脑开机记录，我发现明明已经到 8 月 6 日，最近一次启动时间却还停在 7 月底，顺着一查，才把合盖、关机和日志这些事情放到一起想。我先在 Windows 事件查看器里筛 6005、6006，又对照 CentOS 的启动、关机和 crash 记录，把看到的时间记下来。那时还想着以后研究 EDR，这些系统日志总得先熟悉。它是一篇从自己电脑上的小疑问长出来的笔记，不过事件有各自的含义，记录也可能缺失，不能只靠两条日志就把全部开关机经历补齐。

---

Windows 和 Linux 都可以通过系统日志调查启动、关机和异常重启的时间。不过，日志可能被清理或覆盖；突然断电时，也可能来不及写入关机事件。因此，日志提供的是线索，不能保证完整还原每一次开关机。

## Windows：查看系统事件

1. 打开“事件查看器”，进入“Windows 日志 → 系统”。
2. 在右侧选择“筛选当前日志”，输入需要查看的事件 ID，例如 `12,13,41,6005,6006,6008`。
3. 查看事件的**来源**、时间和详细信息，并结合相邻事件判断。

| 事件来源与 ID | 含义 | 使用时注意 |
| --- | --- | --- |
| Kernel-General 12 | 操作系统启动 | 可作为启动时间线索。 |
| Kernel-General 13 | 操作系统正在关机 | 与其他事件一起判断关机过程。 |
| EventLog 6005 | 事件日志服务已启动 | 常出现在启动过程中，但含义是日志服务启动。 |
| EventLog 6006 | 事件日志服务已停止 | 常出现在正常关机过程中，但含义是日志服务停止。 |
| Kernel-Power 41 | 系统未正常关机后重新启动 | 原因可能有多种，需继续排查。 |
| EventLog 6008 | 上次关机异常 | 是异常关机线索，不单独证明具体原因。 |

事件 ID 可能由不同来源使用，筛选时应同时检查来源。合上笔记本盖子后，设备可能睡眠、休眠、关机或继续运行，取决于电源设置；不能仅凭合盖动作判断关机。

## Linux：查看启动记录

使用 systemd 的系统可查看当前保存的启动记录：

```bash
journalctl --list-boots
```

查看上一次启动的日志，可使用：

```bash
journalctl -b -1
```

可用范围取决于日志是否持久保存及保留策略。也可使用 `last -x` 查看系统维护的登录与重启记录；记录不存在或不完整时，不能据此断言事件未发生。

## 还原时间线

排查时先确认机器时区和系统时间是否准确，再结合启动、关机、异常事件及其他设备日志核对。异常断电可能没有正常关机记录，日志轮转、清理和损坏也会留下缺口，因此启动与关机事件不一定成对出现。

参考：[Microsoft：使用系统事件日志排查意外重启](https://learn.microsoft.com/en-us/troubleshoot/windows-server/performance/troubleshoot-unexpected-reboots-system-event-logs)、[systemd journalctl 文档](https://www.freedesktop.org/software/systemd/man/latest/journalctl.html)。

有记录是一条线索，没记录却不一定代表没发生。把日志保留范围和异常断电这些缺口也写进去，得到的结论虽然没那么痛快，但会更经得起回头核对。
