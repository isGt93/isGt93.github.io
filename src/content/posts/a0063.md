ailx10说：这篇是在2021年12月之前写的，后来又改过。那阵子我开始做新员工第一轮面试官，自己也还在摸索怎么问问题。与其一上来就拿冷门技巧难人，我先想了个简单办法：把常见漏洞用一句话讲清楚，能不能让别人听懂？于是列出了 SQL 注入、XSS、CSRF、上传下载、文件包含、命令执行等一串问题，写着写着早就超过标题说的十项了。它最初就是一份面试小抄，里面有些解释也过于省略。现在读它，不妨把答案当成起点，再追问条件、影响和边界，别只背一句顺口的话。

---

回答安全概念题时，除了说出攻击形式，还应解释数据如何跨越信任边界、漏洞可能造成什么影响，以及防御需要控制哪个环节。以下定义用于入门，不代表每种漏洞都能在任何环境中实现同一种攻击效果。

| 概念 | 简要解释 |
| --- | --- |
| SQL 注入 | 不可信输入被拼入 SQL 语句并影响其结构，使数据库执行超出预期的查询或操作。 |
| 跨站脚本（XSS） | 应用将不可信内容以不安全方式输出到页面或交给浏览器执行，使攻击者脚本在受影响站点上下文中运行。 |
| 跨站请求伪造（CSRF） | 攻击者诱使已认证用户的浏览器向目标站点发送非用户意愿的请求，利用站点对请求来源或意图验证不足。 |
| 不安全文件上传 | 服务端未充分限制上传内容、存储位置或后续处理，导致恶意文件被访问、解析或执行等风险。 |
| 不安全文件下载 | 下载接口缺少授权或路径限制，使用户可能读取不应访问的文件。 |
| 路径遍历 | 应用未安全处理用户提供的路径，可能访问预期目录之外的文件；它不是“暴力扫描目录”的同义词。 |
| 本地文件包含（LFI） | 应用根据不可信输入包含本地文件，造成非预期读取或执行，影响取决于语言和包含方式。 |
| 远程文件包含（RFI） | 应用不安全地包含远程位置的内容，可能造成代码执行；是否可利用取决于运行时配置及实现。 |
| 变量覆盖 | 不可信数据影响了本不应由用户控制的程序变量，从而改变程序状态或执行流程。 |
| 代码注入 | 不可信输入被解释为程序代码执行，例如错误使用动态求值接口。 |
| 信息泄露 | 应用或系统向未授权方暴露敏感信息，例如凭据、源代码、内部路径或错误细节。 |
| 弱口令 | 密码易被猜测、复用或破解，使账户更容易遭到未授权访问；实际风险还取决于限速和多因素认证等措施。 |
| 缓冲区溢出 | 访问超出缓冲区边界，可能破坏内存或泄露数据；不只发生在栈上，也不只涉及字符串。 |
| 会话劫持 | 攻击者取得或控制有效会话凭证后冒用用户身份；获取 Cookie 只是可能路径之一。 |
| 命令注入 | 不可信输入影响操作系统命令的解析或执行，导致应用执行非预期操作。 |

## 反序列化漏洞

反序列化把存储或传输的数据恢复为程序对象。当程序对不可信数据进行危险的反序列化，或没有限制对象类型、属性与后续行为时，可能造成逻辑篡改、资源耗尽，某些条件下也可能导致代码执行。影响取决于具体格式、库和应用逻辑，不能把所有反序列化操作都视为漏洞。

## 如何继续学习

将每个概念与一次正常请求对照：找出数据入口、解释器或敏感操作、权限边界、实际影响及防御措施。实验应在获得授权的环境中进行，不能仅凭概念名称推断漏洞可被利用。

参考：[OWASP 注入风险](https://top10.owasp.org/2025/A05_2025-Injection/)、[OWASP 安全备忘录索引](https://cheatsheetseries.owasp.org/IndexTopTen)。

一句话能开头，不能替代完整理解。挑一个正常请求作对照，再把漏洞条件和防护位置补出来，这些问答才能变成自己能讲明白的知识，而不只是面试时的台词。
