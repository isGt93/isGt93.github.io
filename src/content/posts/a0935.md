ailx10说：这篇是我2022年4月写的。Neo4j 更新节点时，我先想到 UUID，转成数值后太大，又裁成小范围，问了架构师才被提醒冲突风险太高。第一反应是字典，可程序下次重跑 ID 不能乱，于是又用熟悉的 SQLite 持久保存名称、类型和编号。写到每行都查或写数据库，速度慢下来，我才想到还能换 Redis。文章就留下这串不太直线的选择：不是开始就找到完美方案，而是一个限制推动下一个改法。把当时为什么选、后来哪里不够用记着，比只展示最终代码更能帮我少绕一遍。

---

在处理neo4j的时候，更新数据时，为了不必要的图查询操作，我额外添加了一个id字段，并且作为节点的索引，而之前我用的是uuid，并且转换成了数字，但是neo4j不支持这么大的数字，于是我又裁剪到16位，得到一个较小的数字（65536），咨询了我们的架构师bao总，说冲突的可能性非常大，于是我又设计了一款，基于sqlite数据库的方式，来存储id和对应的字段值、字段类型。

我的第一反应是应该构建一个字典，但是考虑到在内存里面，下次运行到时候，id都变了，所以就考虑到离线存储，由于在上一个小工具项目里，我灵活的运用过sqlite来存储数据，所以这次依法炮制，只不过每一行数据都要查询数据库或者写入数据库，导致性能比较慢，等到项目完成时，我才想到来redis也可以做这件事，而且redis是内存数据库，以可以save保存。

![](/notes-assets/c4f4391e365682c4e0c2.jpg)

```
import sqlite3

import os

import pandas as pd





def create_db():

    dbfile = "id.db"

    if os.path.exists(dbfile):

        conn = sqlite3.connect(dbfile)

        c = conn.cursor()

        return c,conn

    else:

        conn = sqlite3.connect(dbfile)

        c = conn.cursor()

        c.execute("""

        CREATE TABLE IDDB

        (ID INTEGER PRIMARY KEY NOT NULL,

        NAME   CHAR(256)   NOT NULL,

        TYPE   CHAR(10)    NOT NULL);

        """)

        conn.commit()

        return c,conn



def getid(c,conn,name,type):

    cursor = c.execute("SELECT ID,NAME,TYPE from IDDB WHERE name='{}' AND type='{}'".format(name,type))

    data = list(cursor)

    if len(data) > 0:

        for row in data:

            id = row[0]

            return id

    else:

        c.execute("INSERT INTO IDDB (type,name) VALUES ('{}','{}')".format(type,name))

        conn.commit()

        id = getid(c,conn,name,type)

        return id



def get_id_src_ip(x,c,conn):

    return getid(c,conn,x.src_ip,"id_src_ip")



def get_id_web_domain(x,c,conn):

    return getid(c,conn,x.web_domain,"id_web_domain")



def get_id_response_content(x,c,conn):

    return getid(c,conn,x.response_content,"id_response_content")



def requestIPNode(c,conn):

    df = pd.read_csv("test3000.csv",usecols=["src_ip","a1","a2"])

    df.dropna(axis=0,how="any",inplace=True)

    df.drop_duplicates(inplace=True,ignore_index=True)

    df["id_src_ip"]=df.apply(get_id_src_ip,args=(c,conn),axis=1)

    df.to_csv("data/requestIPNode.csv",index=False)





if __name__ == "__main__":

    c,conn = create_db()

    requestIPNode(c, conn)

    conn.close()
```

数据库能保存映射，不代表SQL拼接和并发问题自动消失。唯一约束、参数化与事务一起补上，ID才会从临时编号变成可以放心依赖的标识。
