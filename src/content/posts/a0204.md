ailx10说：这篇是我2025年3月写的。我想拿这道 easy\_hash 题说明一个挺容易混淆的地方：MD5 不能直接倒算，不等于这种小题就无从下手。题目把每个字符单独做了摘要，候选范围一下子变得很小，我就先给可打印字符建一张表，再把题目的结果逐个查回来。于是它更像是查表，而不是把哈希算法“破解”了。笔记里还放了脚本，但分隔方式得和题目输出一致，不然思路没错，也会读错数据；这套办法也不能当成真正密码存储的建议。

---

编辑核查提示：按字符枚举是有限候选集合的查表，不是通用 MD5 逆运算。普通 MD5（即使加盐）不适合作为现代口令存储方案。

MD5 将输入映射为 128 位摘要，常写为 32 个十六进制字符。对有限且很小的候选空间，可以预先计算并比对摘要；这不是通用的逆向算法。

主要应用场景：

MD5 存在碰撞问题，不适用于需要抗篡改的数字签名或安全完整性校验；密码应使用专门的口令散列方案，例如 Argon2id、scrypt、bcrypt 或 PBKDF2，并按实际环境配置。

难度系数：1

题目给的是一个正向flag加密过程，要求我们进行逆向

```
import hashlib

text = "flag{demo}"
hashes = [hashlib.md5(ch.encode()).hexdigest() for ch in text]
print(" ".join(hashes))
```

本题每个字符分别计算摘要，可对已知字符范围逐项比对。

![](/notes-assets/86dc97d9ed6a9a1653be.webp)

构建可打印 ASCII 字符到摘要的表，按输入顺序查找；不存在的值应报错，避免悄悄丢失信息。

然后做好匹配字典，直接查字段，就能拿到flag

```
import hashlib

def recover_ascii(data):
    lookup = {hashlib.md5(chr(i).encode()).hexdigest(): chr(i)
              for i in range(32, 127)}
    result = []
    for digest in data.split():
        if digest not in lookup:
            raise ValueError(f"未知摘要: {digest}")
        result.append(lookup[digest])
    return "".join(result)

# 将 data 替换为题目给出的、以空白分隔的摘要。
```

运行结果：Recovered flag: `flag{We1c0me_t0_the_w0r1d_0f_md5}`

这里利用的不是推翻MD5计算，而是输入空间太小且重复可查。把算法和使用方式分开，这道题留下的就不只是一个查表脚本，还有对保护粒度的直觉。
