ailx10说：这篇是我2024年8月写的。买了 Cloudflare 域名以后，我顺手拿自己的站点试它的代理和防护。先观察地址怎样变成代理节点，再用 HTTP 请求看控制台事件，看到拦截的同时，正常访问也有卡顿。这种体验比宣传里的“打开就好”复杂一点，我就一起记下来。后来 hping3 没发出预期结果，当时也猜过是不是四层防护，但本地没发成和远端挡住终究不是一回事。文章留下的是一次自己的站点测试：既看拦截数字，也得记得回头看看正常用户访问到底顺不顺。

---

- 最近 ResellerClub 无法正常登录了，无法管理我的域名，弃坑。
- 今天，花了300多块钱，买了 GoDaddy 的域名（3年），结果不让转移到其他厂商，弃坑。
- 最终，开通了PayPal，花了56块钱，买了 Cloudflare 的域名（1年），入坑。

---

1、自带CDN防护，我的网站域名是`ddos.hackbiji.cc`，IP是`144.34.162.13`

国内 DNS 查询返回代理地址，但这不足以证明源站 IP 完全隐藏。

![](/notes-assets/56b77075a90675424089.webp)

国外 DNS 查询返回代理地址；其他记录、历史数据或直接访问仍可能暴露源站。

![](/notes-assets/f144c40f54f674711c5c.webp)

2、模拟CC攻击

```
ab -n 10000 -c 100 http://ddos.hackbiji.cc:8080/
```

![](/notes-assets/8bbf353fe5fbc021188a.webp)

3、Cloudflare 观察到 HTTP DDoS 事件

![](/notes-assets/05124c1f4ce5d8976846.webp)

4、本机 hping3 未发出数据：原因未查明，不能作为远端防御证据

```
hping3 -SA -p 8080 --fast --rand-source ddos.hackbiji.cc
```

![](/notes-assets/458fba09896b893d250e.webp)

（1）HTTP DDoS 攻击防护（自己配置的）

可自动缓解基于 HTTP 的 DDoS 攻击，如 HTTP 泛洪、放大 HTTP 攻击和反射 HTTP 攻击。

![](/notes-assets/ca5f5d9de834c62f3fe3.webp)

（2）网络层和 SSL/TLS DDoS 攻击防护（无需配置）

可自动缓解基于 SSL/TLS 和网络层 DDoS 攻击，如 SYN 泛洪和 UDP 反射攻击。

![](/notes-assets/b44c32298eb381a599de.webp)

这份记录里有观察，也有当时的猜测，两者最好一直分开。代理侧出现事件，不代表源站每个入口都被保护；一次本地发包失败，也不能替远端防护作证。
