ailx10说：这篇是在2022年8月之前写的，后来又改过。以前做护网时，临时遇到过“写个正则找乱码”的问题，当时一紧张，没写出来，事后想起还有点尴尬。后来趁周末重新翻资料，从可打印 ASCII、中文和中日韩字符范围一点点拼规则，把那道没答好的题再做一遍。于是有了这篇笔记，也顺手试了匹配异常字符之后的内容和整段文本。现在回看，问题还得再说准确些：白名单外的字符不一定是乱码，乱码也未必都在白名单外。那次补课值得留下，但规则能检测什么，不能夸大。

---

检查文本时，正则表达式可以筛选不符合预期的字符，但不能可靠判断一段文字是否发生了编码错误。原文通过排除指定字符范围寻找“乱码”；更准确的名称是**检测白名单之外的字符**。

## 为什么白名单不等于乱码检测

例如，`é`、表情符号和某些生僻汉字都可能是合法文字，却可能不在预先设定的白名单中。反过来，错用编码产生的乱码也可能恰好由白名单中的字符组成。`U+FFFD`（替换字符）常见于解码失败后的替换，但它也可能是文本中有意出现的字符，不能单凭它证明原因。

此外，`[\u4e00-\u9fa5]` 只覆盖部分汉字，并不代表全部中文；允许的字符范围应按业务实际要求制定。

## 用白名单筛选可疑字符

下面的 Python 示例允许可打印 ASCII、换行、制表符和部分常用汉字。它用于演示方法，**不是**完整的中日韩字符范围：

```python
import re

outside_allowed = re.compile(r"[^\x20-\x7e\u4e00-\u9fff\n\r\t]")
text = "Hello，世界🙂"

for match in outside_allowed.finditer(text):
    print(f"位置 {match.start()}: {match.group()!r}")
```

这个例子会报告中文逗号和表情，因为两者不在示例白名单中；它们并不因此变成乱码。如果业务允许这些字符，应修改规则并使用真实样本验证。`finditer` 的位置是 Python 字符串中的索引，不是原始文件的字节偏移。

如果只需要判断是否有白名单之外的字符，可使用 `outside_allowed.search(text)`；如果要提取所在行，可在逐行读取时调用它。不同语言的正则引擎和 Unicode 支持有所差异，应按使用环境测试。

## 排查真正的编码问题

优先保留原始字节，并确认数据来源声明的编码。已知文件应为 UTF-8 时，可以使用严格解码发现不符合 UTF-8 的字节：

```python
from pathlib import Path

data = Path("input.txt").read_bytes()
try:
    text = data.decode("utf-8", errors="strict")
except UnicodeDecodeError as exc:
    print(f"UTF-8 解码失败，起始字节位置：{exc.start}")
```

严格解码失败说明字节不符合所选编码，仍需确认正确编码；成功也不能证明文本在此前没有被错误转码。排查时应保留原文件，通过来源编码、处理链路和可复现样本共同判断。

参考：[Python 正则表达式文档](https://docs.python.org/3/library/re.html)、[Python 编解码器文档](https://docs.python.org/3/library/codecs.html)。

白名单外的字符需要检查，不等于它本身有错。保留原始字节、确认编码，再用正则辅助筛选，才不会为了清理文本，把原本正确的内容也一起删掉。
