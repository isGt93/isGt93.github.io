ailx10说：这篇是在2021年12月之前写的，后来又改过。工作重心从网络转向终端时，最先让我惦记的就是：能不能知道这段流量究竟是哪个进程发的？下班后搜了一晚上，找来 wsexplorer 和 openQPA，补 Python 2.7、PyQt4 等依赖，再拿搜狗输入法等进程试抓包。这篇保留了旧工具的限制和界面，也留下把两个视角接起来的那点兴奋：网络包不再只是一组地址，终端上的进程终于有机会和它对上。装依赖虽然琐碎，却是那次实验真正走进数据之前的一段必经路。

- chrome进程（一堆中文乱码）
- 搜狗输入法进程
- 其他普通程序进程

## openQPA[\[1\]](#ref_1)

进入python2.7虚拟环境

```
conda activate mypqa
```

安装依赖包，最核心的是pyqt4[\[2\]](#ref_2)

```
pip install E:\hacker\PyQt4-4.11.4-cp27-cp27m-win_amd64.whl
pip install httplib2
pip install connect
pip install dpkt
```

退出虚拟环境

```
conda deactivate
```

运行python主程序，首先选择网卡，然后启动抓包

可以轻松找到搜狗云（sogoucloud.exe）进程的网络报文

![](/notes-assets/7dd1ab4c80568e865b59.jpg)

也可以点击分析，内容没有wireshark打开的详细，估计是想突出重点内容

![](/notes-assets/fda42983c086d9200a3f.jpg)

最后官网给出的特色：

> 进程抓包：QPA是基于进程抓包的，实时准确判定每个包所属进程，优于仅基于网卡抓包的软件  
> 分析智能：QPA按流量类型自动归类，分析简便，优于基于一条条会话的分析模式  
> 识别引擎：QPA是基于正则表达式书写规则，能提取IP、端口、报长与内容等维度特征

网络包本身不会带着PID走过网线，关联还得依赖本机状态。连接复用和进程生命周期一变，结果就可能不同，所以对应关系也需要实际核对。
