本文记录一道历史蓝队分析题，结合 Web、RDP 和 FTP 日志，以及接收目录中的程序线索；部分时间线和题目答案仍需核对。

核查提示：200不能单独证成功；页面版本与2024入侵时间存在时间线疑点，多项题答案未完整给，需图和完整记录回查。 原实验、代码和图片细节未逐项复测。

2.攻击者的webshell文件名？

---

有Web服务器，先看Web日志，发现 `192.168.126.135` 大量 404 请求，推测这是在漏洞扫描，频繁访问 `POST /system.php HTTP/1.1` 响应吗 200 推测是漏洞利用成功了。

查找该时间段内被修改的文件，找到 `system.php` ，该文件是一个加密型 PHP Webshell，具有极高的隐蔽性。它通过异或（XOR）加密和 Base64 编码与攻击者通信，并利用 PHP 的 `eval()` 函数执行远程指令。

非常有意思的是，该 PHP 后门采用了 Session 驻留机制。在第一次请求时，它仅将 Payload 存入 Session 而不执行，必须在第二次请求时才会正式生效。

查看入侵时间段修改文件时，还发现了`3389.bat` ，这是一个 典型的 Windows 远程桌面（RDP）启用脚本，常被攻击者用于在入侵后开启 3389 端口以便远程控制。

提取最近 5 次成功的 RDP 登录（LogonType\=10），找到嫌疑人 `hack887$` 以及登录的IP地址`192.168.126.129`， 查看所有本地用户`Get-LocalUser | Select Name, Enabled, Description`，也能锁定攻击者是 `hack887$` 。

人的第一反应是从web进来的，我甚至改了数据库的admin密码，登录进去了，看到wordpress 版本是6.9，找了一圈，也没有看到这个版本的漏洞信息，没有想到竟然还有FTP服务器，查看日志，发现是暴力破解了FTP口令。

查看FTP日志，观察到上传Webshell的时间是 `2024/02/29 13:01:39` （回顾Webshell的访问时间），上传之后，立马连接Webshell的。

还有QQ号需要发挥脑洞了：查看文档，发现 Tencent Files 腾讯文件夹，进入发现QQ号文件夹。找到了攻击者的QQ号：`777888999321` ，在 FileRecv 文件夹下发现 FRP隧道工具，打开配置文件发现C2服务器和C2端口。

这题的Webshell 有点意思啊，**system.php** 只是一个极其精简的“外壳”（Shell），它本身不具备复杂功能。**核心功能**（如文件管理、命令执行）是在连接时由客户端动态推送到服务器 Session 中的。

状态200不是成功通行证，旧文件日期也未必就是入侵时间。把矛盾和缺失答案留下，后面的复盘才不会被一条看似顺畅却未经核对的故事带跑。
