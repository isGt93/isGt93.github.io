ailx10说：这篇是2022年1月之前写的，后来又改过。注册表这次，我从已有 Empire 会话往 HKCU Run 写入口，重启、登录后观察会话重新出现，再另试提升模块。写起来几条命令，实际有两段不同的故事：怎样在用户登录时再次执行，和之后能否变成更高权限。笔记把它们放在一起，回看时更要分清每段各自的起点。Run 项不是传统意义往进程里“注入”，也不是永久控制的保证；真正帮我理解的是那一轮退出、重启和回来后的对照，知道触发时机在哪里。

---

本文记录已有会话后配置当前用户 Run 注册表项的历史实验，Run 通常在用户登录时触发，而不是仅重启即可保证执行。

这是实验的前提：你要先拿到一个agent（重命名为ailx10）

实验环境：

- 服务端：Kali OS
- 客户端：Win7

原文为实验关闭部分防护，这属于特定实验条件，不是生产建议。

## 第一步：在完成第一个实验的基础上，进入模块

- 进入这个agent（interact ailx10）
- 进入模块（usemodule persistence/userland/registry）

![](/notes-assets/d022494b503f927ed65c.jpg)

## 第二步：开始下配置

- 下配置（set Name ailx10）
- 下配置（set RegPath HKCU:Software\\Microsoft\\Windows\\CurrentVersion\\Run）

![](/notes-assets/fbf30cbae90477fcb8cc.jpg)

原文在注册表中观察到该项；后续触发仍需对应用户登录及运行条件。

![](/notes-assets/c22ba1ed2c0b299fa8de.jpg)

## 第三步：重启电脑

重启后还需用户登录；单次重新上线不能说明永久控制。
![](/notes-assets/839a744c0d5bb86fb243.jpg)

再来感受一下成功的喜悦，来个放大版的

![](/notes-assets/edfb5420f88104874c50.jpg)

本篇完～

这次重连是一个具体结果，不是永远有效的保证。把登录触发和重启分清，再看后续权限变化，才更容易解释这条链哪里成立、哪里还需要别的条件。
