ailx10说：这篇是2022年1月之前写的，后来又改过。WMI 横向这次，我先用 WMIC 在远端建进程，把输出写到文件，再通过管理共享读回来；之后在 Kali 装 impacket，试 wmiexec 的交互效果。两种方法放一起，才看出有的命令只负责启动，结果还得自己找路取。笔记里用的是有权限的账号，并没有绕开认证这个前提。做这个练习让我更在意反馈通道：窗口没出现、页面没回显，都不代表远端没有动作；同样，没有在眼前看到日志，也不能说这条路天生不会留下记录。

---

本文记录使用 WMI 远程管理和 Impacket wmiexec 的历史实验。是否有日志取决于审计配置，未观察到日志不代表没有记录。

## 1、使用WMI远程命令执行

原实验使用具备远程执行权限的账户；域用户身份本身不自动赋予该能力。

```
wmic /node:192.168.160.143 /user:HACKBIJI\Administrator /password:W2ngluoanquan process call create "cmd.exe /c ipconfig >c:\ip.txt"
```

![](/notes-assets/c4d24df0fc9c685725d2.webp)

- 去windows server 2012域用户的C盘下，可以发现生成的 **ip.txt** 文件

![](/notes-assets/1720e975a0808b759a35.webp)

- 建立`IPC$` (win7域用户--\> windows server 2012域用户)

```
net use \192.168.160.143\ipc$ "W2ngluoanquan" /user:HACKBIJI\Administrator
```

![](/notes-assets/a0c5a75960daf3092d60.webp)

- 获取ip.txt文件信息 （windows server 2012域用户）

```
type \192.168.160.143\c$\ip.txt
```

![](/notes-assets/b0c18ad72207656940b6.webp)

## 2、impacket工具包中的wmiexec

Impacket 的 wmiexec 需要目标身份、认证和远程管理权限；域信息是否可省略取决于环境中的身份解析。

```
python wmiexec.py Administrator:W2ngluoanquan@192.168.160.143
```

![](/notes-assets/54226ec79595344af11b.jpg)

本篇完～

命令返回了结果，只说明对应权限和通路成立了。有没有日志、身份怎样解析，还要看具体环境；没在这次操作里看到，不该直接写成系统从来不记录。
