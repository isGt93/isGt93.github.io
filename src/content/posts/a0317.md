ailx10说：这篇是2019年12月之前写的，后来又改过。继续做上传时，我把检查搬到后端，用 pathinfo 取扩展名，只拦 PHP。接着换成 phtml 再试，环境却照样把它交给解释器，前面那张黑名单一下就显得不够用了。这篇留了完整前后端代码，方便看清问题不是函数自己坏了，而是我允许了什么、漏了什么，又把文件存在哪个会执行的目录里。一个小练习让我把扩展名检查和服务器映射联系起来；名字看着不像常见脚本，不等于它在当前环境里不会被执行。

---

本例讨论扩展名黑名单遗漏与服务器脚本映射的组合问题。pathinfo() 本身不是漏洞；能否执行取决于服务器是否将相应扩展名交给解释器。

后台代码：

```
// upload2.php by ailx10
<?php
if($_FILES["file"]["error"] > 0)
{
    echo "Return Code:" . $_FILES["file"]["error"] . "<br />";
}
else
{
    $info = pathinfo($_FILES["file"]["name"]);
    $ext = $info['extension'];
    if(strtolower($ext) == "php")
    {
        exit("php Not allowed suffixes");
    }

    echo "Upload:" . $_FILES["file"]["name"] . "<br />";
    echo "Type:" . $_FILES["file"]["type"] . "<br />";
    echo "Size:" . ($_FILES["file"]["size"]/1024) . " kb<br />";
    echo "Temp file:" . $_FILES["file"]["tmp_name"] . "<br />";
    if(file_exists("upload/" . $_FILES["file"]["name"]))
    {
        echo $_FILES["file"]["name"] . "already exists.";
    }
    else
    {
        move_uploaded_file($_FILES["file"]["tmp_name"],"upload/" . $_FILES["file"]["name"]);
        echo "Stored in:" . "upload/" . $_FILES["file"]["name"];
    }
}
?>
```

参考文献：《Web安全攻防：渗透测试实战指南》电子工业出版社

上传通过只是前半段，文件被怎样访问和解释是后半段。把两段接起来，才知道问题来自允许范围与服务器处理规则没有对齐。
