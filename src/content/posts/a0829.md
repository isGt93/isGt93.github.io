本文记录 HTTP 指纹、代理与历史 Web 服务评估；原登录尝试未明确证明成功，HTTP 302 不能单独用于确认认证。

核查提示：443明文telnet不是标准TLS测试；代理与登录尝试明确失败，302不能单独判断认证结果。 旧版内容与实验仍需逐项核验。

![](/notes-assets/38cb1325c91778ab794e.webp)

本章介绍了Web服务的指纹，识别和评估反向代理机制，枚举运行在Web服务器上的虚拟主机和Web站点，还详细介绍了如何识别子系统和激活的组件，研究Web服务器存在的已知漏洞，对可访问的Web站点进行爬虫，来获取有用的文件和目录，还对访问的认证机制进行口令猜测，知识真的太多了，坚持，成为安全专家只差一点点了。

1、Web服务器指纹识别

1）人工的Web服务器指纹识别

HTTP HEAD 手动识别，遗憾的是400 Bad Request，仅仅识别到Server是nginx

```
telnet en.ustc.edu.cn 443
HEAD HTTP/1.1
```

![](/notes-assets/65c719b6a64da756282e.webp)

同样的使用HTTP OPTIONS 手动识别，也能识别出Server，我想思路可能就是根据返回的不同，来枚举不同的服务器，到底是Apache，还是Nginx，亦或是IIS等

```
telnet www.zhihu.com 443
OPTIONS / HTTP/1.0
```

![](/notes-assets/bc347788b490bda1af12.webp)

2）自动化的Web服务器指纹识别

介绍了古老的攻击 httprint ，现在已经不流行了，作为开源工具，还是值得学习一下的，你别说，打分还挺准的

```
mkdir /usr/share/httprint
cd /usr/share/httprint
wget http://www.net-square.com/_assets/httprint_linux_301.zip
unzip httprint_linux_301.zip
cd httprint_301/linux
./httprint -h http://<URL> -s signatures.txt
```

5、暴力破解

在本地电脑上搭建一个dvwa

```
docker pull vulnerables/web-dvwa
docker run --rm -it -p 80:80 vulnerables/web-dvwa
```

使用hydra对dvwa进行口令破解

遗憾的是这个案例中POST登录请求和返回，不好区分登录成功和失败

```
hydra -l admin -P passwd.txt 192.168.0.100 http-post-form "/login.php:username=^USER^&password=^PASS^: login.php"  -vV 
```

![](/notes-assets/e6a8f4a06a77c83aeca0.svg)

这个dvwa网站的首页，用burpsuite去打登录口令，也全是302重定向

![](/notes-assets/a2a0b415e3310f750005.svg)

明文连接443和真正TLS测试不是一回事，登录尝试也不能只认302。保留失败路径，下一次换工具时才知道问题是方法、环境还是理解上的缺口。
