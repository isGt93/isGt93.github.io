ailx10说：这篇是在2020年1月之前写的，后来又改过。上学时我主要在 Windows 下写小程序，真正转到 Linux 开发、面对上万行项目之后，才发现以前那点调试本事不太够用。这篇就是工作需要逼着我往前走时留下的总结：先沿调用流、数据流理解项目，再练单步、条件断点、观察点、回溯和栈帧切换，最后碰一碰多进程。工具命令不少，但我想记住的并不是命令表，而是遇到问题该停在哪儿、看什么。它写给当时那个跨平台的新手，也适合拿着一个真实程序边查边用。

---

阅读程序时，可以先梳理函数之间的调用，再追踪关键变量如何变化。GDB 能让程序在指定位置暂停，帮助检查两条线索。

## 启动与断点

编译测试程序时加入调试信息，例如 `gcc -g demo.c -o demo`，然后运行 `gdb ./demo`。优化级别、编译器和程序状态会影响可观察到的变量和执行顺序。

```gdb
break main
run
next
step
finish
continue
```

`next` 通常跨过当前行中的函数调用，`step` 尝试进入有调试信息的函数，`finish` 运行到当前函数返回。可用 `break demo.c:20` 指定文件和行号，或用 `break demo.c:20 if i == 40` 设置条件断点。条件断点只在程序实际经过该位置并且条件成立时停下，并不会直接跳转到目标迭代。

## 查看数据和调用栈

```gdb
print value
info locals
backtrace
frame 1
list
x/4xw address
```

`backtrace` 显示调用栈，`frame 1` 切换到编号为 1 的栈帧；`x/4xw address` 从地址开始按十六进制查看四个 word。打印长数组时可查看 `help set print elements`，并按需要调整显示上限。

## 观察变量与多进程

`watch variable` 在被监视表达式的值发生变化时暂停。可用的硬件观察点数量和适用范围取决于目标环境。

当程序调用 `fork` 时，GDB 默认跟踪父进程；使用 `set follow-fork-mode child` 可改为跟踪子进程。也可以使用 `attach PID` 附加到有权限调试的现有进程。暂停的程序状态、权限限制和多线程行为都可能影响观察结果。

参考：[GDB 手册](https://sourceware.org/gdb/current/onlinedocs/gdb/)、[调试 fork](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Forks.html)。

断点、观察点和回溯各自回答不同问题，没必要一次把帮助页背完。带着一个具体疑问进入调试器，找到能解释它的那一小段执行过程，命令才会慢慢变成自己的工具。
