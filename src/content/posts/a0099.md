ailx10说：这篇是我2024年6月写的。继续试 Web SSH 时，我换到了 webssh2。和前一款直接装服务不同，这回要先拉代码，改自己的 SSH 端口，再构建 Docker 镜像、映射浏览器入口。第一次输入凭据连上以后，我又观察到再次访问时的表现，便把这些使用细节一并写下来。那一阵连续试项目，文章看着像一串安装步骤，背后其实是在给自己的网站找一个合适入口：能连上只是第一步，配置方式、浏览器体验和登录状态怎么保留，也都得亲自走过才知道。

---

WebSSH2 提供浏览器中的 SSH 终端界面。原文记录了从源码构建容器、配置 SSH 端口、通过浏览器连接测试主机的过程；它还观察到首次登录后再次访问无需输入密码。

后一个现象只能说明当时浏览器、服务及会话状态下的观察，不能推断所有部署都会无条件免密。应检查会话有效期、浏览器凭据保存、服务端会话配置，以及退出和过期后的行为。

## 部署前检查

- 浏览器到网关的连接使用可信 TLS，并限制允许访问网关的人和网络。
- 验证 SSH 主机密钥，限制可连接的目标，避免网关成为任意目标的访问入口。
- 设置合理的认证、会话管理、日志和权限；不要把原文中的公开 IP 和 HTTP 示例直接作为生产配置。
- 以当前项目文档为准核对配置项和镜像版本。

参考：[WebSSH2 项目与配置说明](https://github.com/billchurch/webssh2)。

少输一次密码确实省事，也更值得把凭据和会话边界弄明白。记录连接过程之外，再把访问限制与传输方式补齐，网页SSH才不只是一个看着顺手的演示。
