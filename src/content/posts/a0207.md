ailx10说：这篇是2023年9月之前写的，后来又改过。这次在 Druid 环境里，我先试了文件输入，再往 JavaScript 的过滤配置里继续看。直接看漏洞说明，好像把请求发出去就结束了，实际做的时候，连接那一步让我试了好几次，才有了后面的结果。所以笔记没有只贴最终成功的图，也记下了我怎么从读取能力走到 JavaScript 执行。这里得分清两件事：能读文件和能绕过脚本开关不是同一个结论，配置、版本和请求字段都会影响实验，不能把某一次跑通当成所有环境都一样。

---

本文记录 CVE-2021-25646 的历史实验，包括采样接口读取文件和 JavaScript 配置相关行为。

读取能力与配置绕过是不同步骤；原 JSON 中 transforms 键的空格需对照原始请求验证，示例回连过程未重跑。

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build //可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明Apache Druid 代码执行漏洞（CVE-2021-25646）环境搭建成功了
