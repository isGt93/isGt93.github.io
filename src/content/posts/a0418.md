本篇文章讲的是SSH隧道的本地转发和SSH协议的远程转发，两个实验的环境都是一样的。我们的网络工程师小黑，可以访问跳板机，但是不能访问目标机。然而，跳板机可以访问目标机。聪明的你，能不能帮助小黑在本地电脑上访问目标机呢？

- 本地端口转发：相当于拉数据，本地从跳板机拉取数据
- 远程端口转发：相当于推数据，跳板机把数据推到本地

本地转发与远程转发以监听端相对 SSH 客户端的位置区分：-L 在客户端监听，-R 在服务端监听。转发方向不决定远程桌面的认证权限。

- kali rolling （192.168.160.140）小黑所处位置
- ubuntu18 （192.168.160.137）跳板机
- windows7 （192.168.160.139）目标机

> **本地转发（只需在本地运行指令）**

![](/notes-assets/fe6948a4819500040319.webp)

## 第一步：在kali rolling上运行SSH本地转发命令

- -C 压缩传输
- -f 将SSH传输转入后台执行
- -N 建立静默连接
- -g 允许远程主机连接本地用于转发的端口
- -L 本地端口转发
- 11001 本地端口
- 192.168.160.139:3389 目标主机：目标端口
- `ailx11@192.168.160.137` 跳板机
- 运行命令，输入跳板机的ssh登陆密码，就可以了

```
ssh -CfNg -L 11001:192.168.160.139:3389 ailx11@192.168.160.137
```

![](/notes-assets/c3672b592406407cbee5.webp)

## 第二步：在kali rolling上通过rdesktop连接本地的11001端口

- 连接本地的11001端口，就会自动通过跳板机，连接到目标机的3389端口

```
rdesktop 127.0.0.1:11001
```

![](/notes-assets/8c6c14523db1236505a2.jpg)

- 见证奇迹的时刻到了，成功弹出了rdp远程窗口

![](/notes-assets/3c87b0c49e59606afa66.jpg)

- 输入目标机的用户名和密码，成功远程登陆

![](/notes-assets/a4616dab1ff0cef3cdd1.jpg)

---

> **远程转发（需要在跳板机上运行指令）**

## 第一步：在跳板机ubuntu18上运行SSH远程转发命令

- -R 远程端口转发
- 11111 kali rolling上的端口
- 192.168.160.139:3389 目标主机：目标端口
- `root@192.168.160.140` kali rolling
- 运行命令，输入kali rolling的ssh登陆密码，就可以了

```
ssh -CfNg -R 11111:192.168.160.139:3389 root@192.168.160.140
```

## 第二步：在kali rolling上通过rdesktop连接本地的11111端口

- 连接本地的11111端口，就会自动通过跳板机，连接到目标机的3389端口

```
rdesktop 127.0.0.1:11111
```

看完这两轮，再遇到L和R时，可以先问端口开在哪边。SSH把路接通，并没有替目标服务做认证；网络路径和登录权限仍是两件需要分别验证的事。
