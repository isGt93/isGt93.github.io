ailx10说：这篇是我2024年5月写的。第一次试 DeepSeek API，我先被文档和接入的简单程度吸引，就想拿一条安全告警试试它到底能讲出什么。注册、调用、看消耗，再把 HTTP 请求响应交进去，让模型解释行为和攻击结果。这篇是那次很小的摸底，不是已经把自动研判完整做成了。它留下了一个很实际的起点：先让模型碰一份自己熟悉的材料，看看回答怎样组织、哪些判断值得再追问，再去想它能接进工作的哪一步。

---

本文记录使用 DeepSeek API 辅助分析 HTTP 告警的一次历史探索。模型名称、价格和配额可能变化，应以当前官方文档为准。

路径、状态码或模型回答本身不足以确认攻击成功；原脚本缺少可靠的结构化输出与错误处理，应结合服务端证据人工复核，避免上传敏感数据。

![](/notes-assets/7e03ed4e34eaca4be659.webp)

> 原文引用了当时的模型宣传及试用价格；这些信息不是当前服务承诺。

```
#!/usr/bin/env python
# -*- coding: utf-8 -*-
# @Time    : 2024/5/8 18:39
# @Author  : ailx10
# @File    : ai1.py

import requests
import json

url = "https://api.deepseek.com/chat/completions"

http_req = """GET /webshell.php HTTP/1.1
Accept: */*
Connection: keep-alive
Host: ctf.hackbiji.top
Upgrade-Insecure-Requests: 1
User-Agent: Custom-AsyncHttpClient"""

http_res = """HTTP/1.1 400 Bad Request
Server: nginx/1.15.9
Date: Sun, 24 Dec 2023 21:14:03 GMT
Content-Type: text/html
Content-Length: 157
Connection: close


<html>
<head><title>400 Bad Request</title></head>
<body>
<center><h1>400 Bad Request</h1></center>
<hr><center>nginx/1.15.9</center>
</body>
</html>"""

promt = f"收到一段安全设备的告警日志，包含HTTP请求和HTTP响应，请判断【攻击成功，攻击失败】，回答内容示例{{'攻击结果':'攻击失败','原因':''}} 请严格遵守示例的JSON返回格式。"

question = f"{promt} 待判断的告警日志如下： {http_req} {http_res}"

payload = json.dumps({
  "messages": [
    {
      "content": "You are a helpful assistant",
      "role": "system"
    },
    {
      "content": question,
      "role": "user"
    }
  ],
  "model": "deepseek-coder",

})
headers = {
  'Content-Type': 'application/json',
  'Accept': 'application/json',
  'Authorization': 'Bearer sk-*****************'
}

response = requests.request("POST", url, headers=headers, data=payload)

print(response.text)
```
