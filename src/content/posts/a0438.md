ailx10说：这篇是2022年1月之前写的，后来又改过。WMI 后门这次先有特权会话，再建启动订阅，到目标上查到对应的 Consumer，重启以后看见它触发连接，最后删掉这个对象再试一次。这种前后对照比单看工具成功提示更有意思：对象在时怎样，拿掉以后又怎样。笔记保留了查询和重启过程，让“持久化”不再只是一个标签。后来再整理，也得记得 Filter、Binding 和文件这些其他部分；删除一个 Consumer 能阻止这次示例，却不能替整台机器证明所有相关残留都已经消失。

---

前置条件：已有经授权的实验会话与相应权限。

---

- 本实验基于上一个实验，如果发现运行的时候，提示上下文不对
- 那基本上就是权限不够，需要提权
- 是的，wmi后门需要提权后才能使用

![](/notes-assets/b0c1ac28e0c8a4d303a2.jpg)

原文使用模块生成新会话，界面星号只是工具标记；实际权限需要独立验证。
![](/notes-assets/e68810db98d116b08cd7.jpg)

- 进入模块（usemodule persistence/elevated/wmi）
- 基本上不要配置，直接 run运行(和 execute一样)
- 得到下面的提示，基本上就成功了一半

```
WMI persistence established using listener ailx10 
with OnStartup WMI subsubscription trigger
```

![](/notes-assets/aaf5606bb0bba8f8829f.jpg)

- 进入目标机器上，验证wmi
- 在powershell中直接输入下面的命令
- 结果中可以看到 CommandLineTemlate中的内容包含 powershell.exe
- 胜利的曙光就在眼前 [\[1\]](#ref_1)～

```
Get-WMIObject -Namespace root\Subscription -Class CommandLineEventConsumer -Filter “Name=’Updater’”
```

![](/notes-assets/1bb430d35cc6002643ba.jpg)

- 重启目标机器
- wmi后门成功建立连接
- 2个红色的之前的（无效）
- 2个绿色的新生成的（有效）

![](/notes-assets/45773e4773f074f8f28b.jpg)![](/notes-assets/37182f48637256f40377.webp)

原文删除了该实验的 CommandLineEventConsumer；清理时还应检查相关 Filter、Binding 和其他载荷。

```
Get-WMIObject -Namespace root\Subscription -Class CommandLineEventConsumer -Filter "Name='Updater'" | Remove-WmiObject -Verbose
```

![](/notes-assets/e800cac8c63e06778c3f.webp)

原文在删除消费者后未再观察到本例上线，不能推断所有持久化都已清除。
![](/notes-assets/ff5429c4cb228683febd.jpg)
