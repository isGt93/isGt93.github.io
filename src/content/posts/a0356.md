ailx10说：这篇是2022年1月之前写的，后来又改过。这篇是疫情分诊项目留下的开发总结。最初想做小程序，后台接入却没那么顺利，于是改成响应式 PHP 网站，把医生设计的流程做成页面，补 AJAX、IP 城市信息、后台记录和 CSV 导出。功能做出来以后，又把 ModSecurity 放上去试防护。它不像平时刷一个题，有明确终点，而是不断遇到现实限制再改方案。我负责的是工程落地，不是给人诊断；回头看，最想留下的就是需求、审核、部署和安全怎么一点点挤进同一个小项目里。

---

本文回顾疫情期间一次分诊网站开发，重点是前后端协作、数据处理与部署，不提供医疗建议。

项目最初尝试小程序方案，流程由具有医学背景的合作者设计。

![](/notes-assets/2d0209106e9f95570b33.jpg)

原项目遇到小程序接入、域名和备案问题，随后改为自适应网站。实际规则应以官方要求为准。

网站后端使用 PHP 完成数据存取与管理。

前端使用 HTML 与 AJAX 更新页面内容。

![](/notes-assets/9c18d7de68656ba5ad4c.jpg)

后台使用 IP 地理库辅助记录位置；IP 位置可能不准确，用户数据需要保护。

原文关于其他项目审核的观察不能用于判断审核原因。

![](/notes-assets/359ff5750fa5d9c8ce3f.jpg)

后台展示最新 100 条记录，完整数据导出 CSV；应注意编码、访问权限和隐私。

![](/notes-assets/5756eca46e350c66221e.jpg)

分诊逻辑由医学背景的合作者设计，此记录不是诊疗建议。

![](/notes-assets/24c26c1e74fef498e122.jpg)

由于字段比较多，需要查看表中字段：

```
show FULL COLUMNS FROM demo.demo;
```

由于想知道用户的IP对应的地理位置，添加城市字段：

```
alter table demo add column city varchar(50);
```

由于打入了测试数据，需要删除：

```
delete from demo where phone="18100000000";
```

由于不怎么熟悉医学领域的业务，所以数据库的表的字段在不停的变，最后全部都加上了注释，总算看明白了。总之，千辛万苦，这个假期最大的收获就是不怕困难。
